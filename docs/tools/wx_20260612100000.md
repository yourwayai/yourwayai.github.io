# Open Notebook：开源且本地化的 NotebookLM 替代方案，彻底将数据主权交还给你！

* **原文链接**: [https://mp.weixin.qq.com/s/xQPnkodgHKQ1jUwJugwpdg](https://mp.weixin.qq.com/s/xQPnkodgHKQ1jUwJugwpdg)
* **作者**: YourwayAI

---

一直以来，我都在寻找一个既能像 Google NotebookLM 那样处理复杂多模态文档，又不至于让我的研究数据完全脱离本地掌控的工具。在尝试过各种笔记应用后，我将目光锁定在了 `open-notebook` 这个开源项目上。它不仅号称是 NotebookLM 的平替，更关键的是，它将数据的"自主权"重新交还到了用户手中。

### 从云端走向本地的知识管理探索

部署过程异常干脆，项目采用了典型的 `docker-compose` 架构。作为一名习惯了在终端处理环境的开发者，这种方案省去了解决 Python 依赖冲突的繁琐。

你需要先创建一个 `docker-compose.yml` 文件。虽然官方提供了直接下载链接，但我建议手动编写以确认每个环境变量的含义：

```yaml
services:
  surrealdb:
    image: surrealdb/surrealdb:v2
    command: start --log info --user root --pass root rocksdb:/mydata/mydatabase.db
    user: root
    ports:
      - "8000:8000"
    volumes:
      - ./surreal_data:/mydata
    restart: always
  open_notebook:
    image: lfnovo/open_notebook:v1-latest
    ports:
      - "8502:8502"
      - "5055:5055"
    environment:
      - OPEN_NOTEBOOK_ENCRYPTION_KEY=change-me-to-a-secret-string
      - SURREAL_URL=ws://surrealdb:8000/rpc
      - SURREAL_USER=root
      - SURREAL_PASSWORD=root
      - SURREAL_NAMESPACE=open_notebook
      - SURREAL_DATABASE=open_notebook
    volumes:
      - ./notebook_data:/app/data
    depends_on:
      - surrealdb
    restart: always
```

将 `OPEN_NOTEBOOK_ENCRYPTION_KEY` 改为任意自定义的密钥字符串，随后执行：

```bash
docker compose up -d
```

等待约 15～20 秒后，打开浏览器访问 `http://localhost:8502`，即可看到产品界面。

### 🆚 为什么选 open-notebook 而不是 Google NotebookLM？

官方 NotebookLM 的核心体验无可挑剔，但它天然携带着三重"枷锁"：

* **数据隐私隐患**：你上传的每一份私密研究资料，都将以某种形式流经 Google 的服务器。
* **模型单一性**：你只能被动接受 Google 提供的模型，缺乏替换更优或更廉价 AI 的灵活性。
* **播客格式僵化**：深度聊天的对话形式是唯一的音频输出形式，无法自定义主持人数量和说话风格。

open-notebook 用一套完全开源且自托管的方案正面击破了这三点限制。

### ⚡ 核心功能全景

**多模态内容支持**：支持直接导入 PDF、YouTube 视频（自动提取字幕）、音频文件、网页、Office 文档等多种格式，统一存入知识库进行管理。

**18+ AI 供应商无缝切换**：借助底层的 `Esperanto` 库，项目同时支持 OpenAI、Anthropic、Google Gemini、Ollama（本地免费）、LM Studio、Groq 等超过 18 个主流供应商，并兼容任何 OpenAI 兼容接口。在本地的 macOS M3 环境测试中，通过 Ollama 挂载本地模型，整体响应延迟与托管 API 相比仅有细微差距。

**专业级播客生成**：这是让我印象最深刻的特性之一。不同于 NotebookLM 固定的双人对话格式，open-notebook 允许你创建自定义的"节目档案（Episode Profile）"，灵活定义主持人数量、说话风格和内容侧重点，从而生成高度个性化的多主持人播客脚本与音频。

**全文与向量双重检索**：针对所有导入内容，系统同时建立传统全文搜索索引与向量嵌入索引，使跨 Notebook 的语义级检索成为可能。当你的知识库积累到一定体量后，这一特性的价值将呈指数级增长。

**深度思考模型支持**：完整兼容 DeepSeek-R1、Qwen3 等推理模型，在处理复杂的学术分析与逻辑推导任务时，质量显著优于标准对话模型。

**REST API 开放接口**：项目内置了完整的 REST API 服务（默认运行在 `http://localhost:5055/docs`），使其能够作为后端核心无缝集成进你自己的应用或自动化工作流。

### 🔧 上手配置中的真实体验

在 AI 供应商配置页面，点击"模型"→"添加配置"→粘贴 API Key，整个流程清晰流畅。你可以通过"测试连接"按钮即时验证密钥的有效性，再通过"同步模型"拉取该供应商下的所有可用模型，最后设置不同任务（聊天、嵌入、语音合成等）的默认模型分配。

整个初始化过程在图形界面内完成，无需手动编辑任何配置文件。

### 🌐 国际化与多语言 UI

当前版本的 UI 已提供英语、葡萄牙语、简体中文、繁体中文、日语、俄语和孟加拉语七种语言的完整本地化支持。对于中文用户而言，整个交互体验无任何语言壁垒。

### ⚠️ 局限性与注意事项

* **对 SurrealDB 的强依赖**：项目选用了相对小众的 SurrealDB 作为后端数据库，而非 PostgreSQL 等主流选型。这在带来一定灵活性的同时，也意味着社区支持资源相对有限，遇到数据库层面的深度问题时，排查难度会较高。
* **播客生成需要 TTS API**：高质量的播客音频生成依赖外部 TTS 服务（如 OpenAI TTS 或 ElevenLabs），并非完全免费的本地化方案，在规模化生成时需要计算额外成本。
* **资源消耗**：若同时启用向量嵌入功能（默认开启），系统对硬件资源的要求会显著提升，建议在配置 16GB 以上内存的机器上运行以获取流畅体验。

对于任何将本地知识管理与 AI 辅助研究视为刚需的极客与内容创作者，open-notebook 是目前开源社区中综合能力最强、可定制性最高的 NotebookLM 平替方案，值得深度体验与长期投入。
