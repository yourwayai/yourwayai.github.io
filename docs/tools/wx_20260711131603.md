# 拒绝 AI 的格式幻觉：用 obsidian-skills 规范本地知识库的生成逻辑

💻 **通用 AI 面对本地笔记的“水土不服”**

在个人知识管理（PKM）领域，许多极客习惯将大语言模型（LLM）引入工作流，用来对长文章进行总结或生成结构化笔记。但在没有标准化约束的过去，这种跨界整合往往伴随着巨大的摩擦力。

当我们直接让通用 AI 助手（如原生的 ChatGPT 或传统的终端 AI 节点）生成一份笔记并存入本地 Vault（知识库）时，它通常会把 Obsidian 视为一个最基础 of 通用文本编辑器。最典型的灾难现场是：它会顽固地使用标准 Markdown 的 `[文本](链接)` 语法，而不是 Obsidian 原生的 `[[双向链接]]`；它分不清 YAML Frontmatter（前言属性）与正文内联标签的区别；在面对文件嵌入 `![[文件名]]` 等特有语法时，更是频频触发格式幻觉。

这就导致了一个尴尬的局面：AI 确实帮你生成了内容，但为了让这些内容在你的本地知识图谱中正确渲染和链接，你不得不花大量时间去手动排版、修改引用格式。这种“半自动”的体验极大拖慢了研究效率。

### 📌 用 Agent Skills 给大模型定规矩

为了解决这种格式上的错位，Obsidian 的 CEO Steph Ango（社区昵称 kepano）在 GitHub 上开源了 `obsidian-skills` 项目。这套方案的底层逻辑非常干脆：既然大模型的预训练数据无法精准对齐每一个本地软件的独有语法，那就给它挂载一本“操作手册”。

该项目并非一个需要安装在 Obsidian 内部的传统插件，而是基于 Agent Skills（一种为智能体提供标准化工具调用说明的开放规范）编写的指令集文件。这些本质上是纯文本（Markdown/YAML 格式）的规则手册，向 AI 详细拆解了 Obsidian 独有的文件结构和 API 逻辑。

部署过程极具现代前端工程的风格。如果你使用的是 Claude Code，只需在你的知识库根目录下打开终端，执行以下命令：

```
npx skills add git@github.com:kepano/obsidian-skills.git
```

执行后，系统会在本地生成一个隐藏目录（通常为 `.claude/skills/`），将包括 `obsidian-markdown`、`json-canvas`、`obsidian-bases` 等核心技能包拉取到本地。当你在终端唤起 AI 时，大模型会优先读取这些结构化约束，从而彻底改变其代码与文本生成行为。

### 📊 以构建可视化概念图谱为例

为了直观展现这套规范库的威力，我们设定一个高阶场景：**让 AI 根据特定主题，直接在本地生成一张包含逻辑节点的可视化白板（Canvas）。**

在没有加载 `json-canvas` 技能前，如果你向大模型下达“生成一个解释 MCP（模型上下文协议）概念的白板”的指令，它最多只能给你返回一段模拟结构的 JSON 代码，你甚至需要手动新建文件并复制粘贴进去，祈祷语法不要报错。

但在挂载了 `obsidian-skills` 之后，工作流发生了质变。大模型在接到指令的第一时间，会主动查阅本地的 `json-canvas.md` 规则文件。它“学会”了 JSON Canvas 这个开源格式的核心 Schema（模式），理解了什么是 `nodes`（节点）、`edges`（连线）以及各种几何图形的坐标换算逻辑。

随后，Claude Code 会直接在你当前的知识库路径下，安静地写出一个名为 `MCP-Concept.canvas` 的文件。当你切回 Obsidian 界面打开它时，你会看到一个布局规整、连线清晰的思维导图已经躺在你的本地库里，且节点之间的双链引用符合 Obsidian 的底层规范。

```
/plugin marketplace add kepano/obsidian-skills  
/plugin install obsidian@obsidian-skills
```

同样的工作流也适用于最近大火的 Bases（结构化数据库）格式。通过对应的 skill 文件，AI 能够准确抓取你指定的几篇 Markdown 笔记的元数据，并汇总输出为一个 `.base` 格式的动态表格，全程不需要你手动配置任何过滤条件。

### ⚠️ 避坑与总结：客观的局限性考量

虽然 `obsidian-skills` 展现了极高的工程美学，但在目前的实际调用中，依然存在一些需要开发者关注的物理局限。

首先是**路径上下文的迷失问题**。Agent Skills 赋予了 AI 读写本地特殊格式的能力，但它无法替 AI 定位你的工作区。如果你在操作时没有将终端的工作目录（CWD）严格设定为 Obsidian Vault 的根目录，AI 极易在创建双链或检索资源文件时发生相对路径错乱，导致生成的链接全部变成无法点击的“孤儿节点”。

其次是**不可忽视的 Token 隐性开销**。每一条被激活的技能（如 `obsidian-markdown`），其背后都是长达数百行的结构化 Prompt 和 JSON Schema 示例。在多轮对话中，这些规则会被持续塞入大模型的系统上下文（System Prompt）中。这不仅会轻微拖慢首字节响应时间（TTFB），在处理重度知识库检索时，也会让你的 API 费用账单出现明显的非业务性增长。如果你使用本地小参数模型（如 Llama 3 8B）来运行这些规范，可能会因为上下文窗口溢出而导致模型直接“降智”。

总体而言，`kepano/obsidian-skills` 并非为普通小白用户准备的开箱即用玩具，而是面向重度 PKM 玩家和效率极客的“基础设施补丁”。它用最轻量级的纯文本协议，向我们证明了一个健康的软件生态应该是什么样：不强行将 AI 封闭在自家的付费云端里，而是开放底层格式标准，让所有符合规范的本地智能体都能成为你的超级助理。
