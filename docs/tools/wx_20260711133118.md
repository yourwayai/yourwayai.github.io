# 如何在受限硬件上跑起大参数模型？AirLLM 部署笔记

* **原文链接**: [https://mp.weixin.qq.com/s/-N6GHPbzuAweyH6QGb3b5w](https://mp.weixin.qq.com/s/-N6GHPbzuAweyH6QGb3b5w)
* **作者**: YourwayAI

手里这台开发机显存只有 8GB，但最近想跑一下 Llama-3 70B 的模型做实验。按照常规量化后的要求，70B 模型至少需要 24GB 以上的显存才能流畅运行，这直接卡死了我的本地实验进度。在翻阅 GitHub 时，我注意到了 AirLLM 这个项目。它的核心卖点是能在极低显存（甚至是 4GB 显存）的硬件上运行大语言模型。今天就来折腾一下，看看它到底是“低功耗解决方案”，还是“因为速度太慢而只能收藏的玩具”。

### 部署实录

AirLLM 的安装过程非常直观，保持了轻量级项目的简洁。环境基于常见的 Python 技术栈：

```
pip install airllm
```

安装完成后，代码调用的方式也相当克制。我尝试在本地加载了一个 70B 的 Llama 模型，逻辑与 Transformers 的原生库非常相似：

```
from airllm import AutoModel  
# 定义模型路径  
model_path = "meta-llama/Meta-Llama-3-70B"  
# 初始化模型  
model = AutoModel.from_pretrained(model_path)  
# 执行推理  
input_text = "What is the capital of France?"  
output = model.generate(input_text)  
print(output)
```

在 M 芯片的 Mac 或 NVIDIA 显卡环境下，代码运行并没有报错。

但在实际运行中，有一个明显的“坑”：它不是为了即时响应设计的。当你调用 `model.generate` 时，显存占用确实保持在了一个极低的水平，因为它采用了分层推理的方式，将模型权重按需加载到内存中，而不是一次性全部塞进显存。

### 核心亮点

AirLLM 最打动我的功能点在于其“层级化推理”的设计思路。

1. **显存利用率最大化**：传统的推理框架要求模型层全部驻留显存，而 AirLLM 将推理过程拆解，确保任何时刻，只有当前计算所需的权重层驻留在 VRAM（显存）中。这对于没有高端显卡的开发者来说，确实提供了运行超大参数模型的入场券。
2. **跨平台兼容性**：不仅支持 GPU，在纯 CPU 且内存有限的环境下，它也能通过类似机制完成推理。这在部署一些边缘计算设备或轻量级服务器时，具有实际参考价值。
3. **代码侵入性低**：如果你已经有基于 HuggingFace Transformers 开发的代码，迁移到 AirLLM 的工作量极小。API 设计尽可能保持了对齐，降低了迁移成本。

### 避坑与总结

必须说清楚的是，AirLLM 并不适合所有场景。

它最大的局限性在于推理速度。由于频繁的权重交换（Disk/RAM -> VRAM），它的 Token 生成速度非常慢。在我的 8GB 显存环境下，70B 模型的输出速度大约只有 0.5-1 tokens/s。这意味着它**绝对不适合**作为聊天机器人后端或需要实时交互的应用。

但它的价值在于：如果你需要处理一个不需要实时性，但必须由大模型进行深度推理、数据标注或长文本分析的任务（比如离线批量处理报告），那么 AirLLM 提供了一种“即使硬件简陋，也能通过时间换空间”的解决方案。

总结：这是一个极具实验性质的库。适合硬件受限，但有特定推理需求的极客用户。如果你的硬件显存足够运行模型（哪怕是 4-bit 量化），请优先选择 vLLM 或 Ollama 等成熟框架。
