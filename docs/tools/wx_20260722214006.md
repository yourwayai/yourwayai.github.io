在过去的一年里，各类 AI 幻灯片生成工具层出不穷。然而，作为深度依赖 Office 生态的职场人或开发者，这些工具在实际工作流中往往是个“灾难”——绝大多数轻量级工具生成的所谓 PPTX 文件，其实是在每一页里塞入了一张排版好的完整大图；而像 Gamma 这类体验极佳的工具，本质上是网页渲染，一旦导出为传统 PowerPoint 格式发给客户，版式就会不可逆地错乱。

在这个背景下，由国内开发者 Hugo He 开源的 **PPT Master** 提供了一条极客且务实的解题思路：**它不仅生成好看的设计，更重要的是，它通过代码将 AI 生成的内容 100% 转化为原生的、可二次编辑的 PPTX 对象。**

### LLM -> SVG -> 翻译为原生控件

PPT Master 的定位并非一个独立带 GUI 的软件，而是作为一个“工作流脚本（Skill）”运行在具有 AI Agent 能力的 IDE 中（如 Claude Code、Cursor、VS Code Copilot 等）。

它的核心技术是一条巧妙的中间路径：**让大模型编写 SVG 代码，再由 Python 脚本将 SVG 精准解析并翻译为 PowerPoint 底层的 DrawingML 矢量语言。** 这完美避开了让 LLM 直接编写臃肿且容易崩溃的 OOXML（Office 格式代码）的雷区。

### 极客部署

PPT Master 的部署完全面向开发者，依赖 Python 3.10+ 环境。以下是我们在实测中最顺畅的部署路径。

**1. 基础环境就绪**  
确保你的系统已安装 Python 及其包管理工具（以 macOS 为例）：

```
brew install python
```

*(注：绝大部分现代文档如 `.docx`, `.html`, `.ipynb` 均已被 Python 原生支持，只有当你需要处理 `.tex` 或 `.rst` 等冷门格式时，才需要额外 `brew install pandoc`。)*

**2. 核心项目获取**  
我们推荐直接 Clone 仓库，这样后续通过脚本拉取更新最为方便：

```
git clone https://github.com/hugohe3/ppt-master.git  
cd ppt-master  
# 安装底层依赖  
pip install -r requirements.txt
```

对于习惯使用 Claude Code CLI 等命令行 Agent 的用户，也可以直接从 Marketplace 注入该技能，而不必下载完整仓库：

```
# 在终端直接全局引入  
npx skills add hugohe3/ppt-master  
# 或在 Claude Code 对话状态下引入  
/plugin marketplace add hugohe3/ppt-master  
/plugin install ppt-master@ppt-master
```

### 工作流与终端指令交互

配置完成后，我们用Cursor（配合 Claude 3.5 Sonnet）跑通了整个流程。你只需在 IDE 中打开`ppt-master` 目录，唤出 AI 对话框。

**触发指令非常直接（无需复杂的 Prompt 调优）：**

```
You: Please create a PPT from projects/q3-report/sources/report.pdf
```

或者直接将大段文本喂给终端：

```
You: Please turn the following into a PPT: [粘贴你的 Markdown/文本内容...]
```

此时，Agent 会接管流程，它不会立刻盲目生成，而是通过终端向你确认参数配置。你会看到类似这样的控制台回显：

```
AI:  Sure. Let's confirm the design spec:  
     [Template] B) Free design  
     [Format]   PPT 16:9  
     [Pages]    8-10 pages  
     ...
```

确认后，AI 开始分析内容并大规模生成 SVG 代码。项目会在 `exports/` 目录下生成最终的 `.pptx` 文件，并在 `backup/` 目录下保留 SVG 源码以供追溯。

### 进阶参数：让图表真正“活”过来

PPT Master 最硬核的功能在于它的进阶编译参数。默认情况下，为了保证跨平台（PowerPoint / Keynote / WPS）的像素级绝对一致，生成的图表会被解析为矢量形状。

但如果你在最终导出阶段通过指令触发了 `--native-objects` 参数：

```
# Agent 在执行导出脚本时附带该参数  
# 输出文件将变为：exports/<name>_<timestamp>_native_charts.pptx
```

此时，原本由 SVG 绘制的柱状图或饼图，会被 Python 脚本**逆向构建为包含底部 Excel 数据表（Data-backed）的真实 PowerPoint 图表对象。** 这意味着生成完毕后，你可以直接右键图表“编辑数据”，这才是真正符合商业级二次修改标准的设计。

**图像与资产的自动化**  
如果你不想让 PPT 看起来太干瘪，可以通过配置 `.env` 环境变量来接入图像引擎：

```
# 拷贝环境变量模板  
cp .env.example .env  
  
# 在 .env 中填入免费的 PEXELS_API_KEY  
PEXELS_API_KEY=your_key_here
```

此时，脚本中的 `image_search.py` 会在生成幻灯片时，自动去图库抓取高质量的商用授权图片并嵌入其中。如果你倾向于 AI 生成配图，也可以测试其支持的后端引擎：

```
# 检视目前支持的 AI 图像生成后端  
python3 skills/ppt-master/scripts/image_gen.py --list-backends
```

### 避坑与总结

PPT Master 是一个将“大模型上限”与“本地脚本下限”结合得非常精妙的开源项目。但需要注意的是：**算力成本决定了出图的成功率。**

由于生成复杂的 SVG 极度消耗上下文（Context Window），官方强烈建议使用 Claude Opus（4.7）或 Claude 3.5 Sonnet，并搭配 `gpt-image-2`。如果在实测中为了节省 Token 切换到小参数模型（如 GPT-4o-mini 或开源小模型），极易出现 SVG 标签闭合错误，直接导致 Python 脚本在解析时抛出语法异常，最终无法生成 PPTX 文件。

如果你是具备一定技术背景、需要处理深度定制文档的咨询师、分析师，并且已经习惯了在 CLI 或Cursor中工作，PPT Master 是目前市面上最能打的“工业级”原生幻灯片生成方案。但前提是：你要舍得为高级模型的 API 消耗买单。
