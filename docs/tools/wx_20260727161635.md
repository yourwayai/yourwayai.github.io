# 拒绝无尽的信息流刷屏：AI 资讯提炼工具 ClawFeed 打造个人专属的高密度智能剪报

* **原文链接**: [https://mp.weixin.qq.com/s/-2-NhwdqMgA9AEuLQhNgSQ](https://mp.weixin.qq.com/s/-2-NhwdqMgA9AEuLQhNgSQ)
* **作者**: YourwayAI

---

今天我们来深度实测并拆解一个能帮你把碎片化时间从信息泥潭中拯救出来的开源 AI 资讯提炼与分发平台：**`ClawFeed`**。

在这个信息爆炸的时期，每天面对社交媒体、技术社区和上百个 RSS 订阅源时，低噪、高质的“智能简报”正成为极客们的刚需。

区别于市面上许多依赖高昂商业云服务、功能单一的“AI 摘要”工具，ClawFeed 在底层上展现出了极高的工程完整性。

它是一个纯本地轻量运行、自带 SQLite 数据库和 Web 仪表盘的系统，更创新地将自身作为 **OpenClaw** 与 **Zylos** 两大智能体框架的插件（Skill），让 AI 智能体自主在后台调度、抓取、提炼，并自动通过 RSS/JSON Feed 格式进行二次分发，这极大地对齐了现代自主智能体（Autonomous Agent）的工程开发心智。

### 部署实录

在进行本地和容器部署前，我们对 ClawFeed 的底层依赖进行了分析：

* • **最新版本**：由开发者 Kevin He 主导，当前主分支版本号由 tag 动态维护，代码库自带完整的 2026 年最新 MIT 协议声明。
* • **数据库与依赖**：主程序采用 Node.js 运行时，数据库使用零配置、便携易迁移的 **SQLite** 存储（数据默认落盘在 `/app/data` 目录）。
* • **测试完整度**：项目在 `test/` 目录下内置了极其规范的测试套件，包含一键模拟测试用户的 `./setup.sh` 和执行 66 个端到端（E2E）接口用例的 `./e2e.sh`。

如果你拥有标准的 Node.js 运行环境，最快捷的 standalone 本地开发部署步骤如下：

```
# 1. 克隆代码仓库并进入目录  
git clone https://github.com/kevinho/clawfeed.git  
cd clawfeed  
  
# 2. 安装项目所需的全部依赖包  
npm install  
  
# 3. 复制并修改环境变量配置文件  
cp .env.example .env
```

为了让多用户体系和定时任务安全跑起来，我们需要在本地的 `.env` 中声明以下核心配置，特别是用于内容抓取鉴权和多用户 Google OAuth 认证的参数：

```
# --- ClawFeed 本地环境变量核心配置示例 ---  
# 服务端口与跨域配置  
DIGEST_PORT=8767  
ALLOWED_ORIGINS=https://digest.yourdomain.com  
  
# 自动摘要 API 密钥防护  
API_KEY=your_secure_random_api_key_here  
  
# 谷歌 OAuth 2.0 账号体系配置（多用户必选，否则进入 Read-only 模式）  
GOOGLE_CLIENT_ID=your-google-client-id-from-cloud-console.apps.googleusercontent.com  
GOOGLE_CLIENT_SECRET=your-google-client-secret-key-goes-here  
SESSION_SECRET=your-random-session-encryption-cookie-secret  
  
# 本地 SQLite 数据路径（默认自动创建）  
DATABASE_PATH=./data/clawfeed.sqlite
```

配置完毕后，我们可以在后台常驻拉起这个 Node.js 进程。运行后，控制面板默认在 `http://127.0.0.1:8767` 端口启动：

```
# 4. 启动开发服务器（支持代码保存自动重载）  
npm run dev  
  
# 终端输出日志示例：  
# > clawfeed@1.0.0 dev  
# > tsx --watch src/server.ts  
#  
# [info] 🚀 ClawFeed API Server running on http://127.0.0.1:8767  
# [info] 💾 SQLite database successfully initialized at ./data/clawfeed.sqlite  
# [info] 📡 Curation system and templates loaded successfully
```

如果你更喜欢容器化运维，直接使用 Docker 在后台一键拉起并持久化挂载数据卷，同时将上述环境变量通过 `-e` 注入容器即可：

```
docker run -d \  
  -p 8767:8767 \  
  -v clawfeed-data:/app/data \  
  -e ALLOWED_ORIGINS=https://digest.yourdomain.com \  
  -e GOOGLE_CLIENT_ID=your-client-id \  
  -e GOOGLE_CLIENT_SECRET=your-client-secret \  
  -e SESSION_SECRET=your-session-secret \  
  -e API_KEY=your_api_key_here \  
  kevinho/clawfeed
```

#### 亮点一：深度拥抱 OpenClaw 与 Zylos 的“智能体原生”设计

传统的部署工具通常只是一个普通的 Web 网站，而 ClawFeed 最让人兴奋的，是其作为“智能体技能（Agent Skill）”的极客设计。

当把它克隆进 OpenClaw 框架的 `~/.openclaw/skills/` 路径后，OpenClaw 的常驻 Agent 在初始化时会自动识别目录下的 `SKILL.md` 规范。

此时，智能体无需人类插手，即可通过底层的定时任务（Cron）在后台自动触发 ClawFeed 摘要生成逻辑、响应终端的书签操作指令、并基于后台日志自主纠错，完成了从“人去操作软件”到“AI 代理自主运维”的代际跨越。

#### 亮点二：多频段梯度摘要与多源导入生态

在资讯收集侧，ClawFeed 内置了极其丰富的集成源：

* • **丰富的数据源接入**：不仅支持经典的 RSS/Atom 格式，更直接集成了 Twitter 用户流、Hacker News 首页、GitHub 热门趋势（Github Trending）、Reddit 子版块以及任意普通网页的自动内容抓取。
* • **多频段资讯摘要（Multi-frequency Digests）**：支持 4 小时、每日、每周、每月四个完全不同的梯度频段提炼，既能让你跟进热点技术（4h 频段），也能帮你回顾深度行业趋势（月度频段）。
* • **一键打包分享（Source Packs）**：支持用户将自己精选的订阅源打包为 Source Pack，分享给社区中的其他极客，实现资讯源的无痛共享。

#### 亮点三：可定制的“降噪规则”与“AI 评估提示词”

市面上大部分 AI 提炼工具的局限性在于无法干预 AI 的偏好。

ClawFeed 贴心地将控制权完整交还给了用户：

* • 你可以通过直接编辑本地 `/templates/curation-rules.md` 来控制内容过滤和去重的技术规则。
* • 同时，通过配置 `/templates/digest-prompt.md` 自定义你专属的 AI 摘要提示词，从而精准指挥类似 **Claude Sonnet 5** 这样的强推理模型，让它输出具有特定语调、排版格式和深度极客洞察的剪报。

### 避坑与总结

在本地部署和高频使用中，我们也发现了 ClawFeed 项目目前的几处技术痛点和架构局限性：

* • **OAuth（开放授权协议）认证的强制门槛**：ClawFeed 提供了完善的个人书签（Mark）和自定义订阅源功能。但这些功能强依赖于 Google OAuth。如果没有在 `.env` 中正确配置 Google Cloud 控制台的客户端凭证，整套系统将自动回退（Fallback）到只读模式（Read-only Mode），无法使用多用户隔离功能。
* • **代理环境对海外源抓取的制约**：由于该项目主要抓取 Twitter、Reddit 等海外技术平台，如果你的本地部署环境没有配置全局系统级网络代理（Proxy），在执行定时抓取任务时极易遇到由于 TLS 连接超时或域名无法解析（DNS Resolution Error）导致的容器后台频繁报错。建议配合以下 Caddyfile 反向代理配置或全局科学上网网关联合部署：

```
# Caddy 生产环境配置示例  
digest.yourdomain.com {  
    # 静态前端资源分发路径  
    handle_path /digest/* {  
        root * /path/to/clawfeed/web  
        file_server  
    }  
  
    # 动态 API 请求反向代理至 Node.js 监听端口  
    handle /digest/api/* {  
        uri strip_prefix /digest/api  
        reverse_proxy localhost:8767  
    }  
}
```
