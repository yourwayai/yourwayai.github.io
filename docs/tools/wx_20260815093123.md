上周在给一个 RAG 知识库塞入几十个技术文档站点时，遇到个老问题：`curl` 下载下来的 HTML 里塞满 `<nav>`、`<script>`、广告位、以及十几层嵌套的 `<div>`。直接扔给 embedding 模型，token 浪费在噪音上，检索精度还下降。

以前的套路是写 Python 脚本，用 `readability-lxml` 或 `trafilatura` 做离线清洗，再存入向量库。但这意味着维护一套爬虫、调度器、去重逻辑——对于“临时把某个页面喂给 Claude/ChatGPT 问两句”这种轻量场景，未免重了。

GitHub 搜到 **MD-This-Page**（1.2k ⭐，MIT 协议），号称“右键一键把当前网页变成干净 Markdown”。看架构：Plasmo 框架、Manifest V3、内容脚本里内嵌 Defuddle（Mozilla Readability 的 TS 移植）+ Turndown 做 HTML→MD。正好我手边有现成的 Chrome/Edge 环境，决定周末把它从源码跑通，顺便摸摸底层细节。

## 部署实录

### 环境与命令

```
# 1. 克隆 & 进目录  
git clone https://github.com/Ademking/MD-This-Page.git  
cd MD-This-Page  
  
# 2. 装依赖（必须 pnpm，lockfile 写死）  
pnpm install  
  
# 3. 起开发服务器（会在 build/chrome-mv3-dev 生成可加载的解包扩展）  
pnpm dev
```

`pnpm dev` 跑完后，Chrome 打开 `chrome://extensions/`，开启“开发者模式” → “加载已解压的扩展程序” → 选 `build/chrome-mv3-dev` 目录。工具栏会多出一个 “.MD” 图标，右键网页也会出现 “.MD this page” 菜单，快捷键默认 `Alt+M`（在 `package.json` 的 `manifest.commands` 里声明）。

### 生产构建与打包

```
# Chrome MV3 打包成 .zip（可直接上传 Chrome Web Store）  
pnpm build:chrome  
  
# Firefox MV3 打包  
pnpm build:firefox  
  
# 双端一次性出包  
pnpm build:all
```

产物分别在 `build/chrome-mv3-prod.zip` 和 `build/firefox-mv3-prod.zip`。解压后能看到标准 MV3 目录结构：`manifest.json`、内容脚本 `content.js`、背景脚本 `background.js`、选项页 `options.html`、预览页 `tabs/markdown.html`、以及打包后的 React 组件 chunk。Plasmo 0.90.3 把 `manifest.json` 的 `background.service_worker` 指向 `background.js`，内容脚本通过 `content_scripts.matches: ["<all_urls>"]` 注入——这是后文要提到的隐私攻击面来源。

### 踩坑记录

| 现象 | 原因 | 解法 |
| --- | --- | --- |
| `pnpm dev` 报 `plasmo: command not found` | Plasmo 0.90.x 把 CLI 做成了本地依赖，不在 PATH 里 | 用 `pnpm plasmo dev` 或 `npx plasmo dev` |
| Firefox 下 `pnpm dev:firefox` 启动后扩展不生效 | `manifest.json` 里 `browser_specific_settings.gecko.id` 必须与 `web-ext` 签名一致 | 先 `pnpm build:firefox` 生成 zip，再用 `web-ext sign` 或临时安装 |
| 内容脚本注入到 `chrome://extensions/` 等特权页报错 | `content.ts` 没做 URL scheme 过滤，`document` 为空 | 自己在 `extractPageData()` 头部加 `if (!document.body) return`；已向上游提 PR |
| 单页应用（SPA）内容抓取为空 | Defuddle 只能拿 SSR 后的初始 DOM，客户端渲染的内容尚未挂载 | 手动触发一次“Open Preview Tab”，或等作者合并 “await networkIdle” 方案 |
| `pnpm build` 报 `katex` 字体缺失 | 生产构建时 `rehype-katex` 需要字体文件，CI 环境无图形界面 | 在 CI 步骤前加 `apt-get update && apt-get install -y fontconfig` |

## 核心亮点

### 1. Defuddle + Turndown：把 “网页清洗” 做在浏览器端

`content.ts` 只有 99 行（90 loc），核心逻辑极简：

```
import Defuddle from "defuddle"  
import TurndownService from "turndown"  
import type { PageData } from "~lib/format"  
  
const turndown = new TurndownService()  
  
function extractPageData(): PageData {  
  const defuddle = new Defuddle(document, {  
    url: location.href,  
    removeExactSelectors: true  
  })  
  
  const result = defuddle.parse()  
  
  let markdown = ""  
  if (result?.content && result.content.trim().length > 0) {  
    markdown = turndown.turndown(result.content).trim()  
  }  
  
  // 兜底：若 Readability 失效，直接拿 <main>/<article>/body 再跑一遍 Turndown  
  if (!markdown) {  
    document  
      .querySelectorAll('script, style, link, noscript, svg, [aria-hidden="true"]')  
      .forEach((el) => el.remove())  
    const body =  
      document.querySelector('[role="main"]') ||  
      document.querySelector("main") ||  
      document.querySelector("article") ||  
      document.body  
    markdown = turndown.turndown(body?.innerHTML || "").trim()  
  }  
  
  return {  
    markdown,  
    title: result?.title || document.title,  
    author: result?.author || "",  
    date: result?.published || "",  
    url: location.href,  
    domain: result?.domain || location.hostname,  
    raw: result  
  }  
}
```

**Defuddle**（`defuddle` npm 包，0.13.0）是 Mozilla Readability 的 TypeScript 移植，原理同 Firefox “阅读视图”：基于启发式规则（标签权重、class/id 关键词、链接密度、文本长度等）把正文从 DOM 树里切出来。比起 `readability-lxml` 这种 Python 移植，它直接运行在浏览器原生 DOM 上，**无需序列化 HTML 再解析**，省去一层转换损耗，也避免了 `lxml` 对某些不合规 HTML 的容错差异。

**Turndown**（7.2.4）把干净的 HTML 片段转成 CommonMark。两者组合的效果是：导航栏、侧边栏、广告、`<script>`/`<style>` 全被 Defuddle 丢弃；正文里的标题层级（`h1`~`h6`）、列表（`ul`/`ol`）、代码块（`pre>code`）、表格（`table`）、图片（`img`）、链接（`a`）结构完整保留。

实测在 **Vercel 文档页**、**GitHub README**、**掘金技术文章**、**Notion 公开页面**、**MDN Web Docs**、**Stripe API Reference** 上，提取出的 Markdown 结构完整度肉眼可见 >95%。唯独 **Angular/React 纯客户端渲染且未 SSR 的页面**（如某些内部管理后台、Twitter/X 时间线、Discord 频道页），首屏 DOM 里只有 `<app-root></app-root>` 或空白 `div`，Defuddle 判定正文为空，兜底逻辑又拿到整个 `body`，反而把一堆脚本标签转成了乱码 Markdown。这是目前已知的硬伤（Issue #1），作者在 PR #12 里尝试引入 `await new Promise(r => requestIdleCallback(r))` 等待水合完成，但尚未合并。

### 2. 为 LLM 工作流设计的 “Prompt 模式” 与 “页面结构图”

`lib/format.ts`（152 行，127 loc）里两个小函数最实用：

```
export function asPrompt(markdown: string): string {  
  return "```markdown
" + markdown + "
```"  
}  
  
export function generatePageMap(  
  markdown: string,  
  title: string = "Document Structure"  
): string {  
  const lines = markdown.split("
")  
  const headings: { level: number; text: string }[] = []  
  
  lines.forEach((line) => {  
    const match = line.match(/^(#{1,6})\s+(.+)$/)  
    if (match) {  
      headings.push({ level: match[1].length, text: match[2].trim() })  
    }  
  })  
  
  if (headings.length === 0) return ""  
  
  // 构建树形结构  
  interface HeadingNode {  
    text: string  
    level: number  
    children: HeadingNode[]  
  }  
  const root: HeadingNode = { text: title, level: 0, children: [] }  
  const stack: HeadingNode[] = [root]  
  
  headings.forEach((h) => {  
    const node: HeadingNode = { text: h.text, level: h.level, children: [] }  
    while (stack.length > 1 && stack[stack.length - 1].level >= h.level) {  
      stack.pop()  
    }  
    stack[stack.length - 1].children.push(node)  
    stack.push(node)  
  })  
  
  // 渲染为纯文本树（类似 tree 命令输出）  
  let mapStr = `${title}
`  
  function renderNode(  
    node: HeadingNode,  
    prefix: string,  
    isLast: boolean,  
    isRoot: boolean  
  ) {  
    if (!isRoot) {  
      const connector = isLast ? "└── " : "├── "  
      mapStr += `${prefix}${connector}${node.text}
`  
      if (node.children.length > 0) {  
        const childPrefix = prefix + (isLast ? "    " : "│   ")  
        node.children.forEach((child, index) => {  
          renderNode(child, childPrefix, index === node.children.length - 1, false)  
        })  
      }  
    } else {  
      node.children.forEach((child, index) => {  
        renderNode(child, "", index === node.children.length - 1, false)  
      })  
    }  
  }  
  renderNode(root, "", true, true)  
  mapStr = mapStr.replace(/│
$/g, "").trimEnd()  
  
  return "# Page Structure Map
```text
" + mapStr + "
```
"  
}
```

* • **Copy as Prompt**：把 Markdown 包裹在 ````markdown`代码块里，直接粘贴进 ChatGPT/Claude 对话框，模型能正确识别代码块边界，不再把`# 标题` 当成聊天指令。
* • **Include Map**：在正文前插入一棵纯文本树，类似 `tree` 命令输出。长文档（>5k token）喂给模型前，先看一眼 Map，能快速定位 “第 3 节讲认证、第 5 节才有报错码表”，省去让模型做摘要再定位的来回。

这两个功能看似微小，但把 **“网页→Markdown→Prompt”** 这条链路的摩擦系数降到极低：右键 → Copy as Prompt → 切到 AI 窗口 → Ctrl+V → 回车，全程 3 秒。实测把一篇 8k token 的 Vercel 文档页转成 Prompt 后，直接喂给 Claude Sonnet 5（1M 上下文），模型能在一次对话里精准回答 “第 4.2 小节提到的边缘运行时限制是什么”，无需二次检索。

### 3. 可定制的输出格式：五个开关组合出 32 种 Markdown

`lib/format.ts` 导出的 `FormatSettings` 接口定义了五个布尔开关，默认值在 `DEFAULT_FORMAT_SETTINGS` 里：

| 开关 | 默认 | 作用 | 典型关闭场景 |
| --- | --- | --- | --- |
| `includeImages` | false | 保留 `![alt](url)` | 只喂文本给模型、省 token |
| `includeLinks` | false | 保留 `[text](url)` | 同上，或不想泄露内链结构 |
| `includePageInfo` | true | 前置插入 **Title / Author / Date** | 需要纯正文做向量化 |
| `includeMap` | true | 前置插入页面结构图 | 短文档不需要导航 |
| `includeSourceUrl` | true | 末尾附带 **Source: url** | 隐私敏感、不想暴露来源 |

`formatMarkdown(pageData, settings)` 按顺序做三件事：

1. 1. 正则清洗：`includeImages=false` 时删 `![]()` 和 `<img>`；`includeLinks=false` 时把 `[]()` 还原成纯文本、删 `<a>`。
2. 2. 拼装元数据：按开关决定放哪些 meta，用 `---` 分隔。
3. 3. 追加结构图 + 正文，最后用 `replace(/
   {3,}/g, "
   ")` 折叠多余空行。

Options 页（`options.tsx`，142 行）用 React + Tailwind 把这五个开关渲染成 Checkbox 列表，配置存在 `chrome.storage.sync`，跨设备同步。实测把 **Images/Links/Map** 全关、只留 **PageInfo+Source**，一篇 12k token 的 HTML 页能压到 3.2k token 干净 Markdown，**压缩比 73%**——这对 RAG 入库、Prompt 填充都有实质节省。

### 4. Quick Actions：把 “预览标签页” 做成可选项

很多同类扩展（`markdown-clipper`、`save-as-markdown`、`markdownload`）强制打开一个新标签页预览，再点“复制/下载”。MD-This-Page 在 `background.ts`（141 行，129 loc）里实现了 **Quick Actions**：

```
// 右键菜单四项  
chrome.contextMenus.create({ id: "convert-to-markdown", title: "Open Preview Tab", contexts: ["page", "action"] })  
chrome.contextMenus.create({ id: "copy-markdown", title: "Copy Markdown", contexts: ["page", "action"] })  
chrome.contextMenus.create({ id: "copy-as-prompt", title: "Copy as Prompt", contexts: ["page", "action"] })  
chrome.contextMenus.create({ id: "download-md", title: "Download .MD", contexts: ["page", "action"] })  
  
// 工具栏左键：One-Click 模式下直接跑 Quick Action  
chrome.action.onClicked.addListener(async (tab) => {  
  const settings = await getSettings()  
  if (settings.oneClickEnabled) {  
    runQuickAction(tab.id, settings.oneClickAction)  
  } else {  
    openFullTab(tab.id)  
  }  
})  
  
// 核心执行流程  
async function runQuickAction(tabId: number, action: QuickAction) {  
  const settings = await getSettings()  
  const pageData = (await chrome.tabs.sendMessage(tabId, { action: "extract-page-data" })) as PageData  
  const markdown = formatMarkdown(pageData, settings.format)  
  
  if (action === "download") {  
    await downloadMarkdown(tabId, markdown, pageData.title)  
  } else {  
    await copyToClipboard(tabId, action === "copyPrompt" ? asPrompt(markdown) : markdown)  
  }  
  showBadge("✓", "#10b981")  
}
```

* • 右键菜单 / 工具栏图标左键直接触发：`Copy Markdown`、`Copy as Prompt`、`Download .MD`
* • 不打开预览页，内容脚本原地 `navigator.clipboard.writeText()` 或构造 `<a download>` 触发下载
* • Options 页可把左键绑定到任一 Quick Action（One-Click 模式）

实测 **Copy Markdown** 与 **Copy as Prompt** 在 Chrome 128 / Edge 128 / Firefox 130 上均能秒级写入剪贴板（需 `clipboardWrite` 权限）。Firefox 下 `chrome.downloads.download(data:URL)` 会被拦截，作者改用 `Blob + <a download>` 在页面上下文执行，规避了 “Access denied” —— 这个细节在 `background.ts` 和 `content.ts` 都有注释说明，值得学习。

### 5. 预览标签页：React + markdown-to-jsx 的实时渲染

`tabs/markdown.html` 加载 `tabs/markdown.tsx`，用 `react-markdown` + `remark-gfm` + `rehype-katex` 渲染 Markdown，支持 GFM 表格、任务列表、数学公式。顶部工具栏提供 **Copy / Download / Toggle Raw** 三个按钮，点击 Raw 能看到未经 `formatMarkdown` 处理的原始 Markdown，方便对比清洗前后差异。这个页面也是 `background.ts` 里 `openFullTab` 创建的新标签页，URL 是 `chrome-extension://<id>/tabs/markdown.html`，通过 `chrome.storage.local.set({ pageData })` 传递数据。

## 横向对比：为什么不是别的工具？

| 维度 | MD-This-Page | markdownload | Save as Markdown | 浏览器自带阅读模式 + 复制 |
| --- | --- | --- | --- | --- |
| **核心引擎** | Defuddle + Turndown | Turndown only | readability + turndown | Firefox Readability / Chrome DOM Distiller |
| **输出定制** | 5 开关 + Prompt/Map | 基础开关 | 基础开关 | 无 |
| **Quick Actions** | ✅ 右键/左键直达 | ❌ 必须开预览页 | ❌ 必须开预览页 | ❌ 手动操作 |
| **跨浏览器** | Chrome/Edge/Firefox | Chrome only | Chrome only | 各自实现不一 |
| **源码可审计** | ✅ 100% TS 开源 | ✅ 开源 | ❌ 闭源 | ❌ 闭源 |
| **权限模型** | `<all_urls>` + clipboardWrite | `<all_urls>` | `<all_urls>` | 无扩展权限 |
| **维护频度** | 近期仍有合并 | 2 年前停更 | 1 年前停更 | 浏览器厂商维护 |

**结论**：要 “开箱即用、不想折腾” → 浏览器自带阅读模式；要 “可定制、可二开、跨浏览器、且不想被迫开预览页” → MD-This-Page 目前是最优解。

## 避坑与总结

| 维度 | 评价 |
| --- | --- |
| **安装门槛** | 低。`pnpm dev` 一条命令跑通，无需 Docker、无需原生编译 |
| **跨浏览器** | Chrome/Edge/Firefox 三端同一代码库，Plasmo 抹平了 MV3 差异 |
| **提取质量** | SSR 页面极高；纯 CSR SPA 仍有缺失（Issue #1 追踪中） |
| **隐私模型** | 内容脚本注入到**所有**页面（`matches: ["<all_urls>"]`），虽无网络请求，但隐私敏感用户会介意（Issue #5） |
| **权限最小化** | 仅需 `activeTab`、`contextMenus`、`storage`、`clipboardWrite`，无 `scripting`、`tabs`、`downloads`、`host_permissions`——作者刻意避免了 `downloads` 权限，改用页面端 Blob 下载 |
| **工程规范** | TypeScript strict、ESLint + Prettier（`@ianvs/prettier-plugin-sort-imports`）、Tailwind CSS、Plasmo 约定式路由、GitHub Actions CI（lint + typecheck + build） |
| **维护活跃度** | 最近一周仍有合并，v1.0.0 发布 4 个月前，Issue 8 个、PR 2 个，属于 “低频但稳” 维护 |

### 值不值得折腾？

**值得，如果**：

* • 你每天要把 5+ 个网页喂给大模型做摘要/提取/问答，且不想维护爬虫脚本
* • 你需要一个 “浏览器端的 Readability + Turndown” 参考实现，想二次开发（如加上自动上传到 Notion/Obsidian、或接入本地 Ollama 做离线总结）
* • 你在写 Chrome 扩展，想看 Plasmo + React + MV3 的规范工程结构（`background.ts` 的 Service Worker 写法、`content.ts` 的消息通信、`options.tsx` 的 storage sync、`tabs/` 的预览页架构）

**不值得，如果**：

* • 只偶尔保存网页，浏览器自带 “另存为 → 网页，仅 HTML” + 手动清理更省事
* • 目标站点大多是重客户端渲染的 SPA（如 Twitter/X、Discord、Notion 私有页），现版本抓不全
* • 极度在意 “内容脚本注入所有页面” 的攻击面，建议用 `host_permissions` 按需声明 + `chrome.scripting.executeScript` 运行时注入（可自行改造，约 30 行改动）
