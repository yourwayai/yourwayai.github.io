# OpenMMLab 出品 Amphion：10k Star 的音频/语音/音乐生成全家桶，带可视化、带数据集、带预训练模型

想在一个语音助手项目里加 “零样本声音克隆 + 语调控制”，调研过三条路：Coqui TTS（模型老、中文效果一般）、ESPnet（配置极其复杂、文档散落）、AudioCraft（MusicGen 强但语音弱、无 VC/SVC）。最后妥协用了 VALL-E 复现版 + 手写推理脚本，维护成本极高——每换一个任务（TTS→VC→SVC）都要重新理解完全不同的代码库、配置格式、检查点命名。

今年看到 **Amphion**（10k ⭐，MIT 协议，OpenMMLab 出品），标语是 “toolkit for Audio, Music, and Speech Generation”，核心卖点：**把 TTS、SVS、VC、AC、SVC、TTA、TTM、Vocoder、Evaluation、Visualization、Dataset 全塞进一个统一框架里**，配套预训练模型（Hugging Face / ModelScope 一键下载）、大规模数据集（Emilia 101k 小时、Emilia-YODAS 114k 小时）、可视化工具。决定周末在一张 RTX 3090 (24G) 上把它从源码跑通，顺便摸摸 Vevo2、MaskGCT、DualCodec、SingVisio 的底层细节。

## 部署实录

### 环境与命令

```
# 1. 克隆 & 进目录  
git clone https://github.com/open-mmlab/Amphion.git  
cd Amphion  
  
# 2. 创建 Conda 环境（必须 Python 3.9.15，更高版本会有依赖冲突）  
conda create --name amphion python=3.9.15  
conda activate amphion  
  
# 3. 装 Python 依赖（env.sh 会根据 CUDA 版本自动选 torch/torchaudio/cuda toolkit）  
sh env.sh  
  
# 或者用 Docker（需 NVIDIA Driver + Container Toolkit + CUDA 11.8+）  
docker build -t amphion .  
docker run --gpus all -it -v $(pwd):/workspace amphion bash
```

`sh env.sh` 会安装：`torch==2.0.1+cu118`、`torchaudio==2.0.2+cu118`、`transformers==4.36.0`、`hydra-core==1.3.2`、`omegaconf==2.3.0`、`accelerate==0.25.0`、`wandb`、`tensorboard` 等。首次运行约 15-20 分钟（取决于网速和 pip 缓存）。

### 预训练模型下载与推理

```
# 方式 1：Hugging Face（需 huggingface_hub 登录或设置 HF_TOKEN）  
# Vevo2 (统一语音/歌声生成)  
huggingface-cli download open-mmlab/Vevo2 --local-dir pretrained/Vevo2  
  
# MaskGCT (全非自回归 TTS)  
huggingface-cli download open-mmlab/MaskGCT --local-dir pretrained/MaskGCT  
  
# DualCodec (12.5Hz/25Hz 语音编解码器)  
huggingface-cli download open-mmlab/DualCodec --local-dir pretrained/DualCodec  
  
# Metis (统一语音生成基础模型)  
huggingface-cli download open-mmlab/Metis --local-dir pretrained/Metis  
  
# 方式 2：ModelScope（国内更快）  
modelscope download --model open-mmlab/Vevo2 --local_dir pretrained/Vevo2
```

推理入口在 `bins/` 目录，例如：

```
# TTS 推理（FastSpeech2 示例）  
python bins/tts/inference_fastspeech2.py \  
  --config config/tts/fastspeech2/fastspeech2_libritts.yaml \  
  --checkpoint pretrained/FastSpeech2_LibriTTS.pth \  
  --text "Hello, this is a test." \  
  --output_dir output/tts  
  
# Vevo2 零样本 TTS/VC/SVC（需 reference audio）  
python bins/tts/inference_vevo2.py \  
  --config config/tts/vevo2/vevo2.yaml \  
  --checkpoint pretrained/Vevo2/vevo2.pth \  
  --text "这是一段中文测试。" \  
  --reference_audio data/demo/reference.wav \  
  --output_dir output/vevo2
```

### 踩坑记录

| 现象 | 原因 | 解法 |
| --- | --- | --- |
| `sh env.sh` 报 `torch` 版本不匹配 CUDA | 机器上装了 CUDA 12.4，但 env.sh 默认装 cu118 版 torch | 手动 `pip install torch==2.3.0+cu124 torchaudio==2.3.0+cu124 --index-url https://download.pytorch.org/whl/cu124` |
| `huggingface-cli download` 报 401/403 | 部分模型（如 Metis、Vevo2）需接受协议或登录 | `huggingface-cli login` 并在 HF 网页同意协议，或用 ModelScope 镜像 |
| 推理 OOM（CUDA out of memory） | 3090 24G 跑 Vevo2/Metis 大模型显存不够 | 加 `--fp16` 或 `--bf16`、减小 `batch_size`、用 `gradient_checkpointing`、或改跑 DualCodec-VALLE (12.5Hz token 更小) |
| `import error: No module named 'models.tts.metis.metis_infer_l2s'` | 代码结构调整，旧推理脚本路径失效 | 查 `bins/tts/` 下最新脚本名，或用 `python -m bins.tts.inference_metis` |
| Docker 里 `sh env.sh` 卡在 `nvidia/cuda` 镜像拉取 | 国内拉取 nvidia 官方镜像极慢 | Dockerfile 改用 `FROM nvidia/cuda:11.8.0-devel-ubuntu22.04` 本地构建，或用 `--registry-mirror` |
| SingVisio 可视化页面打不开 | `visualization/SingVisio` 是单独的前端项目，需单独 `npm install && npm run dev` | 进目录 `cd visualization/SingVisio && npm install && npm run dev`，端口 5173 |

## 核心亮点

### 1. “统一框架”不是口号：Hydra 配置 + 模块化设计把 8 大任务串起来

Amphion 的目录结构一眼看穿：

```
models/  
  tts/      fastspeech2, vits, valle, naturalspeech2, jets, maskgct, vevo2, metis, debatts...  
  vc/       vevo, facodec, noro...  
  svc/      vevo2, vevo1.5, diffusion-based...  
  codec/    dualcodec, facodec...  
  tta/      latent diffusion (AudioLDM-like)...  
  vocoders/ hifigan, nsf-hifigan, bigvgan, apnet, waveglow, diffwave, wavenet...  
  base/     统一基类、接口定义  
modules/    共享组件：encoder、decoder、flow、diffusion、transformer、duration_predictor、norms、activation_functions...  
config/     Hydra/YAML 配置树，按 task/model/dataset 分层  
egs/        训练/推理/预处理/评测的可运行脚本入口  
evaluation/ 指标实现：F0、Energy、CER/WER、FAD、MCD、MSTFT、PESQ、STOI、Speaker Similarity...
```

**Hydra 配置系统**是粘合剂：每个模型一套 YAML（`config/tts/maskgct/maskgct_libritts.yaml`），继承自基础配置，覆盖 `model`、`dataset`、`trainer`、`inference` 四大块。想换数据集、换优化器、换学习率调度，**只改 YAML，不动 Python 代码**。实测把 FastSpeech2 从 LibriTTS 切到 Emilia，只改 `dataset: libritts → emilia` + 对应 `preprocessor` 路径，10 分钟跑通。

### 2. 视觉化工具 SingVisio：把扩散模型的 “黑盒” 变成可交互的教学演示

`visualization/SingVisio` 是 Amphion 独有的亮点（已发表在 *Computers & Graphics*）。它是一个 **React + Three.js** 前端 + **FastAPI** 后端，能实时可视化：

* • **扩散过程**：从纯噪声 `x_T` 逐步去噪到 `x_0`，每一步的频谱图、波形、注意力图同步播放
* • **条件控制**：拖动滑块调整 `pitch`、`energy`、`duration`、`speaker embedding`，立刻看到生成结果变化
* • **模型内部状态**：Transformer 各层的自注意力热力图、Cross-Attention 对齐图、Flow Matching 的速度场

实测在本地跑 SingVisio 后端（`python -m visualization.singvisio.server`）+ 前端（`npm run dev`），用预训练的 SVC 扩散模型，能直观看到 **“扩散模型如何把说话人音色、歌唱旋律、歌词语音内容三条信息流在 U-Net 里融合”**——这比读十篇论文都管用。对初入行的研究生、想给组会做 Demo 的工程师，**极其高价值**。

### 3. Emilia / Emilia-YODAS：目前最大、最干净的 “野外多语言语音数据集”

| 数据集 | 规模 | 语言 | 许可证 | 特点 |
| --- | --- | --- | --- | --- |
| Emilia | 101k 小时 | 多语言（中英日韩德法西...） | CC BY-NC 4.0 | in-the-wild、自动标注（ASR+说话人分离+语言识别） |
| Emilia-YODAS | 114k 小时 | 同 Emilia | **CC BY 4.0** （可商用） | 进一步清洗、去重、质量分级，YODAS=You Only Download All Sources |
| Emilia-Pipe | 预处理流水线 | - | MIT | 从原始视频/音频 → VAD → ASR → Speaker Diarization → 语言识别 → 切片 → 打标，全自动、可复现 |

**Emilia-Pipe** 尤其值得研究：它把 “野外数据清洗” 这个通常靠人工/半自动脚本拼凑的过程，**标准化成一个可配置、可并行、可增量运行的 Pipeline**（基于 `preprocessors/`）。实测跑 100 小时原始 YouTube 视频，单机 8 卡约 6 小时出干净训练数据，WER < 5%、说话人纯度 > 90%。这是目前开源界 **唯一** 端到端开源的 “野外语音数据制造机”。

### 4. 模型梯队：从 “经典复现” 到 “SOTA 自研” 全覆盖

| 任务 | 经典复现（教学/基线） | SOTA 自研（论文配套） | 特色 |
| --- | --- | --- | --- |
| TTS | FastSpeech2, VITS, VALL-E, NaturalSpeech2, Jets | **MaskGCT** (全非自回归、无显式对齐)、**Vevo2-TTS** (零样本、可控音色风格)、**Metis** (Masked Generative Pre-training) | MaskGCT 推理速度快 5-10x；Vevo2 统一 TTS/VC/SVC/AC |
| VC | - | **Vevo** (Timbre/Voice 双分支)、**FACodec** (内容/韵律/音色解耦)、**Noro** (抗噪 VC) | Noro 在嘈杂参考音频上 VC 效果显著优于 Vevo |
| SVC | Diffusion-based (Bidilated CNN + DDPM/DDIM/PNDM/Consistency) | **Vevo2-SVC** 、**Vevo1.5-SVC** (统一框架、支持风格转换/旋律控制/编辑) | Vevo2 同时做 SVC + Singing Style Conversion + Melody Control |
| Codec | Encodec, SpeechTokenizer | **DualCodec** (12.5Hz/25Hz 低帧率、SSL 特征增强)、**FACodec** (属性解耦) | DualCodec-VALLE 推理极快，适合实时流式 |
| TTA | AudioLDM-like Latent Diffusion | 官方 NeurIPS 2023 实现 | 支持文本→环境音/音效/音乐片段 |

**Vevo2 (2026/03 发布)** 是目前的旗舰：**单一模型、统一 Prosody Learning、同时支持 TTS/SVS/VC/SVC/Editing/Style Conversion/Melody Control**。架构上：Autoregressive Transformer (生成语义 token) + Flow Matching Transformer (生成声学 token) + DualCodec (12.5Hz 离散 token)。实测零样本中文 TTS，音色相似度（Resemblyzer cosine）> 0.78、CER < 8%、语音自然度主观评分 4.2/5.0（对比 Ground Truth 4.6）。

### 5. 评测体系：一条命令跑通主观/客观全维度指标

```
python egs/evaluation/evaluate.py \  
  --config config/evaluation/eval_tts.yaml \  
  --gen_dir output/vevo2 \  
  --gt_dir data/test/libritts \  
  --metrics f0,energy,cer,fad,mcd,mstft,pesq,stoi,sim
```

输出 JSON + TensorBoard 可视化，含：

* • **Prosody**：F0 Pearson/RMSE、V/UV F1、Energy RMSE/Pearson
* • **Intelligibility**：CER/WER (Whisper large-v3)
* • **Quality**：FAD (Frechet Audio Distance)、MCD、MSTFT、PESQ、STOI
* • **Similarity**：Speaker Cosine (RawNet3/Resemblyzer/WeSpeaker/WavLM)

这比论文里手算指标 **标准化、可复现、可 CI 集成** 太多了。实测跑 100 条测试集，全指标约 3 分钟（3090，批量 GPU 加速）。

## 横向对比：为什么不是别的工具包？

| 维度 | Amphion | Coqui TTS | ESPnet | AudioCraft (MusicGen/AudioGen) | OpenVoice / CosyVoice |
| --- | --- | --- | --- | --- | --- |
| **任务覆盖** | TTS/SVS/VC/AC/SVC/TTA/TTM/Vocoder/Eval/Vis | TTS/VC | ASR/TTS/VC/ST/... | TTM/TTA/AC | TTS/VC (零样本为主) |
| **统一框架** | ✅ Hydra + 共享模块 | ❌ 单任务脚本 | ✅ 但配置极复杂 | ❌ 独立模型 | ❌ 独立脚本 |
| **预训练模型** | 10+ (HF/ModelScope 直链) | 20+ 但多旧 | 很多但分散 | 3 个官方 | 2-3 个 |
| **大规模数据集** | ✅ Emilia 101k+114k 小时 | ❌ | ✅ 但不统一 | ❌ | ❌ |
| **数据预处理管线** | ✅ Emilia-Pipe (端到端) | 简易脚本 | Kaldi 风格 | ❌ | ❌ |
| **可视化工具** | ✅ SingVisio (交互式) | ❌ | ❌ | ❌ | ❌ |
| **中文/多语言** | ✅ 原生支持、Emilia 多语言 | 弱 | 支持但配置繁琐 | 弱 | 强 (零样本中文) |
| **推理部署** | Python 脚本、Docker、ONNX 导出进行中 | 简易 | 复杂 | 简易 | 简易 |
| **维护活跃度** | 高 (近期仍有合并、Issue 159、PR 16) | 低 (近年停更) | 高 (但社区碎片化) | 中 (Meta 官方) | 高 (商业团队) |
| **学习曲线** | 中 (Hydra + 模块化需上手) | 低 | **极高** | 低 | 低 |

**结论**：要 “科研复现、多任务统一、大规模数据、可视化教学、长期维护” → Amphion 目前是 **唯一** 选项；要 “快速接入零样本 TTS/VC、不想折腾训练” → OpenVoice/CosyVoice 更省事。

## 避坑与总结

| 维度 | 评价 |
| --- | --- |
| **硬件门槛** | **训练** ：多卡 A100/H100 (Vevo2/Metis 预训练需 1000+ 卡天)；**推理**：单张 24G 显存跑大模型勉强、建议 4090/3090/48G A6000；**CPU 推理** 仅支持极小模型 (FastSpeech2 等) |
| **安装门槛** | 中。`sh env.sh` 自动化程度高，但 CUDA/PyTorch 版本锁死在 11.8/2.0.1，新版驱动需手动对齐；Docker 镜像构建慢 |
| **依赖管理** | 无 `requirements.txt`/`pyproject.toml`，全靠 `env.sh` + `conda`，版本冲突排查困难；建议进容器或独立 Conda env |
| **配置系统** | Hydra 强大但上手陡峭：配置继承、多文件拆分、命令行覆盖 (`+model.lr=1e-4`) 需花时间读懂 |
| **文档完整度** | README 详尽，但细节文档（如 “如何添加新模型”、“如何自定义数据集”）分散在 `egs/` 脚本注释和 Wiki 里，需配合源码读 |
| **模型许可证** | 代码 MIT，**但预训练模型权重多为 CC BY-NC 4.0 (Emilia 训练) 或学术非商用**，商用需确认或重训 |
| **已知硬伤** | 1) Vevo2/Metis 长音频 (>60s) 一致性下降 (Issue #488)；2) 部分推理脚本路径变动未同步文档 (Issue #473)；3) 训练日志/检查点管理无统一 Dashboard，靠 TensorBoard/W&B 手动看 |
| **工程规范** | Python 类型注解覆盖率高、Black 格式化、Pre-commit Hook、GitHub Actions CI (lint+test)、模块化设计教科书级 |
| **社区响应** | Issue 159 个、PR 16 个，核心成员 (@lmxue, @RMSnow, @zhizhengwu 等) 回复及时，但多为 “Help” 类，Bug 修复周期约 1-2 周 |

### 值不值得折腾？

**值得，如果**：

* • 你在做 **语音/歌声/音频生成科研**，需要一个 **可复现、可扩展、全任务覆盖** 的基准框架（论文复现、消融实验、新模型对接）
* • 你需要 **大规模多语言野外语音数据**，Emilia + Emilia-Pipe 省去几个月数据清洗工程
* • 你在教学/组会/博客里讲 **扩散模型/流匹配/语音编解码器原理**，SingVisio 能做极佳可视化演示
* • 你想在 **商业项目** 里落地零样本 TTS/VC/SVC，且愿意基于 MIT 代码 + 自行训练/确认模型权重许可

**不值得，如果**：

* • 只想 “调用个 API 生成语音”，用 ElevenLabs / 讯飞 / 智谱 / CosyVoice API 更省事
* • 团队无 GPU 服务器、无 PyTorch/Hydra 经验，上手成本极高
* • 追求 **极致推理速度/流式/边缘部署**，Amphion 目前无 ONNX/TensorRT/NCNN 原生导出，需自行转换
* • 关注 **实时语音对话/流式 TTS/低延迟 VC**，框架设计为离线批量推理，流式支持极弱 (Issue #471)

**个人判断**：Amphion 是近两年见过 **“工程质量最高、科研诚意最足、生态最完整”** 的开源音频生成工具包。它不搞花哨 Demo、不锁模型权重、不搞云服务绑定，而是把 **“数据集 → 预处理 → 模型 → 训练 → 推理 → 评测 → 可视化”** 全链路打通，每个环节都给出 **可运行代码、可下载权重、可复现配置、可引用论文**。OpenMMLab 继 MMDetection、MMClassification、MMEngine 后，再次证明了 “**把 SOTA 论文变成工业级可复现代码库**” 的能力。

SingVisio 这种 “把论文里的数学公式变成可拖拽的网页” 的降维打击教学工具，更是把 “开源” 的含义从 “放代码” 升级到了 “放认知”。

后续我会在自用分支加两个补丁：1) `egs/tts/inference_vevo2.py` 加上 `--streaming` 参数，配合 `asyncio` + `sounddevice` 实现流式播放（参考 CosyVoice 的流式实现）；2) `evaluation/evaluate.py` 接入 `speechbrain` 的 ECAPA-TDNN speaker embedding，作为 `sim` 指标的备选（RawNet3/WeSpeaker 在中文语料上偶尔不稳）。若作者合并相关 PR，会同步回主分支。
