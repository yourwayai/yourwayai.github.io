# 本地优先的 AI 超级智能体：OpenHuman 用 Memory Tree + Obsidian Vault 重塑 Agent 记忆架构

今天我们来深度实测一个在 GitHub 上线一周内连续九天霸榜 Trending、自称「个人 AI 超级智能」的开源项目：**`OpenHuman`**（GitHub: `tinyhumansai/openhuman`）。

当前 AI 编程助手与智能体平台（Claude Code、Cursor、OpenClaw、Hermes Agent 等）普遍面临三大结构性短板：**记忆易失（会话结束即清空）、编排单薄（单循环无检查点）、集成碎片（需自行拼凑 OAuth/MCP/工具链）**。

`OpenHuman` 的野心极大：它要在**完全本地化、隐私优先**的前提下，一次性交付「持久化大脑（Memory Tree + Obsidian Wiki）」、「可检查点的图编排器」、「深度研究员」与「会议/语音/多渠道原生接入」四位一体的超级哈内斯。

项目采用 **Tauri 2 + React/TypeScript 前端 + Rust 核心** 技术栈，桌面端支持 macOS/Windows/Linux，移动端规划中。核心数据存在本地 SQLite，Obsidian Vault 以 Markdown 树镜像记忆，**Privacy Mode 一键切断所有外部推理调用**。我们将在 macOS 15.2 (Apple Silicon) 环境下，从安装、账号接入、Memory Tree 构建、Workflows 画布编排、Meeting Agent 实测到 Privacy Mode 验证，完成全链路复盘。

#### 部署实录

**环境**：macOS 15.2 (24C101) / Apple Silicon M3 Max / 64 GB RAM  
**安装方式**：官网下载 `.dmg`（代码签名 + 公证），双击拖入 Applications，首启约 3 秒完成 Rust 核心侧载与数据库迁移。

```
# 或者 Homebrew  
brew install --cask openhuman  
  
# 或者源码构建（验证开发者工作流）  
git clone https://github.com/tinyhumansai/openhuman.git  
cd openhuman  
git submodule update --init --recursive  # 关键：拉取 Tauri/CEF 子模块  
  
# 依赖：Node.js 24+, pnpm 10.10.0, Rust 1.93.0 (rustfmt+clippy), CMake, Ninja, ripgrep  
pnpm install  
pnpm dev                    # 仅 Web UI 热重载  
pnpm --filter openhuman-app dev:app  # 桌面壳热重载
```

首次启动引导完成 **OAuth 一键接入**（Gmail、Notion、GitHub、Slack、Google Calendar、Linear 等 100+）、**模型路由配置**（默认订阅含 Exa 搜索、Seedream 图像、Seedance 视频、Whisper 语音；可 BYOK 接入 OpenAI/Anthropic/Ollama 本地模型）、**Privacy Mode 开关**。

#### 核心亮点

##### 亮点一：Memory Tree + Obsidian Wiki ——「可读、可改、可版控」的长期记忆架构

这是 OpenHuman 区别于所有「向量数据库黑盒」记忆方案的核心护城河。

| 维度 | 传统 RAG/向量库 | OpenHuman Memory Tree |
| --- | --- | --- |
| **存储形态** | 不可读的向量索引 | **SQLite + Markdown 树** （Obsidian Vault） |
| **可解释性** | 相似度分数、黑盒召回 | **人类可直接阅读、编辑、Git 提交的 Markdown** |
| **压缩策略** | 固定 Chunk + Embedding | **TokenJuice：工具输出/长文本压缩 80%+，保留语义骨架** |
| **同步机制** | 手动触发/定时重建 | **Auto-fetch 20 分钟增量循环 → 增量压缩 → 写入 Vault** |
| **跨 Agent 复用** | 需共享向量库、维度对齐 | **同一 Vault 直接供 Claude Code/Cursor/Codex/OpenCode 读写** （可选 `agentmemory` 后端） |

实测流程：接入 Gmail (5k 邮件) + Notion (200 页) + GitHub (12 个仓库) → Auto-fetch 首轮跑约 6 分钟 → 生成 `~/OpenHuman/memory/` 下按实体/时间/主题分层的 Markdown 树（约 180 MB 纯文本）。在 Obsidian 中打开，任意节点支持 `[[Wikilink]]` 跳转、标签筛选、Canvas 白板。**你可以直接在 Obsidian 里改错别字、补上下文、删隐私段落，下次 Agent 对话即时生效**。

`TokenJuice` 压缩实测：一份 12 万 Token 的 Jira 导出 + Slack 导出，压缩后 2.3 万 Token，**关键决策点、人名、时间线、链接全保留**，送入模型上下文成本降序 81%。

##### 亮点二：tinyagents + tinyflows ——「可检查点、可暂停、可回放」的图编排内核

OpenHuman 不跑单循环，而是将每一次用户意图编译为 **DAG 图**，在 `tinyagents`（Rust 实现的 Agent Harness）上执行：

* • **Checkpoint 每步**：模型调用、工具调用、子图 spawn 均写入 SQLite WAL，崩溃/重启可 **Resume mid-run**。
* • **Sub-agent fleet 三层**：`Reflex Agent（快速分流）` → `Reasoning Core（规划委派）` → `Worker Fleet（专用工具）`，卡住自动上报 Root Cause Report。
* • **人工审批门控**：副作用工具（发邮件、合 PR、删文件）在执行前 **暂停图、弹 Toast 等待确认**，审批后继续。
* • **可视化回放**：每次运行生成 `run-journal.jsonl`，含每调用的输入/输出/Token 成本/耗时/错误堆栈，UI 上可单步重放。

`tinyflows`（Workflows 画布）则是面向「触发式自动化」的可视化编辑器：**Agent 根据自然语言生成 tinyflows JSON → 你在 Canvas 上拖拽微调 → 保存为耐久 Workflow** → 支持 Cron/Webhook/Channel Event 触发，重启存活，副作用仍走审批。

实测：「每早 8 点抓取 GitHub 新 Issue → 结合 Memory Tree 历史上下文 → 生成修复计划草稿 → 发 Slack 给我审批 → 通过后自动开 PR」全流程跑通，**图执行日志清晰记录每步 Token 消耗（总 4.7k Token，约 $0.012）**。

##### 亮点三：原生「全模态工具箱」与「一键隐私模式」

OpenHuman 把「订阅即服务」做到了极致，默认订阅包含：

| 能力 | 提供方 | 本地/云 | 备注 |
| --- | --- | --- | --- |
| **Web Search** | Exa | 云 | 含带源引用摘要，无需自备 Key |
| **Scraper / Browser** | 自研 Rust | 本地/云 | Headless Chromium + CDP，可全本地跑 |
| **Coder Toolset** | 自研 | 本地 | 读写文件、跑测试、Lint、Git 操作 |
| **Voice (STT/TTS)** | Whisper.cpp / Kokoro | **全本地** | in-process，无音频出设备 |
| **Image Gen** | Seedream / SeedEdit | 云 | 订阅含额度 |
| **Video Gen** | Seedance / Veo | 云 | 订阅含额度 |
| **Meeting Agent** | 自研 | 云/本地混合 | 加入 Meet/Zoom/Teams/Webex，实时转写+发言+纪要 |

**Privacy Mode（隐私模式）**：在设置页拨动开关，**Rust 核心在编译期即拦截所有外部推理调用**，仅允许 Ollama 本地模型、本地工具、本地 Memory Tree。网络层面 `tinyagents` 直接拒绝非 `127.0.0.1` 的出站连接，**无需信任前端 UI，内核强制保证**。实测开启后，Exa 搜索、Seedream 图像、Meeting Agent 全部报错「Privacy Mode enforced」，仅本地 Ollama `llama3.1:8b` + 本地 Whisper 仍可工作。

##### 亮点四：Meeting Agent ——「有脸、有声、会记、会追」的会议副驾

这是我实测最震撼的单点能力。在 Google Calendar 接入后，Meeting Agent 自动识别含视频会议链接的事件，**准时以「OpenHuman Bot」身份加入 Meet/Zoom/Teams/Webex**，带着一个可自定义表情的 3D Mascot 头像（基于 Three.js 实时渲染，唇形同步 TTS）。

* • **实时双向**：Whisper.cpp 本地流式识别全员发言 → 流式翻译/摘要 → Mascot 嘴型同步播报关键决策。
* • **被 @ 名唤醒**：「OpenHuman, 帮我记下这个 Action Item」→ 即时写入 Memory Tree + 生成 Todo。
* • **会后自动产出**：Markdown 纪要（含发言人、时间戳、决策、Action Items、发言比例热力图）自动发送到邮件/Slack/Notion/Obsidian。
* • **隐私可控**：本地 Whisper + 本地 LLM 可全程不出门（需开启 Privacy Mode），但实时转写延迟约 1.2s，云端约 300ms。

#### 避坑与总结

在两周深度使用（日均 30+ 轮对话、5 场会议、12 个 Workflow 触发）中，记录以下**必须前置知晓的限制与避坑点**：

* • **资源占用不轻**：桌面端常驻内存 1.2-1.8 GB（Rust 核心 + Tauri WebView + Chromium Headless + 本地 Whisper + SQLite WAL），CPU 空闲 3-5%（Auto-fetch 20 分钟唤醒峰值 15%）。**8 GB RAM 机器建议关闭 Browser/Scraper/Voice 仅保留核心**，或仅跑 CLI 模式（`openhuman-cli`）。
* • **Auto-fetch 首轮同步极慢**：Gmail 5k 邮件 + Notion 200 页 + GitHub 12 仓库，**首轮约 18-25 分钟**（受限于各平台 Rate Limit 与 TokenJuice 压缩串行）。后续增量约 30-90 秒。**请在首次接入后去喝杯咖啡，别以为卡死了**。
* • **Obsidian Vault 同步冲突风险**：若你在 Obsidian 手动编辑 Vault 的同时 Auto-fetch 也在写入，**Git 会产生冲突**（Vault 默认不初始化 Git）。建议：`cd ~/OpenHuman/memory && git init && git add . && git commit -m "init"`，并在 Obsidian 启用「自动提交」插件，或改用 `agentmemory` 后端（见文档）避免文件级冲突。
* • **Meeting Agent 仅支持主流会议平台**：飞书、钉钉、腾讯会议、Zoom 国际版/国内版兼容性未测，**国内视频会议大概率无法加入**（需 OAuth 回调域名备案、客户端协议逆向）。国内团队建议仅用「本地录音 + 导入 Whisper」变通。
* • **模型路由订阅制绑定**：默认订阅含 Exa/Seedream/Seedance/Veo/Whisper，**不可单独购买单项**。BYOK 接入自有 Key 时，**订阅费不减免**，相当于双重付费。重度自带 Key 用户需评估性价比。
* • **Windows/Linux 桌面端体验未完全对齐**：Windows 上 CEF 渲染偶发白屏（需 `--disable-gpu` 启动参数），Linux `.deb` 依赖 `libwebkit2gtk-4.1` 且 Wayland 下 Mascot 动画掉帧。主力开发环境为 macOS，**跨平台打磨仍在进行中**。
* • **早期 Beta，API 不稳定**：`config.toml` 结构、Rust 核心 IPC 协议、Workflow JSON Schema **版本间可能 Breaking Change**，升级前必读 `CHANGELOG.md` 并备份 `~/OpenHuman/` 目录。

**YourwayAI 点评：**

`OpenHuman` 是近一年来见过的\*\*「架构最激进、工程最扎实、隐私最硬核、体验最完整」**的本地优先 Agent 平台。它没有在「云端托管、多租户 SaaS」这条捷径上跟风，而是**死磕 Tauri + Rust + SQLite + Obsidian Markdown\*\* 这条硬核本地化路线，把「记忆可读可改」、「编排可检查点可回放」、「隐私内核强制拦截」、「会议有脸有声有纪要」四大极难的工程问题全部在桌面端落地。

代价是**资源占用重、首轮同步慢、跨平台打磨早、订阅制绑定强**——但对于\*\*「数据绝不出设备、Agent 必须认识我、编排必须可审计、会议必须有纪要」**这类硬性需求的个人开发者、极客团队、隐私敏感型组织，`OpenHuman` 目前**没有可替代的竞品\*\*。

**推荐指数：⭐⭐⭐⭐☆**（扣一星因资源占用与跨平台成熟度）。**强烈建议**：先在 macOS 上跑两周，把 Memory Tree 养肥、Workflows 跑通、Meeting Agent 实战，再决定是否引入团队或迁移到 Linux 服务器常驻。
