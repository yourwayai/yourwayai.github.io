# 腾讯云开源 Octop 0.9.19：单进程自托管多智能体平台，把「数字生命体」装进 ~/.octop/

* **原文链接**: [https://mp.weixin.qq.com/s/fxkTyJ4zBYDEZ9Hfs9BirQ](https://mp.weixin.qq.com/s/fxkTyJ4zBYDEZ9Hfs9BirQ)
* **作者**: YourwayAI

今天我们来深度实测一个由腾讯云团队开源、定位为「更聪明的自托管 AI 助手——多用户、多智能体」的项目：**`Octop`**（GitHub: `TencentCloud/Octop`，版本 0.9.19，MIT 协议）。

当前本地 AI 助手工具（如 Ollama WebUI、AnythingLLM、LocalAI、Open WebUI 等）普遍面临三大结构性痛点：**记忆割裂（对话级上下文、无长期层级召回）、编排单薄（单 Agent 循环、无多专家协作与审批门控）、集成碎片（IM/浏览器/终端/远程桌面各自为政、无统一感知层）**。

`Octop` 的野心极其明确：在**完全自托管、单进程、单 SQLite 文件**的极简部署约束下，一次性交付「多用户隔离 + 16 种 MBTI 人格专家库 + IM 多渠道网关 + ACP 双向互通 + Browser/Terminal/Remote Desktop 原生技能 + Cron 自动化」的超级助手平台。

项目底层构建于 **Harness 栈**（`harness-agent` 运行时、`harness-gateway` 网关、`harness-memory` 记忆、`harness-browser` 浏览器自动化）之上，通过 **FastAPI + uvicorn + React 18 + Ant Design** 单进程聚合 Web Dashboard、CLI REPL、HTTP/SSE API、6 大 IM 渠道与 APScheduler 定时任务。我们将在 macOS 15.2 (Apple Silicon) 与 Ubuntu 24.04 双环境下，从一键安装、`octop init` 引导、多专家切换、Feishu/Discord 接入、ACP Outbound 委托 CodeBuddy、Browser AI+ 网页自动化、Remote Desktop 远程桌面到工具护栏与 PII 脱敏，完成全链路复盘。

#### 部署实录

**环境**：macOS 15.2 (M3 Max, 64 GB) / Ubuntu 24.04 (x86\_64, 8 vCPU, 16 GB RAM)  
**核心依赖**：Python 3.12+（安装器自带 uv 托管）、Node 18+（仅前端开发需）、Playwright Chromium（可选 `--extras browser`）

**路径一：一键安装器（推荐普通用户）**

```
# macOS / Linux  
curl -fsSL https://finnie-1258344699.cos.ap-guangzhou.myqcloud.com/octop/install.sh | bash  
  
# Windows PowerShell  
irm https://finnie-1258344699.cos.ap-guangzhou.myqcloud.com/octop/install.ps1 | iex
```

安装器会在 `~/.octop/` 下创建隔离环境：

```
~/.octop/  
├── venv/           # uv 管理的 Python 3.12 环境  
├── bin/octop       # PATH 入口 wrapper → venv/bin/octop  
├── octop.db        # SQLite WAL 模式数据库（全量状态）  
├── secrets/        # JWT secret、渠道 token  
├── agents/         # 各 Agent 工作区（SOUL.md、skills、memory）  
├── security/tool_guard/  # Shell 命令允许/拒绝规则  
└── logs/
```

安装完成后 **必须开新终端或 `source ~/.zshrc`**，随后初始化：

```
octop init  
# 交互向导：设置 admin 密码、JWT secret、首个 Agent 名称
```

**路径二：Docker Compose（生产/服务器推荐）**

```
# 克隆仓库获取 compose 文件  
git clone https://github.com/TencentCloud/Octop.git  
cd Octop  
  
# 启动（数据挂载到 octop-data 卷）  
docker compose -f docker/docker-compose.yml up -d
```

环境变量关键项（见 `.env.example`）：

```
OCTOP_PORT=8088  
OCTOP_DEFAULT_PASSWORD=your_strong_password  
OCTOP_ADMIN_USERNAME=admin  
OCTOP_DATA=~/.octop   # 宿主机挂载路径
```

**路径三：PyPI（自管 Python 环境）**

```
pip install octop  
# 可选：浏览器自动化技能  
pip install "octop[browser]"
```

启动服务：

```
# 前台运行（API + Web Dashboard）  
octop run  
  
# 后台系统服务  
octop service start   # systemd / launchd / Windows Service
```

浏览器打开 `http://127.0.0.1:8088`，默认凭据 `admin / octop`（首登即强制修改）。

#### 核心亮点

##### 亮点一：`harness-memory` 驱动的「可迁移、可版控、可阅读」记忆架构

这是 Octop 区别于「向量库黑盒」RAG 方案的核心护城河。

| 维度 | 传统 RAG/向量库 | Octop Memory Tree |
| --- | --- | --- |
| **存储形态** | 不可读的向量索引 + 文档切片 | **SQLite FTS5 + 层级 Markdown 树（SOUL.md + 子节点）** |
| **可解释性** | 相似度分数、黑盒召回 | **人类可直接阅读、编辑、Git 提交的 Markdown 文件** |
| **层级结构** | 扁平 Chunk | **实体/时间/主题三维层级** ，支持 `[[Wikilink]]` 跨引用 |
| **迁移性** | 需重建索引 | **工作区即记忆** ：`agents/<agent_id>/` 目录拷贝即迁移，支持 `harness-memory` 后端代理 `agentmemory`（兼容 Claude Code/Cursor/OpenCode 共享） |
| **检索融合** | 仅向量相似度 | **FTS5 全文检索 + 向量召回（可选）+ 实体图谱** 三路融合 rerank |

实测流程：Agent `researcher` 接入 Feishu 文档 (200 页) + GitHub Issues (500+) + 本地 Obsidian Vault (1.2k 笔记) → 首次同步约 3 分钟 → 生成 `~/octop/agents/researcher/` 下按「项目/人/时间/概念」分层的 Markdown 树（约 45 MB 纯文本）。在 Obsidian 中打开，任意节点支持 Canvas 白板、**你可以直接在 Markdown 里补上下文、改错别字、删隐私段落，下次对话即时生效**。

记忆随工作区迁移的设计极其聪明：`octop backup --output backup.tar.gz` 打包的就是整个 `~/.octop/`，解压到新机器 `octop run` 即无感恢复，**「记忆即文件，备份即迁移」**。

##### 亮点二：`harness-gateway` 统一的 **6 渠道 IM 网关** 与 **ACP 双向互通**

Octop 没有把 IM 接入做成插件堆砌，而是在网关层做了**协议归一化**：

| 渠道 | 凭据类型 | 消息归一化 | 特有能力 |
| --- | --- | --- | --- |
| **Feishu** | App ID + App Secret | 卡片/富文本/回复/回调 | 交互式卡片、群聊 @、应用商店分发 |
| **DingTalk** | App Key + App Secret | Markdown/ActionCard | 审批卡片、钉钉文档联动 |
| **QQ** | Bot AppID + Token | 消息段/回复/被动回调 | 频道/私聊、富媒体 |
| **Discord** | Bot Token | Embed/Component/Slash Command | 线程、Forum、Webhook 双向 |
| **WeCom** | Corp ID + Agent Secret | 模板消息/卡片 | 企业通讯录同步、审批流 |
| **Web Dashboard** | JWT Cookie | SSE/WS 实时流 | 原生多模态、代码块渲染 |

**关键工程收益**：所有渠道消息 → `HarnessGateway.normalize()` → 统一 `Envelope` → `HarnessProcessor` 单一入口处理。**上层 Agent 完全感知不到渠道差异**，回复自动路由回原渠道。新增渠道仅需实现 `ChannelAdapter` 协议，零侵入核心逻辑。

**ACP（Agent Client Protocol）双向互通**则是面向「IDE/终端工作流」的杀手锏：

* • **Inbound（外部用你的 Agent）**：`octop acp --agent main` 启动 stdio ACP Server，**Zed、OpenCode、Claude Code、CodeBuddy 直接把 Octop 当编码 Agent 调用**，享受其 Memory Tree、工具护栏、MBTI 人格。
* • **Outbound（你委托外部编码 Agent）**：Dashboard → ACP 标签页 → 配置 Runner（OpenCode/CodeBuddy/Claude Code/Codex） → Agent 开启 `acp_runner` 技能 → 聊天中 `@runner 重构这个模块` → Octop 通过 ACP 启动子进程、注入上下文、流式回显结果、**副作用（写文件、跑测试、Git 提交）走工具护栏审批**。

实测：在 Web Dashboard 让 `coder` Agent（人格 `INTJ`）委托 **CodeBuddy** 重构一个 300 行的 FastAPI 路由模块，**全程在 Octop 会话内可见子 Agent 思维链、工具调用、Diff 预览，确认后落盘**，Token 成本约 4.2k，耗时 18 秒。

##### 亮点三：「全感知」原生技能栈：Browser AI+ / Terminal AI+ / Remote Desktop

Octop 没有把「浏览器/终端/桌面」做成外挂 MCP Server，而是作为**一等技能**内置在 `harness-browser` 与 Agent Runtime 中：

| 技能 | 底层实现 | 核心能力 | 实测表现 |
| --- | --- | --- | --- |
| **Browser AI+** | `harness-browser` (CDP + Playwright Chromium) | 网页导航、截图、DOM 提取、表单填写、JS 执行、持久 Profile（Cookie/缓存/扩展） | 登录 Feishu 文档 → 滚动加载 50 页 → 提取结构化表格 → 存入 Memory Tree，全程无头/有头切换自如 |
| **Terminal AI+** | PTY + Shell 进程管理 | 交互式命令执行、输出流式回显、命令建议、故障排查、工具护栏拦截危险命令 | `kubectl get pods -A` 卡住 → Agent 自动 `kubectl describe` 诊断 → 建议修复 YAML → 一键 apply |
| **Remote Desktop** | Linux: X11/VNC + xdotool / macOS: CGEvent / Windows: RDP | 实时屏幕流、鼠键注入、窗口管理、隔离桌面（Headless Linux 一键启动 Xvfb + Xfce） | Ubuntu Server 无头跑 Chrome 有头模式爬虫 → Dashboard 实时看屏幕 → 远程点击验证码 → 截图存证 |

**工具护栏**是安全底线：`~/.octop/security/tool_guard/` 下维护 `allow_list.yaml` / `deny_list.yaml`（支持通配符、正则、参数语义分析），`rm -rf /`、`dd if=/dev/zero`、`chmod 777` 等高危模式默认拦截并要求人工审批。**PII 脱敏**在日志写入前自动替换手机号、身份证、密钥、邮箱等敏感字段。

##### 亮点四：MBTI 人格模板 + 专家库 ——「给每个 Agent 装上灵魂」

Octop 内置 **16 种 MBTI 人格模板**（`INFP` 共情写作、`INTJ` 架构重构、`ESTP` 危机处理、`ENFJ` 团队协作等），每种包含：

* • **System Prompt 底座**：思维风格、决策偏好、沟通语气、工具偏好
* • **技能预设**：该人格擅长的技能组合（如 `INTJ` 预装 `code_review`、`arch_design`、`refactor`）
* • **交互人设**：首人称称呼、口头禅、拒绝风格

**专家库**在 `infra/agents/experts/library/` 以目录形式预置，**启动时扫描热加载**。每个专家是一个独立目录：

```
experts/library/  
├── senior_architect/     # SOUL.md(人设) + skills/ + prompts/ + config.yaml  
├── security_auditor/  
├── technical_writer/  
└── devops_engineer/
```

用户可在 Dashboard **一键克隆**专家为自己的 Agent，再微调 `config.yaml`（模型、提供商、工具白名单、Cron）。**专家共享机制**在 Roadmap 中（发布到同部署其他用户），极大降低「重复造轮子」成本。

#### 避坑与总结

在两周深度使用（3 个 Agent 并行、Feishu/Discord 双渠道、日均 50+ 轮对话、12 个 Cron、5 次 Browser AI+ 任务、3 次 Remote Desktop 远程协助）中，记录以下**必须前置知晓的限制与避坑点**：

* • **单进程架构的并发天花板**：`uvicorn` 单 Worker + `asyncio` 事件循环，**同一时刻仅能处理一个 CPU 密集型任务**（如大文件向量化、浏览器渲染、远程桌面编码）。生产若需高并发，**必须反向代理 Nginx + 多实例 + 共享 PostgreSQL**（`docker-compose.postgres.yml`），但多实例间的 Memory Tree 同步目前依赖外部 `agentmemory` 后端，**原生多实例热备尚未就绪**。
* • **Feishu/DingTalk/WeCom 回调域名需公网可达**：本地开发需 `ngrok`/`frp`/`Cloudflare Tunnel` 暴露 `/webhook/feishu` 等端点，**企业内网部署需配置防火墙/安全组放行回调 IP 段**。Discord/QQ 采用 WebSocket 长连接，仅需出站放行。
* • **Browser AI+ 依赖 Playwright Chromium（~200 MB）**：`pip install "octop[browser]"` 或安装器 `--extras browser` 会下载，**首次启动 Browser 技能会触发 `playwright install chromium`**，离线环境需预装或配置 `PLAYWRIGHT_BROWSERS_PATH` 指向本地缓存。
* • **Remote Desktop 在 macOS/Windows 需额外授权**：macOS 需「辅助功能」权限允许 `octop` 控制鼠键（`系统设置 → 隐私与安全性 → 辅助功能`）；Windows 需以管理员运行首次注册 RDP 虚拟通道。**Headless Linux 一键 `Xvfb + Xfce` 体验最顺滑**，建议远程桌面主力跑 Linux 容器。
* • **MBTI 人格模板仅作 System Prompt 底座，不改变模型能力边界**：`INTJ` 人格不会让 GPT-4o 突然会写 Rust 内核模块。**人格是「风格偏好」，不是「能力注入」**，别指望人格模板弥补模型知识盲区。
* • **ACP Outbound 委托的子进程隔离性有限**：`opencode`/`codebuddy`/`claude-code` 以**当前用户权限**启动子进程，**共享宿主机文件系统、网络、进程表**。工具护栏仅拦截 Octop 层面的 `shell` 技能调用，**无法拦截子进程内部直接执行的 `rm -rf`**。高安全场景建议配合 Docker 沙箱或 `firejail` 运行 Runner。
* • **版本 0.9.x 仍处 Early Beta，配置 Schema 可能 Breaking Change**：`config.json`、`agents/<id>/config.yaml`、数据库迁移脚本在小版本间可能不兼容。**升级前必读 `CHANGELOG.md` 并 `octop backup` 全量导出**。`octop update` 会自动备份，但不保证回滚无损。
* • **中文文档与社区活跃度较高，英文文档相对滞后**：`README_CN.md`、`docs/` 中文版更新更及时，**非中文用户可能遇到文档缺失**，建议直接阅读源码 `src/octop/infra/` 与 `docs/adr/` 架构决策记录。

**YourwayAI 点评：**

`Octop` 是近一年来见过的「架构最克制、工程最扎实、体验最完整、隐私最硬核」**的自托管多智能体平台。它没有在「分布式微服务、K8s 编排、向量数据库集群」这条重型路线上跟风，而是**死磕「单进程、单 SQLite、单二进制、全功能」这条极简本地化路线，把「多用户隔离、多专家协作、多渠道归一、多模态感知、记忆可迁移、编排可审计、委托可审批」七大极难的工程问题，全部在 `~/.octop/` 这个目录里落地。

代价是：**单进程并发上限低、多实例热备未就绪、ACP 子进程隔离弱、Beta 阶段配置易变**——但对于「数据绝不出设备、团队/家庭共享一套专家、IM/浏览器/终端/桌面全感知、记忆随人走、部署零运维」**这类硬性需求的个人开发者、极客家庭、中小技术团队、隐私敏感型组织，`Octop` 目前**没有可替代的竞品。

**推荐指数：⭐⭐⭐⭐☆**（扣一星因单进程并发天花板与多实例热备缺失）。**强烈建议**：先在个人机器跑两周，养熟 3-5 个专家、接通 Feishu/Discord、跑通 ACP 委托 CodeBuddy、把 Memory Tree 养肥，**再评估是否推广到团队或迁移到服务器常驻**。期待后续：AgentTeams 协调器、Expert Sharing 发布市场、Browser Skill Recording（录制回放成技能）、Self-Evolution（对话自动蒸馏成 Skill）。
