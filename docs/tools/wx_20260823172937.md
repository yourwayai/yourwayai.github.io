# Alfred、Raycast 都在用，为什么还要装一个 Cling？实测三款启动器的文件搜索差异

今天测试了 Cling（GitHub: FuzzyIdeas/Cling），一个主打「Instant fuzzy find any file on macOS」的原生 Swift 应用。关注它的起因很简单：Spotlight 索引不到隐藏文件、dotfiles、应用沙盒数据，Alfred 和 Raycast 的文件搜索虽然快，但要么要 Powerpack 要么要 Pro，且对系统级路径的覆盖依然有盲区。Cling 的定位很精准——不做启动器、不做计算器、不做剪贴板历史，只做一件事：把全盘文件名模糊搜出来，顺手就能开、拖、删、发。

### 部署实录

环境：MacBook Pro M1 Max / macOS Sequoia 15.5 / 64 GB 内存。

安装方式有三种，我全试了一遍：

```
# 方式 1：Homebrew（推荐，自动更新）  
brew install --cask cling  
  
# 方式 2：官网直装（低技术门槛）  
# 访问 https://lowtechguys.com/cling 下载 .dmg，拖进 Applications  
  
# 方式 3：源码构建（极客自留地）  
git clone https://github.com/FuzzyIdeas/Cling.git  
cd Cling  
xcodebuild -scheme Cling -configuration Release
```

Homebrew 版本是 v2.6.9（上周发布），官网直装是 v2.6.10（昨天发布，修复了离线卷缓存显示问题）。首次启动会请求「完全磁盘访问权限」——不给权限只能搜 Home、Library、Applications 三个范围，给了权限才能搜 System、Root 卷。权限弹窗跳转到「系统设置 > 隐私与安全性 > 完全磁盘访问权限」，勾选 Cling 即可，无需重启 App。

首次建索引大概花了 2 分 17 秒（约 120 万文件，NVMe SSD），菜单栏图标会显示进度环。索引完成后，点击菜单栏图标或 `⌘⌥Space`（默认全局热键，可改）呼出搜索窗，输入 `tsconf` 瞬间出现 `tsconfig.json`、`tsconfig.base.json`、`tsconfig.prod.json` 三个结果，延迟肉眼不可见。

**遇到的坑**：

1. 1. **Pro 激活不持久**（Issue #26）：输入 License Key 后显示激活成功，但退出 App 或重启 Mac 后恢复 Free 状态。作者建议 `killall Cling; rm ~/Library/Application\ Support/Cling/*` 清理后重装最新版再激活，我按此操作后问题解决——疑似 Paddle 授权回调的本地缓存写入时机问题。
2. 2. **中文输入法下回车被拦截**（Issue #25，v2.6.6 已修复）：拼音输入时按回车确认原文会被误判为「打开文件」。作者在 `onKeyPress(.return)` 与 `NSEvent` 本地监控两处加了 `hasMarkedText()` 判断，升级后不再复现。
3. 3. **外接盘休眠导致卡顿**（v2.6.8 修复）：选中文件在休眠的外接盘上时，动作栏在主线程做文件类型检测会冻结 UI 几秒。新版已移至后台线程。

### 核心亮点

**1. 模糊匹配算法不做「字母散射」匹配，而是逐词前缀匹配**  
这是 Cling 与 Spotlight/Alfred 最大的体感差异。输入 `nihao`，Spotlight 会把路径里含有 n、i、h、a、o 这五个字母（顺序任意、间隔任意）的文件全捞上来；Cling 只匹配「以 nihao 开头」或「路径分段里有以 nihao 开头的词」的文件。v2.6.9 新增的「Literal search」模式（Settings > Search 开启）更极致：`ni hao` 必须按空格分词、逐词前缀匹配，`nihao` 不再拆分。这对知道大概文件名、只想快速定位的场景极其友好——不用造复杂查询语法，输错一个字母也能容错。

**2. 索引覆盖系统卷、隐藏文件、dotfiles、应用沙盒**  
给完全磁盘访问权限后，`/private/var`、`/System/Volumes/Data`、`~/Library/Containers/com.xxx/Data` 这些 Spotlight 永远不索引的路径全在结果里。实测搜 `.ssh/config`、`.gitignore`、Docker 容器里的 `config.json`、Xcode DerivedData 目录下的 `.xcscheme`，全能秒出。这对开发者、运维、需要钻进应用容器改配置的人是刚需。

**3. Stash（⌘S）与 Sort Shortcuts（⌘1~⌘5）把「搜→动作」流程压缩到键盘不离手**  
搜到一组文件要批量处理时，`⌘S` 把它们钉到结果列表上方的 Stash 栏，继续搜别的关键词，Stash 里的文件一直在，支持 Quick Look、拖拽到 Terminal/编辑器、右键「用 … 打开」、`⌘⌫` 移入废纸篓。排序快捷键默认 `⌘1` Name、`⌘2` Path、`⌘3` Size、`⌘4` Date、`⌘5` Relevance，再按一次倒序，Settings 里可改绑。这两个功能把「找到文件→做点什么」的中间环节全键盘化了，不用切鼠标、不用记复杂前缀参数。

### 避坑与总结

**内存占用是硬指标**：README 明确写「100 MB 到 1 GB 视文件总量而定」。我这边 120 万文件，后台常驻 ~680 MB（Activity Monitor 实测），前台激活时峰值 ~920 MB。作者利用 `NSDiscardableContent` 标记后台索引为可清除，内存压力大时 macOS 会自动换出到磁盘，再次唤起需重建约 3-5 秒。16 GB 内存机器建议只开 Home/Library/Applications 三个范围（Free 版默认），别勾 System/Root，否则常驻内存轻松破 GB。

**定价与授权模型**：7 天试用（自动、无需绑卡），试用期后自动降级为 Free 版（三范围、500 结果上限）。Pro 版 $29 买断、终身授权、最多 3 台 Mac，解锁 System/Root 两个范围、无结果上限、优先技术支持。授权走 Paddle，Issue #26 反馈的激活不持久在 v2.6.10 后通过「清理缓存+重装」可规避，但属于已知瑕疵，作者回复表示正在排查 Paddle 回调逻辑。

**不适用场景**：

* • 需要全文内容搜索（Cling 只索引文件名/路径/元数据，不读文件内容）
* • 依赖 Raycast/Alfred 生态的扩展、脚本、Workflow 用户（Cling 只有 Raycast 扩展，无 Alfred Workflow）
* • Windows/Linux 跨平台需求（纯 macOS 原生 Swift AppKit，无移植计划）

**个人判断**：值不值得折腾？**值得，前提是你日常真有「知道文件名大概长什么样、但 Spotlight 搜不到」的痛点**。如果你 90% 的搜索都在 `~/Downloads`、`~/Documents`、应用自带文件里，Spotlight + Alfred Free 足矣。但如果你天天钻 `/private/var/log`、Docker volumes、Xcode DerivedData、Node.js `node_modules` 深处找配置文件、日志、临时产物，Cling 的模糊匹配精度、系统卷覆盖、Stash 批量操作能实实在在省下每天十几次「造查询语法→等索引→再筛选」的时间。买断对比年、8/月，性价比极高。

**一个明确建议**：先用 Free 版跑两周，把 Home/Library/Applications 三范围吃透，确认「系统卷搜索」是真刚需再买 Pro。别为「可能用到」买单，为「已在用且痛」买单。
