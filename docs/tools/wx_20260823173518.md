今天在本地跑通了 **Drawnix**（GitHub: `plait-board/drawnix`，目前约 13.4k Star），一个主打「一体化白板」的开源项目。关注它的缘由很简单：团队在评估自建白板方案，Excalidraw 虽成熟但插件机制弱、不原生支持思维导图；Miro、FigJam 又是闭源 SaaS。Drawnix 号称在一个代码库里同时搞定思维导图、流程图、自由画，底层还沉淀出了 **Plait 框架**（源自 PingCode Wiki 的生产级技术资产），这技术背书让我决定实测一把。

#### 部署实录

项目提供两条主流部署路径，我分别在 **MacBook Pro M3 Max (macOS 15.6)** 和 **Ubuntu 22.04 (Intel i7-12700 + 32GB RAM)** 上验证：

**路径 1：Docker 一键部署（推荐生产/快速试用）**

```
# 拉取最新镜像（v0.3.0，2025-09-04 发布）  
docker pull pubuzhixing/drawnix:latest  
  
# 启动，映射 8080 端口  
docker run -d -p 8080:80 --name drawnix pubuzhixing/drawnix:latest
```

浏览器访问 `http://localhost:8080` 即可看到编辑器界面。镜像体积约 **210 MB**，冷启动 3-5 秒。注意：官方镜像基于 Nginx 静态资源服务，**不包含后端协作服务**——即多人实时协作、持久化存储需自行对接（文档未给出现成方案，Issues #256 讨论中提到需自建 WebSocket 服务）。

**路径 2：本地源码构建（适合二次开发/调试插件）**

```
git clone https://github.com/plait-board/drawnix.git  
cd drawnix  
# 需 Node.js 18+、pnpm 9+（项目用 Nx 管理 monorepo）  
corepack enable  
pnpm install  
pnpm run start  # 启动开发服务器，默认 http://localhost:4200
```

M3 Max 上 `pnpm install` 耗时约 1 分 20 秒，`pnpm run start` 编译约 45 秒。Ubuntu 机器上因无原生 ARM 优化，构建时间翻倍。源码结构为 Nx monorepo：

```
apps/web          # drawnix.com 前端入口  
packages/drawnix  # 核心应用逻辑（大脑）  
packages/react-board  # React 视图层渲染  
packages/react-text   # 富文本渲染模块（基于 Slate）
```

**坑点提示**：`pnpm run start` 默认绑定 `0.0.0.0:4200`，若 4200 端口被占用（常见于同时跑 Grafana/Prometheus），需在 `nx.json` 或 `project.json` 修改端口；另外首次构建会下载大量 `@nx/*` 插件，国内网络建议配置 `registry.npmmirror.com` 加速。

#### 核心亮点拆解

**1. Markdown 一键生成思维导图——真·大纲转结构**  
在画布空白处粘贴如下 Markdown：

```
# 项目规划  
## 后端  
### API 设计  
#### RESTful  
#### GraphQL  
### 数据库  
## 前端  
### 组件库选型  
### 状态管理
```

按下 `Enter` 或点击工具栏「思维导图」图标，瞬间生成可拖拽、可折叠、可换主题的思维导图。节点支持富文本编辑（双击进入 Slate 编辑器），支持 `Tab`/`Shift+Tab` 调整层级、`Enter` 新增同级节点。对比手动在 Excalidraw 里拖框拉线、调对齐，效率提升至少 **5 倍**。导出 `.drawnix` JSON 后，节点坐标、层级、样式全保留，二次打开可继续编辑——这比 Mermaid.js 只能「渲染不可编辑」强得多。

输入：

通过拒绝用户请求权限校验业务逻辑返回 403写入数据库返回结果

点击「流程图」工具，画布直接渲染出标准流程图，**每个节点、连线均可拖拽调整位置、修改文本、换样式**。这是 Drawnix 区别于「Mermaid 在线预览器」的关键：它把 Mermaid 解析为 **Plait 内部图元模型**，而非单纯 SVG 渲染。实际测试含 30+ 节点的复杂流程图，渲染延迟 < 200ms，拖拽 60fps 无卡顿（M3 Max / Chrome 139）。

**3. 插件架构：双 UI 框架（React/Angular）共存的工程化落地**  
这是我最感兴趣的技术点。Plait 框架将 **核心图元模型**（节点、边、画布坐标系、撤销栈、命令总线）与 **视图层** 彻底解耦：

* • `packages/react-board`：React 19 实现的渲染器，用 `requestAnimationFrame` 批量刷新，配合 `useMemo` 避免重渲染
* • `packages/drawnix-angular`（独立仓库）：Angular 版渲染器，复用同一套核心模型
* • 富文本编辑统一委托给 **Slate**（目前仅支持 Slate，文档称未来可接入 ProseMirror/Quill）

这意味着：若团队主技术栈是 Angular，可直接引用 `drawnix-angular`；React 团队用 `react-board`。**核心业务逻辑（思维导图布局算法、流程图自动布局、连线路由）只维护一份**，这在开源白板里极罕见——Excalidraw、tldraw 均强绑定 React。代价是：插件开发需同时懂 Plait 核心 API 与目标框架渲染机制，学习曲线陡峭；文档目前只有源码级注释，无独立插件开发指南。

**4. 无限画布 + 自动保存 + 多格式导出，基础体验拉满**

* • 画布缩放 0.1x–800%，鼠标滚轮/触控板双指缩放丝滑
* • 6 套内置主题（亮/暗/高对比度等），一键切换
* • 浏览器 `localStorage` 自动保存，刷新不丢数据（单文件上限约 5MB，超限会报错，需手动导出 JSON 备份）
* • 导出支持：PNG/JPG（可选透明背景）、`.drawnix`（自有 JSON）、SVG（实测大流程图 SVG 导出会丢失部分连线样式，已提 Issue #198）

#### 避坑与总结

| 维度 | 评价 | 备注 |
| --- | --- | --- |
| **部署门槛** | ⭐⭐⭐⭐⭐ Docker 一键跑通，源码构建仅需 Node 18+ | 无数据库、Redis 等外部依赖 |
| **核心功能完整度** | ⭐⭐⭐⭐ 思维导图/流程图/自由画三合一，Markdown/Mermaid 双向转换可用 | 协作、权限、模板库、评论等 SaaS 特性**全无** |
| **二次开发友好度** | ⭐⭐⭐ 插件架构设计先进，但文档缺失、API 未稳定、示例稀缺 | 需啃源码，适合有强定制需求的团队 |
| **性能上限** | ⭐⭐⭐⭐ 单画布 200+ 节点仍流畅，Plait 内部用 QuadTree 空间索引优化命中测试 | 未测试 1000+ 节点场景 |
| **社区活跃度** | ⭐⭐⭐⭐ 13.4k Star，近期月均 30+ PR，v0.3.0 刚发布 | 核心维护者 `@pubuzhixing8` 响应快，但贡献者多集中在修 Bug |

**个人判断**：

* • **适合**：需要**私有化部署**、想把「大纲→思维导图」「Mermaid→流程图」纳入自有知识库/文档系统的中小团队；愿投入前端资源做二次开发、接入协作后端的工程化团队。
* • **不适合**：开箱即用要多人实时协作、要现成模板市场、要权限管理、要移动端 App 的场景——这些全得自己造轮子。
* • **我的决策**：团队决定在内部文档平台集成 Drawnix 的**只读渲染模式**（引用 `react-board` 渲染 `.drawnix` JSON），编辑端仍用 Excalidraw + 自建协作服务。理由：Drawnix 协作栈缺失是硬伤，短期内官方不太可能补齐（Issues #256 讨论倾向「社区自建」）。

**后续关注点**：v0.4.0 计划引入「协作协议抽象层」（Issue #289），若能提供基于 Yjs/Automerge 的参考实现，可重新评估全栈替代 Excalidraw 的可能性。
