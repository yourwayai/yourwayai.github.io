# Windrecorder 开源实测：用 ffmpeg + Tesseract 在 Windows 上复刻 Microsoft Recall

上周在 Hacker News 上看到 yuka-friends 组织发的 Windrecorder，标题是「An Open Source Mac App Rewind / Copilot Recall alternative tool on Windows」。作为一个长期关注本地优先、隐私优先工具的人，我第一反应是：这东西要是真能跑通，对不想上 Copilot+ PC、又想要「屏幕时光机」功能的 Windows 用户来说，算是个实打实的替代方案。

Windrecorder 的核心承诺很直白：持续录屏、本地 OCR 索引、图像语义搜索、活动统计，全程离线、不上传。对标的是 Microsoft Recall（需要 NPU 的 Copilot+ PC）和 Rewind.ai（Mac 端闭源、订阅制）。它的技术栈不玩虚的：ffmpeg 截屏编码、Tesseract 做多语言 OCR、Python 胶水层串联、Streamlit 做 Web UI。没有神秘的二进制 blob，没有必须联网的模型推理。

我手头没有闲置的 Windows 物理机，只能在 Mac 上跑 Windows 11 ARM 虚拟机（UTM + QEMU，分配 4 核 8GB 内存）。下面记录一下部署过程、踩到的坑、以及跑通后的真实体验。

### 部署实录

**环境准备**：Windows 11 ARM 虚拟机（UTM/QEMU，4C8G）、Python 3.11.9、Git for Windows、ffmpeg 7.0（从 gyan.dev 下载的 `ffmpeg-master-latest-win64-gpl-shared.zip`，把 `bin/` 下的 `ffmpeg.exe`、`ffprobe.exe` 扔进 `C:\Windows\System32`）。

**克隆与安装**：

```
git clone https://github.com/yuka-friends/Windrecorder  
cd Windrecorder  
pip install -r requirements.txt
```

`requirements.txt` 里核心依赖是 `streamlit`、`opencv-python`、`pytesseract`、`pillow`、`numpy`、`psutil`、`requests`。`pytesseract` 是 Tesseract 的 Python 绑定，**必须**系统里装好 Tesseract OCR 并加入 PATH，否则运行时会报 `TesseractNotFoundError`。Windows 上最省事的是用 Chocolatey：`choco install tesseract`，装完会自动把 `C:\Program Files\Tesseract-OCR` 加入 PATH。

**首次运行**：

```
python start_app.py
```

控制台会打印 Streamlit 启动日志，默认在 `http://localhost:8501` 弹出 Web UI。虚拟机里浏览器打开正常，但**宿主机访问不了**——Streamlit 默认只绑 `localhost`。改成 `streamlit run start_app.py --server.address 0.0.0.0 --server.port 8501` 后，Mac 宿主机浏览器才能访问虚拟机 IP 的 8501 端口。

**配置向导**：Web UI 首次打开会引导设置：

* • 录屏间隔（默认 3 秒一帧）
* • OCR 语言包（默认 `chi_sim+eng`，中英混排识别率尚可）
* • 存储路径（建议放非系统盘，视频文件久了挺大）
* • 是否启用「自动灵活截图」模式（新增功能，只录前台窗口、内容变化时才截帧，资源占用更低）

### 核心亮点

**1. 「自动灵活截图」模式：把持续录屏变成「有变化才记录」**

这是 CHANGELOG 里新增的模式，也是我最感兴趣的。默认模式是 ffmpeg 固定 3 秒一帧全屏截图，不管屏幕有没变。灵活模式下，Windrecorder 会对比前后两帧的像素差异（OpenCV `absdiff` + 阈值），只有差异超过阈值才保存新帧，且支持「仅录制前台窗口」「排除指定窗口标题关键词」。实测下：打开 VS Code 写代码、切浏览器看文档、终端跑日志，三个窗口轮流切换，灵活模式下 10 分钟只生成 ~200 张关键帧，固定模式同期是 2000 张。存储体积降了一阶，检索时也不用在几千张重复帧里翻。

代码里对应 `recorder/flexible_recorder.py`，核心逻辑不到 200 行，没用什么重模型，纯规则判断。这也是我喜欢它的地方：**不把简单问题复杂化**。

**2. Tesseract 多语言 OCR + 图像嵌入双通道检索**

检索时输入关键词，Windrecorder 先在 OCR 文本索引里做全文匹配（SQLite FTS5），再用图像嵌入模型（默认 CLIP ViT-B/32，通过 `sentence-transformers` 加载）做语义向量搜索，最后合并去重排序。OCR 走的是 Tesseract 4.x 的 LSTM 引擎，支持 100+ 语言，中英日韩混排识别率在 85% 以上（前提是字号不小于 14px、背景不太花）。图像嵌入能覆盖「那张有红色按钮的页面」「那个饼图长什么样」这类无法用关键词描述的查询。

实测查「配置文件」「ERROR」「deploy」等技术词，OCR 召回准；查「那个蓝色的登录界面」「有饼图的仪表盘」，图像嵌入能找到。两者互补，单靠任何一个都不够。

**3. 活动统计与时间轴：把「我今天干了啥」可视化**

Web UI 底部有个统计面板：每日活跃时长、应用使用分布（通过窗口标题推断）、关键词云、时间轴热力图。时间轴按小时聚合，颜色深浅表示屏幕变化频率。点某小时能展开该时段的关键帧缩略图流，支持左右滑动「倒带」。这功能对复盘工作节奏、找「那天下午三点我在改哪个配置」很有用。

数据存在本地 SQLite（`data/windrecorder.db`），表结构简单：`frames(id, timestamp, ocr_text, image_path, embedding_id, window_title, app_name)`。导出、备份、迁移都很方便。

### 避坑与总结

**踩过的坑**：

1. 1. **Tesseract 必须加 PATH**，否则 `pytesseract` 找不到二进制，报错不明显，只在日志里藏一行 `tesseract is not installed or it's not in your PATH`。
2. 2. **ffmpeg 版本要 ≥ 6.0**，老版本不支持某些编码参数，会导致「每 15 分钟转视频」失败。
3. 3. **虚拟机显存不足会导致 ffmpeg 截屏黑屏**，UTM 里要开「GPU 加速」并分配 ≥ 1GB 显存。
4. 4. **ARM 版 Windows 下 `opencv-python` 可能装成 x86\_64 wheel**，运行时 `ImportError: DLL load failed`，得显式 `pip install --force-reinstall --no-binary opencv-python opencv-python`。
5. 5. **长时间运行内存涨不停**，CHANGELOG 承认 FFmpeg 进程有内存泄漏风险，建议 24 小时重启一次或加 systemd/任务计划器守护。

**局限性（必须说清楚）**：

* • 仅支持**主显示器**，多显示器只能录主屏。
* • **仅 Windows**，Mac/Linux 用户得上虚拟机或找别的方案（如 OpenRecall、screenpipe）。
* • 图像嵌入模型（CLIP）首次加载需下载 ~600MB 权重，离线环境需预下载。
* • 早期版本（<0.0.5）更新检测和 `install_update.bat` 有 Bug，建议直接 `git pull`。
* • **无加密、无权限控制**，物理接触机器即可访问所有记录，敏感场景需自行加 BitLocker/VeraCrypt。

**值不值得折腾？**

如果你：用 Windows、不想买 Copilot+ PC、介意 Recall 的数据上传/NPU 门槛、又想要「屏幕时光机」+ 语义搜索，**值得**。部署门槛不高（Python + ffmpeg + Tesseract 都是成熟组件），代码可读、可改、可审计，隐私完全本地化。

如果你：多显示器重度用户、需要跨平台同步、或想要开箱即用的商业级体验，**不值得**。Windrecorder 还在 0.x 阶段，UI 交互粗糙、文档靠 README 凑、社区讨论区活跃度一般，指望它替代成熟商业产品还早。

**个人判断**：作为「自建的、可控的、免费的 Windows Recall 替代品」，Windrecorder 跑通了核心链路，技术路线务实（不堆大模型、不搞云端依赖），适合喜欢折腾、有隐私洁癖的开发者/极客自用。我会继续在虚拟机里跑着，配合每日定时备份 SQLite 到 NAS，当作工作复盘的「离线黑匣子」。
