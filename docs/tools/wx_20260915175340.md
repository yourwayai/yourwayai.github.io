# Python-Type-Challenges：把「看不懂类型报错」变成「能手写泛型协议」的练习场

Python 3.5 引入 `typing` 模块至今快十年，类型提示从「可选装饰」变成了大型项目标配。但问问身边写 Python 的工程师：有多少人真正搞清楚 `TypeVar` 的协变/逆变？能手写出 `@overload` 精准匹配多态签名？敢在 CI 里开启 `--strict` 且不报错？

我自己的经历：读 PEP 484、585、604、612、646、673、681、695……每个 PEPs 单独看懂了，组合到一起写业务代码时，mypy 报一堆 `Incompatible type in assignment`、`Type variable bound violated`，只能靠 `# type: ignore` 压着。去年想系统补课，找了半圈：

* • **官方文档**：权威但碎片化，缺乏「从易到难」的练习路径
* • **Real Python / 动手学深度学习类教程**：偏入门，讲不透 `ParamSpec`、`TypeGuard`、`Self` 这些进阶特性
* • **TypeScript 的 type-challenges**：思路对标，但语言不同，泛型约束、结构化子类型、协议类的语义差异大，硬套会绕进沟里
* • **Exercism / LeetCode**：练算法不练类型系统，类型注解通常只是附带

**核心痛点**：缺一个**专门针对 Python 类型系统、按难度分级、可在线/本地交互运行、带参考解答和类型检查器验证**的练习集。

### 破局点

laike9m（李克，Python 核心开发者、mypy 贡献者）开源了 Python-Type-Challenges。它的思路极简：**不讲理论、只给题目**。每道题就是一个 `question.py`，里面有 TODO 注释和期望通过的类型检查用例（用 `typing.assert_type` 断言）；你填类型注解，跑 `mypy`/`pyright`，绿了就过。目前收录 40+ 道题，分四级：**Basic（9）、Intermediate（13）、Advanced（18）、Extreme（4）**，覆盖从 `Optional`/`Union` 到 `ParamSpec`、`Concatenate`、`TypeIs`、`TypeGuard`、`Self`、`Never`、`dataclass_transform` 等 Python 3.9-3.13 的新特性。

对标 TypeScript 的 type-challenges（antfu 维护），但**完全按 Python 类型系统语义设计**：用 `Generic[T]` 而非 `<T>`，用 `Protocol` 结构化子类型而非接口，用 `TypeVarTuple`/`Unpack` 做变长泛型而非元组类型。这点很关键——**同一个题目换语言，类型系统层面的解法往往不通用**。

### 核心工作流拆解

**场景**：你是个写了三年 Python 的后端工程师，平时用 `List[str]`、`Dict[str, int]`、`Optional[int]` 没问题，但看到 `Callable[[int], str] | None` 就头大，更别提 `TypeVar('T', bound=BaseModel, covariant=True)` 了。想用两周业余时间把类型系统补扎实。

**Step 1：本地跑通环境（5 分钟）**

```
git clone https://github.com/laike9m/Python-Type-Challenges  
cd Python-Type-Challenges  
# 推荐 PDM，自动锁版本、隔离环境  
pdm install  
pdm dev  # 启动本地 Flask 服务，访问 http://localhost:5000  
# 或不想装 PDM：  
pip install -r requirements.txt  
flask run
```

本地 Web 界面左侧题目列表，右侧代码编辑器（Monaco Editor，支持语法高亮、补全），底部实时跑 `pyright` 显示类型错误。**不需要配置 mypy.ini/pyrightconfig.json**，项目内置了严格模式配置，开箱即用。

**Step 2：按难度推进，每题「写注解 → 跑类型检查 → 对比解答 → 复盘」**

以 `basic-optional` 为例：

```
# question.py  
def foo(x):  # TODO: 让 foo 接受 int、None、或无参数  
    pass  
  
foo(10)  
foo(None)  
foo()  
foo("10")  # expect-type-error
```

你写出 `def foo(x: int | None = 0):`，跑 `pyright` 绿灯。再看 `solution.py`：

```
def foo(x: int | None = 0):  # Python 3.10+ union 语法  
    pass
```

一样。**关键是 `expect-type-error` 那行**：它告诉你「这行代码必须报类型错误」，这是类型系统练习特有的「负向测试」——不光要让合法代码过检，还要让非法代码**被拦住**。这思维转换（从「跑通业务逻辑」到「约束类型空间」）是练类型系统的核心。

**Step 3：进阶题揭示类型系统边界**

`advanced-generic-class` 让你写泛型栈：

```
class Stack[T]:  # Python 3.12+ 原生泛型语法  
    def __init__(self) -> None:  
        self.items: list[T] = []  
    def push(self, item: T) -> None: ...  
    def pop(self) -> T: ...
```

`advanced-overload` 让你用 `@overload` 做精准返回类型分发：

```
@overload  
def process(response: bytes) -> str: ...  
@overload  
def process(response: int) -> tuple[int, str]: ...  
@overload  
def process(response: None) -> None: ...  
def process(response: int | bytes | None) -> str | None | tuple[int, str]: ...
```

`extreme-variance` 逼你面对协变/逆变/不变的实战抉择：

```
# 协变：只读容器  
class ImmutableList[+T]: ...  
# 逆变：只写回调  
class Callback[-T]: ...
```

每道题解答里都有**版本标注**：`# Before 3.12 you have to write: T = TypeVar('T'); class Stack(Generic[T]):`。这对维护老项目（还在 3.9/3.10）的人极其友好——**同一道题，新旧语法对照着学，迁移成本极低**。

**Step 4：遇到卡住的题，去 Discussions 或 Issues 看社区讨论**

目前 10 个开放 Issue、活跃 Discussions，作者本人高频回复。比如 `#92` 讨论 Windows 下 UTF-8 编码问题，`#45` 讨论 `TypeGuard` vs `TypeIs` 语义差异。这比独自啃 PEPs 高效得多。

**Step 5：把练习迁移到真实代码库**

练完后，回到工作项目：把 `def process(data):` 改成带 `@overload` 的精准签名，把 `class Repository:` 改成 `class Repository[T: BaseModel]`，开启 `mypy --strict`，CI 绿灯。这才是练习的终点——**不再靠 `# type: ignore` 交保护费，而是让类型系统替你拦住重构时的回归 Bug**。

### 总结

**适用人群**：

* • Python 3.9+ 项目维护者，想系统补齐类型提示短板
* • 从 TypeScript/Java 转 Python，想快速建立「Python 类型系统心智模型」的工程师
* • 想在 CI 强制 `--strict`、消灭 `# type: ignore` 的团队

**不适用场景**：

* • 完全不懂 Python 基础语法的新手（先去学语法）
* • 只写脚本、不做类型检查的一次性任务
* • 需要「视频讲解+手把手」教学模式的学习者（这是练习集，不是课程）

**可操作结论**：克隆下来，跑通本地服务，从 `basic-any` 开始，每天 2-3 道，**两周吃透 40 道题**。配合 `mypy --strict` 落地到项目里，类型报错率能下降 80% 以上。这是我见过**投入产出比最高**的 Python 类型系统训练方式——无视频废话、无理论灌输、纯「题目+类型检查器+参考解」闭环。
