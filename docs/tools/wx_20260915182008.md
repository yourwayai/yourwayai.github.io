# Maxun：把「写爬虫、养代理、修选择器、抗反爬」变成「录一下、说一下、生成 API」的无代码平台

做过数据采集的工程师、运营、分析师都绕不开这四座大山：

1. 1. **写爬虫门槛高**：会写 `requests`/`httpx` 的不懂动态渲染；会写 Playwright/Puppeteer 的又得处理 `navigator.webdriver` 特征、TLS 指纹、验证码、动态类名、Shadow DOM、无限滚动、懒加载……**写一个稳定的提取器，动辄 1-2 天**。
2. 2. **维护成本不可控**：网站前端一改版（React 重构、CSS-in-JS 换类名、DOM 结构调整），**选择器全挂**，报警响个不停，得重写、重测、重部署。
3. 3. **反爬对抗是无底洞**：IP 池轮转、住宅代理贵（$5-15/GB）、请求头伪造、行为模拟（鼠标轨迹、停留时间）、验证码打码平台对接……**基础设施投入远超业务逻辑**。
4. 4. **非技术人员完全依赖开发**：运营要抓竞品价格、PM 要采集用户评论、投资要监控舆情，**全得排开发排期、写需求文档、等交付**，数据时效性靠后。

**典型笨办法工作流**：

```
找开发写 Scrapy/Playwright 爬虫 → 买 Bright Data/Oxylabs 住宅代理 → 搭 Redis 去重 + PostgreSQL 存储 →  
配 GitHub Actions/Celery 定时跑 → 网站改版 → 选择器失效 → 重写选择器 → 重测 → 重部署
```

**投入**：持续 1-2 人天/周维护、$200-1000/月代理费、**零自愈、零自然语言交互、非技术零参与**。

### 破局点

Maxun（getmaxun 组织、AGPLv3 开源、可自托管）把上述链路压缩为 **「Recorder Mode（浏览器录制）」+「AI Mode（自然语言提取）」+「统一运行时/调度/SDK/API」** 四层：

| 层 | 能力 | 核心差异 |
| --- | --- | --- |
| **交互层** | **Recorder Mode** ：浏览器扩展录制点击/输入/滚动/翻页 → 自动生成可复用 Robot（JSON 步骤序列） | **非技术可操作** ，所见即所得，录制即代码 |
| **智能层** | **AI Mode** ：输入 Prompt（如「提取前 50 部电影的片名、评分、时长」）+ 目标 URL → LLM 解析 DOM/Markdown → 结构化 JSON | **无需写选择器** ，LLM 理解语义、自动适配布局微调 |
| **执行层** | 统一 Robot 运行时：自动分页、无限滚动、登录态复用、代理轮转、截图/Markdown/HTML 多格式输出 | **内置反爬缓解** （真实浏览器指纹、行为模拟）、零维护基建 |
| **交付层** | **自动生成 REST API** → 直接 `GET /api/robots/{id}/runs/{runId}/data` 拿 JSON/CSV；**一键导出 Google Sheets/Airtable**；**SDK/CLI/MCP** 程序化调用 | **数据即服务** ，下游系统零对接成本 |

**关键差异点**：

* • **开源自托管（AGPLv3）**：数据不出本地/私有云，合规可控；商用需回馈或赞助
* • **双模式互补**：Recorder 适合固定流程、高精度；AI Mode 适合探索性、半结构化、选择器易变场景
* • **全链路产品化**：不是库、不是框架，是**开箱即用的平台**（Web UI + 后端 + 调度 + API + SDK + CLI + MCP）

### 核心工作流拆解

**场景**：你是电商运营，每周要监控 5 个竞品在 Amazon/自建站的「价格、库存、评分、评论数、促销标签」，导表给定价团队。

**旧流程**：找开发写 5 个爬虫 → 维护 5 套选择器 → 代理池轮转 → 定时跑 → 导 CSV → 发群里。

**Maxun 流程**：

**Step 1：部署（二选一）**

* • **托管版**：打开 https://app.maxun.dev 注册登录，**零部署**，免费额度可跑小规模
* • **自托管**（Docker Compose，5 分钟）：

```
git clone https://github.com/getmaxun/maxun  
cd maxun  
cp .env.example .env  
# 填入：数据库、Redis、JWT_SECRET、可选代理配置  
docker compose up -d  
# 访问 http://localhost:3000
```

**Step 2：Recorder Mode 录制提取器（以 Airbnb 房源列表为例）**

1. 1. 点「New Robot」→ 选「Extract」→ 选「Recorder Mode」
2. 2. 安装浏览器扩展（Chrome/Edge/Firefox），点「Start Recording」
3. 3. 在浏览器里正常操作：

* • 打开 `https://www.airbnb.com/s/Shanghai/homes`
* • 点「价格」筛选、输入范围
* • 滚动加载更多、点「下一页」
* • 对着某张卡片：右键 → 「Select Data」→ 框选「标题、价格、评分、评论数、房型」
* • 点「Done」，扩展自动生成步骤序列（含选择器、等待、翻页逻辑）

4. 4. 回 Web UI，预览提取结果，**点「Save Robot」**

**Step 3：配置调度与代理（可选）**

* • Settings → 「Schedule」：每天 06:00 自动跑
* • Settings → 「Proxy」：填入住宅代理（支持 IPcook/Nodemaven/Novada 等合作商，或自建）
* • Settings → 「Pagination」：已自动识别「下一页」按钮，可手动调整最大页数

**Step 4：AI Mode 尝试（针对 IMDb Top 250 这种结构相对固定、选择器易变的场景）**

1. 1. 新建 Robot → 选「Extract」→ 选「AI Mode」
2. 2. Target URL: `https://www.imdb.com/chart/top/`
3. 3. Prompt: `提取前 50 部电影的：中文片名、英文片名、年份、评分、时长、导演、主演前 3 位`
4. 4. 点「Generate」，LLM 返回解析策略，**可预览、微调、确认**

**Step 5：拿数据、接系统**

* • **Web UI**：查看 Run 记录、下载 JSON/CSV、一键推 Google Sheets/Airtable
* • **REST API**：

```
curl -H "Authorization: Bearer ***" \  
  "https://app.maxun.dev/api/robots/robot_abc123/runs/latest/data?format=json"
```

* • **Node SDK**：

```
import { MaxunClient } from '@getmaxun/node-sdk'  
const client = new MaxunClient({ apiKey: proces..._KEY })  
const data = await client.robots.run('robot_abc123', { format: 'json' })
```

* • **MCP（Model Context Protocol）**：直接在 Cursor/Cline/Claude Desktop 配置 `maxun-mcp`，Agent 可自然语言调用「帮我抓取竞品最新价格」

**投入产出对比**：

| 指标 | 旧方案（自建爬虫） | Maxun |
| --- | --- | --- |
| 首个提取器上线 | 1-2 天 | **10-30 分钟** （Recorder） / **3-5 分钟**（AI Mode） |
| 网站改版修复 | 2-4 小时/次 | **Recorder：重新录制受影响步骤（分钟级）** **AI Mode：多半自适应，无需动手** |
| 非技术人员自助 | ❌ 完全依赖开发 | ✅ **运营/PM 可独立录制、调度、导表** |
| 基础设施维护 | 自建代理池、监控、重试 | **平台内置** （代理集成、自动重试、错误分类） |
| 数据交付 | CSV/数据库/手工给 | **REST API + Google Sheets + Airtable + SDK + MCP** |
| 合规/数据主权 | 视部署而定 | **自托管完全可控，AGPLv3 开源可审计** |

### 避坑与总结

**实测踩过的坑**：

1. 1. **Recorder Mode 对 Shadow DOM / iframe / Canvas 渲染内容支持有限**——遇到这类站点（如某些图表库、地图组件），录制的选择器会指向宿主元素而非内部内容，**需切 AI Mode 或人工补选择器**。
2. 2. **AI Mode 依赖 LLM 上下文窗口与成本**——大页面（DOM > 100k tokens）需先用 Scrape Robot 抓 Markdown 再喂 LLM，单次成本约 $0.05-0.30（Claude 3.5 Sonnet / GPT-4o），**批量跑需预估 Token 预算**。
3. 3. **自托管资源占用**：PostgreSQL + Redis + Backend + Frontend + Worker 最低 **2C4G**，建议 4C8G 生产跑稳；Docker Compose 默认不含反向代理/SSL，**生产需自配 Nginx/Traefik + 证书**。
4. 4. **登录态复用**：支持「导入 Cookie/Storage State」，但**复杂 OAuth/MFA/设备指纹站点**（如 LinkedIn、Twitter/X）仍易失效，需定期人工刷新 Cookie 或配合无头浏览器登录流程。
5. 5. **AGPLv3 传染性**：**商用自托管修改代码必须开源**，或购买商业许可/赞助，**法务务必确认合规性**再落地内网。

**局限性（必须说清楚）**：

* • **非「通用爬虫框架」**：不适合「抓全站、建搜索索引、增量爬取万级页面」——Crawl Robot 适合中等规模（<10k 页面），大规模仍需 Scrapy/分布式爬虫集群。
* • **AI Mode 非银弹**：高度动态、加密接口、GraphQL 批量查询、WASM 渲染的站点，LLM 看不到底层请求，**仍需 Recorder 录制网络请求或配合 HAR 导入**。
* • **代理集成虽内置但非免费**：IPcook/Nodemaven/Novada 等合作商需单独付费，**Maxun 本身不提供代理 IP**，仅做轮转/认证/地域管理。
* • **社区生态尚早**：SDK 仅有 Node（Python/Go 社区维护中）、插件机制未开放、第三方 Robot 市场不存在，**二次开发靠读源码、提 PR**。

**值不值得接入？**

**值得**，如果你：

* • 团队**有大量「非标准化、高频变动、中小规模」采集需求**（电商监控、招聘聚合、舆情追踪、竞品调研、线索挖掘）
* • **缺爬虫工程师**、或想把爬虫工程师从「改选择器」解放出来做高价值事
* • 需要**数据即 API/表格、直接对接下游 BI/CRM/Agent**，不想搭数据管道
* • **合规要求数据不出境/不经第三方 SaaS**，需自托管可审计

**不值得**，如果你：

* • 只有**极少量、一次性**采集需求（Python + requests/Playwright 临时写更快）
* • 目标站点**高度对抗、需极致性能/并发**（如实时竞价、高频交易数据、全网搜索引擎级爬取）
* • 团队**已有成熟爬虫平台、迁移成本 > 收益**
* • **无法接受 AGPLv3** 且不想购买商业许可

**个人判断**：Maxun 是 **「Browserbase/Stagehand 思路的开源平台化落地」**：用真实浏览器录制规避反爬、用 LLM 理解语义替代脆弱选择器、用产品化交付（API/Sheets/SDK/MCP）消除「采集后还得清洗/对接」的最后一公里。它没发明新技术，但把 **Recorder + AI + 调度 + 代理 + 交付** 串成了一个**非技术可用、工程师可扩展、合规可自托管**的整体。对「有采集需求、无爬虫团队、重数据主权」的中小团队，**它是目前开源界最接近「开箱即用的无代码数据平台」**。建议先跑托管版免费额度跑 3-5 个真实业务场景，评估提取准确率、AI 成本、调度稳定性，再决定是否自托管落地。
