准备技术面试的开发者通常有两套教材：一套是 **LeetCode/算法题**（数据结构、复杂度、刷题技巧），另一套是 **System Design/系统设计**（分布式、CAP、一致性、微服务、数据库分库分表）。但中间有一层常被忽视、却在大厂机器编码轮、架构轮、甚至系统设计细节轮高频出现的：**Low Level Design（LLD） / Object Oriented Design（OOD）**。

典型痛点：

* • 面试官说「设计一个停车场/电梯/缓存/限流器」，你会写 `if-else`、不会拆接口、不会套模式、不会画类图
* • 背得出「单例双重检查锁」「工厂方法抽象工厂区别」，但遇到「这个场景该用策略还是模板方法」卡住
* • 知道 `synchronized`/`ReentrantLock`/`volatile`，但不会把「生产者消费者」「读写锁」「线程池拒绝策略」落到具体类里
* • 系统设计画得出服务拓扑，低级设计画不出类之间的组合/聚合/依赖/泛化关系（UML 箭头全搞混）

现有资源要么太散（博客碎片）、太深（GoF 原著 400 页）、太偏（只讲 Java、只讲 C++）、太旧（没讲 `java.util.concurrent`、没讲虚拟线程），**缺一份「按面试频次分层、概念-模式-题目三位一体、多语言代码对照、免费可离线」的系统性索引**。

### 破局点

awesome-low-level-design（`ashishps1/awesome-low-level-design`，作者 Ashish Pratap Singh，同名 System Design 仓库 `awesome-system-design-resources` 也是他维护）的定位极其清晰：**只做 LLD/OOD 面试准备的「免费资源导航图」**。不写代码、不讲视频、不搞付费课，只把全网公开的优质文章、教程、代码仓库、题目、书籍、课程按 **LLD 知识体系** 分类、去重、标注难度、链接直达。

按 ecosyste.ms 统计，仓库聚合了 **400+ 个精选资源**，核心分类如下：

**关键设计**：每个模式/题目条目不是单纯链接，而是 **「概念解释链接 + UML 图链接 + 多语言实现链接（Java/Python/Go/C++）+ 面试常见变体/追问」**。例如「单例模式」条目下会同时给出：

* • Refactoring.Guru 单例页（概念+UML+伪代码）
* • AlgoMaster.io 单例深度解析（双重检查锁、静态内部类、枚举、序列化破坏、反射破坏、集群单例）
* • Java/Python/Go 线程安全实现对比
* • 面试追问：「Spring 怎么保证 Bean 单例？」「分布式环境下单例怎么做？」

### 核心工作流拆解

#### 典型用例：两周冲刺 LLD 面试

**第 1-3 天：补基础、建脑图**

* • 按 `Fundamental Concepts` → `OOP Fundamentals` → `Design Principles` 顺序读完 16 个核心资源
* • 产出：**一张手绘脑图**，把 SOLID 5 条原则、DRY/KISS/YAGNI、组合优于继承、里氏替换判定标准、依赖倒置三种实现方式（接口/抽象类/回调）全挂上去
* • 验收：合上脑图能默写「开闭原则在策略模式里怎么体现」「接口隔离原则违反时会出现什么症状」

**第 4-10 天：模式分类攻克、代码对照**

* • 按 **创建型 → 结构型 → 行为型** 顺序，每天 2-3 个模式
* • 每模式 **「看 UML → 读概念 → 跑代码 → 改变体 → 背追问」**：

1. 1. 打开 Refactoring.Guru 对应页面，盯着类图看 5 分钟，直到能默画
2. 2. 读 AlgoMaster.io 深度解析，重点记「意图」「适用性」「优缺点」「与相似模式区别」
3. 3. 克隆对应语言实现仓库（如 `deep3072/Low-Level-Design` Python 版、`divyadhimaan/low-level-design` Java 版），跑通、改参数、加日志、破坏单例、替换策略
4. 4. 写 3 个面试追问的 30 秒口头答案

* • 产出：**模式速查卡**（一面 A4，正面 23 模式意图+关键角色，反面高频追问）

**第 11-12 天：并发专题、手写经典题**

* • 读 `Concurrency Concepts` 18 个资源，重点搞懂：`AQS` 状态机、`ReentrantLock` 公平/非公平、`Condition` 信号机制、`ThreadPoolExecutor` 7 个参数、`CompletableFuture` 组合式异步、`Virtual Thread` 与平台线程切换
* • 做 `Concurrency Problems` 9 道：生产者消费者（阻塞队列/信号量/管道）、读写锁（缓存场景）、完成服务（倒计时/栅栏）、线程池拒绝策略自定义、Future 超时取消传播
* • 产出：**并发模板库**（GitHub Gist，随时复制粘贴）

**第 13-14 天：实战题目、限时模拟**

* • 挑 `LLD Interview Problems` 3 道核心题（停车场/电梯/缓存/限流器 选 2）+ 1 道冷门题（事件总线/插件系统）
* • 每题 **45 分钟限时**：需求澄清 5 分钟 → 核心类识别 5 分钟 → 类图画草稿 10 分钟 → 核心代码写完 20 分钟 → 扩展点/权衡讲 5 分钟
* • 对照仓库给的参考实现复盘：接口设计是否正交？异常处理是否完备？锁粒度是否最小？扩展点是否符合开闭原则？

#### 另一条线：平时不面试、只想「写出更好的代码」

| 日常场景 | 仓库对应资源 | 怎么用 |
| --- | --- | --- |
| 发现 `if-else` 链超过 3 层 | 行为型→策略模式/状态模式 | 看 UML、抽 `Strategy` 接口、注入实现、配合工厂选策略 |
| 同事改你的类、你改同事的类、互相踩坏 | 设计原则→依赖倒置/接口隔离 | 抽稳定接口、高层模块依赖抽象、接口按客户端需求拆细 |
| 多线程下 Map 并发修改崩/数据不一致 | 并发→概念/问题 | 换 `ConcurrentHashMap`/加读写锁/用 `StampedLock`/上虚拟线程+结构化并发 |
| 要给第三方库加适配层、又不想污染核心域 | 结构型→适配器/外观/代理 | 选对象适配器/类适配器、外观简化接口、代理加懒加载/权限/日志 |

### 总结

**适用人群**：

* • 面试大厂（Google/Amazon/Uber/Microsoft/字节/阿里/美团等）机器编码轮、LLD 轮、架构轮的后端/全栈工程师
* • 想系统性补齐「设计模式只知其名」「SOLID 只能背定义」「UML 画不出来」「并发只会 synchronized」的中高级开发者
* • 技术面试官：拿来出题、定评分标准、对齐团队 LLD 基线

**不适用场景**：

* • 纯算法刷题选手（去 LeetCode/NeetCode）
* • 只做分布式架构、不关心单进程内类设计的架构师（去 awesome-system-design-resources）
* • 要现成可跑的完整项目代码（仓库只给资源链接，实现代码在被链接的第三方仓库里）
* • 只会动态语言、拒绝看静态类型代码的开发者（大部分 UML/模式示例以 Java/C# 为主，Python/Go 覆盖较少）

**一个可操作的结论**：  
把这个仓库当「**LLD 面试知识地图 + 免费资源导航**」用。不要试图把 400+ 链接全点一遍——**按「脑图→速查卡→模板库→限时模拟」四步走**，两周把高频考点过一遍、手写 5-6 道经典题、背会 23 模式意图与追问。面试时遇到「设计一个 X 系统」，你的大脑会自动弹出：**核心实体 → 接口拆分 → 模式选型 → 类图草稿 → 关键代码 → 并发处理 → 扩展点预留**，而不是盯着屏幕发呆。
