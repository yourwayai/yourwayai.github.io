# img2threejs：把一张参考图「重构」为可读、可动画、可维护的 Three.js 过程化代码，而非生成不透明网格

img2threejs（GitHub: `img2threejs/img2threejs`，4.2k+ ⭐）近期完成大规模重构（PR #9，2026-07-20），将管线拆分为 `forge/`（Python 阶段脚本）、`grimoire/`（领域知识/评分卡）、`docs/` 三大目录，确立了「分级质量把关的过程化重构」作为核心工作流。它不是传统的图生 3D 模型工具（如 Tripo、Meshy、CSM），而是**一个面向 AI 编码助手的技能包**——装入 Claude Code / Codex CLI / OpenCode 后，给一张参考图，Agent 按固定流程输出 **TypeScript 工厂函数**、**ObjectSculptSpec JSON**、**对比渲染图**，全程无不透明网格下载。

### 核心优势解析

#### 1. 重构而非重建：代码优先、过程化几何、可读可改

传统图生 3D 输出 **GLB/USDZ/网格**，内部拓扑不可见、UV 混乱、无参数化、难动画。img2threejs 的核心主张：**从像素推导几何意图，在代码层重建**。

* • **过程化几何**：输出 `THREE.BoxGeometry`、`CylinderGeometry`、`LatheGeometry`、`ExtrudeGeometry` 等基元组合，参数（尺寸、倒角、分段数）显式写在工厂函数里。想改「把手柄加粗 2 mm」——改参数重跑，不用重导模型。
* • **着色器而非贴图**：材质用 `MeshStandardMaterial` + 程序化噪声/渐变/发光，避免烘焙贴图分辨率限制、UV 接缝、内存占用。
* • **雕刻运行时**：`root.userData.sculptRuntime` 暴露 **枢轴**、**插槽**、**碰撞体**、**破坏组**，直接可用于动画绑定、交互逻辑、物理模拟。

**白话注解**：

* • **过程化**：用代码「描述怎么画」而非「存画好的结果」，像 CAD 参数化建模。
* • **雕刻运行时**：模型自带「挂载点」「关节轴」「碰撞盒」，拿来就能做游戏/交互。
* • **ObjectSculptSpec**：一份 JSON 规格书，记录每个部件的几何类型、尺寸、材质、层级关系，是代码与视觉的契约。

#### 2. 分级质量把关管线：四阶段、每阶可视化对比、失败即阻断

管线在 `forge/` 下按阶段编号，Python 3.10+ 标准库实现，**零第三方依赖**：

| 阶段 | 目录 | 核心脚本 | 产出 | 质量门 |
| --- | --- | --- | --- | --- |
| Stage 1：摄入 | `forge/stage1_intake/` | `probe_image.py` 、`solve_camera_pose.py`、`delight_albedo.py` | 图像评估、相机位姿、去光照反照率 | 图像清晰度、主体完整度、相机解算重投影误差 < 2px |
| Stage 2：规格 | `forge/stage2_spec/` | `new_pre_spec_assessment.py` 、`new_sculpt_spec.py`、`validate_sculpt_spec.py` | `assessment.json` 、`object-sculpt-spec.json` | 规格通过 `--strict-quality`：部件覆盖率 ≥ 90%、置信度 ≥ 0.7、无几何自相交 |
| Stage 3：构建 | `forge/stage3_build/` | `generate_threejs_factory.py` 、`bake_projected_texture.py` | `src/createObjectModel.ts` 、对比渲染图 | TypeScript 编译通过、渲染与参考图 SSIM ≥ 0.85（需配置 Showcase 仓库） |
| Stage 4：运行时 | `forge/stage4_runtime/` | （集成到工厂） | `userData.sculptRuntime` | 枢轴/插槽/碰撞体拓扑自检通过 |

**关键机制**：每阶段脚本既可被 Agent 自动调用，也可**手动单步运行**。`python3 forge/next.py --state .img2threejs/state.json` 是统一入口，读取状态索引、决定下一步、执行、写回状态。**失败不继续、列出具体指标、指引修复**——例如 `validate_sculpt_spec.py --strict-quality` 报错「部件 #3 倒角半径超限，导致自相交」，Agent 必须修规格再跑，不能跳过。

#### 3. Token 高效的 Agent 协作：不喂像素、喂规格、喂对比

传统多模态 Agent 直接把图片扔给模型生成代码，Token 消耗大、幻觉多、难控制。img2threejs 的设计：**图像只在 Stage 1 被视觉模型「读」一次**，产出结构化评估/规格；后续 Stage 2-3 **纯文本上下文**（JSON 规格、评分卡、代码片段）在 Agent 间流转。

* • **Intake 阶段**：视觉模型输出「主体边界框、主要几何类别、材质线索、相机参数」，约 2-3k Token。
* • **Spec 阶段**：文本模型按 `grimoire/` 评分卡写规格、自查、互查，约 5-8k Token。
* • **Build 阶段**：代码模型按规格生成工厂、自测、修补，约 10-15k Token。
* • **总 Token**：单次完整重构约 20-25k Token，远低于「图片+完整代码」单轮喂入的 100k+。

**投影优先路径**（可选，`grimoire/character/likeness_maximization.md`）：若需极高相似度，Stage 1 先解相机位姿（`solve_camera_pose.py`）、去光照（`delight_albedo.py`），Stage 3 投影烘焙纹理（`bake_projected_texture.py`）。但文档明确警告：**单视图无法保证 100% 相似度，必须输出区域置信度、建议补拍**。

#### 4. 面向 Agent 的技能包设计：安装即用、技能间可组合

* • **安装**：`git clone https://github.com/img2threejs/img2threejs.git ~/.claude/skills/img2threejs`（或 Codex/OpenCode 对应目录），多宿主共享同一 checkout、用软链接避免漂移。
* • **入口**：`img2threejs.md` 技能清单，Agent 读取后获得「分级管线、评分卡、脚本入口、常见坑」完整上下文。
* • **可组合**：与 `bunpav`（Three.js 游戏脚手架）、`primitive-lab`（参数滑块实时调）、`audio-lab`（SFX 层）等技能并列，共享 `ObjectSculptSpec` JSON 作为契约。

### 行业影响

#### 与主流图生 3D 的本质区别

| 维度 | Tripo / Meshy / CSM / Rodini | img2threejs |
| --- | --- | --- |
| **输出物** | GLB/USDZ/网格（不透明） | TypeScript 工厂 + Spec JSON + 对比图 |
| **几何本质** | 神经隐式场/密集网格 | 过程化基元组合（参数化） |
| **可编辑性** | 需进 Blender 重拓扑/重 UV | 改参数、改代码、Git diff |
| **动画就绪** | 需重绑定骨骼、重画权重 | 自带枢轴/插槽/碰撞体运行时 |
| **Token/算力** | 单次推理重（显存 16-24 GB） | 轻量管线，Agent 端推理为主 |
| **适用场景** | 快速概念、背景资产、3D 打印 | 游戏/交互/可维护资产管线、代码优先团队 |

#### 它不解决、也不声称解决的问题

* • **单视图几何歧义**：背面、遮挡内部、薄壁厚度——规格里会标注 `confidence: "low"`、`approximation: "assumed_wall_thickness_2mm"`，需人工或多视图补全。
* • **复杂有机形态**（人脸、生物、布料）：过程化基元难以高效逼近，建议改用高斯溅射/神经网格管线。
* • **生产级美术管线替代**：它是「从 0 到 1 的可用原型」，不是「从 1 到 100 的交付资产」。

#### 生态信号

* • **Agent 技能市场化**：img2threejs 作为技能包分发，而非 CLI 工具分发，标志着「AI 编码助手技能」正成为新的软件分发单位。
* • **代码即资产**：Three.js 代码可直接进 CI/CD、单元测试、代码审查、版本控制，模糊了「美术资产」与「工程代码」的边界。
* • **评分卡即规范**：`grimoire/` 下的评分卡（几何覆盖率、材质保真度、拓扑整洁度、动画就绪度）正在形成领域特定的质量标准。
