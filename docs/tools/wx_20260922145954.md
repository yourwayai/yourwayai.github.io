# CaskHub 0.8：把 Homebrew Cask 变成原生 App Store，连图标都是从 .icns 里解包出来的

上周末在 Mac Mini M4 上重装系统，顺手把常用的 CLI 工具全走 `brew bundle` 恢复了。唯独 GUI 应用——Chrome、VS Code、Docker Desktop  
——这些平时手动下 DMG 拖进 Applications 的家伙，依然得一个个去官网点下载。想偷懒找个 Homebrew Cask 的图形前端，对比了 Applite、Cork、Taphouse 后，最终留下了 CaskHub。理由很具体：它不造本地数据库，直接吃 Homebrew 官方 `/api/cask.json` 和安装统计 API；图标来自作者另一个项目 CaskFlow 的管线，从厂商 `.icns` 里按校验和解包、不跑安装脚本；最关键的是 0.8 版新增的 **Health 页**——一键跑 `brew doctor`、`brew update`、同步收藏、清理缓存与孤儿依赖，这正是我每次手动 `brew cleanup -n` 看到几十 GB 可回收空间时最想要的按钮。

### 部署实录

```
# 方式一：Homebrew Cask（推荐，自带自动更新）  
brew install --cask caskhub  
  
# 方式二：GitHub Releases 下载 .dmg（v0.8.0 要求 macOS 15.6+，Apple Silicon / Intel 通吃）  
# https://github.com/alielsokary/CaskHub/releases/tag/0.8.0
```

首启会检测 Homebrew 是否存在，没有则引导安装（跑官方安装脚本 `/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"`）。有 Brew 则直接读取 `brew --prefix`、解析 `brew list --cask --versions` 与 `brew outdated --cask --json`，几秒钟渲染出完整库。

**实测环境**：Mac mini M4（macOS 15.6.1），Homebrew 4.4.0，约 240 个已安装 Cask。冷启动到可交互约 3 秒；全量目录（约 6000+ Cask）加载分类、图标、热度榜约 1.2 秒——分类与 Recently Added 日期均来自 CaskFlow 离线打包进 App Bundle 的 JSON，不走网络，离线也能浏览。

### 核心亮点

#### 1. 「采纳模式」把野生安装拉进 Brew 管辖

这是 CaskHub 最区别于 Applite 的单一功能。点击侧边栏 **Adopt Apps**，它会扫描 `/Applications` 与 `~/Applications` 下所有 `.app`，跟 Homebrew Cask 目录做包名/版本/校验和三重匹配。匹配上的显示「可采纳」，一键执行 `brew install --cask --force <token>` 但**不重新下载、不移动文件**，只是在 `/opt/homebrew/Caskroom` 建元数据、写入 receipt，后续 `brew upgrade --cask` 就能管到了。

实测采纳了 17 个「野生」App（含 3 个 Mac App Store 装的、2 个 pkg 安装的、12 个手动拖拽的），成功 15 个，2 个因版本号不匹配失败——CaskHub 会在详情弹窗把 `brew cask info` 的 SHA256 与本地文件实算 SHA256 并排显示，自己判断是否 `--force`。Shelf Setup 页还能把不想采纳的加入忽略列表，持久化到 `~/Library/Application Support/CaskHub/ignored.json`。

#### 2. Health 页：把 `brew doctor/cleanup/autoremove` 做成了可视化仪表盘

0.8.0 新增。顶部四块卡片：

* • **Homebrew Checkup** → 跑 `brew doctor`，把警告/错误逐行展开，附带官方文档链接
* • **Update Homebrew** → `brew update` 实时流式输出
* • **Sync Collection** → 拉取最新 `/api/cask.json`、重算分类/热度/Recently Added
* • **Reclaim Space** → 这才是杀手锏：聚合 `brew cleanup --prune=all --dry-run` 的可回收字节数、列出 `~/Library/Caches/Homebrew` 下前 20 大缓存文件、列出 `brew autoremove --dry-run` 的孤儿依赖，**每项旁边都有「执行」按钮**，点一下跑对应命令并刷新数字。

实测点一下 Reclaim，回收 14.3 GB（Chrome 旧版本 3.2 GB、Docker 旧镜像层 6.1 GB、孤儿依赖 8 个 formula 共 5 GB）。以前这得开三个终端、敲四条命令、还得人工确认每个包名。

#### 3. 图标管线：不跑安装脚本、只解包 `.icns`

CaskFlow（作者同名另一仓库）的管线逻辑：

1. 1. 从 Cask 的 `url` 下载厂商原始产物（`.dmg`/`.pkg`/`.zip`/`.tar.gz`）
2. 2. **不执行任何安装脚本**，用 `7z`/`hdiutil`/`pkgutil` 只展开归档
3. 3. 从 `Contents/Resources/AppIcon.icns` 或 `Contents/Resources/*.icns` 提取最大尺寸（通常 1024×1024）
4. 4. 校验 SHA256 写入元数据，转 PNG/WebP 入库

这意味着 CaskHub 里看到的每个图标都是**厂商原版、无水印、无圆角蒙版、无低分辨率占位符**。Applite 也用 CaskFlow 图标，但 CaskHub 是上游直连、同步最快。

### 避坑与总结

| 优点 | 缺点/局限 |
| --- | --- |
| 零配置、零订阅、MIT 协议、SwiftUI 原生、支持 macOS 15.6+ 双架构 | **要求 macOS 15.6+** ，老 Intel Mac（停留在 Ventura/Monterey）无法运行 |
| 直接吃官方 API，不造本地 SQLite，目录永远最新 | 离线时无法安装/更新/采纳（需联网跑 `brew`），纯浏览可离线 |
| Adopt 模式真正解决「已装应用纳管」痛点，校验和透明可核验 | 采纳失败时仅显示 SHA 不匹配，不会自动尝试模糊匹配版本号，需人工判断 |
| Health 页把 `brew doctor/cleanup/autoremove` 可视化，一键回收十几 GB | `brew cleanup --prune=all` 会清**所有**旧版本缓存，回滚变难，建议先 `--dry-run` 看清单 |
| Brewfile 导入/导出在 Shelf Setup，迁移新机器一把梭 | 不支持 Formula（仅 Cask）、不支持 Services、不支持 Tap 管理，定位极窄 |

**个人判断**：如果你平时 90% 的 GUI 应用都走 `brew install --cask`，CaskHub 是目前**最诚实、最轻量、最贴近 CLI 行为**的图形前端。它不试图替代 Homebrew、不造私有数据库、不搞订阅制，只是把 `brew search/info/install/upgrade/uninstall/cleanup/doctor/autoremove/bundle` 这组高频命令套了个原生 SwiftUI 壳，把「采纳野生安装」和「磁盘回收」这两个 CLI 最麻烦的场景做成了按钮。不足是门槛卡在 macOS 15.6+，且 Formula/服务管理完全不碰——但这也是它不臃肿的原因。

**值不值得折腾**：值得。`brew install --cask caskhub` 成本极低，留着当「Brew 可视化仪表盘」也好、当「App Store 替代品」也好，随用随开、不留后患。
