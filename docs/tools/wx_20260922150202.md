维护多框架组件库是前端团队的常见痛点：React 版用 hooks、Vue 版用 composition API、Svelte 版用响应式语句、Solid 版用信号。**同一个 Button、Input、Select，逻辑一样，却要按框架语法重写四遍**。BuilderIO 开源的 Mitosis（13.9k Star、MIT 协议）给出的答案是：**写一份 JSX Lite 代码，编译输出各框架原生代码**。

核心思路：定义一个**框架无关的中间表示（IR）**，源码用类 JSX 的简化语法（`@builder.io/mitosis` 包提供 `useState`、`useEffect` 等统一 hooks），再通过插件化生成器（generators）分别输出 React、Vue、Qwik、Solid、Angular、Svelte、React Native、HTML 等目标代码。我按文档在 macOS M2 Pro / Node 20 / pnpm 8 环境下跑通了完整流程，记录下安装、配置、编译产物对比、踩坑点。

### 部署实录

**环境**：macOS 14.5、Node 20.12、pnpm 8.15、TypeScript 5.4

**安装**：

```
# 新建项目  
pnpm create @builder.io/mitosis@latest my-components  
# 或手动安装核心包  
pnpm add -D @builder.io/mitosis @builder.io/mitosis-cli
```

**最小配置**（`mitosis.config.js`）：

```
export default {  
  // 输出目标框架  
  targets: ['react', 'vue', 'svelte', 'solid', 'angular', 'qwik'],  
  // 输出目录  
  outDir: 'dist',  
  // 启用 TypeScript 类型生成  
  typescript: true,  
  // 样式处理：css-modules / styled-components / emotion / vanilla-extract  
  style: 'css-modules',  
}
```

**写一个组件**（`src/Button.lite.tsx`）：

```
import { useState } from '@builder.io/mitosis'  
  
type ButtonProps = {  
  label: string  
  onClick?: () => void  
  variant?: 'primary' | 'secondary'  
  disabled?: boolean  
}  
  
export default function Button({ label, onClick, variant = 'primary', disabled = false }: ButtonProps) {  
  const [count, setCount] = useState(0)  
  return (  
    <button  
      class={`btn btn-${variant}`}  
      onClick={() => { onClick?.(); setCount(c => c + 1) }}  
      disabled={disabled}  
    >  
      {label} (clicked {count} times)  
    </button>  
  )  
}
```

**编译**：

```
npx mitosis build
```

**产物结构**：

```
dist/  
├── react/  
│   ├── Button.tsx          # 标准 React 组件，useState、useEffect 原生  
│   ├── Button.module.css   # CSS Modules  
│   └── index.ts            # 导出  
├── vue/  
│   ├── Button.vue          # <script setup>、ref、onMounted  
│   └── Button.module.css  
├── svelte/  
│   ├── Button.svelte       # $state、$effect、onMount  
│   └── Button.module.css  
├── solid/  
│   ├── Button.tsx          # createSignal、createEffect、onMount  
│   └── Button.module.css  
├── angular/  
│   ├── button.component.ts # @Component、signal、effect  
│   ├── button.component.css  
│   └── button.module.ts  
└── types/  
    └── Button.d.ts         # 统一类型定义
```

### 核心亮点

**1. JSX Lite：受限但够用的统一源语言**

Mitosis 不直接吃标准 JSX，而是定义 **JSX Lite** 子集：

| 支持 | 不支持 / 受限 |
| --- | --- |
| `useState` 、`useEffect`、`useContext`、`useRef`、`useMemo`、`useCallback` | 自定义 hooks（需内置或通过插件注册） |
| `<Component />` 组合 | 任意 JS 表达式在 JSX 中（仅允许简单引用、三元、映射） |
| `class={` btn btn-${variant}`}` 模板字符串 | `className={cn('btn', variant && 'btn-primary')}` 等工具函数 |
| `onClick={() => {...}}` 内联函数 | 复杂控制流（需提取到组件体） |
| TypeScript 接口、类型别名 | 泛型组件（v0.13+ 实验性支持） |

**设计权衡**：限制源语言表达力，换取**确定性翻译**。生成器只需处理有限模式，避免「任意 JSX 转任意框架」的不可判定性。

**2. 统一 hooks → 框架原生响应式映射**

| Mitosis Hook | React | Vue | Svelte | Solid | Angular |
| --- | --- | --- | --- | --- | --- |
| `useState` | `useState` | `ref` | `$state` | `createSignal` | `signal` |
| `useEffect` | `useEffect` | `watchEffect` | `$effect` | `createEffect` | `effect` |
| `useContext` | `useContext` | `inject` | `getContext` | `useContext` | `inject` |
| `useRef` | `useRef` | `ref` (shallow) | 无直接对应 | `createRef` | 无直接对应 |

**实测**：`useEffect` 依赖数组在 Vue 编译为 `watch([deps], cb)`、Svelte 编译为 `$effect(() => { ... })`、**依赖追踪语义基本一致**。但 `useRef` 在 Svelte/Angular 无直接等价，生成器会降级为普通变量并警告。

**3. 类型系统：单一来源，多框架分发**

源码 `ButtonProps` 接口编译后：

* • React：`export interface ButtonProps { label: string; onClick?: () => void; ... }`
* • Vue：`defineProps<ButtonProps>()` + `withDefaults`
* • Svelte：`export let label: string; export let onClick: () => void; ...`
* • Solid：`Component<ButtonProps>` + `createSignal` 类型推导
* • 统一 `dist/types/Button.d.ts` 供消费者导入

**实测**：类型导出完整，**泛型组件（实验性）在 React/Vue/Solid 输出基本可用，Svelte/Angular 仍有缺口**。

**4. 样式隔离：CSS Modules 默认，插件化扩展**

默认 `style: 'css-modules'` 生成 `Button.module.css`，各框架原生支持（React `styles.btn`、Vue `<style module>`、Svelte `:global(.btn)` 等）。也可切 `styled-components`、`emotion`、`vanilla-extract`，**样式不参与跨框架翻译，原样复制**，避免 CSS-in-JS 运行时差异。

### 避坑与总结

**踩过的坑**：

1. 1. **自定义 hooks 不能直接用**：Mitosis 不能直接编译项目内的 `useCustomHook()`。需在 `mitosis.config.js` 的 `plugins` 里注册，或把逻辑内联到组件体。**文档未强调这一点，首次编译报错让人困惑**。
2. 2. **事件处理器签名差异**：React `onClick={(e) => ...}` 编译到 Vue 变 `@click="e => ..."`，但 `e.target` 类型在 Vue 里是 `EventTarget` 需断言，**类型定义未自动处理 DOM 事件差异**。
3. 3. **Svelte/Angular `useRef` 降级**：生成代码里 `useRef` 变成普通变量，**丢失了 ref 稳定引用语义**，涉及 DOM 焦点管理的组件需手工修正产物。
4. 4. **CSS 变量 / Tailwind 不直接支持**：`style: 'css-modules'` 下无法直接用 `@apply` 或 CSS 变量引用，**需在各框架项目里配置 PostCSS 统一处理**。
5. 5. **增量编译缺失**：`mitosis build` 每次全量重新编译，**大型组件库（200+ 组件）冷启动 30s+**，watch 模式仅监听源文件变更重建单文件，**依赖图变更不触发重建**。

**局限性（必须说清楚）**：

* • **非「任意 React 组件迁移工具」**：只能写 JSX Lite，**现有 React 组件库不能直接喂给 Mitosis**，需人工降级重写。
* • **运行时行为 100% 一致不可保证**：如 `useEffect` 清理函数时机、并发渲染边界、Suspense 集成，**各框架运行时差异无法靠编译消除**，复杂交互组件仍需分框架测试。
* • **生态工具链不完整**：ESLint/Prettier/Stylelint 配置需手工适配 `.lite.tsx`，VS Code 语法高亮需装专用扩展，**CI 集成成本不低**。
* • **版本锁定风险**：Mitosis 自身频繁发布（月更），生成器内部 API 不稳定，**升级可能导致产物破坏性变化**，需锁版本、加回归测试。

**值不值得用？**

**值得**，如果你：

* • 维护**多框架设计系统**（内部同时服务 React、Vue、Svelte 团队）
* • 组件逻辑**以状态管理、事件分发为主、副作用可控**（表单、数据展示、基础 UI）
* • 接受**源语言受限、产物需二次审查**的工程约束
* • 团队有 **TypeScript / 编译器基础**，能排查生成代码问题

**不值得**，如果你：

* • 只有**单一框架**，或仅需 Web Components 互操作
* • 组件大量依赖 **React 生态 hooks、Context 模式、并发特性**
* • 追求\*\*零  
  配置、开箱即用」的迁移方案

**个人判断**：Mitosis 是 **「用编译器换人力」的务实尝试**。它没承诺「完美迁移」，而是用 **受限源语言（JSX Lite）+ 确定性生成器** 换取 **80% 样板代码自动化、类型系统统一、样式隔离标准化**。对「多框架并存、组件逻辑可控、团队接受编译器约束」的场景，它能把「维护 N 套代码」降到「维护 1 套源码 + 审查 N 套产物」。但别指望它能跑通复杂 React 生态组件，**边界在「副作用可控、状态管理可序列化、无运行时强耦合」**。我会在新设计系统项目里作为基础层引入，旧组件库迁移则按需人工改写。
