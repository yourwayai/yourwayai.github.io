# 大厂设计系统怎么开源？Cloudflare 用 Base UI 做底、Tailwind v4 做 Token、Oxlint 守规矩

2025 年 10 月，Cloudflare 开源 Kumo（`@cloudflare/kumo`），定位：**生产级 React 组件库**，构建现代 Web 应用。核心技术栈：

* • **Base UI**（无头无障碍原语）做底座
* • **Tailwind CSS v4**（`light-dark()` 语义 Token）做样式系统
* • **Oxlint + 自定义规则**强制语义 Token、禁原始色值、禁 `dark:` 前缀
* • **Registry 代码生成**（TypeScript 类型提取 → 变体/示例/样式元数据 → `component-registry.json/md`）
* • **Figma 插件双向同步**（37 个组件生成器、Token 同步）
* • **pnpm monorepo + Vite+ + Vitest + Changesets** 工程化全家桶

MIT 协议、3.5k+ Star、Node 24+、ESM-only、核心包 39 个组件、3500+ 行 AGENTS.md 文档化工程约束。

### 核心优势解析

**1. 语义 Token 单一来源：设计系统「编译进」组件库**

传统组件库：Tailwind 配色随意用（`bg-blue-500`、`text-gray-900`）、暗黑模式靠 `dark:` 变体、设计稿与代码两张皮。

Kumo **反其道而行**：

* • **仅允许语义 Token**：`bg-kumo-base`、`text-kumo-default`、`border-kumo-line`、`ring-kumo-hairline`、`bg-kumo-brand`、`bg-kumo-elevated`/`recessed`（层级语义）
* • **禁原始色值、禁 `dark:`**：Oxlint 自定义规则 `no-raw-colors`、`no-dark-variant`，**CI 直接挂掉**
* • **自动暗黑模式**：CSS Custom Properties + `light-dark()`，**Token 定义里内置了 light/dark 两套值**，组件零感知
* • **主题扩展**：`data-theme="fedramp"` 等主题仅需在父元素加属性，Token 自动切换

```
/* scripts/theme-generator/config.ts → 生成 theme-kumo.css */  
:root {  
  --kumo-base: #ffffff;  
  --kumo-elevated: #f8fafc;  
  --kumo-recessed: #f1f5f9;  
  --kumo-brand: #0969da;  
  --kumo-line: #e2e8f0;  
  --kumo-hairline: #e2e8f0;  
  --kumo-default: #0d1117;  
}  
@media (prefers-color-scheme: dark) {  
  :root {  
    --kumo-base: #0d1117;  
    --kumo-elevated: #161b22;  
    --kumo-recessed: #0d1117;  
    --kumo-brand: #58a6ff;  
    --kumo-line: #30363d;  
    --kumo-hairline: #30363d;  
    --kumo-default: #e6edf3;  
  }  
}  
[data-theme="fedramp"] { /* FedRAMP 合规主题覆盖 */ }
```

**组件里零硬编码**：

```
// Button.tsx  
export const Button = forwardRef<HTMLButtonElement, ButtonProps>(  
  ({ variant = "primary", size = "md", className, ...props }, ref) => {  
    const base = cn(  
      "inline-flex items-center justify-center font-medium transition-colors",  
      "focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-kumo-brand",  
      variants[variant], sizes[size]  
    );  
    return <button ref={ref} className={cn(base, className)} {...props} />;  
  }  
);  
const variants = {  
  primary: "bg-kumo-brand text-white hover:bg-kumo-brand/90",  
  secondary: "bg-kumo-elevated text-kumo-default hover:bg-kumo-recessed",  
  ghost: "text-kumo-default hover:bg-kumo-elevated",  
  // ...  
};
```

**设计系统变更 = 改 `config.ts` → `pnpm codegen:theme` → 全库自动生效**，无需逐组件改类名。

**2. Base UI 封装：无障碍能力「开箱即合规」**

Base UI（前身 Radix UI Primitives）提供 **键盘导航、焦点管理、ARIA 属性** 的无头实现。Kumo **封装而非重写**：

* • 39 个组件全基于 Base UI 原语（`Popover`、`Dialog`、`Select`、`Combobox`、`DatePicker` 等）
* • **40 个 primitives 自动生成再导出**（`packages/kumo/src/primitives/`），`pnpm codegen:primitives` 一键同步 Base UI 更新
* • **复合组件用两级 Context**：`CommandPalette`（14 子组件）、`Dialog`、`Select`、`CheckboxGroup`、`RadioGroup` 等 13 个组件用 `createContext` 管理状态，**符合 Base UI 模式、React DevTools 可调试**

**3. Registry 代码生成：组件元数据「构建时确定、运行时可查、AI 可读」**

构建流水线核心环节：

```
kumo-docs-astro demos → dist/demo-metadata.json  
         ↓  
ts-json-schema-generator → TypeScript 类型提取（Props/Variants/Sub-components）  
         ↓  
Enrichment：变体 + 示例 + 子组件 + 样式元数据（语义 Token 用法、CSS 变量引用）  
         ↓  
Output：ai/component-registry.{json,md} + ai/schemas.ts
```

* • **Hash 缓存**（`.cache/component-registry-cache.json`）、**8 并行批次**、**类型提取失败静默降级到仅变体**
* • **人工覆盖表**（`metadata.ts`：`ADDITIONAL_COMPONENT_PROPS`、`PROP_TYPE_OVERRIDES`）补齐类型系统盲区
* • **产物随 npm 包发布**：`ai/component-registry.json`、`ai/component-registry.md`、**AI Agent 直接读取知晓所有组件 API**、CLI `npx @cloudflare/kumo doc Button` 命令行查阅

**4. 工程化治理：约束即自由**

| 治理点 | 实现 | 效果 |
| --- | --- | --- |
| **脚手架强制** | `pnpm --filter @cloudflare/kumo new:component` （Plop 注入 `index.ts`、`vite.config.ts`、`package.json`） | 杜绝手建文件漏导出、漏类型、漏构建入口 |
| **导入规范** | `no-cross-package-relative-imports` （Oxlint） | 只许 `@cloudflare/kumo`、`@cloudflare/kumo/primitives/x`，禁 `../../kumo/src/...` |
| **废弃检测** | `no-deprecated-props` 读 Registry 数据 | `Select.hideLabel` → 报错建议 `aria-label`；`DropdownMenu.Item.href` → 建议 `DropdownMenu.LinkItem` |
| **语义 Token 强制** | `no-raw-colors` 、`no-dark-variant` | 杜绝 `bg-blue-500`、`dark:bg-black` 进主分支 |
| **Changeset 强制** | Pre-push Hook 校验 `packages/kumo/` 必须有 changeset | 版本管理零遗漏，发布流程自动化 |
| **PR 描述校验** | CI 解析 PR Body 必选 Review/Test 选项 | 规范化评审流程，`skip-pr-description-validation` 标签可豁免 |

**5. Figma 双向同步：设计稿↔代码单向流变双向流**

* • **37 个组件生成器**（`packages/kumo-figma/src/generators/`）：从 Registry 读取组件元数据 → 生成 Figma 组件/变体/自动布局/Token 绑定
* • **Token 同步**：`config.ts` 定义 → 生成 Figma Variables（Color/Spacing/Radius/Shadow/Typography）
* • **开发流**：设计师改 Figma Token → `pnpm --filter @cloudflare/kumo-figma build` → 设计稿与代码同步，**消除「设计稿 8px、代码 10px」的像素对齐会议**

### 行业影响

**它与同类开源组件库的区别在于：**

| 维度 | Kumo | Radix UI | shadcn/ui | Headless UI | Mantine | Chakra UI |
| --- | --- | --- | --- | --- | --- | --- |
| **定位** | **设计系统强绑定组件库** | 无头原语库 | 复制粘贴组件集 | 无头原语库 | 全功能组件库 | 全功能组件库 |
| **无障碍底座** | **Base UI 封装** | 自研原语 | Radix UI | 自研原语 | 自研 | 自研 |
| **样式系统** | **Tailwind v4 + 语义 Token 强制** | 无（CSS-in-JS/用户自选） | Tailwind v3 + 用户自定义 | 无 | CSS Modules + 语义 Token | Emotion + 语义 Token |
| **暗黑模式** | **`light-dark()` 自动、禁 `dark:`** | 用户自行实现 | `dark:` 手写 | 用户自行实现 | `data-theme` + Token | `colorMode` + Token |
| **设计系统同步** | **Figma 双向 + Registry 代码生成** | 无 | 无 | 无 | Figma 单向 | 无 |
| **工程化治理** | **Oxlint 自定义规则 + Changeset + Registry** | 基础 ESLint | 无 | 基础 ESLint | ESLint + 自定义 | ESLint + 自定义 |
| **AI/代码生成友好** | **Registry 产物随包发布、CLI 查询、MCP 潜力** | 无 | 无 | 无 | 无 | 无 |
| **适用场景** | **已有/建设设计系统的团队、需强治理、需 Figma 同步** | 想完全控制样式的团队 | 快速起步、无设计系统 | 想完全控制样式的团队 | 功能全、开箱即用 | 功能全、样式系统成熟 |

**生态信号**：

* • **「设计系统即代码」落地范本**：把 Figma Token、语义色值、组件变体、无障碍模式、文档示例**全纳入构建流水线**，而非停留在 Notion/Confluence 文档里
* • **Base UI 生态关键节点**：作为 Base UI 首个「官方级」深度封装库，**验证了 Base UI「原语层稳定、上层随意封装」的架构假设**
* • **AI Agent 时代的组件库元数据标准**：`component-registry.json` 结构化导出，**让 Agent 能「读懂」组件库、生成正确代码、不幻觉 Props**，为 `v0`/`Bolt`/`Cursor` 类工具提供高质量上下文
* • **Cloudflare 内部犬食化**：已用于 Cloudflare Dashboard、Workers、Pages 等核心产品，**大规模生产环境验证过性能、无障碍、主题切换、国际化**
