上个月整理 NAS 里积攒 8 年的 12 万张照片（含 Sony RAW、Live Photo、Android Motion Photo、ComfyUI 生成图），macOS「照片」打开要转半分钟、Windows「相册」直接卡死、Immich 装 Docker 还得配 PostgreSQL/Redis/机器学习微服务、PhotoPrism 索引跑了一晚内存涨到 16 GB。想找个「不装数据库、不跑服务端、双击即用、AI 搜索全本地」的工具，翻到 **Lap**（`julyx10/lap`，v0.3.1，GPL-3.0）。作者 julyx10 明确定位：**「离线优先、面向大型本地库、AI 功能全设备端推理」**。周末在 M3 MacBook Pro（macOS 15.6，16 GB 内存）与 Ryzen 7900X/RTX 4070（Windows 11，32 GB）双机实测，记录真实体验。

### 部署实录

#### macOS（Apple Silicon，Homebrew 方式最省事）

```
# 官方提供签名 .dmg，直接下载安装  
# https://github.com/julyx10/lap/releases/download/v0.3.1/Lap_0.3.1_aarch64.dmg  
  
# 或 Homebrew Cask（自动更新）  
brew install --cask lap
```

首启会引导选择「照片根文件夹」（可多选、可选子文件夹），随后后台启动扫描器。

#### Windows（需 VC++ Redistributable，v0.2.2 已加自动检测）

```
# 下载 .msi 安装包  
# https://github.com/julyx10/lap/releases/download/v0.3.1/Lap_0.3.1_x64_en-US.msi  
  
# 安装后首启同理选根文件夹
```

#### Linux（AppImage / Flatpak / 源码构建）

```
# AppImage 最简单  
wget https://github.com/julyx10/lap/releases/download/v0.3.1/Lap_0.3.1_amd64.AppImage  
chmod +x Lap_0.3.1_amd64.AppImage  
./Lap_0.3.1_amd64.AppImage
```

**源码构建**（想改代码/调试 AI 模型加载）：

```
# 依赖：Rust stable、Node.js 20+、pnpm、CMake、nasm、pkg-config  
# macOS 额外：xcode-select --install、brew install nasm pkg-config autoconf automake libtool cmake  
# Ubuntu 额外：sudo apt install libwebkit2gtk-4.1-dev libappindicator3-dev librsvg2-dev patchelf nasm clang pkg-config autoconf automake libtool cmake  
  
git clone --recursive https://github.com/julyx10/lap.git  
cd lap  
git submodule update --init --recursive  
cargo install tauri-cli --version "^2.0.0" --locked  
./scripts/download_models.sh   # 下载 AI 模型（CLIP、人脸检测/识别、标签分类，约 1.2 GB）  
./scripts/download_ffmpeg_sidecar.sh  
cd src-vite && pnpm install && cd ..  
cargo tauri build   # 产物在 src-tauri/target/release/bundle/
```

**实测环境与耗时**：

| 环境 | 照片数 | 扫描建索引 | AI 模型加载 | 内存稳态 | 启动冷启动 |
| --- | --- | --- | --- | --- | --- |
| M3 MBP 16GB | 12 万（混合 RAW/JPG/MP4） | 22 分钟 | 首次 8 秒（后续缓存） | 1.8 GB | 2.1 秒 |
| Ryzen 7900X/RTX 4070 32GB | 12 万 | 14 分钟 | 首次 3 秒（GPU 加速） | 2.1 GB | 1.6 秒 |

**关键观察**：扫描器是 **Rust 重写的并行扫描器**（`src-tauri/src/scanner/`），用 `walkdir` + `rayon` 并行读取文件元数据、LibRaw 解析 RAW EXIF、ffmpeg 提取视频缩略图、写入 **SQLite（`sled` 存储引擎）** 索引。不建全文索引、不跑外部数据库进程，**单文件 `library.db` 约 1.4 GB**（12 万张），可直接拷贝迁移。

### 核心亮点

#### 1. 本地 AI 四件套：零上传、零 GPU 门槛（CPU 也能跑）

| 功能 | 模型 | 推理后端 | 实测延迟（M3/RTX 4070） |
| --- | --- | --- | --- |
| **自然语言搜索** | CLIP ViT-B/32 (ONNX) | `ort` (ONNX Runtime) | 文本编码 12 ms / 图像编码 8 ms/张（批量） |
| **相似图搜索** | 同 CLIP 图像嵌入 | 同上 | 12 万张向量检索 < 200 ms（HNSW 索引） |
| **人脸聚类** | SCRFD (检测) + ArcFace (识别) | 同上 | 首次全库人脸索引 6 分钟，增量秒级 |
| **智能标签** | MobileNetV3 (ImageNet-1k) | 同上 | 单张 15 ms，批量后台跑 |

**模型管理**：首次启用 AI 功能时，前端调用 `download_models.sh` 下载 `.onnx` 到 `$APPDATA/Lap/models/`（或 `~/Library/Application Support/Lap/models/`），**模型文件不随应用打包、避免体积膨胀、可离线手动放入**。推理全程 **CPU（ONNX Runtime CPU EP）**，有 NVIDIA GPU 自动切 CUDA EP，Apple Silicon 暂不支持 CoreML EP（Issue #234 规划中），但 M 系列 CPU 推理已足够快。

**隐私承诺**：README 明写「Private AI tools run locally on your machine」。网络请求仅两处：**检查更新（GitHub Releases API）** 与 **可选的逆地理编码（Nominatim/OpenStreetMap，可关）**。

#### 2. 为「大库」而生的工程细节

* • **虚拟化网格**：Vue 3 + `@tanstack/vue-virtual`，只渲染可视区 + 缓冲区 DOM，**12 万缩略图滚动 60 FPS、内存不涨**。
* • **LibRaw 原生解码**：RAW 缩略图直接读嵌入 JPEG、或 LibRaw 半解码生成，**不调用外部 `dcraw`/`exiftool`**，Windows/Linux/macOS 行为一致。
* • **Live Photo / Motion Photo 支持**：识别 `.heic`/`.mov` 配对、播放时合成、导出可选「只导视频/只导封面/全导出」。
* • **四面板对比**：选中 2-4 张照片按 `C` 进入对比模式，**同步缩放/平移、同步直方图、EXIF 并排**，专为「挑最佳一张」设计。
* • **智能相册（Smart Albums）**：类似智能播放列表，规则如「评分 ≥ 4 且 拍摄日期 2024-01 至 2024-12 且 标签含『风景』」，**实时求值、不复制文件**。
* • **副本/近似照片审查**：v0.3.1 强化，**感知哈希 + CLIP 嵌入双重判定**，分组展示、标记保留/删除、批量操作进系统垃圾桶（或永久删除开关）。
* • **AI PNG 提示词导入**：v0.3.0 新增，扫描 ComfyUI/Automatic1111/InvokeAI/NovelAI 生成的 PNG，**读取 `tEXt/zTXt` chunk 里的 `parameters`/`prompt` 字段**，自动填入照片备注（不覆盖已有备注），AI 绘图重现极其方便。

#### 3. 「文件夹即库」的零侵入设计

* • **不移动、不重命名、不建副本**：Lap 只读你指定的文件夹树，索引写在自有 `library.db`，**删除 Lap 配置文件夹、原照片完全不受影响**。
* • **外部修改自动同步**：`notify-debouncer` 监听文件系统事件，**新增/修改/删除/重命名** 文件/文件夹，**增量更新索引、不全量重扫**（v0.2.3 引入）。
* • **导出/分享**：右键「导出」可选「原文件/编辑后 JPEG/调整尺寸/去 EXIF」，**不锁定原始文件**。

### 避坑与总结

| 优点 | 缺点/局限 |
| --- | --- |
| **真·离线优先** ：无服务端、无云同步、AI 模型本地跑、数据全在自己盘里 | **无云同步/多端同步** ：手机端、Web 端、NAS 直连均无（Roadmap 标注「不做同步，专注本地管理」） |
| Rust+Tauri 原生性能，10 万+ 库秒开、滚动不卡 | **Apple Silicon GPU 加速缺失** ：AI 推理走 CPU，M 系列虽快但大库全量重索引仍需分钟级 |
| 单 `library.db` + 文件夹结构，**迁移备份极其简单**（拷两文件走人） | **编辑能力极弱** ：仅裁剪/旋转/曝光简单调整，无曲线/色阶/局部调整、无非破坏性编辑图层 |
| 人脸聚类+智能标签+自然语言搜索+相似图，**本地 AI 四件套开箱即用** | **人脸识别准确率依赖光照/角度** ，侧脸/遮挡/婴儿期照片易漏聚/错聚，需人工合并/拆分 |
| ComfyUI/A1111 提示词自动导入，**AI 绘图复现零成本** | **视频支持仅缩略图/播放** ，无视频剪辑、无关键帧提取、无视频 AI 搜索 |
| GPL-3.0 完全开源、社区活跃（月更、Issue 响应快）、作者独自维护三年 | **单人维护风险** ：核心架构、AI 管线、UI 全靠 julyx10 一人，若弃坑接手难度大 |

**个人判断**：Lap 解决的核心问题是「**给『不想上云、有大量本地照片、想用现代 AI 搜索/整理』的用户，一个『下载即用、不侵入文件、性能够用、隐私绝对』的桌面工具**」。它不像 Immich/PhotoPrism 那样试图做「自建 Google Photos」（需服务器、需数据库、需 Docker、需维护），也不像 digiKam 那样堆砌专业级编辑/元数据管理（学习曲线陡峭、UI 老旧）。Lap **只做三件事：快浏览、本地 AI 搜、安全整理**，并把这三件事的工程细节（虚拟化、并行扫描、ONNX Runtime、LibRaw、SQLite、感知哈希）全做到「够用、不坑、可维护」的水平。

**适用场景**：

* • 摄影爱好者/内容创作者：本地 5 万-50 万张照片/视频，要自然语言搜「2023 年秋天北京公园穿红衣服的女儿」、要挑近似照片删减、要导入 AI 绘图提示词
* • 隐私敏感用户：医疗/法律/家庭敏感照片**绝不上传**、需完全离线管理
* • 多系统切换者：macOS/Windows/Linux 三端同一套文件夹、同一套索引文件拷贝即用

**不适用场景**：

* • 需要手机端随时查看/上传/同步（去 Immich/PhotoPrism/Ente Photos）
* • 需要专业级 RAW 编辑（去 darktable/RawTherapee/Lightroom）
* • 需要多人协作/权限控制/共享相册（去 Nextcloud Photos/Immich）
* • 只有 4 GB 内存老机器（AI 模型加载会 OOM，可关闭 AI 功能仅作浏览器）

**值不值得折腾**：**值得下载 .dmg/.msi/AppImage 试跑一次**。选个 1-2 万张照片的文件夹、开 AI 搜索、输「夕阳 海边 剪影」、看结果；拖两张相似照片进对比面板、按 `C` 同步放大；右键一张 ComfyUI 生成图「查看提示词」。十分钟体会完「本地 AI 相册」的手感。若你的痛点正是「大库卡顿、不想上云、想 AI 搜」，Lap 是目前**最诚实、最轻量、最少妥协**的答案。
