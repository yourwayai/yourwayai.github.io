# Snippai v0.3：截图即思考，公式转 LaTeX、表格转 Excel、代码自动解释、全本地跑、~1 秒出结果

上周改论文、查源码、整理文档，连续三天重复同一个动作：**截图 → 打开浏览器 → 粘贴到 ChatGPT/Claude → 输「帮我把这公式转 LaTeX / 这表格转 Markdown / 这段代码解释一下」→ 等回复 → 复制回编辑器**。想找个「截图直接变结构化数据、不上传、不开浏览器、不输提示词」的工具，对比了 Snagit（重、贵、无 AI）、Snipaste（轻但无 AI）、ShareX（配置复杂、AI 需外挂 API）、Umi-OCR（仅 OCR、无公式/表格/代码理解），翻到 **Snippai**（`xyTom/snippai`，v0.3.2，MIT 协议）。Slogan 是「Snip Anything Solve Everything」，作者 xyTom 定位：**「AI 驱动的截图工具，将屏幕内容快速转化为可用信息」**。周末在 M3 MacBook Pro（macOS 15.6）与 Ryzen 7900X/RTX 4070（Windows 11）双机实测，记录真实体验。

### 部署实录

```
# macOS（Apple Silicon，官方签名 .dmg）  
# https://github.com/xyTom/snippai/releases/download/v0.3.2/Snippai_0.3.2_aarch64.dmg  
  
# Windows（.msi 安装包，含 VC++ Redistributable 自检）  
# https://github.com/xyTom/snippai/releases/download/v0.3.2/Snippai_0.3.2_x64_en-US.msi  
  
# Linux（AppImage，FUSE 依赖）  
wget https://github.com/xyTom/snippai/releases/download/v0.3.2/Snippai_0.3.2_amd64.AppImage  
chmod +x Snippai_0.3.2_amd64.AppImage  
./Snippai_0.3.2_amd64.AppImage
```

**源码构建**（想改快捷键/加模型/调试 Rust 侧）：

```
# 依赖：Rust stable、Node.js 20+、pnpm、Tauri CLI  
# macOS 额外：xcode-select --install  
# Ubuntu 额外：sudo apt install libwebkit2gtk-4.1-dev libappindicator3-dev librsvg2-dev patchelf  
  
git clone https://github.com/xyTom/snippai.git  
cd snippai  
pnpm install  
# 首次需下载 AI 模型（约 200 MB，含 OCR/公式/表格/代码模型）  
pnpm tauri dev   # 开发模式，热重载  
# 或生产构建  
pnpm tauri build  # 产物在 src-tauri/target/release/bundle/
```

**实测环境与启动**：

| 环境 | 冷启动 | 内存稳态 | 模型加载首次 | 截图→结果延迟 |
| --- | --- | --- | --- | --- |
| M3 MBP 16GB | 1.8 秒 | 420 MB | 3.2 秒 | 0.8-1.5 秒 |
| Ryzen 7900X/RTX 4070 32GB | 1.2 秒 | 380 MB | 1.1 秒 | 0.4-0.9 秒 |

**关键观察**：Tauri 2.0 + Rust 后端 + React/TypeScript 前端，**无 Node.js 运行时、无 Chromium、二进制约 45 MB**。模型文件（ONNX 格式）首次启动时自动下载到 `$APPDATA/Snippai/models/`（或 `~/Library/Application Support/Snippai/models/`），**全本地推理、无网络请求**（仅检查更新用 GitHub Releases API）。

### 核心亮点

#### 1. 「无提示词」四大 AI 动作：框选 → 选图标 → 直接得结构化结果

截图后弹出工具栏，**四个 AI 图标对应四条专用管线**，无需输入任何文本提示：

| 图标 | 动作 | 管线细节 | 输出格式 |
| --- | --- | --- | --- |
| **公式** | 数学公式 → LaTeX | YOLOv8 检测公式区域 → Pix2Text/UniMERNET 识别 → LaTeX 后处理（清理多余空格、修正命令） | `$$...$$` / `$...$` 可直接粘贴 Typora/Overleaf/Notion |
| **表格** | 表格 → 结构化 | TableMaster/TableFormer 检测表格 → 单元格文本 OCR → 行列对齐修正 → 导出 | Excel (.xlsx) / CSV / Markdown Table / JSON |
| **代码** | 代码块 → 解释/重构 | PaddleOCR 文本识别 → 语言自动检测（Tree-sitter） → LLM 本地小模型（CodeLlama-7B-Q4/StarCoder2-3B）生成解释/重构建议 | Markdown 代码块 + 自然语言解释 + 重构建议 |
| **文本** | 通用 OCR + 翻译/摘要 | PP-OCRv4 多语言识别 → 段落重排 → 可选：本地翻译模型（NLLB-200-600M）/ 摘要模型 | 纯文本 / Markdown / 翻译对照 / 摘要 |

**实测样例**：

* • **公式**：截《数学分析》教材某页积分公式，输出 `$$\\int_{-\\infty}^{\\infty} e^{-x^2} dx = \\sqrt{\\pi}$$`，识别准确率 ~98%（手写体 ~92%），复杂分式/根号/求和符号全对。
* • **表格**：截财报 PDF 某页 12×8 合并单元格表格，导出 Markdown 仅第 3 行第 5 列对齐偏移，Excel 导出完美保留合并单元格，**省去手工对齐 20 分钟**。
* • **代码**：截 GitHub 某 Rust 函数（含生命周期/泛型/宏），输出：语言识别 `rust`、功能解释「实现带超时的异步重试包装器」、重构建议「用 `tokio::time::timeout` 替代手动 `select!`、错误类型统一为 `anyhow::Error`」，**可直接当 Code Review 备忘**。
* • **文本**：截中英混排技术文档，OCR 错字率 < 1%，一键翻译成中文/英文，**比划词翻译插件快在「保留排版+批量处理」**。

#### 2. 本地推理架构：ONNX Runtime + 模型量化 + 硬件加速自适配

```
用户截图  
    ↓  
前端：Canvas 裁剪 → base64 → IPC 传给 Rust 后端  
    ↓  
Rust 后端：  
  1. 图像预处理（resize/normalize/pad，OpenCV/Rust-image）  
  2. 模型推理（ORT Session，CPU EP / CUDA EP / CoreML EP 自动选择）  
  3. 后处理（NMS/解码/格式化）  
  4. 结果 JSON 回 IPC 给前端  
    ↓  
前端：渲染结果面板 → 复制/导出/编辑
```

**模型体量与精度平衡**（v0.3.2 打包）：

| 模型 | 任务 | 大小 | 量化 | 精度备注 |
| --- | --- | --- | --- | --- |
| PP-OCRv4\_det | 文本检测 | 2.8 MB | INT8 | 长文本行检测召回率 96% |
| PP-OCRv4\_rec | 文本识别 | 12 MB | INT8 | 中英数混排字符级准确率 98% |
| YOLOv8n\_formula | 公式检测 | 6 MB | FP16 | 公式区域 mAP@0.5 94% |
| UniMERNET\_small | 公式识别 | 45 MB | INT8 | LaTeX 编译通过率 91% |
| TableMaster | 表格结构 | 38 MB | INT8 | TEDS 指标 0.89 |
| CodeLlama-7B-Q4 | 代码解释 | 4.2 GB | Q4\_K\_M | 可选下载，默认不含（需手动开启） |

**硬件加速**：Windows/Linux 有 NVIDIA GPU 自动走 CUDA EP（推理加速 3-5×），macOS 走 CPU EP（Metal/CoreML EP 适配中，Issue #89）。**无 GPU 机器纯 CPU 也能跑**，只是公式/表格/代码动作延迟 1-2 秒。

#### 3. 交互细节：为「高频、快节奏」打磨

* • **全局快捷键**：默认 `Cmd+Shift+2`（macOS）/ `Ctrl+Shift+2`（Win/Linux）触发区域截图，**可改、可多绑定**（如 `Cmd+Shift+3` 直接进公式模式）。
* • **结果面板**：截图右侧滑出，**Markdown 实时渲染、LaTeX 用 KaTeX 即时预览、表格可编辑单元格、代码高亮**。
* • **一键导出**：`Cmd+C` 复制纯文本/Markdown/LaTeX，**`Cmd+E` 导出文件**（自动命名 `snippai_20250115_143022_formula.tex`）。
* • **历史记录**：本地 SQLite 存最近 500 条，**可搜索、可重跑 AI 动作、可删**。
* • **设置面板**：模型下载路径、默认导出格式、快捷键、代理、语言、主题（跟随系统/浅/深）、**是否启用代码解释（需下载 4 GB 模型）**。

### 避坑与总结

| 优点 | 缺点/局限 |
| --- | --- |
| **真·离线优先** ：模型本地跑、截图不上传、无账号、无遥测（仅可选更新检查） | **代码解释模型太大（4 GB）** ：默认不含、需手动下载、4 GB 内存机器跑不动、建议 16 GB+ |
| **四大专用管线各司其职** ：公式/表格/代码/文本**互不干扰、各自最优模型**，比大模型多任务准 | **公式识别手写体/低分辨率/复杂排版仍有误差** ：需人工核对 LaTeX 编译报错、修正 `\left`/`\right` 配对 |
| **表格导出 Excel 保留合并单元格、CSV/Markdown 兼容性强** ，直接进 Pandas/Excel 可用 | **表格跨页/极长表格不支持自动拼接** ：需手动截多张、再合并 |
| **Tauri 原生性能** ：启动快、内存低、无 Electron 那套、跨平台体验一致 | **Linux Wayland/高 DPI 下截图/全局热键偶发失效** （v0.3.2 部分修复、需 `WAYLAND_DISPLAY` 兼容模式） |
| **MIT 协议、单人维护但更新极快** （周更、Issue 响应 < 24h）、社区活跃 | **单人维护风险** ：核心 AI 管线、Rust 后端、React 前端全靠 xyTom 一人，文档/测试/国际化滞后 |
| **无提示词、零配置、开箱即用** ，符合「截图即思考」直觉 | **无标注/画箭头/马赛克/贴图等传统截图工具能力** ：定位互补而非替代 Snipaste |

**个人判断**：Snippai 解决的核心问题是「**把『看到屏幕上有公式/表格/代码/外语想拿走』这个高频微痛点，从『截图→开浏览器→粘贴→输提示词→等回复→复制』 6 步，压缩为『框选→点图标→复制』 3 步，且全本地、可离线、可审计**」。它不像 Snagit 那样做「全能截图编辑器」，不像 Umi-OCR 那样做「通用 OCR」，而是**只做『结构化提取』这一件事，并为每种结构（公式/表格/代码/文本）配专用模型、专用后处理、专用导出格式**——**极简、极专、极快**。

**适用场景**：

* • 科研/学生：论文公式转 LaTeX、教材表格进 Excel、外文文献翻译摘要
* • 开发者：StackOverflow/博客/文档里的代码截图直接得解释/重构、配置文件/日志/错误栈 OCR 后 grep
* • 数据分析：网页/PDF/图片里的表格一键变 DataFrame、财报/统计年鉴批量结构化
* • 隐私敏感场景：内部代码/合同/财务报表**绝不上传**、需本地结构化

**不适用场景**：

* • 需要标注/画图/马赛克/贴图/录屏/长截图（去 Snipaste/ShareX/Snagit）
* • 仅需纯文本 OCR、不需要公式/表格/代码理解（Umi-OCR/Pot 更轻）
* • 只有 4-8 GB 内存、无独立显卡、且必须用代码解释功能（会 OOM）
* • Linux Wayland 下全局热键/截图不可靠（需等 Tauri 2.1/Wayland 协议完善）

**值不值得折腾**：**值得下载 .dmg/.msi/AppImage 试跑一次**。找张含公式/表格/代码的截图、按快捷键框选、点对应图标、看右侧面板渲染结果、按 `Cmd+C` 粘贴到编辑器。两分钟体会完「截图即结构化」的爽感。若你的日常高频包含「公式进 LaTeX、表格进 Excel、代码要解释、外语要翻译」，Snippai 是目前**最诚实、最轻量、最少干扰**的本地 AI 截图工具。
