家里有台 NAS（真·关机省电）、台打印机服务器（树莓派跑 CUPS）、台 Windows 工作站（偶尔远程桌面）、几台 Linux 实验机。以前要远程开机，要么记 MAC 地址手敲 `wakeonlan`、要么写 systemd service、要么在路由器里配 WOL 转发——**每次都要找终端、查 IP、记 MAC、输命令**。想找个「有 Web 面板、能定时、能看状态、能扫网、能接 Tailscale、部署不疼」的工具，翻到 **UpSnap**（`seriousm4x/UpSnap`，v5.3.2，MIT 协议）。作者 seriousm4x 定位：「简单的 Wake-on-LAN Web 应用，SvelteKit + Go + PocketBase」。周末在树莓派 Zero 2 W（64-bit Ubuntu Server 24.04、1 GB 内存）与主力服务器（Ryzen 5700G、32 GB、Proxmox VE LXC）双环境实测部署，记录真实体验。

### 部署实录

#### 方式一：Docker Compose（推荐，生产就用这个）

```
# docker-compose.yml  
version: '3.8'  
services:  
  upsnap:  
    image: seriousm4x/upsnap:5.3.2  
    container_name: upsnap  
    network_mode: host          # WoL 需广播包，host 网络最省事  
    # 或用 macvlan/bridge + 环境变量 BROADCAST_ADDRESS=192.168.1.255  
    volumes:  
      - ./data:/app/data        # PocketBase SQLite + 上传文件  
      - ./config:/app/config    # 可选：自定义配置  
    environment:  
      - TZ=Asia/Shanghai  
      # 可选：反向代理下需设置  
      # - PUBLIC_URL=https://upsnap.example.com  
      # 可选：Tailscale Funnel 集成  
      # - TAILSCALE_AUTHKEY=***  
    restart: unless-stopped  
    # 网络发现需 nmap + root 权限  
    privileged: true            # 或 --cap-add=NET_RAW --cap-add=NET_ADMIN
```

```
mkdir -p data config  
docker compose up -d  
# 访问 http://<host-ip>:8090  
# 首次访问会引导创建管理员账号（PocketBase Auth）
```

#### 方式二：裸机二进制（极简，树莓派 Zero 2 W 实测）

```
# 下载对应架构二进制（Go 静态编译，含 PocketBase 内嵌）  
wget https://github.com/seriousm4x/UpSnap/releases/download/v5.3.2/upsnap_linux_arm64.tar.gz  
tar -xzf upsnap_linux_arm64.tar.gz  
chmod +x upsnap  
  
# 安装 nmap（网络扫描/ARP 追踪需要）  
sudo apt update && sudo apt install -y nmap  
  
# 以 root 运行（发送广播 WoL 包、nmap 扫描需要）  
sudo ./upsnap serve --http 0.0.0.0:8090  
# 或用 systemd 服务
```

#### 方式三：Tailscale Sidecar（零端口转发、零公网 IP）

```
# docker-compose.tailscale.yml（参考 tailscale-dev/upsnap-docker-example）  
services:  
  upsnap:  
    image: seriousm4x/upsnap:5.3.2  
    network_mode: host  
    volumes:  
      - ./data:/app/data  
    environment:  
      - TAILSCALE_AUTHKEY=${TAIL...KEY}  
      - TAILSCALE_HOSTNAME=upsnap  
    restart: unless-stopped  
  
  tailscale:  
    image: tailscale/tailscale:latest  
    network_mode: host  
    volumes:  
      - ./tailscale-state:/var/lib/tailscale  
    environment:  
      - TS_AUTHKEY=${TAIL...KEY}  
      - TS_HOSTNAME=upsnap-sidecar  
      - TS_EXTRA_ARGS=--advertise-routes=192.168.1.0/24 --accept-routes  
    cap_add:  
      - NET_ADMIN  
      - NET_RAW  
    restart: unless-stopped
```

**效果**：Tailnet 内任意设备访问 `http://upsnap:8090`，**无需开防火墙、无需公网 IP、无需反代**，Tailscale ACL 还能管谁能访问。

**实测环境与资源占用**：

| 环境 | 部署方式 | 冷启动 | 内存稳态 | CPU 闲置 | 二进制大小 |
| --- | --- | --- | --- | --- | --- |
| 树莓派 Zero 2 W (1GB) | 裸机 root | 2.1 秒 | 48 MB | <1% | 18 MB |
| Ryzen 5700G LXC (2GB) | Docker host 网络 | 1.3 秒 | 62 MB | <1% | 18 MB |

**关键观察**：**单二进制内嵌 PocketBase（SQLite）+ SvelteKit 静态前端 + Go 后端**，无外部数据库、无 Redis、无 Node.js 运行时、**部署极其轻量**。`host` 网络模式下 WoL 广播包直接发往物理网卡，**无需配置广播地址、无需 `NET_BROADCAST` 权限折腾**。

### 核心亮点

#### 1. 「设备即记录」的极简数据模型：PocketBase 做认证+存储+实时

UpSnap 不造数据库、不造认证，**全托管给 PocketBase**（Go 内嵌 SQLite、自带 Auth、实时订阅、文件存储、Admin UI）：

```
// 核心设备结构（简化自 PocketBase Collection schema）  
type Device struct {  
    ID          string    `json:"id"`           // PocketBase 自动生成  
    Name        string    `json:"name"`         // 显示名  
    MAC         string    `json:"mac"`          // 核心：MAC 地址（必填）  
    IP          string    `json:"ip"`           // 可选：IP 地址（用于状态检测/ARP 追踪）  
    BroadcastIP string    `json:"broadcast_ip"` // 可选：自定义广播地址（跨 VLAN 需要）  
    Port        int       `json:"port"`         // 可选：WoL 端口（默认 9）  
    SecureOn    string    `json:"secure_on"`    // 可选：SecureOn 密码（部分网卡支持）  
    // 定时任务（Cron 表达式）  
    WakeSchedule  string `json:"wake_schedule"`   // 如 "0 7 * * 1-5" 工作日 7 点  
    SleepSchedule string `json:"sleep_schedule"`  // 关机计划  
    // 状态检测端口  
    CheckPorts string `json:"check_ports"`       // 逗号分隔：22,3389,80  
    // 关机命令（SSH/WinRM/自定义）  
    ShutdownCommand string `json:"shutdown_command"`  
    // 分组/标签  
    Group     string `json:"group"`  
    Tags      string `json:"tags"`  
    // 审计  
    Created   time.Time `json:"created"`  
    Updated   time.Time `json:"updated"`  
}
```

**PocketBase 红利**：

* • **Admin UI 自带**：`http://<host>:8090/_/` 进去能改 Collection、建索引、看数据、跑查询、**开发调试极其方便**
* • **实时订阅**：前端 `pb.collection('devices').subscribe('*', callback)`，**设备增删改、唤醒日志、状态变化、WebSocket 消息全实时推送**，无轮询
* • **Auth 体系**：邮箱密码、OAuth2（GitHub/Google/GitLab/OIDC）、MFA、API Token、**现成可用、无需写一行 Auth 代码**
* • **文件存储**：设备图标、导出 CSV、备份 SQLite **全走 PocketBase Files API**

#### 2. WoL 发送器：Go 标准库实现、跨平台、支持 SecureOn/自定义端口/广播地址

```
// 内部 wol.SendMagicPacket 逻辑（简化）  
func SendMagicPacket(mac, broadcastIP string, port int, secureOn string) error {  
    hwAddr, _ := net.ParseMAC(mac)  
    // 构造魔术包：6 字节 0xFF + 16 次 MAC 地址  
    packet := make([]byte, 6+16*6)  
    copy(packet[:6], bytes.Repeat([]byte{0xFF}, 6))  
    for i := 0; i < 16; i++ {  
        copy(packet[6+i*6:6+(i+1)*6], hwAddr)  
    }  
    // SecureOn 密码（可选，追加在包尾）  
    if secureOn != "" {  
        pw, _ := hex.DecodeString(strings.ReplaceAll(secureOn, "-", ""))  
        packet = append(packet, pw...)  
    }  
    // UDP 广播发送  
    conn, _ := net.Dial("udp", fmt.Sprintf("%s:%d", broadcastIP, port))  
    defer conn.Close()  
    _, err := conn.Write(packet)  
    return err  
}
```

**实测细节**：

* • **广播地址自动推断**：若未设 `BroadcastIP`，按 `IP` 所在子网算 `.255`（如 `192.168.1.100/24` → `192.168.1.255`）
* • **跨 VLAN/子网**：手动填目标子网广播地址，或在路由器开 `ip directed-broadcast`/WOL 代理
* • **IPv6 支持**：v5.3.0+ 支持 IPv6 多播 `ff02::1`（需网卡/交换机支持）
* • **并发发送**：前端「全选唤醒」时，**Go 协程并发发包、不阻塞 UI**，百台设备秒级完成

#### 3. 状态检测：ICMP + TCP 端口双模式、nmap 网络发现

| 检测方式 | 实现 | 用途 |
| --- | --- | --- |
| **Ping (ICMP)** | Go `net.Dial("ip4:icmp", ip)`（需 root/CAP\_NET\_RAW） | 基础在线判断 |
| **TCP 端口** | `net.DialTimeout("tcp", fmt.Sprintf("%s:%d", ip, port), 3*time.Second)` | 服务级可用性（SSH/RDP/HTTP/自定义） |
| **ARP 扫描** | `nmap -sn -PR <cidr>` 解析 XML 输出 | 发现局域网设备、自动填 MAC/IP、追踪 IP 变化 |
| **WebSocket 实时日志** | 前端订阅 `wol_logs` 集合 | 看每次唤醒发包详情、成功/失败/耗时 |

**网络发现流程**（点击「Scan Network」）：

1. 1. 前端调用 `POST /api/scan` → 后端启动 `nmap -sn -PR -oX - <cidr>`
2. 2. 解析 XML → 对比现有设备 MAC → **新设备自动创建记录、已有设备更新 IP/在线状态**
3. 3. 结果实时推送前端，**扫描 192.168.1.0/24 约 8 秒（千兆有线）、发现 40+ 设备**

#### 4. 定时唤醒/关机：Cron 表达式 + 时区感知 + 执行日志

```
// 调度器核心（每分钟跑一次）  
func (s *Scheduler) tick() {  
    now := time.Now().In(s.location) // 用户设定时区  
    for _, device := range s.devices {  
        // 唤醒计划  
        if device.WakeSchedule != "" && cronMatch(device.WakeSchedule, now) {  
            s.wakeDevice(device)  
        }  
        // 关机计划  
        if device.SleepSchedule != "" && cronMatch(device.SleepSchedule, now) {  
            s.shutdownDevice(device)  
        }  
    }  
}
```

**关机命令示例**：

* • Linux/SSH：`ssh user@ip 'sudo shutdown -h now'`（需免密钥/ sudoers NOPASSWD）
* • Windows/WinRM：`winrm invoke -r:ip -u:user -p:pass "shutdown /s /t 0"`
* • 自定义：`curl -X POST http://ip:port/shutdown`（自建 Agent）

**执行日志**：每次定时触发、手动触发、成功/失败/输出**全记录在 `wol_logs` 集合**，可筛选、可导出、可设保留天数。

#### 5. 前端：SvelteKit + Tailwind + 实时 WebSocket、零打包体积焦虑

* • **SvelteKit SSR/CSR 自动切换**：首屏 SSR 渲染设备列表、后续 SPA 导航、**无 hydration 崩溃风险**
* • **Tailwind CSS + Headless UI**：响应式仪表盘、深色模式、移动端可用、**无组件库锁定**
* • **实时 WebSocket**：`pb.realtime.subscribe('devices', ...)` / `subscribe('wol_logs', ...)`，**唤醒按钮点下去、日志面板毫秒级出现「Sent magic packet to aa:bb:cc:dd:ee:ff via 192.168.1.255:9」**
* • **PWA 支持**：`manifest.json` + Service Worker，**手机「添加到主屏幕」= 原生 App 体验**

### 避坑与总结

| 优点 | 缺点/局限 |
| --- | --- |
| **单二进制/单镜像、内嵌 SQLite、无外部依赖** ：部署极简、备份拷 `data/` 走人 | **网络发现/ARP 追踪需 nmap + root/NET\_RAW** ，非特权容器需额外 `--cap-add` |
| **PocketBase 托管 Auth/存储/实时/Admin UI** ：零 Auth 代码、零迁移脚本、开箱即用 | **PocketBase 单写入器** ：高并发写入（如百台设备同时唤醒日志）可能锁竞争、吞吐上限 ~1k ops/s |
| **WoL 核心逻辑纯 Go、跨平台、支持 SecureOn/自定义广播/端口** | **跨子网 WoL 仍需网络层配置** （路由器 directed-broadcast/WOL 代理），应用层解决不了 |
| **定时任务 Cron 表达式+时区+日志、关机命令可自定义** | **关机依赖 SSH/WinRM/自定义命令** ，无统一 Agent、Windows 免密关机配置麻烦 |
| **Tailscale Sidecar 官方示例、零公网 IP 安全访问、ACL 可控** | **Tailscale Funnel/Serve 集成仍实验性** ，自签证书/证书轮换需手动跟进 |
| **SvelteKit 前端轻快、实时 WebSocket、PWA 可装手机** | **无多租户/团队/权限模型** ：PocketBase Auth 只有「用户/管理员」，无「只读/分组管理员」细粒度 |

**个人判断**：UpSnap 解决的核心问题是「**把『Wake-on-LAN 这件小事』从『终端命令/脚本/记 MAC 地址』升级为『可视化、可调度、可发现、可鉴权、可审计』的网络设备管理面板**」。**它不造 WoL 协议、不造网络拓扑、不造关机 Agent，只把「发魔术包、查在线、扫网络、定时跑、记日志、管账号」这套管理层做得极简、极标准、极易部署**。技术栈选择（Go+PocketBase+SvelteKit）**恰到好处**：Go 发包快、PocketBase 省运维、SvelteKit 体验好，**三者各司其职、无过度设计**。

**适用场景**：

* • 家庭/实验室/中小办公室：**10-200 台设备**、需统一唤醒/关机/状态监控、不想装 Zabbix/Prometheus/Ansible
* • 远程办公/混合办公：**Tailscale 组网 + UpSnap 面板**，随时随地开家里 NAS/工作站、无公网 IP、无端口映射
* • 运维/开发自用：\*\*「设备清单+一键唤醒+定时开关机」\*\*最小可用集合、Docker 一行部署、配置文件即代码
* • 学习参考：**Go+SQLite+WebSocket+前端实时**的标准全栈最小实现、PocketBase 实战范例

**不适用场景**：

* • 大规模企业网络（>500 设备、需 CMDB/资产管理/变更流程/合规审计）
* • 需要 **Agent 级管理**（硬件监控/固件升级/配置下发/补丁分发）
* • 纯 Windows 环境且依赖 WinRM/AD 域控关机（UpSnap 只是发命令、不管命令怎么跑通）
* • 高并发写入场景（如秒级心跳上报、海量日志入库），PocketBase SQLite 会成瓶颈

**值不值得折腾**：**值得 `docker run --network=host seriousm4x/upsnap:latest` 跑一次**。两分钟进 Web 面板、加俩设备（输名字/MAC/IP）、点「Wake」看日志、设个「工作日 8 点唤醒」、再按「Scan Network」看自动发现。十分钟体会完「有个 Web 面板管 WoL 是什么体验」。若你有「分散设备、想统一管唤醒、不想装重监控、能接受 Docker/二进制部署」，UpSnap 是目前**最诚实、最轻量、最少坑**的开源答案。
