# Papra：极简自托管文档归档平台，全文检索+OCR+邮件收集+标签组织，Docker 一键部署

去年把家里的纸质文档（发票、保修卡、合同、银行账单、医疗报告）扫成 PDF 丢到 NAS 共享文件夹，结果积了 3000+ 文件、**找一张三年前的显示器发票要翻半小时文件名**。试过 Paperless-ngx，功能强但部署需 PostgreSQL + Redis + RabbitMQ + Tesseract + 消费者容器，**单机 4 容器、内存 4 GB 起步、配置 YAML 两百行**；试过 Nextcloud Documents，主打协作编辑、检索弱、OCR 需额外 App。想找个「极简、单容器/少依赖、现代 UI、全文检索+OCR+邮件收集、自托管」的工具，翻到 **Papra**（`papra-hq/papra`，v26.6.0，AGPL-3.0）。作者 Corentin Thomasset 定位：「极简文档管理与归档平台，设计为简单易用、人人可及」。周末在主力服务器（Ryzen 5700G、32 GB、Proxmox VE LXC）与树莓派 4B（8 GB、Ubuntu Server 24.04）双环境实测部署，记录真实体验。

### 部署实录

#### 方式一：Docker Compose（官方推荐，生产就用这个）

```
# docker-compose.yml（精简自官方示例）  
version: '3.8'  
services:  
  papra:  
    image: ghcr.io/papra-hq/papra:latest  
    container_name: papra  
    ports:  
      - "3000:3000"  
    environment:  
      - DATABASE_URL=postgresql://papra:***@db:5432/papra  
      - REDIS_URL=redis://redis:6379          # 可选：仅用于缓存/会话，非必需  
      - MINIO_ENDPOINT=minio:9000             # 对象存储（可选：本地文件系统也行）  
      - MINIO_ACCESS_KEY=***  
      - MINIO_SECRET_KEY=***  
      - MINIO_BUCKET=papra  
      - MINIO_USE_SSL=false  
      - TESSERACT_LANGUAGES=eng,chi_sim,fra,deu  # OCR 语言包  
      - EMAIL_IMAP_HOST=imap.gmail.com        # 邮件收集配置  
      - EMAIL_IMAP_PORT=993  
      - EMAIL_IMAP_USER=your@email.com  
      - EMAIL_IMAP_PASSWORD=***

      - minio

      - minio_data:/data

      - "9000:9000"  
      - "9001:9001"

  postgres_data:  
  redis_data:  
  minio_data:
```

#### 方式二：最小依赖模式（无 Redis/MinIO，仅 PostgreSQL + 本地文件系统）

```
# docker-compose.minimal.yml  
version: '3.8'  
services:  
  papra:  
    image: ghcr.io/papra-hq/papra:latest  
    ports:  
      - "3000:3000"  
    environment:  
      - DATABASE_URL=postgresql://papra:***@db:5432/papra  
      - STORAGE_DRIVER=local                  # 关键：用本地文件系统替代 MinIO  
      - STORAGE_LOCAL_PATH=/app/data/storage  
      - TESSERACT_LANGUAGES=eng,chi_sim  
      - NEXTAUTH_SECRET=***  
      - NEXTAUTH_URL=http://localhost:3000  
    volumes:  
      - ./data:/app/data  
    depends_on:  
      - db  
    restart: unless-stopped  
  
  db:  
    image: postgres:16-alpine  
    environment:  
      - POSTGRES_USER=papra  
      - POSTGRES_PASSWORD=***  
      - POSTGRES_DB=papra  
    volumes:  
      - postgres_data:/var/lib/postgresql/data  
    restart: unless-stopped  
  
volumes:  
  postgres_data:
```

**核心观察**：**CadenceMQ（自研任务队列）内嵌在 Node.js 进程里，用 PostgreSQL 做持久化、无需 Redis/RabbitMQ**——这是 Papra 与 Paperless-ngx 最大架构差异。官方文档明确：「为避免自托管部署需 Redis/RabbitMQ，我们自建了基于 Postgres 的队列」。

**实测环境与资源占用**：

| 环境 | 部署模式 | 冷启动 | 内存稳态 | CPU 闲置 | 存储 |
| --- | --- | --- | --- | --- | --- |
| Ryzen 5700G LXC (4GB) | 完整栈 | 12 秒 | 1.2 GB | <2% | PostgreSQL 200 MB + MinIO 1.5 GB |
| 树莓派 4B 8GB | 最小栈 | 8 秒 | 680 MB | <3% | PostgreSQL 150 MB + 本地文件 |

**首次配置向导**：访问 Web 端 → 创建组织（如 "Family"） → 创建管理员账号 → 可选：配置邮件收集/OCR 语言/存储后端 → 进仪表盘。

### 核心亮点

#### 1. 三大入库通道：上传、邮件、监控文件夹

| 通道 | 配置方式 | 处理流程 |
| --- | --- | --- |
| **Web 上传** | 拖拽/点击选择、支持多文件、批量标签 | 前端直传 → 后端流式写入存储 → 发布 `document.created` 事件 → CadenceMQ 拾取 → 文本提取/OCR/缩略图/全文索引 |
| **邮件收集** | 环境变量配 IMAP（Host/Port/User/Pass/Folder/SSL） | 后台轮询（默认 5 分钟）→ 抓取未读 → 下载附件 → 同 Web 上传流程 → 标记已读/移动到归档文件夹 |
| **文件夹监控** | 环境变量 `WATCH_PATH=/app/data/watch` + `WATCH_INTERVAL=60` | `chokidar` 监听目录 → 新文件/变更 → 同 Web 上传流程 → 可选：处理后移动/删除原文件 |

**实测邮件收集**：配置 Gmail IMAP（需应用专用密码）、指定 `INBOX/Papra` 标签、发测试邮件带 PDF 附件 → **2 分钟内自动入库、OCR 出文本、打标签 "email"、关联原邮件元数据（发件人/主题/日期）**。比 Paperless-ngx 的 `mail` 命令行工具**零配置、零系统服务、全 Web 可视化**。

#### 2. 文本提取管线：@papra/lecture 多格式 + Tesseract OCR

```
// @papra/lecture 核心接口（简化）  
interface ExtractionResult {  
  text: string;           // 提取全文  
  pages: Page[];          // 分页文本/尺寸/旋转  
  metadata: DocumentMeta; // 作者/创建日期/PDF 版本/加密状态  
  thumbnail: Buffer;      // 首页缩略图 (PNG, 256px)  
}  
  
async function extract(file: Buffer, mime: string): Promise<ExtractionResult> {  
  switch (mime) {  
    case 'application/pdf': return pdfExtract(file);      // pdf-parse + pdf.js  
    case 'image/*': return ocrExtract(file);              // Tesseract.js (WASM) 或原生 tesseract  
    case 'application/vnd.openxmlformats-officedocument.wordprocessingml.document':  
      return docxExtract(file);                           // mammoth  
    case 'text/*': return textExtract(file);              // 直接读取  
    // ... 支持 10+ 格式：xlsx, pptx, odt, ods, odp, epub, rtf, html  
  }  
}
```

**OCR 细节**：

* • **语言包**：环境变量 `TESSERACT_LANGUAGES=eng,chi_sim,fra,deu`，**首次启动自动下载 `.traineddata` 到 `/usr/share/tessdata`**（约 50 MB/语言）
* • **引擎选择**：`OCR_ENGINE=tesseract`（默认，原生二进制）或 `tesseract.js`（WASM，无需系统依赖、较慢）
* • **预处理**：ImageMagick 自动旋转/去倾斜/二值化/增强对比度 → 显著提升识别率
* • **输出**：每页文本 + 坐标 → **全文索引存入 PostgreSQL `tsvector`、PDF 叠加隐藏文本层（可搜索 PDF）**

**实测识别率**：

* • 中英混排发票（300 DPI 扫描）：**字符级准确率 ~96%**，金额/日期/商家名基本无误
* • 手写便签：~72%（Tesseract 固有短板，非 Papra 问题）
* • 复杂表格 PDF：文本提取顺序偶尔乱序，**建议导出 CSV/Excel 单独处理**

#### 3. 全文检索 + 标签 + 组织：PostgreSQL 原生 FTS + 关系模型

```
-- 核心检索表（简化）  
CREATE TABLE documents (  
  id UUID PRIMARY KEY,  
  organization_id UUID REFERENCES organizations(id),  
  title TEXT,  
  content TEXT,                    -- 提取全文  
  content_tsv TSVECTOR GENERATED ALWAYS AS (  
    to_tsvector('simple', coalesce(title,'') || ' ' || coalesce(content,''))  
  ) STORED,  
  tags UUID[] DEFAULT '{}',        -- 标签 ID 数组  
  correspondent_id UUID,           // 往来单位  
  document_type_id UUID,           -- 文档类型  
  created_at TIMESTAMPTZ,  
  updated_at TIMESTAMPTZ,  
  -- 索引  
  INDEX idx_content_tsv USING GIN (content_tsv),  
  INDEX idx_tags USING GIN (tags),  
  INDEX idx_org_created ON (organization_id, created_at DESC)  
);
```

**检索体验**：

* • **前端搜索框**：输入「发票 2024 显示器」→ 后端 `plainto_tsquery` + `websearch_to_tsquery` → **毫秒级返回高亮片段**
* • **高级过滤**：标签多选/排除、往来单位、文档类型、日期范围、是否有附件、OCR 状态
* • **保存搜索**：常用查询存为「智能视图」，侧边栏一键访问
* • **标签管理**：层级标签（父子）、颜色、使用计数、批量打标/移除

#### 4. 组织与权限：多租户、角色、邀请、审计

| 概念 | 说明 |
| --- | --- |
| **组织** | 顶层租户，隔离文档/用户/设置/邮件账号/标签/类型/往来单位 |
| **角色** | `Owner` （全权）、`Admin`（管理用户/设置）、`Editor`（增删改文档）、`Viewer`（只读/搜索） |
| **邀请** | 邮件邀请链接、一次性 Token、可预设角色、过期时间 |
| **审计日志** | 文档 CRUD、登录、设置变更、邮件收集、OCR 任务、**全记录 `audit_logs` 表、可导出** |

**实测多组织**：创建 "Family"、"Work" 两组织、切换下拉框瞬间隔离数据、**无跨组织泄露风险**。

#### 5. 现代前端：Next.js 14 (App Router) + React 18 + Tailwind + shadcn/ui

* • **服务端渲染 + 流式传输**：文档列表 SSR、详情页 `Suspense` 流式加载 OCR 文本/缩略图、**首屏 FCP < 800ms**
* • **乐观更新**：打标签/移动/重命名**即时响应、后台同步、失败回滚 Toast 提示**
* • **键盘快捷键**：`/` 聚焦搜索、`n` 新建、`e` 编辑、`d` 删除、`t` 打标、`j/k` 列表导航
* • **深色模式**：跟随系统/手动切换、CSS 变量零闪烁
* • **PWA**：`manifest.json` + Service Worker 缓存静态资源、**离线可看已缓存文档列表/详情**

### 避坑与总结

| 优点 | 缺点/局限 |
| --- | --- |
| **极简部署** ：Docker Compose 单文件、最小栈仅 PostgreSQL、无 Redis/RabbitMQ 强依赖 | **OCR 语言包下载慢/失败** ：国内需配镜像源或预置 `.traineddata` 到镜像 |
| **自研队列 CadenceMQ** ：基于 Postgres、无额外基建、支持重试/延迟/优先级/死信 | **队列吞吐上限** ：单实例 ~500 jobs/min，大批量导入（>1 万文档）需横向扩展 Worker 进程 |
| **三大入库通道全 Web 配置** ：邮件收集/文件夹监控无需写 systemd/cron | **邮件收集仅 IMAP** ：不支持 Exchange/Graph API/POP3、无规则路由（如「发件人含 invoice 进特定标签」） |
| **PostgreSQL 原生全文检索** ：无需 Elasticsearch/Meilisearch、多语言分词、高亮片段 | **中文分词依赖 `zhparser` 扩展** （需自行安装/编译），默认 `simple` 分词器单字切分、召回率低 |
| **现代 UI/UX** ：Next.js 14 + Tailwind + shadcn/ui、键盘优先、PWA、深色模式 | **无移动端 App** ：PWA 体验受限于 iOS Safari 推送/后台同步限制 |
| **AGPL-3.0 完全开源** ：自托管无功能限制、数据完全掌控、可二次开发 | **AGPL 传染性** ：若作为 SaaS 对外提供服务，修改代码必须开源、商业化需谨慎 |
| **活跃开发** ：月更、v26.6.0 已有 AI 自动标签、外部内容提取、CLI/SDK 规划中 | **生态薄** ：无第三方插件市场、无现成 n8n/自动化集成、API 文档尚简略 |

**个人判断**：Papra 解决的核心问题是「**给『不想折腾基建、要现代体验、要全文检索+OCR+邮件收集』的个人/家庭/小团队，一个『极简依赖、开箱即用、可长期演进』的文档归档平台**」。它不像 Paperless-ngx 那样追求「功能全、企业级、消费者多」（代价是重依赖、陡峭学习曲线），也不像 Nextcloud 那样追求「协作平台」（文档只是众多 App 之一）。Papra **只做文档归档这一件事**，并把「入库→提取→索引→检索→标签→组织」这条主线的每个环节**做到「够用、好用、可自动化」**。

**适用场景**：

* • 个人/家庭：发票/保修/合同/账单/医疗报告**扫描/邮件转发/拖拽上传 → 自动 OCR → 全文搜索 → 标签整理**
* • 小团队/工作室：项目合同/客户往来/财务单据**多组织隔离、角色权限、审计合规**
* • 自托管极简主义者：**拒绝 Redis/RabbitMQ/Elasticsearch、只要 PostgreSQL + 单容器/双容器**
* • 开发者学习参考：**Next.js 14 + Prisma + PostgreSQL FTS + 自研队列 + Tesseract + shadcn/ui** 的现代全栈实战范例

**不适用场景**：

* • 大规模企业（>5 万文档、高并发、需集成 ERP/CRM/BPM、需高可用集群）
* • 重协作编辑/版本控制/审批流/电子签名（去 Nextcloud/OnlyOffice/Seafile）
* • 相册/视频/音频管理（去 Immich/PhotoPrism/Plex）
* • 无法接受 AGPL-3.0 的商业化场景（除非购买商业许可或隔离部署）
* • 需要现成「规则引擎/自动分类/工作流自动化」（Paperless-ngx 的 `matching_algorithm`/`workflows` 更成熟）

**值不值得折腾**：**值得 `docker compose up -d` 跑一次**。五分钟进 Web 向导、建组织、传张发票 PDF、看 OCR 出文本、搜关键词、加标签、配个邮件收集规则、发封测试邮件看自动入库。十分钟体会完「极简文档归档」的爽感。若你的痛点正是「文档散落、找不到、不想装重栈、要现代 UI」、且能接受 AGPL，Papra 是目前**最诚实、最轻量、最少妥协**的开源答案。
