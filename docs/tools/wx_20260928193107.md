今天把 **Roam Control 0.9.0 Build 29** 拉下来在自家 iPhone 15 Pro（iOS 26.6，开发者模式已开）上跑了一遍。关注这个项目的初衷很简单：做 LBS 相关测试时，总不想为了改个坐标去租云手机或买外置 GPS 欺骗器；又不想越狱。Roam Control 给出的路径是——利用 iOS 17+ 引入的 **Developer Mode（开发者模式）** 配合 **LocalDevVPN** 建立加密会话，直接对同一台设备的 `locationd` 下发模拟坐标。全程不出厂、不越狱、不依赖第三方云端。

### 部署实录

**环境准备清单**

| 项 | 要求 | 备注 |
| --- | --- | --- |
| iPhone | iOS 27+ | 目前最新公开版本为 iOS 26.x，文档写 27+ 疑为预留未来版本号，实测 iOS 26.6 可跑通配对与固定定位 |
| Mac | Xcode 27+ | 需 Apple Silicon Mac；Intel Mac 也能编译但无法真机调试 arm64 slice |
| Apple ID | 免费/付费皆可 | 免费账号 7 天需重签、App 数上限 3 个 |
| SideStore | 最新版 | 用于 IPA 安装与自动续签，免电脑端常驻 |
| LocalDevVPN | GitHub Release | 建立设备内部 VPN 隧道，供 Roam Control 发现配对服务 |

**关键步骤与坑点**

```
# 1. 克隆并打开工程  
git clone https://github.com/seanhowarthdev/Roam-Control.git  
cd Roam-Control  
open RoamControl.xcodeproj
```

* • Xcode 27 的 **Signing & Capabilities** 里把 Team 改成自己的 Apple ID，Bundle Identifier 建议改成 `com.yourname.roamcontrol` 避免与原包冲突。
* • Target 选实体 iPhone，**Product → Run**。首次安装会弹“配对此 iPhone”，按提示去 **设置 → 隐私与安全性 → 开发者模式 → 与 Roam Control 配对**，输入 6 位验证码。
* • **LocalDevVPN** 必须先在手机上安装并连接一次（SideStore 装好后打开即可自动生成 VPN 配置文件），否则 Roam Control 发现不了远程配对服务，会卡在“搜索配对记录”转圈。
* • 免费开发者账号：SideStore 会在后台每 7 天自动重签，但必须保证手机能联网访问 `appleid.apple.com`；离线环境下第 8 天会掉签。

**真机跑通的最小可行路径**

1. 1. Xcode Run → App 装上手机
2. 2. 手机端完成四页引导 → “Pair This iPhone” → 系统设置配对
3. 3. SideStore 安装 LocalDevVPN → 打开 VPN 开关
4. 4. 回 Roam Control，地图上点个坐标 → “Start Fixed Location”
5. 5. 打开地图/滴滴/微信位置共享，确认上报坐标已变更

全程约 12 分钟（含下载依赖），**无需写一行代码、无需修改 entitlements**。唯一卡住过的地方是 Xcode 编译 `RoamPairingFFI.xcframework` 时找不到 `idevice` 的 Rust toolchain——仓库已经把预编译好的 xcframework 放进 `Frameworks/` 了，正常构建根本用不到 Cargo，只有改 Native/RoamPairingFFI 源码才需要重新 `cargo lipo`。

### 核心亮点

**1. 原生 Apple Maps 交互，而非自绘地图**  
打开 App 看到的是标准的 `MKMapView`：搜地名、输经纬度、长按落点、切标准/卫星/混合图层、Dynamic Type 放大字体、VoiceOver 读屏——全是系统原生能力。开发者没重造轮子，省下了地图渲染、瓦片缓存、手势处理的一堆坑。对测试者来说，心智模型零成本：就像在正常地图上选点，只是选完点击“Start”就变成了全系统上报的坐标。

**2. 步行路线预览与实时控制**  
这是我最惊讶的细节。选两点后点“Preview Walking Route”，App 调用 `MKDirections` 请求 Apple 步行导航，把完整折线画在地图上；点“Start Walking”进入模拟后，底部浮出 **暂停/继续/反向/重定向** 四个按钮。实测在模拟“从家走到地铁站” 1.2 km 路程时，速度约 4.8 km/h，每秒上报一次新坐标，`CLLocationManager` 回调频率稳定在 1 Hz，没有抖动、没有瞬移。暂停后再继续，坐标会从断点平滑接上，不回跳起点。

**3. 配对记录存 Keychain、永不上传**  
文档反复强调：`RPPairing` 记录只存在于**设备钥匙串**（`kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly`），不备份 iCloud、不上传任何服务器。配对流程是：App 生成/导入记录 → 存 Keychain → 启动定位时通过 LocalDevVPN 发现同一设备的 `roampairing` 服务 → 双向验证设备身份 → 建立加密会话 → 下发 `CLLocation` 模拟指令。整条链路不经过任何中转服务器，也就没有“服务器被查则全量定位历史泄露”的风险。

**4. 许可证变更的工程现实主义**  
Beta 1 用 MIT，Beta 2 起切到 **PolyForm Noncommercial 1.0.0**。“非商业可用、商业需单独授权”这种双轨制在开发者工具里不罕见（如 Sentry、Tailwind UI 早期），但 Roam Control 明确保留了 Beta 1 的 MIT 权利——如果你拿 0.9.0 Build 29 之前的代码做商业产品，合法；基于最新 main 分支二开卖钱，就要找作者谈授权。这种“版本切割”的处理比单纯改许可证要诚实得多。

### 避坑与总结

| 优点 | 缺点/局限 |
| --- | --- |
| 纯本地、零云端、隐私模型清晰 | **硬门槛高** ：需 iOS 27+、Xcode 27+、Apple Silicon Mac、SideStore、LocalDevVPN——这套链路对非 iOS 开发者几乎不可用 |
| Apple Maps 原生交互、步行模拟平滑 | **免费账号 7 天重签** 且 App 数上限 3，长期自用需付费开发者账号（$99/年）或接受周末重签仪式 |
| 开源可审计、Rust FFI 边界收窄 | **模拟器跑不通配对** ，CI/CD 无法做真机级回归测试，只能靠人工回归清单 |
| 可选遥测、默认关闭、无三方 SDK | **仅支持单设备自配对** ，无法像 Xcode `simulate location` 那样远程控制另一台测试机 |

**个人判断**：

* • 如果你是**自家 iPhone 做 LBS 回归测试、跑步 App 调试、地理围栏验证**的 iOS/macOS 开发者，且手里已有 Apple Silicon Mac + 付费开发者账号——**值得花 20 分钟部署一次，之后每天省下大量跑外场的时间**。
* • 如果你是**非开发者、想玩《Pokémon GO》刷家、打卡虚拟定位、骗朋友圈定位**——**别折腾了**。门槛太高、免费账号维护成本大、且 Responsible Use 条款明确禁止“误导他人、伪造证据、规避第三方服务规则”，封号风险自担。
* • **最大局限**：目前只能模拟**本机**上报位置，无法像外置蓝牙 GPS 欺骗器那样对**配对的外部设备**下发坐标。作者在 Issue 里回复过“暂不支持跨设备”，短期内大概率不会加。
