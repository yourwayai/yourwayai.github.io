# Nanonets 开源 DocStrange：7B 模型驱动的文档转 Markdown，支持全本地 GPU 推理与自建 Web UI

周末把 **DocStrange v1**（GitHub 主分支 `d72ce26`，2025-08 更新）拉到本地跑了一遍。关注它的原因很直接：手头积压了几百份扫描版合同、手机拍的收据、混排版 PPT，需要批量转成**干净的 Markdown + 结构化 JSON**喂进 RAG 流水线。市面上云端 API（AWS Textract、Azure Form Recognizer、Google Document AI）要么贵、要么数据出境合规过不去、要么对中文手写体识别率堪忧。DocStrange 打出的牌是：**7B 参数模型 + 多引擎 OCR 兜底 + 完全本地跑 + 自带 Web UI + MCP 接口给 Claude Desktop 用**——这套组合拳正好卡在我的痛点上。

### 部署实录

**环境与依赖清单**

| 项 | 要求 | 实测版本 |
| --- | --- | --- |
| Python | ≥3.8 | 3.11.9 (conda) |
| GPU | NVIDIA CUDA 11.8+ | RTX 3090 24GB / CUDA 12.4 |
| 系统库 | `poppler-utils``tesseract-ocr``libgl1` | Ubuntu 22.04 `apt install -y poppler-utils tesseract-ocr libgl1` |
| 磁盘 | 模型缓存 ~6-8 GB | 首次下载自动落 `~/.cache/docstrange` |

**关键安装命令**

```
# 1. 仅库（云端模式默认，无需 GPU）  
pip install docstrange  
  
# 2. 带 Web UI 依赖（Flask + 前端资源）  
pip install "docstrange[web]"  
  
# 3. 开发模式（含 MCP server、测试套件）  
git clone https://github.com/nanonets/docstrange.git  
cd docstrange  
pip install -e ".[dev]"
```

**实测踩坑点**

1. 1. **首启模型下载无进度条** —— `DocumentExtractor(gpu=True)` 初始化时会从 HF Hub 拉 7B 模型权重（约 6.2 GB），终端只打一行 `Downloading...` 没进度条，以为卡死其实在跑。建议先 `python -c "from docstrange import DocumentExtractor; DocumentExtractor(gpu=True)"` 单独预热。
2. 2. **CPU 模式极慢** —— README 说“Works on GPU or CPU”，但 `cpu=True` 下单页 PDF 推理 40-60 秒，GPU 下 1.2-1.8 秒。**生产环境没 GPU 别考虑本地模式**，老老实实用云端免费额度。
3. 3. **Web UI 端口冲突** —— 默认 8000，跟常用的 `uvicorn`/`jupyter` 撞车。`docstrange web --port 8080` 或 `run_web_app(port=8080)` 解决。
4. 4. **tesseract 语言包** —— 识别中文扫描件需 `tesseract-ocr-chi-sim`，否则只能跑英语。`apt install tesseract-ocr-chi-sim tesseract-ocr-chi-tra` 补齐。
5. 5. **MCP server 不在 PyPI 包里** —— 必须 `git clone` 后 `pip install -e ".[dev]"`，再把 `mcp_server_module/server.py` 指到 Claude Desktop config。这是给本地开发用的，不随 `pip install docstrange` 分发。

**最小可行验证流（云端模式，免 GPU）**

```
from docstrange import DocumentExtractor  
extractor = DocumentExtractor()  # 默认云端，匿名免费额度有限  
result = extractor.extract("scan_contract.pdf")  
print(result.extract_markdown()[:500])  # 立刻看到结构化输出
```

云端匿名额度每天只有几十次，**跑 `docstrange login`（Google OAuth）或配 `api_key` 后解锁 10,000 页/月**，实测够个人/小团队日常用。

### 核心亮点

**1. 表格还原度：从“能看”到“能用”**  
这是我最在意的指标。测了 3 份含合并单元格、跨页表格、斜线表头的财报 PDF：

* • **Markdown 输出**：`| 年份 | 营收(亿) | 同比 |` 对齐完美，合并单元格用空单元格占位，不丢行不乱序。
* • **CSV 输出**：`result.extract_csv()` 直接给出标准 CSV，`pandas.read_csv(io.StringIO(csv))` 零报错入库。
* • **对比基线**：`pdfplumber` + `camelot` 组合要手写坐标修正；`marker-pdf` 对合并单元格经常拆行；DocStrange **零配置**把最难的那张“跨页+合并单元格+小计行”表格全对齐。底层是 7B 模型做 **Layout Detection → Table Structure Recognition → Markdown 序列化** 一条龙，不再拼接多模型。

**2. Schema 指定提取：把“非结构化”变“强类型”**

```
schema = {  
    "contract_number": "string",  
    "parties": [{"name": "string", "role": "string"}],  
    "total_value": "number",  
    "clauses": [{"title": "string", "content": "string"}]  
}  
structured = result.extract_data(json_schema=schema)
```

输出直接是符合 schema 的嵌套 dict，**字段缺失返回 null、类型不匹配不报错**（由模型尽力推断）。实测从 20 页合同里抠 `contract_number`、`parties[0].name`、`total_value` 三个字段，准确率 19/20，唯一漏掉的是手写盖章处的甲方名——OCR 层识别不出盖章遮挡的汉字，这在任何方案里都是硬伤。

**3. 双模式无缝切换：同一套代码，云端/本地一行切换**

```
# 云端（默认，需联网）  
extractor = DocumentExtractor()  
  
# 本地 GPU（完全离线，首次下载模型后断网也能跑）  
extractor = DocumentExtractor(gpu=True)  
  
# 本地 CPU（仅兜底演示，别上生产）  
extractor = DocumentExtractor(cpu=True)
```

`extract()`、`extract_markdown()`、`extract_data()` 等所有方法签名完全一致。这意味着**开发联调用云端（快、免配置）、生产落地切本地（合规、零延迟、无额度焦虑）**，代码零修改。对数据敏感项目（医疗、金融、法务）极其友好。

**4. MCP Server：给 Claude Desktop 装上“文档导航仪”**  
克隆仓库后配上 MCP，Claude Desktop 里就能：

* • `@docstrange 打开 /path/to/100页合同.pdf`
* • `@docstrange 摘要第 3 章“违约责任”条款`
* • `@docstrange 把所有金额字段按 schema 拿出来`  
  底层是 **Token-aware 分块 + 层级导航**（按 Heading 切 chunk、超长自动滑窗）+ **语义检索**（内嵌 embedding），把 100 页文档变成可对话的知识库。实测 80 页扫描件合同，Claude 定位“第 7.3 条赔偿上限”用时 <3 秒，不再把全文塞进上下文窗口。

**5. 免费云端额度诚意足：10k 页/月，仅需 Google 登录**  
注册即送 10,000 页/月，**无信用卡、无绑卡、无自动扣费**。对比：AWS Textract 免费层 1,000 页/月（仅首年）、Azure Form Recognizer 免费 500 页/月。Nanonets 这步棋走得很聪明：用免费云端把开发者拉进生态，等数据量上来、合规要求紧了，自然迁移到本地部署或企业版。

### 避坑与总结

| 优点 | 缺点/局限 |
| --- | --- |
| 7B 模型表格/版面理解显著好于开源小模型 | **模型权重不开源** （仅推理代码开源，MIT License），无法微调、无法审计模型内部、无法离线部署到无网环境（首次必须联网下载） |
| 云端/本地双模式一行切换，API 完全兼容 | **本地 GPU 显存占用 ~14 GB** （7B FP16 + OCR 引擎 + 激活值），RTX 3080 10GB 跑不起来，3090/4090/A100 才稳 |
| Schema 指定提取 + JSON Schema 强约束，直接可入库 | **手写体/盖章遮挡/极低分辨率照片** 识别率仍依赖 Tesseract 兜底，中文手写体准确率 ~60%（云端模式略高） |
| 内置 Web UI、CLI、MCP、Python SDK 四合一 | **无批量异步接口** （`extract()` 同步阻塞），百万级文档需自建任务队列+进程池 |
| 10k 页/月免费云端额度，登录即用 | **PPTX/XLSX 支持较弱** ：PPT 只提取文本框不还原版面，Excel 只转第一个 Sheet 的 CSV |

**个人判断**：

* • 如果你是**构建 RAG/知识库的后端工程师**，需要把 PDF/Word/扫描件/表格批量转成 **LLM-Ready Markdown + 结构化 JSON**，且有**数据不出境/合规**要求——**直接上本地 GPU 模式**，一次部署长期受益，10k 页/月云端额度做开发联调备用。
* • 如果你是**非技术业务方**，只想偶尔把几张发票、合同拖进网页导出 Excel——**直接用 `docstrange.nanonets.com` 网页版**，登录 Google 免费用，别折腾本地环境。
* • 如果你**手里只有 CPU 服务器/笔记本无独显**——**别强行本地跑**，CPU 模式 40 秒/页不可用，云端免费额度覆盖绝大多数轻量场景。
* • **最大局限**：核心 7B 模型**不开源权重**，这意味着你无法在私有数据上继续预训练、无法做领域适配微调、无法审计模型是否存在隐私记忆泄露。对金融/医疗/政企合规审计严格的场景，这是必须向法务确认的红线。
