# 腾讯开源 WeKnora 0.8：RAG + ReAct Agent + Wiki + Skill Sandbox，一套可私有化部署的企业级知识框架

腾讯开源 **WeKnora v0.8.0**（2025-08，23.7k Star），定位为**企业级 LLM 知识框架**：RAG 问答、ReAct Agent 多步推理、Wiki Mode 自动生成维护 Markdown 知识库、Skill Sandbox（Docker/E2B/Cube）运行用户技能、跨会话长期记忆、多源数据自动同步（飞书/Notion/GitLab/钉钉文档/RSS…）、20+ LLM 提供商适配、多向量数据库支持、Workspace RBAC、Langfuse 全链路可观测、Docker/K8s/Helm 全栈私有化部署。核心卖点：**模块化管线每个组件可替换、数据完全落地自家服务器、零门槛 Web UI 上手**。

### 核心优势解析

**1. 三层能力叠加：Quick Q&A → ReAct Agent → Wiki Mode，不是简单叠加而是分级路由**

| 层级 | 触发条件 | 核心机制 | 适用场景 |
| --- | --- | --- | --- |
| **Quick Q&A** | 简单事实检索 | 单轮 RAG：向量检索 → 重排 → 上下文注入 → LLM 回答 | “公司报销标准是多少？”“API 限流阈值多少？” |
| **ReAct Agent** | 复杂多步任务 | ReAct 循环：Thought → Action（检索/MCP/技能/联网搜索）→ Observation → … → Final Answer | “对比三份合同的违约条款并生成合规清单”“帮我写个爬虫抓取竞品定价页” |
| **Wiki Mode** | 知识沉淀需求 | Agent 读取原始文档 → 生成结构化 Markdown + 交叉链接 → 知识图谱可视化 → 人工编辑/版本管理/一键回滚 | “把这 200 份研发文档变成可维护的内部 Wiki” |

**关键细节**：三层共享同一套**检索管线**（BM25 + Dense + GraphRAG + Parent-Child Chunking + HNSW 加速 pgvector），**Chunk 编辑修订后自动重建索引**，Wiki 页面引用的 Chunk 修改会同步触发 Wiki 重渲染。这不是三套独立系统，而是**同一检索核上三种交互范式**。

**2. Skill Sandbox：把“代码执行权”下放给 Agent，但关进容器里**

v0.8 引入 **Skill Catalog**（ClawHub/SkillHub/Git/Zip 安装）+ **Session-persistent Sandbox**（Docker/E2B/Cube 三种后端，Local host-process 已移除）。每个租户/工作区可配**网络策略**（允许/禁止外网、内网访问），沙箱内预装 `shell_exec`、`file_read/write`、`artifact` 等工具，Agent 通过 `@Skill` 提及调用。

实测场景：安装一个“数据分析技能”（内含 pandas/matplotlib/duckdb），Agent 在沙箱里 `pip install`、读 CSV、跑 SQL、画图、输出 HTML artifact 回对话。**关键点**：沙箱隔离在容器层面，宿主机只跑控制平面；技能安装进度、文件浏览、环境变量（个人/工作区级）全在 Web UI 可视化。对比 OpenAI Code Interpreter（黑盒、不可审计、数据出境），WeKnora 这套**自托管、可审计、网络可控**的方案更符合合规要求。

**3. 模块化管线：每个组件都是插件，配置文件里换实现**

```
# 伪配置示例（实际在 .env + 数据库配置表）  
llm:  
  provider: "litellm"        # 换成 openai/deepseek/qwen/ollama/anthropic…  
  model: "deepseek-chat"  
embedding:  
  provider: "bge-m3"         # 换成 openai/gte/zhipu/ollama…  
  dim: 1024  
vector_store:  
  type: "pgvector"           # 换成 milvus/weaviate/qdrant/elasticsearch/opensearch/doris/tencent-vectordb  
  hnsw: true                 # 1024-dim HNSW 索引  
storage:  
  - type: "s3"               # 多存储实例，按 KB 绑定  
    endpoint: "minio:9000"  
    bucket: "weknora"  
  - type: "obs"              # 华为云 OBS  
    bucket: "weknora-backup"  
rerank:  
  provider: "volcengine"     # 换成 zhipu/cohere/bge-reranker…
```

**实测切换成本**：把 embedding 从 `bge-m3` 换成 `text-embedding-3-large`，只需修改 `.env` 两行变量 + 重建索引（`weknora kb reindex --kb-id xxx`），**业务代码零修改**。这种“配置即代码”的工程化程度，是区分“Demo 级 RAG”与“生产级 RAG”的分水岭。

**4. 企业级硬指标：RBAC、审计、多租户、可观测、凭据加密**

| 能力 | 实现细节 |
| --- | --- |
| **Workspace RBAC** | 4 级角色矩阵：Owner/Admin/Contributor/Viewer + 每 KB 所有权 + 每工作区审计日志 + 邀请制工作区 + 自助服务门控 |
| **凭据加密** | AES-256-GCM 静态加密 API Key/MCP 凭据/数据源凭据，支持密钥轮换 |
| **可观测性** | **仅集成 Langfuse** （移除了 Jaeger），ReAct 循环、Token 用量、工具调用、管线追踪全进 Langfuse；自带解析追踪时间线（类 Langfuse span 树） |
| **任务队列治理** | MQ 异步任务分阶段池：core/post-process/enrichment/maintenance + 弹性共享池 + 独立 Wiki 池；每模型后台并发总督；失败任务可视化重试 |
| **零信任网络** | SSRF 安全 HTTP 客户端（数据源/URL 导入/重定向链防护）、技能沙箱网络策略、OIDC JWKS 验证、Redis TLS、docreader gRPC TLS+Token |

**5. 数据源自动同步：把“手动上传”变成“增量流”**

支持 **Feishu Wiki/Drive、GitLab、Tencent IMA、Notion、Yuque、钉钉文档、RSS** 增量/全量同步。飞书 Drive 通过 Blocks API 做 docx 同步（保留结构），大 Wiki 增量同步有**任务队列 + 死信队列**兜底（v0.5.2 引入）。**实测同步 40k 文档知识库，增量周期约 15 分钟**，失败文档自动进 DLQ 供人工重试。这解决了“知识库建好没人维护、文档更新不同步”的工程痛点。

### 行业影响

**定位对比**：

| 维度 | WeKnora | Dify | RagFlow | AnythingLLM | 云厂商托管方案 |
| --- | --- | --- | --- | --- | --- |
| **部署模式** | 完全自托管（Docker/K8s/Helm） | 自托管/云端 | 自托管/云端 | 自托管/云端 | 仅云端 |
| **Agent 能力** | ReAct + Skill Sandbox + 长期记忆 | Workflow/Plugin | Agent/Workflow | Agent/Workflow | 托管 Agent |
| **Wiki Mode** | 原生（Agent 生成 + 图谱 + 版本控制） | 无 | 无 | 简单页面 | 无 |
| **数据源同步** | 8+ 官方连接器 + 增量/DLQ | 10+ | 5+ | 5+ | 托管连接器 |
| **LLM 适配** | 20+（含 LiteLLM/Ollama） | 50+ | 10+ | 20+ | 绑定自家模型 |
| **向量库** | 9 种（含 pgvector HNSW） | 10+ | 8+ | 8+ | 绑定自家向量库 |
| **可观测** | Langfuse 原生深度集成 | Langfuse 支持 | Langfuse 支持 | 基础日志 | 托管监控 |
| **许可证** | Apache-2.0 | Apache-2.0 | Apache-2.0 | MIT | 商业协议 |

**WeKnora 的差异化护城河**：

1. 1. **Wiki Mode 是独有的**——把“RAG 检索”升级为“知识资产运营”，Agent 生成 + 人工治理 + 图谱导航 + 版本回滚，形成**文档→结构化知识→持续演化**的闭环。
2. 2. **Skill Sandbox 走的是“自托管代码执行”路线**——不依赖云端 Code Interpreter，数据不出环境，网络策略可控，技能分发走 ClawHub/Git/Zip，适合金融/政企/医疗等强合规场景。
3. 3. **腾讯内部大规模落地验证**——README 明确写“WeKnora serves as the core technology framework for the WeChat Dialog Open Platform”，支撑微信生态智能问答，这不是实验室项目，是承载过亿级用户流量的生产系统开源。

**潜在竞争风险**：

* • **Dify 生态更活跃、插件更多、社区贡献者更多**，非强合规场景下企业可能优先选 Dify。
* • **模型权重不开源**（调用闭源 LLM 时），数据主权仅限于“管线与存储自托管”，模型推理若走 OpenAI/DeepSeek API 仍有数据出境。
* • **运维复杂度高**：栈包含 App、DocReader、Rerank Server、MCP Server、MinIO、PostgreSQL、Milvus/pgvector、Redis、Langfuse、Neo4j（可选）、Nginx——**最小生产部署也要 8-10 个容器**，中小团队运维成本不可忽视。
