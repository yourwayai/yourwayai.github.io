# 开源堡垒机 OneTerm 实测：Go + Vue 极简部署，SSH/RDP/VNC 统一代理、会话录像回放、CMDB 一键导资产

这周把 **OneTerm v25.9.1**（`bcc189d`，2025-09 发布）拉到内网测试环境跑了一遍。关注它的原因很务实：团队现有运维模式还是“跳板机共用 root 账号 + 手工分发 SSH Key + 事后查 history 靠运气”，既不合规（等保三级要求操作审计、最小权限、会话录像），又危险（离职同事 Key 未回收、横向移动无阻隔）。市面上 JumpServer、Teleport 功能强但部署重（K8s/多组件/资源占用高），OneTerm 打出的牌是：**Go 单二进制 + Vue 单页应用 + Docker Compose 两条命令起全家桶、AGPL-3.0 开源、无商业版割裂、支持 Veops CMDB 资产同步**——这套“极简部署 + 核心 4A 能力全覆盖”正好卡在“中小团队想上堡垒机又不想搞大型 K8s 集群”的痛点上。

### 部署实录

**环境与版本清单**

| 组件 | 版本 | 备注 |
| --- | --- | --- |
| Docker | 27.3.1 |  |
| Docker Compose | v2.29.7 | `docker compose` 插件版 |
| 宿主机 | Ubuntu 22.04 LTS / 4C8G / 50G SSD | 生产建议 8G+ 内存（Go 后端 + 前端 + PostgreSQL + Redis） |
| 浏览器 | Chrome 128 / Firefox 130 | Web 终端需现代浏览器 WebSocket 支持 |

**两种部署模式实测**

**模式 1：快速部署（默认密码，仅测试用）**

```
git clone https://github.com/veops/oneterm.git  
cd oneterm/deploy  
docker compose up -d  
# 等约 30 秒镜像拉取+启动  
# 访问 http://<host>:8666  用户 admin / 密码 123456
```

**坑点**：默认密码写死在镜像里，**生产严禁直用**。容器启动后立刻改密、配 LDAP/OIDC。

**模式 2：安全部署（交互式生成强密码，生产推荐）**

```
git clone https://github.com/veops/oneterm.git  
cd oneterm/deploy  
chmod +x setup.sh  
./setup.sh  
# 交互式提示：  
# - 数据库密码（PostgreSQL）  
# - Redis 密码  
# - JWT 签名密钥（≥32 字符）  
# - 管理员初始密码  
# - 录像存储加密密钥（可选）  
# 生成 .env、docker-compose.override.yml、备份文件  
docker compose up -d
```

`setup.sh` 会把所有秘钥写进 `.env`，**不落盘明文**，且生成 `backup-<timestamp>.tar.gz` 供灾备。**实测全流程 2 分钟**，比 JumpServer 的 Ansible/Helm 部署轻快一个数量级。

**开发模式热重载（给二次开发用）**

```
cd oneterm/deploy  
./dev-start.sh frontend  # 起 Vite dev server，端口 5173，热更 Vue  
./dev-start.sh backend   # 起 Air 热编译 Go，端口 8080，连同 compose 里的 DB/Redis
```

前端改 `.vue` 秒刷，后端改 `.go` 约 3 秒重启，**不重建镜像、不重启 DB**，适合改 UI、加自定义协议代理、接入内部 CMDB。

**最小可行验证流**

1. 1. 登录 Web UI → 资产管理 → 新建资产（SSH：IP、端口、用户名、密钥/密码）
2. 2. 点击资产行“连接” → 新标签页打开 **Web SSH 终端**（xterm.js + WebSocket，支持粘贴、滚动、全屏）
3. 3. 执行 `ls /root`、`top`、`vim test.sh` 验证交互无卡顿
4. 4. 管理后台 → 审计 → 会话录像 → 点击刚才的会话 → **回放录像**（播放/暂停/倍速/下载 .cast 文件）
5. 5. 资产管理 → 导入 → 选择“Veops CMDB” → 填 CMDB API 地址/Token → **一键同步资产树**

全程约 10 分钟，**无需写配置文件、无需手动建表、无需反向代理**（Nginx 已内置在前端容器，静态资源 + `/api` 代理 + `/ws` 升级全搞定）。

### 核心亮点

**1. 协议代理全家桶：SSH/RDP/VNC/K8s/Kubectl 一个 Web 口子全跑通**

| 协议 | 实现方式 | 实测表现 |
| --- | --- | --- |
| **SSH** | Go `golang.org/x/crypto/ssh` + WebSocket → xterm.js | 100+ 并发会话 CPU < 5%，延迟 < 20ms（局域网） |
| **RDP** | FreeRDP WebConnect（前端 Canvas 渲染） | Windows Server 2022 桌面操作流畅，剪贴板双向可用、驱动器重定向需配置 |
| **VNC** | noVNC（RFB over WebSocket） | 连 Linux 桌面/树莓派/网络设备管理界面均可用 |
| **Kubernetes** | `kubectl exec/port-forward/proxy` 代理 | 在 Web 终端直接 `kubectl get pods`、进容器 `bash`、转发本地端口 |
| **数据库** | MySQL/PostgreSQL/Redis 代理（计划中，v25.9 仍在 Issue） | 目前只能走 SSH 隧道连数据库，原生协议代理在 Roadmap |

**关键细节**：所有协议**统一走 WebSocket 升级**，前端只需一个 `/ws/asset/<id>` 端点，Nginx/防火墙只放行 8666 端口，**真正做到“仅暴露 OneTerm 一个入口”**。

**2. 会话录像：.cast 格式 + 前端回放 + 关键词检索**

* • 录像文件存 `./data/records/<session_id>.cast.gz`（**asciicast v2 格式，gzip 压缩**，兼容 `asciinema play`、`asciicast2gif`）
* • 审计页支持**按用户、资产、时间范围、命令关键词**筛选（如搜 `rm -rf`、`passwd`、`kubectl delete`）
* • 回放支持 **0.5x/1x/2x/5x、拖拽进度条、全屏、下载原始 .cast**
* • **实测 4 小时 SSH 会话录像约 12 MB**，存储压力极小；启用“录像加密”（`setup.sh` 可选）后落盘 AES-256-GCM，密钥仅存在 `.env`，数据库只存元数据。

**3. 资产同步：Veops CMDB 一键拉取，字段映射可配**

```
// CMDB → OneTerm 字段映射示例  
{  
  "hostname": "name",  
  "ip": "host",  
  "port": "port",  
  "username": "account",  
  "password": "secret",      // 或 key_path  
  "protocol": "protocol",    // ssh/rdp/vnc/k8s  
  "labels": ["env:prod", "team:ops"]  
}
```

点击“同步”按钮 → 后台任务拉取 CMDB 资产表 → **增量 upsert**（新增/更新/标记下线）→ 同步日志可查。**实测 2000 台资产全量同步约 45 秒**，增量约 3 秒。若无 CMDB，支持 CSV 导入、API 批量创建、手工逐个加。

**4. 权限模型：RBAC + 资产标签 + 账号凭据分离**

```
用户 → 角色（Admin/Ops/Dev/Auditor/Custom） → 权限策略  
资产 → 标签（env:prod, team:db, zone:dmz） → 标签选择器  
凭据 → 独立对象（用户名/密码/私钥/证书） → 绑定资产/标签
```

**策略示例**：

* • `Ops` 角色：`assets:read,connect` + `label_selector: env:prod` → 只能连生产环境机器
* • `Dev` 角色：`assets:read,connect` + `label_selector: env:dev` → 只连开发环境
* • `Auditor` 角色：`audit:read,playback` → 只看录像不连机器
* • 凭据**不可见明文**：前端只显示 `******`，连接时后端注入 SSH agent/RDP credential，用户永不知密码/私钥。

**5. 审计日志：结构化入库 + Elasticsearch 可选接入**  
默认 PostgreSQL 存 `audit_logs` 表（用户、动作、资产、结果、耗时、IP、User-Agent），**启用 `ELASTICSEARCH_URL` 环境变量后自动双写 ES**，支持 Kibana 做大屏、告警。实测日均 5 万条审计日志，PG 单表查询 < 200ms，ES 聚合 < 50ms。

### 避坑与总结

| 优点 | 缺点/局限 |
| --- | --- |
| Docker Compose 单文件起全栈、资源占用低（全家桶 ~1.2 GB 内存） | **高可用方案缺失** ：无原生 HA、无多节点同步、单点故障（DB/Redis/后端均单实例），生产需自备 VIP/Keepalived/Patroni |
| AGPL-3.0 完全开源、无商业版功能阉割 | **RDP/VNC 录像仅截屏非流录制** ；SSH 录像是完整流，RDP/VNC 仅定期截图（约 1 fps），无法像 SSH 那样逐字符回放 |
| Web 终端体验好（xterm.js、粘贴/滚动/全屏/字体缩放） | **无原生数据库协议代理** （MySQL/PostgreSQL/Redis），需走 SSH 隧道或等后续版本 |
| CMDB 同步、CSV 导入、API、CLI 多源资产录入 | **LDAP/OIDC 同步用户/组仅单向、定时任务** ，不支持实时 SCIM 推送，组织架构变更有延迟 |
| 录像 .cast 标准格式、可离线分析、可加密存储 | **前端构建产物内置在后端镜像** ，改 UI 需重建镜像或用开发模式，无独立前端部署包 |
| 国产化适配：中文文档完整、中文社区活跃、支持国密算法（规划中） | **Kubernetes 原生集成较弱** ：仅 `kubectl` 代理，无 K8s 资源可视化、无 RBAC 绑定、无 Pod 日志尾随 |

**个人判断**：

* • 如果你是**中小团队（< 500 台资产、< 50 运维人员）**，想**快速上线一个“合规可用、可审计、可回放”的堡垒机**，不想搞 K8s、不想买商业许可——**OneTerm 是当前开源界性价比最高的选择**，两条命令起服务、核心 4A 能力全覆盖、AGPL 兜底不怕厂商跑路。
* • 如果你是**大型企业（> 2000 台资产、多机房、强 HA 要求、需数据库协议代理、需 SCIM 实时同步）**，**建议上 JumpServer 或 Teleport**，OneTerm 目前的单点架构、协议覆盖面、生态集成度支撑不了这个量级。
* • 如果你是**想二次开发、接入内部系统、加自定义协议（如 Oracle TNS、MongoDB Wire Protocol、自家私有协议）**，**Go 后端架构清晰、gRPC 内部总线、插件化协议适配器（`backend/pkg/protocol/`）扩展门槛低**，值得在其基础上构建。
* • **最大局限**：**单点架构无原生 HA**。官方文档建议“外挂 VIP + PostgreSQL Patroni + Redis Sentinel + 多副本后端挂 Nginx”，但这套方案**未提供 Helm/Operator、未经官方压测验证、升级时需手动滚动**。对“堡垒机挂了全公司运维瘫痪”零容忍的场景，这是必须在架构评审阶段敲定的硬约束。
