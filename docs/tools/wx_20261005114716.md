# PPT 还在用静态图片？bolt-slides 让每页幻灯片跑活数据、渲 3D、嵌入真实产品原型

周末把 **bolt-slides**（`53b55bc`，2025-09 初次开源）拉到本地跑了一遍。关注它的起因很简单：每次做技术分享、融资路演、方案评审，都在 **Figma/Canva/Notion/DeckDeckGo/Slidev** 里纠结——要么模板丑、要么动画卡、要么想放个真实的 API 返回/3D 模型/可跑的代码片段根本塞不进去。StackBlitz 团队（WebContainer 那帮人）换个思路：**幻灯片本身就是一个 React 单页应用，每页是一个组件，想放什么就 `import` 什么、想交互就写 `useState`、想同屏演讲就用 `BroadcastChannel`**。这套“幻灯片即 Web App”的范式转换，正好卡在“想做有交互、有实时数据、有真实产品嵌入的技术演示”的痛点上。

### 部署实录

**环境与依赖清单**

| 项 | 要求 | 实测版本 |
| --- | --- | --- |
| Node.js | ≥18 | 20.17.0 |
| 包管理器 | npm / pnpm / yarn | npm 10.8.2 |
| 浏览器 | Chrome 120+ / Firefox 121+ / Safari 17+ | 需支持 `BroadcastChannel`、`IntersectionObserver`、CSS `:has()` |

**安装与启动（极简）**

```
git clone https://github.com/stackblitz/bolt-slides.git  
cd bolt-slides  
npm install          # 约 45 秒，依赖极少：react、react-dom、vite、typescript、@types/react  
npm run dev          # 起 Vite dev server，默认 http://localhost:5173
```

**无额外配置、无数据库、无后端、无 Docker、无环境变量**。打开页面即看到 **26 页内置演示**，覆盖所有组件、主题、动画、演讲模式、标注、网格视图。

**实测踩坑点**

1. 1. **首屏加载约 1.2 秒**（Vite 冷启动 + React 编译），之后 HMR 热更新 < 100ms。生产构建 `npm run build` 产出 `dist/` 约 420 KB（gzipped 130 KB），**可直接丢 Netlify/Vercel/Cloudflare Pages/GitHub Pages/任何静态托管**。
2. 2. **演讲模式需双标签页** —— 按 `P` 打开 Presenter Mode 新标签，**必须允许弹窗**，否则被拦截。`BroadcastChannel` 同步当前页、备注、计时器，**局域网/跨设备同步需同源**，远程协作需自行加信令服务器。
3. 3. **标注锚定在内容坐标而非屏幕坐标** —— `Annotator` 组件用 `element.getBoundingClientRect()` + 滚动偏移计算相对位置，**响应式缩放、移动端横竖屏切换时笔迹自动跟随目标元素移动**，这是细节做到位的体现。
4. 4. **主题切换仅改 CSS 变量** —— `src/styles/tokens.css` 里 `--primary`、`--radius`、`--font-heading` 等 20+ 变量，**换一套视觉风格只需覆盖 `:root` 块**，技能文档里内置 9 套现成主题（编辑奢华/深色技术/极简学术/高对比度/品牌色等）。
5. 5. **TypeScript 严格模式** —— `tsconfig.json` 开启 `strict: true`、`noUncheckedIndexedAccess`，写自定义 Slide 组件时类型提示全程可用，**不容易写出运行时崩的代码**。

**最小可行验证流**

```
# 1. 起开发服务器  
npm run dev  
  
# 2. 浏览器打开 http://localhost:5173  
#    ←/→ 翻页、S 侧边栏、G 网格视图、A 标注、P 演讲模式、F 全屏  
  
# 3. 删掉演示稿，写自己的  
# src/App.tsx  
import { Deck, Cover, Slide, Build, Agenda, ... } from './deck'  
import './styles/tokens.css'  
  
export default function App() {  
  return (  
    <Deck>  
      <Cover kicker="My Talk" title="Hello bolt-slides" subtitle="Slides that are web apps" />  
      <Slide center nav="Demo">  
        <h2>Live data fetch</h2>  
        <Build at={1}><LiveChart /></Build>  {/* 自己写的组件，fetch 实时数据 */}  
      </Slide>  
    </Deck>  
  )  
}  
  
# 4. 保存 → 浏览器自动刷新 → 立刻看到新演示稿
```

### 核心亮点

**1. “幻灯片即 React 组件”：想放什么、想怎么交互、全由代码决定**

```
// 真实场景：嵌入产品实时仪表盘  
import { Slide, Build } from '../deck'  
import { LineChart } from '../components/data/Charts'  
  
export function MetricsSlide() {  
  const [data, setData] = useState([])  
  useEffect(() => {  
    const ws = new WebSocket('wss://api.myprod.com/metrics')  
    ws.onmessage = e => setData(JSON.parse(e.data))  
    return () => ws.close()  
  }, [])  
  return (  
    <Slide nav="Live Metrics">  
      <h2>Real-time Dashboard</h2>  
      <Build at={1}><LineChart data={data} animated /></Build>  
    </Slide>  
  )  
}
```

**对比传统工具**：

| 能力 | PowerPoint/Keynote | Slidev | **bolt-slides** |
| --- | --- | --- | --- |
| 嵌入实时 WebSocket 数据 | ❌ | ❌ (需 iframe hack) | ✅ 原生 React `useEffect` |
| 嵌入可运行代码片段（Monaco/CodeMirror） | ❌ | ✅ (Shiki 仅高亮) | ✅ `CodeWindow` 组件可编辑、可运行 |
| 嵌入 Three.js/React Three Fiber 3D 场景 | ❌ | ✅ (需 `<ClientOnly>`) | ✅ 直接 `import { Canvas } from '@react-three/fiber'` |
| 演讲者备注双屏同步 | ✅ (原生) | ✅ (需配置) | ✅ `BroadcastChannel` 零配置 |
| 标注内容锚定（缩放不漂移） | ❌ | ❌ | ✅ 原生实现 |
| 作为链接分享（无需导出 PDF） | ❌ | ✅ | ✅ **单链接、响应式、无安装** |

**2. 内置组件库：30+ 现成“乐高积木”，覆盖 90% 技术演示场景**

| 类别 | 组件 | 典型用法 |
| --- | --- | --- |
| **结构** | `Cover``Agenda``Section``Split``Bento``Slide` | 封面、议程、分节、左右分栏、Bento 网格、通用页 |
| **数据** | `Charts` (bar/line/donut) `Table``StatGrid``BigNumber``CountUp``VisualDashboard` | 实时图表、可排序表格、指标卡、数字滚动、仪表盘组合 |
| **叙事** | `Quote``Contrast``Comparison``Timeline``Steps``Chat` | 引言、对比、时间线、步骤、对话气泡 |
| **产品** | `CodeWindow``BrowserFrame``Pricing``Team` | 代码窗口（可编辑/高亮/行号）、浏览器框、定价表、团队卡片 |
| **视觉** | `Globe``TiltCard``SpotlightCard``Marquee``Accordion``Tabs` | 3D 地球、倾斜卡片、聚光灯卡片、跑马灯、手风琴、标签页 |

**所有组件**：

* • **响应式优先**（移动端/平板/桌面/超宽屏均自适应）
* • **支持 `<Build at={n}>` 渐进揭示**（点击/方向键逐步展示，回退可撤销）
* • **支持 `notes` 属性**（演讲模式显示，编辑时持久化到 `localStorage`）
* • **无外部重依赖**（图表用轻量 `uCharts`、3D 用 `three` 按需引入、代码高亮用 `shiki`）

**3. AI Agent 协作：`.bolt/skills/slides/SKILL.md` 把“如何写好演示稿”教给了 AI**

```
# .bolt/skills/slides/SKILL.md 核心片段  
## 设计原则  
- 一页一核心观点，配合 Build 渐进揭示  
- 用 `Cover` 定调，`Agenda` 预设期待，`Section` 分章节  
- 数据类页必须用 `Charts`/`StatGrid`，禁用截图  
- 代码类页必须用 `CodeWindow`，保持可编辑/可复制  
- 视觉留白 ≥ 40%，字号 ≥ 28px，对比度 ≥ 4.5:1  
  
## 组件选择指南  
- 需对比 → `Contrast` / `Comparison`  
- 需讲故事 → `Timeline` / `Steps` / `Chat`  
- 需展示产品 → `CodeWindow` / `BrowserFrame` / `Pricing`  
- 需炫技/品牌 → `Globe` / `TiltCard` / `SpotlightCard`  
  
## 主题配置  
- 修改 `src/styles/tokens.css` `:root` 变量  
- 9 套预设主题：`editorial` `technical` `academic` `high-contrast` `brand` `dark` `light` `minimal` `warm`
```

**实测 AI 协作流**：

1. 1. 在 Bolt.new / Cursor / Claude Code 打开仓库
2. 2. Prompt：`"帮我做一个 10 页融资路演 Deck：我们是做 AI 代码审查的，目标投资人是 Sequoia，风格用 technical 主题，要有实时指标页、架构图页、竞品对比页、团队页、融资问页"`
3. 3. Agent 读取 SKILL.md → 生成 `src/App.tsx` 完整演示稿 → `npm run dev` 即看
4. 4. **二次修改再提一句**：“第 3 页架构图换成 Three.js 3D 拓扑图，数据从 `/api/topology` 取” → Agent 直接改组件、加 `useEffect`、跑通

**这不是“AI 生成 PPT 大纲”，而是“AI 生成可运行的 React 应用”**——差距在于**后者可直接上线、可嵌入真实数据、可二次开发、可版本控制**。

**4. 演讲模式工程化：双标签同步、计时器、备注编辑、下一页预览**

```
// src/deck/PresenterMode.tsx 核心逻辑  
const channel = new BroadcastChannel('bolt-slides-presenter')  
// 观众页：发送 { type: 'NAVIGATE', slide: 7, build: 2 }  
// 演讲页：接收 → 同步渲染、更新计时器、显示下一页缩略图、编辑备注写回 localStorage
```

* • **零服务端、零配置、跨标签/跨设备（同源）同步**
* • **计时器**：开始/暂停/重置、超时变色、震动提醒（`navigator.vibrate`）
* • **备注编辑**：演讲时改备注 → `localStorage` 持久化 → 下次排练自动复原
* • **深度链接**：URL Hash `#7` 直接定位第 7 页，**分享链接直达任意页**

### 避坑与总结

| 优点 | 缺点/局限 |
| --- | --- |
| 幻灯片即 Web App、无限可编程、实时数据/3D/代码全能嵌 | **编写门槛高** ：需会 React/TypeScript/Vite，非前端同学无法直接上手（虽有 AI 协作降维打击） |
| 组件库完善、响应式、主题化、Build 渐进揭示、标注锚定 | **无 WYSIWYG 编辑器** ：不像 Slidev 有 CLI 创建、不像 Canva 有拖拽，**纯代码作者ing**，修改需刷新浏览器 |
| AI Agent 技能内置、一提示词生成完整 Deck、二次修改对话式 | **AI 生成质量依赖上下文长度** ：复杂 Deck（>30 页、多组件组合）超出 Agent 上下文窗口需分步生成、人工拼装 |
| 单链接分享、静态托管零成本、无后端依赖、离线可用（Service Worker 可加） | **演讲模式仅同源同步** ：跨域/远程协作需自建信令（WebRTC/WebSocket 服务器），官方未提供 |
| MIT 许可、商业友好、StackBlitz 维护、WebContainer 生态互补 | **无 PDF 导出** （需自行 `puppeteer` 截图/打印）、**无演讲者视图录制**、**无远程观众链接分享**（需自建） |
| 极轻依赖、冷启动快、构建产物小、TypeScript 严格、无运行时崩溃惊喜 | **动画/过渡效果相对基础** ：无复杂进场/退场/路径动画（如 Framer Motion 级），需自行引入动画库 |

**个人判断**：

* • 如果你是**技术演讲者、Developer Advocate、融资创始人、方案架构师**，需要**展示真实产品、实时数据、可运行代码、3D 可视化、交互式原型**，且**愿意写 React / 让 AI 写 React**——**bolt-slides 是目前唯一把“幻灯片”做成“可交付的 Web 产品”的开源方案**，单链接分享、静态托管、版本控制、CI/CD 集成全免费送。
* • 如果你是**非技术产品经理、销售、市场、HR**，只想**快速出一套好看的静态 PPT**——**别碰这个**，用 Canva/Gamma/Beautiful.ai/Notion Slides，效率高 100 倍。
* • 如果你是**Slidev 用户，想要“演讲模式更稳、标注不漂移、组件更现成、AI 协作更强”**——**bolt-slides 值得迁移**，组件 API 相似度高（`Cover`/`Slide`/`Build`/`notes` 同名），迁移成本约“改 import 路径 + 调整 tokens.css”。
* • 如果你是**想做“在线演示 SaaS”、多用户协作编辑、模板市场、导出 PDF/视频、远程观众同屏**——**bolt-slides 只是内核**，需自建：认证/数据库/实时协作/渲染农场/计费/管理后台，**工程量不小**。
* • **最大局限**：**“代码即幻灯片”对非前端受众的认知门槛**。哪怕有 AI Agent 生成，修改细节（如“第 3 页第 2 个 Build 的字号大 2px”、“把表格第 4 列改成进度条”）仍需读懂生成的 JSX/TSX/TS/CSS 结构。**长期看，若社区能孵化出“可视化编辑器 → 双向同步源码”，才能真正破圈**。目前更适合“技术人给技术人看”的高密度信息场景。
