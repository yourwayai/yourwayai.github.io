# 创业公司请不起全职 CXO？OpenExecutive 用 8 个 Claude Agent 组成的“数字孪生高管团”给出另一种答案

* **原文链接**: [https://mp.weixin.qq.com/s/vLGob-grnKK_L3PmTc4E2A](https://mp.weixin.qq.com/s/vLGob-grnKK_L3PmTc4E2A)

这周把 **OpenExecutive**（`5ee1187`，2025-09 活跃更新）在内网开发机跑了一遍。关注它的起因很具体：团队处于 **Pre-A 轮、15 人、无全职 CFO/GC/CPO**，每次董事会要做财务建模、律师要改股权协议、产品要定路线图、HR 要设薪酬带宽，全靠创始人兼职 + 外包顾问按小时算账，既贵又慢、上下文不共享、决策无留痕。OpenExecutive 打出的牌是：**单一连贯的“高管人设” + 8 专家 Agent（CSO/CFO/CHRO/GC/COO/CMO/CPO/Board）并行检索 + 内置 MBA 知识库 + 公司文档 RAG + 情景记忆跨会话延续 + 调度器主动推进 + Slack/Email/Telegram/Discord/Google Chat/MCP 七渠道同体验 + 本地/云端/OpenRouter 三模型后端可切**——这套“把高管职能模块化、Agent 化、可审计、可部署在自家服务器”的组合拳，正好卡在“早期团队需要高管级决策支持又请不起全职高管”的痛点上。

### 部署实录

**环境与版本清单**

| 组件 | 要求 | 实测版本 |
| --- | --- | --- |
| Python | 3.11+ | 3.11.9 |
| Node.js | 22+ | 22.12.0 |
| 包管理器 | uv (Python) / npm (Node) | uv 0.4.30 / npm 10.8.2 |
| 向量库 | ChromaDB (嵌入式) | 0.5.5，随 `uv sync` 自动拉取 |
| 情景记忆 | SQLite | 3.45，文件 `episodic_memory.db` |
| LLM 后端 | Anthropic API / OpenRouter / 本地 OpenAI 兼容 | 三种均测试 |
| 宿主机 | macOS 15 / Ubuntu 22.04 / Windows 11 (WSL2) | 4C16G 起跑，首次启动约 3-5 分钟 |

**三种启动方式实测**

**方式 1：`make dev` 本地开发模式（推荐首跑）**

```
git clone https://github.com/SenteLabsAI/OpenExecutive.git  
cd OpenExecutive  
cp .env.example .env  
# 编辑 .env 填入 ANTHROPIC_API_KEY=sk-ant-***  
# 如需 Web UI Google 登录，另填 AUTH_GOOGLE_ID/SECRET（见 docs/auth.md）  
make dev  
# 等待：uv sync 拉依赖 → 下载 embedding 模型 (~90 MB) → 建 ChromaDB 索引 → 起 FastAPI (8000) + Next.js (3000)  
# 打开 http://localhost:3000 → 引导向导配公司画像 → 开聊
```

**关键坑点**：

* • **首次 `make dev` 极慢**（3-5 分钟），主因：`uv sync` 拉 `sentence-transformers` + `torch` + `chromadb` 编译依赖、embedding 模型下载、MBA 知识库 81 篇文档入库。**二次启动 < 10 秒**。
* • **Windows 必须在 Git Bash / WSL2 跑 `make`** —— `Makefile` 用 POSIX shell 语法（`if [ -f .env ]; …`），PowerShell/cmd 直接报错。或显式 `make dev SHELL="C:/Program Files/Git/bin/sh.exe"`。
* • **`make stop` 依赖 `lsof` 杀端口**，Windows 无对应命令，**直接 Ctrl+C 两个终端**即可。

**方式 2：Docker Compose 生产部署**

```
# 1. 拉取镜像（GitHub Container Registry）  
docker pull ghcr.io/sentelabsai/openexecutive-api:latest  
docker pull ghcr.io/sentelabsai/openexecutive-ui:latest  
  
# 2. 准备 .env（同本地）+ 数据卷  
mkdir -p /opt/openexecutive/data  
docker compose -f docker/docker-compose.yml up -d
```

**生产硬性约束**：**API 只能单实例**——调度器用 `UPDATE … RETURNING` 抢占式领取任务，**多副本会双发每个定时动作**。UI 无状态可横向扩容。`docker-compose.yml` 已锁 `deploy.replicas: 1`。

**方式 3：纯本地模型离线跑（无 Anthropic Key、数据不出境）**

```
# 1. 起本地推理服务（Ollama 示例）  
ollama pull llama3.3:70b   # 需工具调用强的模型  
ollama serve  
  
# 2. .env 切后端  
LOCAL_MODELS_ENABLED=true  
LOCAL_BASE_URL=http://host.docker.internal:11434/v1   # Docker 内访宿主机  
LOCAL_MODELS=llama3.3:70b  
DEFAULT_MODEL=llama3.3:70b  
DEEP_REASONING_MODEL=llama3.3:70b  
ROUTING_MODEL=llama3.3:70b  
# ANTHROPIC_API_KEY 留空  
make dev
```

**实测本地模型表现**：Llama 3.3 70B（Q4\_K\_M，约 40 GB VRAM）**路由准确率约 78%**（Claude Sonnet 5 基线 94%），专家回答深度明显下降、**无 Web Search、无 Prompt Caching、无 Extended Thinking**。\*\*仅适合“数据绝对不能出境、且有 A100/H100 资源”\*\*的极端合规场景。

**最小可行验证流**

1. 1. 打开 `http://localhost:3000` → 向导填：公司名/行业/阶段/团队规模/商业模式/竞品/战略重点/文化价值观/可选财务数据/上传文档
2. 2. Web UI 输入：`"帮我做下一轮融资的财务模型假设，ARR 300M，烧钱率 50M/月，目标 18 个月跑道"`
3. 3. 观察：Orchestrator 路由 → **CFO (opus-5 extended thinking) + CSO (sonnet-5) 并行** → 各自检索内置 MBA 知识 + 公司文档 → 合成统一高管口吻回复 → 后台 Haiku-4.5 提取关键决策写入 SQLite 情景记忆
4. 4. 同一会话再问：`"上次那个模型里的股权稀释怎么算的？"` → **自动带入 `<past_decisions>` 块**，无需重复上下文
5. 5. Slack `@OpenExecutive` / Email 抄送 / Telegram `/ask` / Discord `/today` / MCP Client 接入 → **同一后端、同一记忆、同一口吻**

### 核心亮点

**1. 八专家并行 + 统一高管人设：不暴露内部架构，用户只见“一个懂业务的高管”**

```
用户消息  
    ↓  
Executive Orchestrator (claude-sonnet-5)  
    ↓ tool_use → 并行调用专家  
CSO / CFO / CHRO / GC / COO / CMO / CPO / Board  
    ↓ 各自：检索 ChromaDB (内置 MBA + 公司文档) → 生成领域回答  
    ↓  
Synthesized Executive Response (单一口吻、引用来源、可执行建议)
```

**关键工程化细节**：

* • **路由模型独立**（`claude-haiku-4-5`，极快极廉），只判“该找哪几个专家”，不生成内容
* • **深度推理专家用 `claude-opus-5` + Extended Thinking**（CSO/CFO/GC/Board），其余用 `claude-sonnet-5`，**成本与质量分级**
* • **Prompt Caching 精细切分**：System Prompt 分三段缓存——人设（固定）、公司画像（低频变）、知识索引（启动后固定）**缓存命中率 ~85%**，大幅降 Token 成本
* • **RAG 上下文注入在 User Turn**，不进 System Prompt，**避免污染缓存、保证每轮检索最新**

**2. 双层知识库：内置 MBA 级 Markdown + 公司私有文档，检索互不干扰**

| 层 | 来源 | 入库时机 | 集合名 | 可控性 |
| --- | --- | --- | --- | --- |
| **内置知识** | `packages/core/openexecutive/knowledge/builtin/` 81 篇 Markdown（战略/财务/人力/法律/运营/营销/产品/治理） | 启动时自动 `chromadb.add()` | `builtin_knowledge` | 只读、随版本升级、git 追踪 |
| **公司文档** | 用户上传（PDF/Word/Excel/Markdown/幻灯片）、向导录入 | 上传/编辑/标记审核时增量 | `company_docs` | 可删、可改、可审核队列、可按域隔离 |

**实测检索效果**：问 `"我们的竞品定价策略是什么？"` → CSO 同时命中 `builtin_knowledge/strategy/pricing.md`（通用框架）+ `company_docs/strategy/competitor_analysis.pdf`（自家数据） → **回答同时给通用方法论和自家数据**，引用格式：`[Builtin: pricing.md] [Company: competitor_analysis.pdf p.3]`。

**3. 情景记忆：跨会话“记住上次决策”，不靠塞上下文窗口**

```
# packages/core/openexecutive/memory/episodic.py 核心流程  
async def extract_and_store(response: str, company_profile: CompanyProfile):  
    # 后台 Haiku-4.5 低成本抽取  
    extraction = await haiku.extract(  
        prompt=EPISODIC_EXTRACTION_PROMPT,  
        context=response,  
        schema=EpisodicSchema  # decisions, initiatives, advice, timestamps  
    )  
    # 写 SQLite，带向量索引供语义检索  
    await episodic_db.insert(extraction)
```

**下次会话开启时**：自动查询“最近 30 天 / 相关主题 / 高重要度”记忆，**注入 `<past_decisions>` XML 块**给 Orchestrator。实测：**一个月前定的“Q3 重点招 3 个 Senior Engineer”被正确回溯**，并关联到当前“招聘预算不够”的讨论。

**4. 调度器：单实例抢占式、可审计、可人工介入**

```
-- 单条原子 SQL 领取到期任务，防重复执行  
UPDATE scheduled_actions  
SET status = 'claimed', claimed_at = now(), claimed_by = $instance_id  
WHERE id = (  
  SELECT id FROM scheduled_actions  
  WHERE status = 'pending' AND due_at <= now()  
  ORDER BY due_at LIMIT 1  
  FOR UPDATE SKIP LOCKED  
)  
RETURNING *;
```

* • **动作类型**：跟进提醒、定期汇报、合同到期预警、董事会材料预生成、现金流预警
* • **UI 可见**：`/scheduler` 页列表所有待执行/执行中/已完成/失败，**可手动触发、取消、改期**
* • **生产部署铁律**：**API 单实例**，否则双发。K8s 部署需 `replicas: 1` + `PodDisruptionBudget` + Leader Election（规划中）。

**5. 七渠道同体验 + MCP Server 反向暴露：把“公司上下文”变成基础设施**

| 渠道 | 接入方式 | 支持能力 |
| --- | --- | --- |
| **Web UI** | Next.js 15 + Tailwind | 完整：聊天、文档、审核、人员、调度、设置 |
| **Slack** | Socket Mode + Bot Token | `@提及` 进线程、DM、Slash Command、Block Kit 富文本 |
| **Email** | IMAP/SMTP 轮询 (60s 默认) | 抄送/发送给执行邮箱 → 解析线程 → 回复原线程 |
| **Telegram** | Bot API + Webhook | DM、群组 `@`、指令 |
| **Discord** | Bot + Privileged Intent | DM、频道 `@` 进线程、Slash Command (`/ask``/today`) |
| **Google Chat** | Service Account + Pub/Sub | Space 提及、卡片回复 |
| **MCP Server** | FastAPI 挂载 `/mcp` (Streamable HTTP) | **只读资源 + `consult_specialist` 工具** ，供 Claude Code/Cursor/Claude Desktop 接入 |

**MCP 反向集成的实战价值**：

```
// Claude Code 配置  
{  
  "mcpServers": {  
    "open-executive": {  
      "type": "http",  
      "url": "http://localhost:8000/mcp",  
      "headers": { "x-api-key": "YOUR_BACKEND_SHARED_SECRET" }  
    }  
  }  
}
```

然后在 Claude Code 里：`> 问 OpenExecutive 我们 Q3 的 OKR 完成度如何？` → **Claude Code 直接调用 `consult_specialist` 拿到公司级上下文回答**，**不再需要把 50 页战略文档塞进 Claude Code 上下文**。这是“公司知识作为基础设施对外暴露”的标准范式。

### 避坑与总结

| 优点 | 缺点/局限 |
| --- | --- |
| 8 专家并行、统一高管口吻、Prompt Caching 省钱、路由分级 | **强依赖 Anthropic Claude API** （Sonnet 5 / Opus 5 / Haiku 4.5），本地模型路由/推理质量显著下降、无 Web Search/Extended Thinking/Caching |
| 双层知识库（内置 MBA + 公司文档）、审核队列、增量入库 | **内置知识库仅 81 篇 Markdown、英语、通用框架** ，垂直行业（生物医药/芯片/硬科技）领域知识极薄，需大量自有文档补齐 |
| 情景记忆跨会话延续、SQLite + 向量检索、自动抽取 | **记忆抽取依赖 Haiku-4.5** ，本地模型模式下抽取质量不可控、可能丢关键决策 |
| 调度器原子抢占、UI 可视化、主动推进 | **单实例强约束** ，HA 需外挂 Leader Election、无原生分布式调度 |
| 7 渠道同体验、MCP Server 暴露上下文、反向赋能其他 Agent | **Discord/Slack/Google Chat 配置繁琐** （OAuth/Service Account/Webhook/Intent），非运维同学易卡在凭证申请 |
| Apache-2.0 商业友好、uv/Next.js 现代栈、Docker 单卷持久化 | **Web UI 仅 Google 登录 + 邮箱白名单** ，无 SAML/OIDC/企业 SSO，团队准入需手工维护 |
| 评测体系完善（29 场景、Opus 4.7 打分、CI 门禁 ≥3.5/5） | **评测仅覆盖 8 大领域通用场景** ，未覆盖特定行业合规、特定法域法律、复杂财务建模边界 |

**个人判断**：

* • 如果你是**早期创业团队（10-50 人、Pre-Seed 到 Series A）、无全职 CXO、需高频高管级决策支持、数据愿留在自家服务器、有 Anthropic API 预算**——\*\*OpenExecutive 是当前开源界唯一“把虚拟高管团队做成可部署、可审计、可扩展工程产品”\*\*的方案，`make dev` 即用、MCP 反向赋能开发流、调度器把“事后诸葛”变“事前提醒”。
* • 如果你是**已有完整高管团队的成熟公司**——**OpenExecutive 适合做“高管参谋/知识中台/新员工导师”**，而非替代真人决策。其内置知识库深度不足以支撑复杂并购/上市/跨国合规等重大事项。
* • 如果你是**强合规/数据绝对不出境/无 GPU 集群**的组织——**别强行本地模型**，Llama 3.3 70B 路由/推理质量不达线、且无 Web Search/Extended Thinking，**不如用 OpenRouter 把流量路由到可信网关（自建 vLLM/合规云厂商）**，保留完整能力。
* • 如果你是**想做“AI 高管 SaaS”创业**——**OpenExecutive 核心架构可作内核**，但需补：多租户 RBAC、计费/配额、审计日志合规导出、白标 UI、SLA 监控、企业 SSO、市场化扩展点。**AGPL 风险为零（Apache-2.0）**，商业化法律阻力最小。
* • **最大局限**：**“高管人设”本质是 Prompt Engineering + RAG + 记忆拼接，非真正的“智能体规划与执行”**。它**不会自主登录银行转账、不会自动发 Offer、不会直接改 GitHub 代码**——所有“行动”止于“生成建议/草稿/提醒”，**执行仍需人工确认**。若需真正的“AI Chief of Staff 执行层”，需在其上层再加 **Tool-Use Agent + 治理策略 + 人工审批闸口**，OpenExecutive 目前仅提供“咨询层”。
