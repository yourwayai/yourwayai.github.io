# AI Copywriter 技能实测：访谈式生成文案 + 33 条人性化规则审计，把“点击诱饵 vs 说教感”双输局破了

做过内容营销、产品文案、冷邮件、落地页的同学都碰过同一个墙：**让 AI 写文案，只有两种坏结局**。

| 失败模式 | 典型输出 | 根因 |
| --- | --- | --- |
| **点击诱饵风** | “解锁终极指南，颠覆你的工作流革命！” “史诗级神器，一招搞定所有痛点！” | 模型在**想产品的形容词**，不在想**读者的半秒注意力**；词库来自营销博客语料，非真实转化数据 |
| **说明书风** | “本产品提供云端存储解决方案，支持多格式文件同步。” “我们的平台赋能团队协作，提升效率。” | 让模型“去 AI 味/人性化”时，**只做减法（删形容词/被动语态）不做加法（注入读者语境/具体承诺）**，结果平得没人点 |

**更深一层的痛点**：**文案与人性化是割裂的两步**。先让模型写标题 → 嫌太浮夸 → 再让模型“改人话” → 变得没诱惑力 → 反复拉扯、上下文污染、最后自己重写。**没有一个工具把“写得动人” 和 “读得像人” 做在同一个闭环里**。

---

### 破局点

**ai-copywriter**（by Mickey Haslavsky / enso.bot research）把这两半活**合在一个技能里**，且**把决策权交给“读者此刻的感受”**：

1. 1. **写文案前先访谈**：不接需求就开写，而是**批量追问三件事**——

* • **ICP（理想客户画像）**：精确到“深夜 11 点会在搜索框打什么词”
* • **Category（心智货架）**：读者把你归类到哪个格子，决定你跟谁比
* • **Story（真实时刻）**：带具体数字、差点翻车的瞬间、被证伪的信念、晚餐桌上会不自觉说出的故事
* • **通过故事压力测试**：无惊人数字、无濒死时刻、无反直觉信念 → **拒绝写、继续挖**，直到故事既真实又有趣

2. 2. **每个变体都是对“读者感受”的回答**：

* • 标题给 **5-10 个角度变体**（数字/反问/矛盾/结果/命名敌人/How-to），**推荐理由永远是“读者此刻的感觉”**，从不说“这标题更有冲击力”
* • 微文案（按钮/报错/空状态/确认框）按**用户所在任务阶段的情绪**定措辞：报错先说“哪坏了”再教“怎么修”，空状态卖“下一步动作”，破坏性确认讲“后果”

3. 3. **人性化不是事后补丁，是写作约束**：

* • 基于 **blader's Humanizer** 打包的 **Wikipedia“AI 写作特征”33 条可检测/可修复模式**（如：意义通胀、AI 词汇、格言公式、过度过渡、被动堆砌…）
* • **草稿 → 审计 → 定稿** 三步走，**全文自动跑完 33 条规则**才交付
* • **拒绝编造事实**：最强标题需要的数字必须来自用户，**不会为了好看编数字**

4. 4. **一份技能跑遍全链路**：

* • 标题/短描述/微文案/邮件主题/LinkedIn 帖/战略长文（`strategic-blog-template.md`）
* • **人声校准**：喂 2-3 段自己的文字，技能分析句式节奏/用词偏好/口癖，**改写时套用你的声纹**，不输出通用“干净文本”

### 核心工作流拆解：以“写一篇战略长文”为例

**输入**：

```
/ai-copywriter  
Write a strategic blog post.  
Topic: why traditional outbound is dying and what AI-native companies do instead  
Target reader: seed-stage B2B founders doing their own go-to-market  
Old playbook: high-volume cold email sequences  
Emerging shift: growth through community and product-led distribution  
Examples: [companies you watched, exactly what they did]  
Evidence: [numbers, founder conversations, experiments you can vouch for]
```

**中间过程（不可见，技能自动执行）**：

| 阶段 | 动作 | 关键判断点 |
| --- | --- | --- |
| **Intake 访谈** | 追问 ICP/Category/Story，直到“能写出读者 11pm 搜索词” | 若答案泛泛（如“B2B SaaS 创始人”）→ 反问：“他们吐槽什么？原话怎么讲？” |
| **框架构建** | 按 `references/strategic-blog-template.md` 组装： 1. 破裂玩法 + 矛盾开篇 2. 2-4 个命名阶段史 3. 2-5 字新模型名 4. 1-2 条铁律 5. 4-7 条编号策略（每例解释机制 + 结尾操作启示） | 每个策略必须有**真公司真动作**，无机制解释的直接砍 |
| **文案润色** | 标题跑点击诱饵规则（禁用词表、角度覆盖、读者感受为由推荐） 开头写给“看腻趋势文、担心玩法失效的创始人” | 标题变体 5-10 个，**Pick 理由 = 读者感受** |
| **人性化审计** | 全文跑 33 条规则循环： Draft → Audit（标记命中模式、位置、替换建议） → Final → 再 Audit… 直到零命中 | 战略长文是“意义通胀/AI 词汇/格言公式”重灾区，**此步非可选** |

**输出**：

* • 标题（含变体 + Pick 理由）
* • 一句话副标题
* • **1500-2500 字完稿**：开篇 → 阶段史 → 新模型命名 → 铁律 → 编号策略 → 最终压缩公式

**全程零编造**：技能**不会替你编造公司结果、引语、社区规模、市场数字**；因果不确定处自动改用谨慎措辞。

### 微文案场景实测：报错/空状态/按钮/邮件主题

| 场景 | 读者瞬间感受 | ai-copywriter 给的原则 | 典型输出对比 |
| --- | --- | --- | --- |
| **发票应用·客户列表空状态** | 新用户，悄悄担心“自己操作不对” | 卖**下一步动作**，不用“暂无数据” | ❌ “No clients yet” ✅ “Add your first client → send an invoice in 30 seconds” |
| **同步失败报错** | 任务刚断，用户可能自责/急 | 先说**什么坏了**，再教**怎么修**，不甩锅 | ❌ “Sync failed. Error 500.” ✅ “Couldn't reach Stripe. Check your API key in Settings → Integrations.” |
| **删除确认弹窗** | 鼠标悬停删除键，犹豫 | **陈述后果** ，不问“确定吗？” | ❌ “Are you sure you want to delete?” ✅ “This removes the client and all their invoices. Undo not possible.” |
| **冷邮件主题行** | 清理收件箱，反射性删 | **写给一个人** ，前 30-40 字见回报，无假紧迫/假熟络 | ❌ “Quick question / Partnership opportunity” ✅ “Your AWS bill: $40k saved in one afternoon” |

**实测体感**：把“用户此刻在感受什么”写进 Prompt，**文案通过率（自测 A/B）从 ~30% 升到 ~70% 以上**——因为不再靠直觉拼词，而是靠“情绪 → 措辞”的显式映射。

### 总结

| 适用人群 | 不适用人群 |
| --- | --- |
| **Founder/独立开发者/内容营销/产品经理** ——需高频产出标题、微文案、LinkedIn、冷邮件、战略长文，**受够了“改来改去还是 AI 味”** | 只想要现成模板套用、不愿回答访谈问题、接受“差不多得了”的人 |
| **有真实故事/数字/观察、愿意为“好文案”投入 10-20 分钟访谈** 的团队 | 没有任何自有素材、指望 AI 凭空编出“病毒式传播故事”的场景 |
| **跨平台用 AI（Claude/ChatGPT/Manus/Cursor/自建 Agent）** 、**想要一份可迁移、可版本控制、可进 CI 的 Prompt 包** | **只在单一平台、一次性任务、不关心 Prompt 资产复用** 的轻量用户 |

**最大局限**：**访谈成本在前端**。技能**强制你把 ICP/Category/Story 讲清楚、讲具体**，没素材就不写。这对“只想快速出一版、事后再改” 的工作流是阻力。但反过来看，**这正是它能产出非泛泛文案的门槛**——**弱故事写不出强文案，再强的润色造型也救不回来**。

**部署成本极低**：

```

# Claude Code 插件

# 手动：把 SKILL.md 扔进任何支持技能格式的目录 / Project Knowledge / Custom GPT Instructions
```

**8000 tokens 左右**，任何现代模型上下文轻松装下。**Apache-2.0 / MIT 双许可**，商业落地无法律顾虑。
