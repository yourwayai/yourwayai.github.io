# 单 Agent 卡上下文、多 Agent 互不通气？agtx 用“共享看板 + 依赖图 + 阶段闸口”给出了工程化答案

这周把 **agtx v1.0.6**（`fc08258`，2025-09 发布）在内网开发机跑了一遍。关注它的起因很具体：团队用 **Claude Code / Codex / Cursor / Gemini CLI** 做过几轮特性开发，痛点三座大山：**单 Agent 上下文窗口易爆、多 Agent 互不通气（各自在各自分支、各自 tmux 窗口、靠人工同步 PR）、任务依赖全靠脑子记/Notion 记/口头传**。

市面方案要么是云端编排（Devin、Factory、SWE-agent 托管版）数据出境、按 token/分钟收费、无法私有化；要么是框架库（LangGraph、AutoGen、CrewAI）要写胶水代码、调试地狱、不自带“可看可摸的看板”。

agtx 打出的牌是：**Rust 单二进制、tmux 专用 server + 多项目 session + 任务窗口、git worktree 物理隔离、Kanban 看板（Backlog→Planning→Running→Review→Done）+ 依赖图自动阻塞下游、10 种插件热插拔、MCP Server 双模式、Orchestrator 实验性自动推进、Oneshot 无人值守全流程、手机扫码看实时终端**——这套“终端原生、黑板架构、可看可摸、可私有化、可插拔规范驱动”的组合拳，正好卡在“想在自家服务器/开发机上跑多 Agent 协作、不想上云、不想写框架代码”的痛点上。

### 部署实录

**环境与版本清单**

| 组件 | 要求 | 实测版本 |
| --- | --- | --- |
| Rust | 1.78+（构建） | 1.80.1 |
| tmux | 3.3+（运行时必须） | 3.4 |
| gh (GitHub CLI) | 可选，用于 PR 操作 | 2.55.0 |
| 宿主机 | Linux / macOS / Windows (WSL2) | Ubuntu 22.04 / macOS 15 / Windows 11 WSL2 |
| 编码 Agent CLI | 至少装一个 | Claude Code、Codex、Cursor、Gemini CLI、OpenCode、Grok、Antigravity、pi、Copilot |

**三种安装方式实测**

**方式 1：官方安装脚本（最快、自动适配平台）**

```
curl -fsSL https://raw.githubusercontent.com/fynnfluegge/agtx/main/install.sh | bash  
# 自动：检测架构 → 下载 GitHub Release 预编译二进制 → 装到 ~/.local/bin/ → 提示加 PATH  
# 约 10 秒完成，二进制约 12 MB（含 serve feature）
```

**方式 2：从源码构建（要最新 main 分支 / 要自定义 feature）**

```
git clone https://github.com/fynnfluegge/agtx.git  
cd agtx  
cargo build --release --features serve   # serve feature 含手机端 Web Server  
cp target/release/agtx ~/.local/bin/  
# 构建约 2-3 分钟（Rust 依赖缓存后 < 30 秒）
```

**方式 3：Docker 沙箱（完全隔离、凭证只读、宿主文件安全）**

```
cd agtx  
./docker/sandbox.sh /path/to/your-project  
# 或在项目目录内  
./docker/sandbox.sh  
# 特性：只挂载目标项目可写、宿主其余只读、~/.claude 凭证只读挂载、非 root 用户（UID/GID 映射宿主）、Docker volume 持久化 agtx 状态、预接受 bypass 权限提示
```

**关键坑点与解法**

1. 1. **tmux 必须先装、且版本 ≥ 3.3** —— agtx 起专用 tmux server `agtx`，旧版 tmux 不支持某些格式化参数，会导致窗口创建失败。`tmux -V` 确认。
2. 2. **首次运行必须在 git 仓库根目录** —— `agtx` 会初始化 `.agtx/`、建 worktree 基础分支（自动检测 `main`/`master`/当前分支）、**项目必须至少有一个 commit**（`git init -b main && git commit --allow-empty -m "init"` 即可）。
3. 3. **`auto_trust = true` 生产慎开** —— 它会自动替 Agent 回答 trust/bypass 提示，**等于给 Agent 无条件执行权限**。建议：本地开发开、CI/共享机器关、Docker 沙箱里开（容器隔离）。
4. 4. **手机端 `W` → `s`（局域网）/ `t`（Tailscale）需二进制含 `serve` feature** —— Release 二进制自带，自行 `cargo build --release`**必须加 `--features serve`**，否则报 "this build has no web server"。
5. 5. **Windows 必须在 WSL2 / Git Bash 跑** —— 原生 PowerShell/cmd 不支持 tmux，也跑不了安装脚本。

**最小可行验证流**

```
# 1. 进项目目录  
cd your-project  
agtx          # 启动 TUI，按 ? 看快捷键  
  
# 2. 创建任务：a 进入创建向导 → 输标题/描述/依赖 → 回车 → 任务落 Backlog  
# 3. 推进任务：选中任务 → 空格/右箭头 → Planning → Running → Review → Done  
#    每阶段切换自动：建 worktree → 起 tmux 窗口 → 启动对应 Agent CLI → 预填任务描述  
# 4. 并行跑多任务：多个 Running 任务 → 各自独立 worktree + tmux 窗口 + Agent 进程  
# 5. 手机看板：W → s（局域网） → 手机扫码 → 安装 PWA → 看板/任务详情/实时终端/虚拟键盘答权限提示  
# 5. Oneshot 无人值守：Terminal 2 跑 `claude` → `/agtx:oneshot Build a CLI todo app in Rust with SQLite storage and tests`  
#    然后离开，TUI/手机看波次规划、任务派发、Review 判定、合入主分支  
# 6. MCP Server：`agtx mcp-serve`（全局）或 `agtx mcp-serve <path>`（项目级） → 给 Claude Code/Cursor 配 MCP
```

全程约 5 分钟从零到“多 Agent 并行跑任务、手机看实时终端、Oneshot 自动跑板”。

### 核心亮点

**1. 黑板架构落地：看板 + 依赖图 + 物理隔离 = 真正的“共享知识库”**

```
┌─────────────────────────────────────────────────────────────┐  
│  CONTROL     orchestrator agent · phase gates · dep graph   │  
└─────────────────────────────┬───────────────────────────────┘  
                              │  
┌─────────────────────────────▼───────────────────────────────┐  
│                       THE BLACKBOARD                        │  
│     backlog  →  planning  →  running  →  review  →  done    │  
│   dependency graph · specs · plans · diffs · reviews        │  
└────▲─────────▲─────────▲─────────▲─────────▲─────────▲──────┘  
     │         │         │         │         │         │  
┌────┴───┐ ┌───┴───┐ ┌───┴───┐ ┌───┴───┐ ┌───┴───┐ ┌───┴───┐  
│ Claude │ │ Codex │ │Gemini │ │Cursor │ │ Grok  │ │  ...  │  
└────────┘ └───────┘ └───────┘ └───────┘ └───────┘ └───────┘  
   KNOWLEDGE SOURCES — one git worktree + tmux window each
```

* • **看板即数据库**：SQLite 存任务、阶段、依赖、制品、审查意见，**单文件、零配置、可备份可迁移**。
* • **依赖图硬阻塞**：Task B `depends_on: [A]` → B 留在 Backlog/Planning，**直到 A 达到 Review 或 Done** → 自动把 A 的 diff/制品/审查摘要注入 B 的上下文（Agent 启动时预填）。
* • **物理隔离**：每任务**独立 git worktree**（`.agtx/worktrees/task-<id>/`）、**独立 tmux 窗口**、**独立 Agent 进程**、**互不可见彼此上下文**，只通过看板交换制品。**无“共享内存竞争”、无“上下文污染”**。

**2. 多 Agent 并行 + 阶段专用 Agent：同一任务不同阶段换不同模型**

```
# ~/.config/agtx/config.toml 或 .agtx/config.toml  
default_agent = "claude"  
  
[agents]  
research = "gemini"      # 搜资料、读文档、竞品分析 → Gemini 2.0 Flash 长上下文、便宜  
planning = "claude"      # 写 Spec、拆任务、架构决策 → Sonnet 5 推理强  
running  = "codex"       # 纯写代码、重构、测试 → Codex / Claude 代码能力强  
review   = "codex"       # 代码审查、找 Bug、建议重构 → Codex 审查视角不同
```

**实测切换体验**：任务从 Planning 推到 Running → agtx **自动关闭 Claude 窗口、在同一 worktree 起 Codex 窗口、把 Spec/Plan 作为上下文注入** → Agent 无缝接力。**无需人工 `git stash`、`tmux kill-pane`、`claude → codex` 切换**。

**3. 插件系统：单 TOML 定义整个 Spec-to-Ship 生命周期，10 种内置即插即用**

| 插件 | 定位 | 核心阶段命令 | 适用场景 |
| --- | --- | --- | --- |
| **void** | 纯 Agent 会话、无技能、无规范 | 无 | 只想要多 Agent 会话管理、完全人工控制 |
| **agtx (默认)** | 内置工作流 + Brainstorm/Sweep/Oneshot 技能 | `/agtx:plan``/agtx:implement``/agtx:review` | 通用开发、技能驱动 |
| **agtx-terse** | Token 极简版、压缩输出 | 同 agtx | 上下文窗口小、省 Token |
| **gsd** | Get Shit Done、结构化规范驱动 | `/gsd:spec``/gsd:plan``/gsd:implement` | 重规范、重交互规划 |
| **spec-kit** | GitHub Spec-Driven、规范即可执行制品 | `/spec:create``/spec:plan``/spec:implement` | 规范先行、文档即代码 |
| **openspec** | 轻量 AI 引导规范框架 | `/openspec:discover``/openspec:define` | 轻量级规范驱动 |
| **bmad** | BMAD Method、AI 敏捷结构化阶段 | `/bmad:plan``/bmad:design``/bmad:build` | 敏捷团队、结构化阶段 |
| **superpowers** | 头脑风暴、计划、TDD、子 Agent 驱动 | `/sp:brainstorm``/sp:plan``/sp:tdd` | 复杂特性、TDD 优先 |
| **oh-my-claudecode** | 37 技能 + 22 专用 Agent 编排 | 丰富技能命令 | Claude Code 深度用户 |
| **agent-skills** | 生产级工程技能覆盖全生命周期 | 各阶段技能命令 | 企业级工程规范 |

**自定义插件仅需一个 `plugin.toml`**：

```
# .agtx/plugins/my-plugin/plugin.toml  
name = "my-plugin"  
version = "1.0.0"  
description = "My custom workflow"  
  
[phases]  
planning = { command = "/my:plan", prompt = "Write a detailed plan...", artifacts = ["SPEC.md"] }  
running  = { command = "/my:impl", prompt = "Implement per SPEC.md", artifacts = ["CHANGES.diff"] }  
review   = { command = "/my:review", prompt = "Review for correctness...", artifacts = ["REVIEW.md"] }  
  
[agent_commands]  
claude = { plan = "/my:plan", implement = "/my:impl", review = "/my:review" }  
codex  = { plan = "$my-plan", implement = "$my-impl", review = "$my-review" }
```

**热插拔**：TUI 按 `P` 切换插件，**运行中任务保持原插件、新任务用新插件**，无需重启。

**4. Oneshot 技能：给目标不给任务单，它自己跑完整看板**

```
/agtx:oneshot Build a CLI todo app in Rust with SQLite storage and tests
```

**内部自动执行**：

1. 1. **波次规划**：生成 4-8 个里程碑脊柱 → 仅为**当前里程碑**拆任务、接依赖
2. 2. **并发 3-6 任务**：依赖就绪即起、依赖未就绪等、`wait_for_board_change` 阻塞而非轮询
3. 3. **解除阻塞**：回答 Agent 的 yes/no 提示、按里程碑计划回答确定性问题、**改变产品的决策升级给人工**（记录在 `oneshot-state.md` 的 Open questions）
4. 4. **判 Review**：小修 `send_to_task` 就地改、大改退回 Running、通过则 `move_to_done_and_merge`
5. 5. **合入冲突自解**：冲突任务留 Review、自带 Agent 跑 `/agtx:merge-conflicts`
6. 6. **下一波规划**：基于**已构建的实际代码**重新规划下一里程碑任务
7. 7. **持久化状态**：`oneshot-state.md` 记录里程碑、看板快照、决策、开放问题，**新会话可接管继续跑**

**实测跑通一个 “Rust CLI + SQLite + 测试” 目标**：约 45 分钟、12 个任务、3 波次、**全程零人工干预、最终合入 main 分支、测试通过**。成本约 $3-5（Claude Code 计费）。

**5. 手机端 Web UI：扫码即得“随身看板 + 实时终端 + 虚拟键盘”**

* • `W` → `s`（局域网 mDNS）或 `t`（Tailscale 尾网）**零配置、零端口映射、配对凭证哈希存储、丢手机即撤销**
* • 页面含：**看板拖拽、任务详情、Git diff 语法高亮、Agent 实时终端流（xterm.js）、虚拟键盘（含 Ctrl/Esc/Tab/方向键）**
* • **实测场景**：Agent 在跑测试卡在权限提示 → 手机震动通知 → 打开 PWA → 看到终端在等 `[y/N]` → 点虚拟键盘 `y` → Agent 继续跑，**人在沙发/会议室/通勤路上都能解除阻塞**。

### 避坑与总结

| 优点 | 缺点/局限 |
| --- | --- |
| 单二进制、零运行时依赖（仅 tmux/gh）、安装极简、Rust 性能稳 | **强依赖 tmux** ：Windows 原生不跑、WSL2 必须、tmux 版本敏感、tmux server 挂了全盘挂（需外挂 systemd/user service 托管） |
| git worktree 物理隔离、无上下文污染、依赖图硬阻塞、制品自动传递 | **Worktree 磁盘占用随任务数线性增长** ：大仓库（>5 GB）跑 10 并发任务 ≈ 50 GB，需监控磁盘或配 `worktree_dir` 挂大盘 |
| 10 种插件热插拔、自定义插件仅写 TOML、Agent 命令自动翻译 | **插件生态仍早期** ：除默认 agtx/void 外，多数插件仅支持 Claude/Codex/Gemini，**Cursor/Copilot/Grok/Antigravity/pi 多为 🟡/❌** |
| Oneshot 无人值守跑完整目标、波次规划、自动判审合入、状态可续跑 | **Oneshot 仅 Claude Code 可用** （需插件 + MCP + auto\_trust），其他 Agent 无对应技能，**成本不可控**（跑大目标易烧 $50+） |
| 手机端 PWA 扫码即用、实时终端、虚拟键盘、Tailscale 远程安全 | **手机端仅“查看+答提示”，无完整 TUI 交互** （不能创建任务、不能拖拽看板、不能切插件），辅助大于主控 |
| MCP Server 双模式（全局/项目级）、Orchestrator 实验性自动推进 | **Orchestrator 实验性、单实例、易卡在复杂冲突/模糊需求** ，生产慎开 O 键，**需人工兜底** |
| Apache-2.0 商业友好、活跃维护（128 commits、17 contributors、27 releases） | **无多用户/权限/审计/SSO/企业管控** ，团队共用靠“共享 Linux 用户 + tmux attach”，非企业级协作模型 |

**个人判断**：

* • 如果你是**独行开发者 / 2-5 人小团队、日常用 Claude Code/Codex/Cursor、想在本地/自建服务器跑“多 Agent 并行、依赖管理、规范驱动、手机随时看进度”**、且**接受 tmux/git worktree 这套“终端原生”范式**——**agtx 是当前开源界工程化最完整、体验最连贯、可定制性最强的选择**，`curl | bash` 即用、插件热插拔、Oneshot 让你体验“目标导向自动化”的尽头。
* • 如果你是**大型团队（>10 人）、需多租户隔离、RBAC、审计日志、合规审批、CI/CD 集成、云端协作**——**agtx 缺乏企业级管控平面**，建议评估 Devin/Factory/SWE-agent 托管版或自建在 agtx 之上（开源可二开、MCP 暴露看板状态）。
* • 如果你是**不想碰 tmux、不想管 worktree、只想要“一个 Agent 帮我写代码”**——**直接用单一 Agent CLI（Claude Code/Codex/Cursor）**，agtx 的复杂度对你是负收益。
* • 如果你是**想做“AI 编程 SaaS / 智能体编排平台”创业**——**agtx 的黑板架构 + MCP Server + 插件系统 + Oneshot 状态机**是极佳内核，**补上：多用户、计费、审计、白标、企业 SSO、云端工作区、插件市场**，比从零写编排层快得多。
* • **最大局限**：**“终端原生”既是核心优势也是硬天花板**。**无 Web 原生 UI、无云端同步、无跨机器 worktree 同步、无浏览器端完整交互**。团队若习惯 “浏览器里看 Jira/GitHub Projects/Linear、在 IDE 里写代码、在 Slack 里讨论”，agtx 的“全在终端里、tmux 里、worktree 里”会有显著认知迁移成本。**长期看，若需破圈，需补：Web 原生看板（读写同步 SQLite）、Language Server Protocol 集成（IDE 插件读任务上下文）、GitHub/GitLab 双向同步（Issue↔Task、PR↔Review）**。目前更适合“终端重度用户、黑板架构信仰者、隐私优先派”。
