# Claude Ads 实测：12 大广告平台统一审计、只读优先、能力门控写入，把“广告运营”变成可证据溯源的工程流程

做过多平台广告投放（Google Ads、Meta Ads、Amazon Ads、TikTok Ads、LinkedIn Ads…）的运营/顾问/代理都碰过同一堆烂账：

| 痛点 | 典型现状 | 后果 |
| --- | --- | --- |
| **数据割裂** | 各平台后台 UI 不同、API 字段不同、导出格式不同、权限模型不同 | 跨平台对比靠手工 Excel、耗时易错、无法自动化 |
| **审计无据** | “这个账号结构有问题”全凭经验口述、无时间戳证据、无置信度标注 | 交接/汇报/合规全靠信任、出事无法溯源 |
| **改动怕手抖** | 直接在后台改预算/出价/定向/创意、无草稿、无对比、无回滚、无审批 | 一手误操作烧光预算、事后无法复现决策链路 |
| **技能不复用** | 每个平台、每个客户、每个顾问都有自己的“检查清单”、无版本、无共享、无标准 | 新人上手慢、质量参差、无法规模化 |
| **平台更新跟不上** | Google Performance Max 新字段、Meta CAPI 变更、TikTok Spark Ads 新规则、Amazon DSP 接口升级 | 审计清单过期、漏检新风险、靠运气不踩坑 |

**核心矛盾**：广告运营是“高频决策、强合规、多平台、大金额”的业务，却缺乏像代码开发那样的“版本控制、代码审查、CI/CD、测试、回滚”工程化基建。

---

### 破局点

**Claude Ads v2.0.2**（`ac21644`，2025-09 发布，9.6k Star，MIT 许可）把**广告运营变成“只读优先、证据支撑、能力门控写入、版本化产物”的技能包**：

1. 1. **统一接口屏蔽平台差异**：12 个平台各有一个 **Skill + Audit Worker + Control Reference + Capability Manifest**，指挥官按统一契约编排，**不关心平台细节**。
2. 2. **只读默认、写入极其受限**：

* • **所有 Adapter 默认只读**（账户读取、报表拉取、结构遍历）
* • **写入需同时满足 8 个门槛**：能力声明启用 + 明确对象 ID + 前后对比 + 所有者批准 + 幂等键 + 审计归档 + 回滚窗口 + 执行前再验证前置条件
* • **无上限 = 无写入**、**永不支持永久删除**

3. 3. **证据评分体系**：每个控制项 `pass/fail/unknown/not_applicable`，**Unknown 不扣健康分、只降覆盖率**；覆盖率 ≥80% 评分、60-79% 临时、<60% 证据不足；平台级失败直接判**整轮部分完成**，不伪装完整。
4. 4. **版本化 JSON 为源真理**：Markdown/HTML/PDF 仅为渲染，**同一 Run Bundle 可渲染多格式、可存档、可 Diff、可喂给下游系统**。
5. 5. **Control Plane 记录产品边界**：Control Plane 目录下**有日期的来源、声明、能力、安全规则、隐私规则、生态决策、发布要求**——**无来源不宣称、无实现不宣称、无审批不变更、无独立验证不发布**。
6. 6. **跨宿主可迁移**：Claude Code 原生插件、`/ads` 命令、**Codex/Gemini/Cursor/Windsurf/Goose 任意支持 Skill 格式的宿主**均可加载同一 `ads/SKILL.md`。

### 核心工作流拆解：以“全平台审计”为例

**输入**：

```
/ads audit all
```

**中间过程（指挥官自动编排）**：

| 阶段 | 动作 | 关键产出 |
| --- | --- | --- |
| **1. Setup 画像** | 若无画像 → `/ads setup` 交互式建立：客户档案、账号映射、KPI 定义、隐私分级、护栏阈值 | `client_profile.yaml` （含平台账号 ID、KPI 目标、隐私标记、预算上限、变更冻结期） |
| **2. 平台路由** | 指挥官读 Capability Manifest → 仅路由到**已实现、有测试、有 Fixture**的平台 Worker | 路由表：`google_ads → google_ads_worker`、`meta_ads → meta_ads_worker`… |
| **3. Worker 并行审计** | 每 Worker： • 读账号结构（Campaign/Ad Group/Ad/Keyword/Asset/Audience） • 跑控制项清单（预算节奏、定向重叠、创意疲劳、转化追踪、政策合规、着陆页体验、否定词覆盖、出价策略匹配度…） • **每项产出：判定 + 证据引用（API 响应片段/截图/时间戳）+ 置信度** | `google_ads_findings.json` 、`meta_ads_findings.json`…（Schema-Valid，含 `control_id`、`status`、`evidence_refs`、`confidence`） |
| **4. 聚合评分** | 指挥官汇总： • 平台健康度 = Pass / (Pass + Fail) • 证据覆盖率 = (Pass + Fail) / (Total - Not\_Applicable) • 组合评分 = 加权平均，**失败平台直接剔除、标记 Partial** | `audit_run_bundle_v2.json` （版本化、含元数据、画像快照、平台发现、聚合评分、覆盖率、Partial 标记） |
| **5. 多格式渲染** | 同一 Bundle → `markdown`（人读）、`html`（分享）、`pdf`（归档/合规） | `audit_report.md` 、`audit_report.html`、`audit_report.pdf` |

### 微操作场景实测：变更草稿 → 审批 → 执行

**场景**：把 Google Ads 某 Campaign 日预算从 改到150。

**旧流程**：进后台 → 找 Campaign → 编辑预算 → 保存 → 祈祷没手滑 → 事后发邮件通知团队。

**Claude Ads 流程**：

```
/ads launch --draft --platform google_ads --operation update_campaign_budget \  
  --campaign_id 123456789 --new_daily_budget 150
```

**系统自动执行**：

1. 1. **能力检查**：`google_ads` Capability Manifest 中是否有 `campaign.budget.update`**且**`enabled: true`、**且** 有测试通过、**且** 有 Fixture
2. 2. **读取当前状态** → 生成 **前后对比**：

   ```
   before:  
     campaign_id: 123456789  
     daily_budget_micros: 100000000  
   after:  
     campaign_id: 123456789  
     daily_budget_micros: 150000000  
   blast_radius: "Single campaign, daily budget +50%, monthly projection +$1,500"
   ```
3. 3. **上限校验**：客户画像中 `monthly_budget_ceiling_usd: 50000` → 预测月支出 50,000 **通过**
4. 4. **生成草稿**：`draft_launch_20250910_143512.json`（含幂等键 `idem_abc123`、审计归档路径、回滚窗口 24h、验证窗口 1h）
5. 5. **人工审批**：在 Web UI / CLI / IM 渠道确认 → **仅此步骤需人工介入**
6. 6. **执行前再验证**：再次读取 Campaign 当前预算，**仍为 $100** → 发起 API 变更 → 轮询确认 → 写入审计日志
7. 7. **产出变更记录**：`change_log_20250910_143512.json`（含前后状态、执行耗时、API 响应、验证结果）

**全程零手工进后台、零口头沟通、全链路可审计、可回滚（24h 内 `/ads rollback <change_id>`）**。

### 总结

| 适用人群 | 不适用人群 |
| --- | --- |
| **代理商/顾问/内部性能团队** ——跑多平台广告、需标准化审计、需安全变更、需可交付报告、愿投入“画像建立+技能学习”前置成本 | \*\*单平台、单账号、低频投放、接受“凭经验改预算”\*\*的轻量用户 |
| **有合规/审计/交接需求** ——需证据留痕、需版本化产物、需变更可追溯 | **没有任何广告账号读取权限、指望 AI 凭空生成审计** 的场景 |
| **跨宿主用 AI（Claude Code/Codex/Gemini/Cursor…）** 、**想要一份可迁移、可版本控制、可进 CI 的 Skill 包** | **只在单一平台、一次性任务、不关心 Skill 资产复用** 的用户 |
| **愿意为“安全”付出“速度”代价** ——每次变更走草稿→审批→再验证，**换来不烧预算、不踩政策、可追责** | \*\*追求“秒级改预算、实时调出价”\*\*的高频算法交易场景 |

**最大局限**：**平台覆盖度与能力深度取决于社区贡献与维护者精力**。目前 12 平台中，**Google Ads / Meta Ads / Amazon Ads 相对完善**，**Reddit/Snapchat/X/Apple/Pinterest/LinkedIn/TikTok/Microsoft 处于“能力声明完整、实现/测试/覆盖率不一”阶段**；新平台（如 TikTok Shop Ads、Retail Media 新玩法）依赖社区提 PR。**没有“官方 SDK 级别的 SLA 保证”**，生产核心账号建议**先跑只读审计、再小范围试写、再全量放开**。

**部署成本极低**：

```
# Claude Code 原生插件（推荐）  
/plugin marketplace add agricidaniel/claude-ads  
/plugin install claude-ads@ai-marketing-hub-claude-ads  
  
# 或本地克隆  
git clone https://github.com/AgriciDaniel/claude-ads.git  
cd claude-ads  
bash install.sh --source=local
```

**Python 3.11/3.12、CPython、Wheel 矩阵、依赖锁文件、Schema 测试、安装/卸载脚本、Playwright/WeasyPrint 可选依赖**——**工程化程度远超普通 Prompt 包**。
