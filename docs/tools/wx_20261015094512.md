# 让AI做SEO审计、广告优化、GA4分析总是泛泛而谈？NotFair用48个专用技能、实时数据源、安全变更闸口给出了工程化答案

上周把 **NotFair Plugin v0.27.5**在 **Claude Code / Codex / Cursor / Gemini CLI** 四个宿主里各跑了一遍。关注它的起因很具体：团队做过几轮 **SEO 审计、Google Ads 优化、GA4 分析、Meta 创意疲劳诊断**，全靠**把各平台后台导出 CSV → 扔给 Claude/ChatGPT → 让它按“最佳实践清单”吐建议**——痛点三座大山：**建议泛泛无据（没实时数据支撑）、改动不敢落地（无草稿/对比/回滚）、技能不复用（每次重写 Prompt、换人重写）**。

市面方案要么是 SaaS 数据上云、按席位收费、无法接入自建 Agent；要么是 Prompt 包无版本、无测试、无安全闸口。NotFair 打出的牌是：**48 个专用 Skill、统一 NotFair MCP、** 只读优先、变更走“能力门控+草稿+审批+幂等+审计+回滚+再验证”八重闸口、MIT 许可、跨宿主无损迁移——这套“把营销运营变成可测试、可审计、可复用、可安全部署的技能工程”的组合拳，正好卡在“想用自建 Agent 做专业营销运营、又要数据不出境、改动可追责”的痛点上。

### 部署实录

**环境与版本清单**

| 宿主 | 安装方式 | 实测版本 | 备注 |
| --- | --- | --- | --- |
| **Claude Code** | 原生插件市场 | 1.0.58 | `/plugin marketplace add nowork-studio/notfair-plugin` → `/plugin install notfair@nowork-studio` |
| **Codex** | CLI + JSON | 0.18.0 | `codex plugin marketplace add nowork-studio/notfair-plugin --json && codex plugin add notfair@nowork-studio --json && codex mcp login NotFair` |
| **Cursor** | 本地目录 / 市场 | 0.45.0 | `git clone ... ~/.cursor/plugins/local/notfair` → 重启 Cursor |
| **Gemini CLI** | 扩展安装 | 0.1.5 | `gemini extensions install https://github.com/nowork-studio/notfair-plugin` → `/mcp auth NotFair` |
| **Kiro** | Powers 面板 | — | 自定义 Power / 注册表安装 |
| **Hermes / 其他** | 手动放 Skill 目录 | — | `INSTALL_FOR_AGENTS.md` 指引 |

**关键坑点与解法**

1. 1. **Claude Code 旧别名冲突** —— v2.0.0 前别名 `agricidaniel-claude-ads`，**必须先删再装**：

   ```
   /plugin marketplace remove agricidaniel-claude-ads  
   /plugin marketplace add nowork-studio/notfair-plugin  
   /plugin install notfair@nowork-studio
   ```
2. 2. **MCP OAuth 必须在宿主侧完成** —— 安装后首次调用实时技能（如 `/notfair:google-ads-audit`）会触发 **NotFair 统一 OAuth 流程**，浏览器弹窗授权 Google/Meta/LinkedIn/X/Reddit/TikTok/GA4/GSC/WordPress/GoHighLevel，**凭证存宿主 OS Keyring（macOS Keychain/Windows Credential Manager/Linux Secret Service），永不落配置文件、永不进环境变量、永不进 Docker**。
3. 3. **Playwright / WeasyPrint 可选依赖** —— 浏览器抓取需 `playwright-core`（自带 browsers.json）、**PDF 渲染需 WeasyPrint + Pango 系统库**，`install.sh` 会预检并提示缺失，**不装不影响核心技能，仅影响“浏览器抓取/PDF 报告”技能**。
4. 4. **Python 3.11/3.12 仅支持 CPython、Wheel 矩阵** —— `install.sh` 用 `pip install --require-hashes --only-binary=:all:` 强制二进制轮子，**非 CPython / 不在矩阵直接报错拦截**，防止源码编译踩坑。
5. 5. **Cursor 本地插件需重启** —— `git clone` 到 `~/.cursor/plugins/local/notfair` 后 **必须重启 Cursor**，热加载不生效。

**最小可行验证流（以 Claude Code 为例）**

```
# 1. 安装插件  
/plugin marketplace add nowork-studio/notfair-plugin  
/plugin install notfair@nowork-studio  
  
# 2. 跑一个只读技能（无需 OAuth）  
/notfair:seo-analysis https://example.com  
# → 自动：抓取站点 + Search Console（若已授权）+ 爬虫数据 → 产出：优先级修复清单 + 证据引用  
  
# 3. 跑一个实时技能（触发 OAuth）  
/notfair:google-ads-audit  
# → 浏览器弹窗授权 Google Ads → 选账号 → 自动：拉账号结构/搜索词/预算/转化/着陆页 → 产出：健康评分 + 证据覆盖率 + 浪费支出清单 + 优化草稿  
  
# 4. 变更草稿（不落地）  
/notfair:google-ads --draft --operation update_campaign_budget --campaign_id 123 --new_budget 200  
# → 产出：变更草稿 JSON（含前后对比、影响半径、幂等键、回滚窗口、上限校验）  
  
# 5. 跨宿主验证：在 Codex 里跑同一技能  
codex plugin marketplace add nowork-studio/notfair-plugin --json  
codex plugin add notfair@nowork-studio --json  
codex mcp login NotFair  
# → `/notfair:meta-ads-creative` 同理产出证据驱动创意简报
```

全程约 10 分钟从零到“多宿主同技能、实时数据、安全变更草稿”，**无需写一行胶水代码、无需配平台 API 密钥、无需搭建数据管道**。

### 核心亮点

**1. 48 个专用 Skill：把“营销大杂烩 Prompt”拆成可测试、可审计、可复用的标准化单元**

| 领域 | Skill 数 | 典型 Skill | 核心契约 |
| --- | --- | --- | --- |
| **SEO** | 19 | `seo-analysis``seo-page``content-writer``keyword-research``schema-markup-generator``seo-drift``backlink-audit` … | 输入：URL/域名/导出文件 → 输出：结构化发现（问题、证据、优先级、修复建议） |
| **GEO/AEO** | 1 | `geo-optimizer` | 输入：内容/URL → 输出：AI 引用优化重写 + 引用潜力评分 |
| **Paid Media 通用** | 8 | `paid-ads-setup``paid-ads-launch``paid-ads-review``paid-ads-optimize``paid-ads-creative` … | 输入：业务画像/账号映射/KPI → 输出：跨渠道计划/周月度记分卡/优化草稿 |
| **Google Ads** | 6 | `google-ads-audit``google-ads``google-ads-copy``google-ads-assets``google-ads-landing` … | 输入：账号 ID/权限 → 输出：健康评分/浪费清单/RSA 合规文案/资源规划/着陆页诊断 |
| **Meta Ads** | 3 | `meta-ads-audit``meta-ads``meta-ads-creative` | 输入：账号 ID/权限 → 输出：追踪健康/结构/创意疲劳/受众/扩量就绪度/创意简报 |
| **其他广告平台** | 5 | `paid-ads-x``paid-ads-linkedin``paid-ads-reddit``paid-ads-tiktok``paid-ads-amazon` | 同模式：审计 → 运营 → 变更草稿 |
| **Analytics** | 2 | `google-analytics``search-console` | 实时查询 GA4/GSC → 对比完整周期 / 检查 URL / 管理站点地图 / 更新配置 |
| **WordPress / CRM** | 2 | `wordpress``gohighlevel` | 读/写连接站点/CRM，**仅执行显式请求的变更** |
| **跨模型复核** | 2 | `gemini``upgrade` | Gemini 二次挑战 / 插件升级摘要 |

**每个 Skill 标配**：

* • `SKILL.md`：职责、输入、决策规则、输出格式、引用文档、脚本路径、评测用例
* • `references/`：平台官方文档、最佳实践、API 规范、合规清单
* • `scripts/`：可复用的 Python/Shell 工具（如 GA4 查询构建器、Schema 验证器）
* • `evals/`：路由/行为评测用例（CI 门禁）

**实测 Skill 调用体感**：`/notfair:seo-analysis example.com` → **不再是“给我建议”，而是“跑一个可验证的审计程序”**——每条发现带 `evidence_refs`（API 响应片段/爬虫快照/时间戳）、`confidence`、`severity`，**产物可直接喂给下游系统/存档/对比**。

**2. 统一 NotFair MCP：一个 OAuth 连 10+ 平台，实时数据源零配置**

| 平台 | OAuth Scope | 读能力 | 写能力（受控） |
| --- | --- | --- | --- |
| **Google Ads** | `adwords` | 账号/推广系列/广告组/关键词/搜索词/预算/转化/着陆页/资源 | 关键词/出价/预算/否定词/推广系列/资源（需能力声明+审批） |
| **Meta Ads** | `ads_management``ads_read` | 账号/推广系列/广告组/广告/创意/受众/像素/转化/预算/投放 | 推广系列/广告组/广告/预算/定向/创意（需能力声明+审批） |
| **GA4** | `analytics.readonly``analytics.edit` | 收购/互动/页面/事件/转化/用户/归因 | 测量配置更新（需能力声明+审批） |
| **Search Console** | `webmasters.readonly``webmasters` | 查询/页面/索引/站点地图/移动端易用性/核心指标 | 站点地图提交/移除（需能力声明+审批） |
| **X Ads / LinkedIn / Reddit / TikTok / WordPress / GoHighLevel** | 各自 OAuth | 读取对应资源 | 显式请求的变更（需能力声明+审批） |

**关键工程化**：

* • **单一 MCP Server（`NotFair`）聚合所有连接**，宿主只需配置一个 `mcp.json`，**凭证隔离在 MCP 层、Agent 进程完全不持有 Token**。
* • **能力声明即代码**：`meta-ads/capability_manifest.json` 列出每个操作的 `enabled`、`tested`、`fixture`，**未显式声明的能力绝不暴露给 Agent**，杜绝“幻觉调用不存在的 API”。
* • **读写分离**：默认只注册**只读 Profile**（如 `google-ads-readonly`），**写入 Profile（如 `google-ads`）需显式切换且通过八重闸口**。

**3. 安全变更八重闸口：把“广告后台手工改”变成“可审计工程变更”**

**实测变更流（Google Ads 日预算 $100 改到 $150）**：

1. 1. **能力检查**：`campaign.budget.update` 在 Manifest 中 `enabled: true`、有测试通过、有 Fixture
2. 2. **前后对比**：`before: 100000000 micros` → `after: 150000000 micros`、`blast_radius: "Single campaign, +50%, monthly +$1,500"`
3. 3. **上限校验**：客户画像 `monthly_budget_ceiling_usd: 50000` → 预测 50,000 **通过**
4. 4. **草稿产出**：`draft_launch_20250910_143512.json`（含 `idem_abc123`、`audit_path`、`rollback_window: 24h`、`verify_window: 1h`）
5. 5. **人工审批**：CLI 确认 `y/N`
6. 6. **再验证**：再次读取 Campaign 预算仍为 $100 → 发起 API → 确认生效
7. 7. **变更记录**：`change_log_20250910_143512.json` 可追溯、**24h 内可 `/notfair:rollback <change_id>`**

**4. 跨宿主无损迁移：同一份 MIT 技能包，在 Claude/Codex/Cursor/Gemini/Kiro 间“开箱即用”**

| 宿主 | 安装命令 | MCP 登录 | 技能调用前缀 | 差异 |
| --- | --- | --- | --- | --- |
| **Claude Code** | `/plugin marketplace add nowork-studio/notfair-plugin && /plugin install notfair@nowork-studio` | 自动 | `/notfair:` | 原生插件、市场分发、版本锁 |
| **Codex** | `codex plugin marketplace add nowork-studio/notfair-plugin --json && codex plugin add notfair@nowork-studio --json` | `codex mcp login NotFair` | `/notfair:` | JSON 输出、工作区级安装 |
| **Cursor** | `git clone ... ~/.cursor/plugins/local/notfair` → 重启 | Cursor 提示 OAuth | `/notfair:` | 本地目录、市场上架后可切远程 |
| **Gemini CLI** | `gemini extensions install https://github.com/nowork-studio/notfair-plugin` | `/mcp auth NotFair` | `@notfair` / 自然语言 | 扩展机制、原生 MCP 客户端 |
| **Kiro** | Powers 面板安装 / 注册表 | Kiro 管理 | 自然语言 | Power 规范、注册表分发 |
| **Hermes / 其他** | 手动放 Skill 目录 | 自行配 MCP | 约定前缀 | 完全手动、最大灵活度 |

**核心设计**：**Skill = 纯文本 `SKILL.md` + 附属文件**，**不绑定任何宿主运行时**，**宿主只需能“加载 Skill 文件 + 连接 MCP Server”**。这才是“可迁移技能”的工程定义——**不是 Prompt 分享，是标准化接口契约**。

### 避坑与总结

| 优点 | 缺点/局限 |
| --- | --- |
| 48 个专用 Skill、职责单一、输入输出契约化、有引用文档/脚本/评测 | **Skill 深度不均** ：Google Ads / Meta Ads / GA4 / GSC 相对完善，**X Ads / LinkedIn / Reddit / TikTok / Amazon / WordPress / GoHighLevel 处于“能力声明完整、实现/测试/覆盖率不一”阶段** |
| 统一 MCP 聚合 10+ 平台 OAuth、凭证隔离在 Keyring、Agent 进程零密钥 | **MCP Server 为单一托管服务** （NotFair 官方运营），**非完全自托管**；企业若要求“MCP 也要自建”，需自行部署同规格网关 |
| 只读优先、变更八重闸口、草稿可审计可回滚、上限硬校验 | **变更延迟高** ：草稿→审批→再验证→执行 → **秒级改预算变分钟级**，不适合高频算法调价场景 |
| MIT 许可、跨宿主无损迁移、版本化发布、CHANGELOG 详尽、社区贡献活跃 | **无图形化 Skill 编辑器/可视化工作流编排** ；新 Skill 需手写 `SKILL.md` + 附属文件，**门槛高于“拖拽式”低代码平台** |
| 实时数据源（GA4/GSC/Ads API）替代“猜最佳实践”、证据引用可溯源 | **数据源受限于平台 API 权限/额率/字段** ；如 Google Ads API v14 以下无 Asset Group 报告 → 对应控制项 `unknown` 降覆盖率 |
| 评测体系（路由/行为/Schema）、CI 门禁、依赖锁、预检安装脚本 | **Windows 原生支持较弱** ：`install.ps1` 存在但 Playwright/WeasyPrint 依赖在 Windows 上易卡环境，**建议 WSL2/Docker** |

**个人判断**：

* • 如果你代理商/顾问/内部增长团队、跑多平台 SEO/广告/分析、需“证据驱动、可审计、可复用、跨宿主”的技能包，NotFair 是当前开源界唯一“把营销运营做成标准化 Agent 技能工程”的方案，`/plugin install` 即用、实时数据、安全变更、MIT 许可。
* • 如果你是单平台、单账号、低频优化、接受“凭经验改”的轻量用户——**直接用平台后台建议/官方优化分/第三方 SaaS 免费版**，NotFair 的“画像建立+OAuth+技能学习”前置成本对你是负收益。
* • 如果你是**企业合规要求“营销数据不出境、MCP 必须自建、变更需四眼审批、审计日志不可篡改”**——**NotFair 核心架构满足大部分**，但 **MCP Server 为官方托管**，需自建同规格网关（参考 `mcp.json`/`server.json` 规范）或与 Nowork 商谈私有化部署。
* • 如果你是**想做“营销 Agent SaaS”创业**——**NotFair 的 Skill 契约 + MCP 聚合 + 安全变更闸口 + 评测体系**是极佳内核，**补上：多租户/计费/白标/企业 SSO/技能市场/可视化编排/分布式回测**，比从零写营销 Agent 快得多。
* • **最大局限**：**“技能覆盖深度”长尾依赖社区贡献**。目前 48 个 Skill 中，**核心 4 平台（Google/Meta/GA4/GSC）约占 60% 功能密度**，其余 6 平台 + WordPress/GoHighLevel **处于“骨架完整、血肉待填”阶段**。生产核心账号建议**分阶段放开**：先跑只读审计 → 再小范围试写草稿 → 再全量放开写入。**没有“官方 SLA 保证”**，风险自担。
