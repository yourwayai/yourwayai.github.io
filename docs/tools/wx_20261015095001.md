# 邮箱还能全跑在Cloudflare边缘节点上？Agentic Inbox用Email Routing+DO+R2+AI Agent重写了自托管邮件的基建范式

上周把 **Agentic Inbox**在自有域名 `mail.example.com` 上部署了一遍。关注它的起因很具体：团队想要一个**完全自托管、数据不出境、可编程、能接 AI Agent** 的邮件系统——现有方案要么是 **Gmail/Outlook**（数据在大厂、API 受限、无法自定义逻辑）、要么是 **Postfix/Dovecot + Roundcube/SOGo**（运维重、需自建服务器、无原生 AI、扩展难）、要么是 **Fastmail/Proton/自建 Mailcow**（半托管、定制受限）。

Cloudflare 打出的牌是：**全跑在 Workers 边缘网络、Email Routing 接收、Durable Objects (SQLite) 存邮件/R2 存附件、Workers AI 跑模型、Cloudflare Access 认证、Hono + React 19 前端、内置 AI Agent（9 工具）、MCP Server 暴露邮箱操作**——这套“零服务器、零运维、边缘原生、AI 原生、可编程”的组合拳，正好卡在“想要一个属于自己的、能写代码控制的、能接 AI 的邮箱”的痛点上。

### 部署实录

**前置条件清单**

| 项 | 要求 | 备注 |
| --- | --- | --- |
| **Cloudflare 账号** | 含已验证域名 | 必须在 Cloudflare 托管 DNS |
| **Email Routing** | 域名级启用 | `Email > Email Routing > Enable` |
| **Email Service** | 启用发送 | `Email > Email Service > Enable` （需验证域名所有权、配 DKIM/SPF/DMARC） |
| **Workers AI** | 启用 | `AI > Workers AI > Enable` （免费额度含 `@cf/moonshotai/kimi-k2.5`） |
| **R2** | 创建桶 | `wrangler r2 bucket create agentic-inbox` |
| **Cloudflare Access** | 生产环境必配 | `Zero Trust > Access > Applications > Add` ，保护 Worker、MCP 端点 |
| **Node.js** | 20+ | 本地开发/部署用 |

**部署步骤实测（约 10 分钟）**

```
# 1. 克隆、装依赖  
git clone https://github.com/cloudflare/agentic-inbox.git  
cd agentic-inbox  
npm install  
  
# 2. 配置 wrangler.jsonc  
# 填入你的域名（DOMAINS）、R2 桶名、Durable Object 绑定名  
# wrangler.jsonc 已预置大部分配置，只需改 domain  
  
# 3. 创建 R2 桶  
wrangler r2 bucket create agentic-inbox  
  
# 4. 本地开发测试  
npm run dev  
# 访问 http://localhost:8788，创建邮箱、收发测试  
  
# 4. 部署到 Cloudflare  
npm run deploy  
# 输出：https://agentic-inbox.<your-subdomain>.workers.dev  
# 或绑定自定义域名：wrangler custom-domain add mail.example.com  
  
# 5. 配置 Cloudflare Access（生产必做）  
# Zero Trust Dashboard > Access > Applications > Add an application > Self-hosted  
# Application domain: mail.example.com  
# Policy: 允许你的邮箱/团队/SSO  
# 部署后 Worker 设置 > Domains & Routes > Enable Cloudflare Access  
# 复制弹窗中的 POLICY_AUD、TEAM_DOMAIN → Worker Settings > Variables and Secrets > 添加为 Secret  
  
# 6. 配置 Email Routing 接收  
# Cloudflare Dashboard > 你的域名 > Email > Email Routing  
# 创建 Catch-all 规则：`*@example.com` → Forward to Worker `agentic-inbox`  
  
# 7. 启用 Email Service 发送  
# Email > Email Service > 你的域名 > Enable  
# 验证 DKIM/SPF/DMARC 记录已由 Cloudflare 自动添加到 DNS  
  
# 8. 创建邮箱  
# 打开 https://mail.example.com → Create mailbox → hello@example.com  
# 即可收发邮件、用 AI Agent 起草回复
```

**关键坑点与解法**

1. 1. **`POLICY_AUD` / `TEAM_DOMAIN` 必须从 Access 弹窗实时获取** —— 文档里的示例值无效，**每次开启/关闭 Access 都会变**，必须按步骤 5 把弹窗里的值存进 Worker Secrets，**否则部署后全员 401/403**。
2. 2. **Email Routing Catch-all 必须指向 Worker** —— 别选 "Send to email address"，**选 "Forward to Worker" 选 `agentic-inbox`**，否则邮件进不来。
3. 3. **Email Service 发送需域名验证通过** —— DKIM/SPF/DMARC 记录未生效前，**Worker `send_email` binding 会报错**，等 DNS 传播（通常 1-5 分钟）。
4. 4. **本地开发 `npm run dev` 不走 Access** —— `wrangler dev` 默认关闭 Access 校验，**生产部署后必须开 Access，否则裸奔在公网**。
5. 5. **MCP Server 同享 Access 保护** — `/mcp` 端点受同一 Access 策略保护，**外部 AI（Claude Code/Cursor）连 MCP 需通过 Access**，或配置 Service Token 绕过（仅限可信自动化）。

**最小可行验证流**

1. 1. 部署完成 → 打开 `https://mail.example.com` → **Create mailbox: `test@example.com`**
2. 2. 从外部邮箱发测试邮件到 `test@example.com` → **几秒内出现在 Inbox**
3. 3. 点开邮件 → 右侧 AI Agent Panel 自动显示 **"Draft Reply"** 按钮 → 点击 → **生成草稿（流式 Markdown、含工具调用可视化）**
4. 4. 审核草稿 → 点 **Send** → 邮件发出 → **Sent 文件夹可查**
5. 5. 试用 AI 工具：`"Search emails from alice about budget"` / `"Draft a follow-up to the last thread"` / `"Summarize this thread"` → **Agent 调用工具、返回结果**
6. 6. 连接 MCP：Claude Desktop 配置 `mcp.json` 指向 `https://mail.example.com/mcp` + Access Service Token → **Claude 直接读邮箱、搜对话、起草回复**

### 核心亮点

**1. 架构：每邮箱一个 Durable Object，原生隔离、自带 SQLite、零运维**

```
┌──────────────┐     ┌──────────────────┐     ┌─────────────────┐  
│   Browser    │────>│  Hono Worker     │────>│  MailboxDO      │  
│  React SPA   │     │  (API + SSR)     │     │  (SQLite + R2)  │  
│  Agent Panel │     │                  │     └─────────────────┘  
└──────┬───────┘     │  /agents/* ──────┼────>┌─────────────────┐  
       │             │                  │     │  EmailAgent DO  │  
       │ WebSocket   │                  │     │  (AIChatAgent)  │  
       └─────────────┤                  │     │  9 email tools  │  
                     │                  │────>│  Workers AI     │  
                     └──────────────────┘     └─────────────────┘
```

* • **MailboxDO（每邮箱一个）**：`Durable Object` 类 `Mailbox`，**自带 SQLite**（`sql` API）、**附件存 R2**（`R2Bucket` binding）、**邮件状态机**（inbox/sent/draft/trash/spam）、**全文搜索**（SQLite FTS5）、**WebSocket 推送新邮件/状态变更**。
* • **EmailAgentDO（每邮箱一个）**：`AIChatAgent` 子类，**持久化聊天历史（SQLite）**、**9 个邮件工具**、**系统提示词可自定义/持久化**。
* • **Hono Worker**：统一入口，**SSR 渲染 React SPA**、**REST API**（`/api/mailboxes/*`）、**Agents SDK 路由**（`/agents/mailbox/:id`、`/agents/email-agent/:id`）、**MCP Server 挂载**（`/mcp`）。

**关键工程化**：

* • **零服务器、零容器、零数据库运维**——Durable Objects 自动迁移、自动扩缩、自动故障转移、**强一致性 SQLite**。
* • **R2 存附件**：`PUT /api/mailboxes/:id/attachments` → 直传 R2，**不经过 Worker 内存、无大小限制（受 R2 限制）**。
* • **Email Routing → Worker**：入站邮件直接触发 Worker `fetch`，**零队列、零延迟、按邮件付费（Email Routing 免费额度充足）**。
* • **Email Service 发送**：Worker `send_email` binding，**DKIM/SPF/DMARC 由 Cloudflare 托管、自动轮换、无需运维**。

**2. 内置 AI Agent：9 个邮件工具、自动起草、人工确认、流式响应**

| 工具 | 功能 | 典型调用 |
| --- | --- | --- |
| `list_emails` | 列邮件（分页、文件夹、查询、时间范围） | "Show me unread emails from last week" |
| `get_email` | 取单封邮件全文（含附件元数据） | "Open the latest email from alice" |
| `search_emails` | 全文搜索（FTS5、支持布尔/短语/通配符） | "Find emails about 'Q3 budget' with attachment" |
| `send_email` | 发邮件（含回复/转发/抄密送、附件、HTML/文本） | "Reply to this email confirming the meeting" |
| `create_draft` | 存草稿 | "Save a draft for the board meeting agenda" |
| `update_draft` | 改草稿 | "Update the draft with the new attachment" |
| `delete_email` | 删邮件（移入 Trash） | "Delete the spam email I just got" |
| `move_email` | 移文件夹（Inbox/Sent/Draft/Trash/Spam/自定义） | "Move this to 'Receipts' folder" |
| `get_thread` | 取完整线程（引用链、内联附件） | "Show me the full conversation with bob" |

**Agent 行为特点**：

* • **自动起草**：新邮件到达 → Agent 自动读取 → **生成草稿存入 Drafts**、**不自动发送**、**UI 显示 "Draft ready" 等待人工审核**。
* • **系统提示词可配置/持久化**：每邮箱可设 `system_prompt`（如 "You are a concise executive assistant. Never invent facts. Always ask before sending."）、**存 SQLite、重启不丢**。
* • **流式 Markdown + 工具调用可视化**：前端 `react-markdown + remark-gfm` 渲染，**工具调用实时展开（参数/结果/耗时）**、**用户可中途打断**。
* • **模型**：`@cf/moonshotai/kimi-k2.5`（Workers AI 免费额度）、**可换任何 Workers AI 支持模型**（`@cf/meta/llama-3.1-8b-instruct` 等）。

**3. MCP Server：把邮箱能力暴露给外部 AI（Claude Code/Cursor/OpenClaw…）**

```
// ~/.config/claude-desktop/claude_desktop_config.json  
{  
  "mcpServers": {  
    "agentic-inbox": {  
      "type": "http",  
      "url": "https://mail.example.com/mcp",  
      "headers": {  
        "Authorization": "Bearer <Access Service Token>"  
      }  
    }  
  }  
}
```

**暴露 Tools（同 Agent 9 工具 + 邮箱管理）**：

* • `list_mailboxes`、`create_mailbox`、`get_mailbox`、`delete_mailbox`
* • `list_emails`、`get_email`、`search_emails`、`send_email`、`create_draft`、`update_draft`、`delete_email`、`move_email`、`get_thread`
* • **参数含 `mailboxId`**，**同一 MCP 连接可操作多邮箱**（受 Access 策略保护，**单一信任边界**）。

**实测 Claude Code 集成**：

```
> 用 agentic-inbox 读取 test@example.com 最新 5 封未读邮件并摘要  
→ Agent 调用 list_emails(mailboxId="test@example.com", folder="inbox", unread_only=true, limit=5)  
→ 返回邮件列表 → Agent 调用 get_email 逐封取全文 → 生成摘要  
→ 全程无需切换界面、邮件数据不出 Cloudflare 边缘
```

**4. 多租户设计：Cloudflare Access = 单一信任边界，无邮箱级 RBAC**

> **文档原话**：“Any user who passes the shared Cloudflare Access policy can access all mailboxes in this app by design. This includes the MCP server at /mcp — external AI tools connected via MCP can operate on any mailbox by passing a mailboxId parameter. There is no per-mailbox authorization; the Cloudflare Access policy is the single trust boundary.”

**含义**：

* • **部署即多租户**：同一个 Worker 实例承载**所有域名下所有邮箱**。
* • **访问控制全靠 Access**：**谁能进 Access，谁就能进所有邮箱、用所有 MCP Tools**。
* • **无邮箱级权限隔离**：**不支持**“用户 A 只能看 `support@`、用户 B 只能看 `sales@`”。
* • **适用场景**：**个人/小团队/单组织内部共享邮箱池**——全员互信、共享收发。
* • **不适用场景**：**多租户 SaaS/代理商托管/严格隔离需求**——需二次开发加邮箱级 ACL 或拆多 Worker 实例。

### 避坑与总结

| 优点 | 缺点/局限 |
| --- | --- |
| 全 Serverless、零服务器、零运维、边缘分发、自动扩缩 | **强绑定 Cloudflare 生态** ：Email Routing/Email Service/Durable Objects/R2/Workers AI/Access **全是 Cloudflare 专有**，迁移极难 |
| Durable Objects 原生隔离、SQLite 强一致、R2 存附件、WebSocket 实时 | **Durable Objects 计费按请求/存储/计算时长** ，大量邮箱/高频收发/大附件成本需预估（免费额度后 百万请求0.15/GB-月存储） |
| 内置 AI Agent、9 工具、自动起草、人工确认、可配提示词、流式渲染 | **模型仅限 Workers AI 目录** （目前 `@cf/moonshotai/kimi-k2.5` 等），**不支持自带模型/外部 API/本地 Ollama**，推理能力受限 |
| MCP Server 暴露全能力、外部 AI 可直驱邮箱、同享 Access 保护 | **无邮箱级权限** 、**Access 策略即全部权限**，不适合多租户/严格隔离场景 |
| React 19 + Hono + Agents SDK 现代栈、TypeScript 严格、开发体验好 | **无原生 IMAP/SMTP/ActiveSync 接口** ，**只能通过 Web UI / API / MCP 访问**，不兼容传统邮件客户端 |
| Apache-2.0 商业友好、Cloudflare 维护、文档完整、部署向导详细 | **无 Webhook/事件流导出** （新邮件/状态变更无法推送到外部系统），**无批量导入/导出**（迁移困难） |
| 单 Worker 承载所有域名/邮箱、配置极简 | **单点故障域** ：Worker 挂了、DO 挂了、R2 挂了、AI 挂了，**全邮箱不可用**，无多区域主动-主动 |

**个人判断**：

* • 如果你是**个人开发者/小团队/初创公司、已在用 Cloudflare 域名/DNS、想要一个"属于自己的、可编程、能接 AI、零运维"的邮箱系统**——**Agentic Inbox 是当前最优雅的答案**，`npm run deploy` 即得生产级邮箱、AI 助手、MCP 接口、边缘分发，成本仅 Workers/DO/R2/AI 按量付费（个人量级基本在免费额度内）。
* • 如果你是**企业邮件系统、需 IMAP/SMTP 兼容、需邮箱级权限隔离、需合规归档/法务保全、需多区域高可用、需迁移历史海量邮件**——**别用这个**，上 Google Workspace / Microsoft 365 / Zoho / 自建 Exchange/Postfix+Dovecot+合规层，Agentic Inbox 的架构不支持这些企业级硬指标。
* • 如果你是**想做"AI 邮件助手 SaaS/多租户托管/代理商白标"创业**——**核心架构可作内核**，但**必须重写：邮箱级 RBAC、IMAP/SMTP 网关、Webhook 事件流、批量导入导出、多区域部署、计费/配额/白标/管理后台**。现有"单一 Access 策略=全权限"模型是硬伤。
* • 如果你是**隐私极客、想完全自托管、不依赖任何云厂商**——**Agentic Inox 反其道而行**：**100% 依赖 Cloudflare**，数据在 Cloudflare 边缘节点（含 R2/DO SQLite），**不在你的服务器上**。真·自托管需自建 Mailcow/iRedMail/Poste.io。
* • **最大局限**：**Cloudflare 供应商锁定 + 无邮箱级隔离 + 无标准协议接口**。这三点构成了"个人/小团队神器、企业/平台/隐私派不可用"的铁三角。若 Cloudflare 有一天调价/下线 Email Routing/改 DO 计费/关 Workers AI 免费额度，整个系统面临重写或弃用。**工程决策时必须把"供应商风险"列入风险登记册**。
