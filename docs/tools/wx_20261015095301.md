上周把 LiveContext CE v0.3.6 拉到内网服务器跑了一遍。简单说，就是想找个能**自己跑、数据不出门、又能让 AI 帮忙写自动化**的工具。

之前我们的自动化是拼出来的：n8n 跑流程、LangChain 自己写 Agent、Retool 做内部工具、Supabase 管数据和权限、Grafana 看监控。五套系统，五套账号，五套监控，数据全在各自孤岛里。Agent 一跑成本失控——啥上下文全塞给大模型，动不动几万 token。改个流程要改三处代码，特别累。

市面上找过，要么是 n8n/Zapier/Make，没原生 Agent，没应用构建器，复杂逻辑还得写代码节点；要么是 LangGraph/AutoGen/CrewAI，纯框架，没可视化，没部署运维，也没业务表单、审批、仪表盘。

LiveContext 打出的牌是：**“聊天 + 工作流 + Agent + 应用”四合一画布**。你在聊天框里发句话，它就在眼前给你造出个能跑的自动化：流程图能看、AI Agent 有预算有审计、还能直接生成个小应用给团队用。不用写代码，不用拼接。

### 怎么装

两种方式，我都试了。

**最简单：一条命令**

```
npx livecontext@latest
```

选个端口（默认 3000），自动拉镜像、起容器、印出地址。配置存在 `./livecontext/.env`，数据在 Docker 卷里。后面管理就用 `npx livecontext@latest status/logs/down/update`。适合本地开发、个人用。

**正经部署：Docker Compose**

```
git clone https://github.com/livecontext-ai/livecontext-ce.git  
cd livecontext-ce  
cp docker/.env.ce.example .env
```

**首启前必须改俩密码**：

```
DB_PASSWORD=***  
MINIO_ROOT_PASSWORD=***
```

加密设置别动，首启会自动生成并持久化。

想要额外功能（要多点内存和盘）：

```
COMPOSE_PROFILES=renderer           # 截图/PDF 渲染  
COMPOSE_PROFILES=browser-agent      # 浏览器 Agent + 网页搜索  
# 都要就写 COMPOSE_PROFILES=renderer,browser-agent
```

然后 `docker compose up -d`，等后端 healthy、前端 up，打开 `http://localhost:3000`。

**首次初始化**：

1. 1. 创建第一个账号（自动成管理员）
2. 2. 进 Settings > AI Providers 接模型：

* • LiveContext Cloud（托管目录、托管账号）
* • 自己带 Key：OpenAI、Anthropic、Gemini、Groq、DeepSeek、OpenRouter、Ollama、Azure、Vertex、Bedrock……只要兼容 OpenAI 格式都行

3. 3. Chat 选模型，发 `"Reply with hello"` 试通没通
4. 4. Settings > Integrations 按需连外部账号（装目录不等于已连账号）

**坑点提前避**：

* • **ARM64 镜像非全版本有**。Apple Silicon/树莓派/云 ARM 实例，先用 `docker buildx imagetools inspect ghcr.io/livecontext-ai/livecontext-ce:v0.3.6` 确认有 `linux/arm64`，没有就别硬跑，模拟极慢。
* • 首启下载几个 GB、初始化库表，**别急着重启**，冷启动 3-8 分钟看网速和盘速。
* • 加密密钥首启自动生成并持久化，**现有安装上千万别改数据库凭证或加密键**，除非你做完整迁移备份，否则历史数据解不开。
* • SMTP 没配前，密码重置、邀请邮件全发不出。`.env` 里填 `SMTP_HOST/PORT/USER/PASS/FROM` 和 `PUBLIC_BASE_URL`。
* • 公网暴露必须 HTTPS + 反代。`.env` 设 `PUBLIC_BASE_URL=https://app.example.com`、`GATEWAY_PUBLIC_URL=https://api.example.com`，**得代理 WebSocket 升级**，单源反代要显式路由 `/api/*` 和 `/ws/*`。
* • 更新：`git pull --ff-only && docker compose pull && docker compose up -d`。**镜像版本锁在 repo 里**，光拉镜像不拉 repo 不会滚大版本。

### 实际怎么用

进 Chat 界面，发句大白话：

> "每天早 9 点抓 CoinGecko 前 50 币价格，算 24h 涨跌幅，涨幅超 10% 发 Slack 到 #alerts，存内置表供仪表盘查"

然后看着它自动干这些：

* • 拆解成：定时触发 → HTTP 请 CoinGecko → 数据转换 → 过滤判断 → Slack 发送 → 表 Upsert
* • 画布上画出工作流图，能拖能改参数
* • 自动建表 Schema（coin、price\_usd、change\_24h、fetched\_at）
* • 生成 Slack 发送节点（得先连 Slack 集成）
* • 生成仪表盘 App（表格 + 筛选 + 实时刷新）

点 "Deploy"，工作流激活，定时器生效。等明早 9 点或手动 "Run Once"，看运行记录、Token 耗用、成功率、Slack 实收、表数据。进 "App" 标签，能看到生成的仪表盘，分享链接、嵌入 iframe、当独立小工具分发。

**全程大概 5 分钟，从零到“有定时抓数、有告警、有表、有仪表盘、可分享”的完整自动化**，零代码、零 SQL、零外部数据库配置。

### 我觉得比较有意思的地方

**1. 真·四合一，不是拼凑**

别的工具要么只有工作流（n8n/Zapier），要么只有 Agent 框架，要么只有应用构建器。LiveContext 把 Chat、Workflow、Agent、App 放同一张画布上，数据模型、权限模型、观测面板全是一套。

你在聊天里说需求 → 设计 Agent 理解意图、拆步骤、选集成、生成 Workflow JSON → 工作流引擎跑（可视化画布、并行分支、循环、信号、人工审批、多触发器） → 跑的时候产出运行记录、Token/耗时/成功率、Agent/工具级指标 → 要用 AI 的节点挂专用 Agent：各自模型、工具、文件、信用预算、审计轨迹 → 产出数据写内置表 → App 构建器直接绑定表/工作流输出做表单、仪表盘、审批屏。

**2. Agent 省钱靠“工作流限制视野”**

传统全能 Agent：整个业务上下文（几万 Token）喂给一个大模型，单次 0.50。

LiveContext 模式：

* • 节点 1 抓数：纯代码，$0
* • 节点 2 转换：纯代码，$0
* • 节点 3 判断：小模型/规则，<100 Token，$0.001
* • 节点 4 发 Slack：纯代码，$0
* • 节点 5 写表：纯代码，$0
* • 仅“理解需求生成工作流”用大模型：一次性投入，复用永久

实测同等任务：

* • LangChain 单 Agent（GPT-4o）：约 次天4.50/月\*\*
* • LiveContext（生成一次 Workflow 约 ，后续纯执行）：0.10/月\*\*
* • 省 97%+，且每步可审计、可重试、改参数不重写代码。

**Agent 约束机制挺细**：

* • 模型隔离：设计用 Opus，执行用 Haiku/本地 Ollama
* • 工具隔离：`allowed_tools: ["http", "slack", "table_write"]`，越权直接拒绝
* • 文件隔离：每 Agent 独立文件存储
* • 信用预算：`credit_budget: 1000`（单位：cent/千 Token），超预算自动熔断、记录审计、不扣主钱包
* • 审计轨迹：每次调用记模型、进出 token、调用工具、耗时、成功与否，**能钻取到原始请求/响应**

**3. 1000+ 集成开箱即用，自定义粘贴 OpenAPI Spec 就行**

启动时自动种子 1000+ 连接器（GitHub/Slack/Notion/Linear/Jira/Salesforce/HubSpot/Stripe/Twilio/SendGrid/PostgreSQL/MySQL/MongoDB/Redis/S3/HTTP/Webhook/GraphQL……），**全离线、无外网依赖、内网环境也能用**。

加自有集成：Settings > Integrations > **粘贴 OpenAPI Spec (JSON/YAML)** → 自动生成节点、参数校验、OAuth/API Key 认证流、错误映射。集成还有版本、变更日志、回滚。

实测：粘贴内部 ERP 的 OpenAPI Spec → 30 秒生成节点 → 工作流里直接用 → **比手写 n8n 节点快 10 倍、类型安全、自动补全**。

**4. 内置表：真不用外挂数据库**

工作流节点/ Agent 工具直接 `Table Read/Write/Delete/Upsert`，UI 里能可视化建表（字段类型、索引、外键、校验），也能工作流节点自动推导建表。类 Excel 网格：筛选、排序、分页、导出 CSV/JSON、全文搜索。表间外键、Join 查询、级联删除/更新。工作区/角色级读写权限，行级安全在规划中。单表/全库导出 Parquet/CSV、定时备份到 MinIO/S3。

币价监控那个工作流，自动建表 `crypto_prices`（coin、price\_usd、change\_24h、fetched\_at、source） → 每次运行 Upsert → App 仪表盘绑定该表 → **实时刷新、可筛选涨幅、可导出**，零 SQL、零迁移脚本、零外部 DB。

**5. App 构建器：工作流直接变可分享的小应用**

节点类型：Form（表单）、Dashboard（仪表盘）、Approval（审批屏）、Custom（自定义 React 组件）。数据绑定直接绑 Table、Workflow 输出、Agent 输出、URL 参数。交互：表单提交 → 触发 Workflow / 调用 Agent / 写 Table；审批通过/拒绝 → 推进 Workflow 信号。分享：生成独立 URL、嵌入 iframe、配置访问权限（公开/工作区/角色/密码）。

币价监控 → 生成 Dashboard App（表格 + 涨幅热力图 + 手动刷新按钮） → 分享链接给运营同事 → **不用登录 LiveContext，直接在浏览器看、可筛选、可导出**。

### 避坑指南

| 优点 | 缺点/局限 |
| --- | --- |
| 四合一、单一数据模型、零拼凑 | **单体 JAR 架构** ：后端全在一个 `monolith-service` JAR，水平扩缩粒度粗、故障域大、热重载弱（改 Java 代码得重建镜像重启） |
| 每 Agent 独立模型/工具/预算/审计、成本可控 | **Java 21 + Spring Boot 3** ：贡献者得懂 Java 生态，前端 TypeScript/Next.js 双栈维护成本高 |
| 1000+ OpenAPI 集成、自定义粘贴 Spec 即生成 | **集成深度不均** ：核心 SaaS 完善，长尾/国内/私有 API 得自维护 Spec、自处理分页/限流/刷新 Token |
| 内置表无需外挂 DB、工作流/Agent 直读写 | **表引擎基于 PostgreSQL、非列式/非 HTAP** ：百万行以上聚合分析慢，大数据量仍需外挂 ClickHouse/Snowflake/BigQuery |
| License 允许免费自托管、内部商用、代理交付 | **许可证非 OSI 标准开源** ：不能作为竞品 SaaS 托管转售，企业法务需确认边界，商业化托管得商谈商业许可 |
| Docker Compose 一键起、npm launcher 零配置 | **ARM64 支持不完整** ，版本间镜像架构矩阵需人工确认，Apple Silicon/云 ARM 可能跑模拟 |
| 组织/工作区/角色 RBAC、审计轨迹、Agent 级指标 | **无原生多区域/高可用/灾备** ：单实例 PostgreSQL/Redis/MinIO，生产核心负载得外挂 Patroni/Sentinel/多 AZ MinIO/跨区域备份 |
| 浏览器 Agent + 网页搜索可选、截图/PDF 渲染器可选 | **可选组件内存/盘占用大** ：`browser-agent` 要额外 2-4 GB、`renderer` 要 1-2 GB，小规格机器慎开 |

### 我个人觉得

* • **中型团队/公司（10-200 人）**，想自建"自动化+AI+内部工具"一体化平台、不想拼凑 n8n+LangChain+Retool+Supabase、要数据完全自托管、Agent 成本可控、业务人员能通过聊天生成自动化 → **LiveContext CE 是目前开源界唯一"四合一画布、开箱即用、工程化完整"的选择**，`npx livecontext@latest` 即得生产级平台。
* • **大型企业（>500 人）**，要多区域高可用、复杂数据治理/血缘/目录、深度集成现有数据栈、严格合规审计/数据血缘 → **单体架构、表引擎、观测体系支撑不了此量级**，建议评估 Temporal/Conductor（工作流）+ LangGraph/AutoGen（Agent）+ 自建 BI/内部工具平台 的组合，或上 n8n Enterprise + 自建 Agent 层。
* • **代理商/顾问/自由职业者**，想为客户交付"自动化+AI"解决方案、收服务费/分成 → **License 1.1 明确允许"为客户部署/托管/维护，每部署服务一客户"**，加入 Partner Program 还能分成，比买 n8n/Zapier/Make 席位转售划算得多。
* • 只要"工作流自动化"、不需要 Agent、不需要 App、不需要内置表 → **n8n Community Edition 更轻、社区更大、节点生态更丰、Go 单二进制部署更简单**，LiveContext 的"四合一"对你是过度设计。
* • 想做"自动化平台 SaaS/白标/多租户"创业 → **核心架构是极佳内核**，补上：多租户隔离、计费/配额/白标/管理后台、多区域部署、列式存储/OLAP、数据血缘/目录、SSO/SCIM/审计日志导出，比从零写快得多。

**最大局限**：**单体架构 + 非标准许可证 + ARM64 支持不全** 三座大山。单体限制了极致扩展与故障隔离；Sustainable Use License 1.1 虽宽松但非 OSI 开源，部分企业法务会卡"非标准许可证"；ARM64 缺口导致 Apple Silicon/云 ARM 实例无法原生跑。选型时必须把这三点列入风险登记册，并有规避预案（如：核心负载跑 AMD64 专用实例、法务预审许可证、核心路径准备拆微服务预案）。
