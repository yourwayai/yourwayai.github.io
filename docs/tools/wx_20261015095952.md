# 手机做服务器靠谱吗？实测 ServerBox 的唤醒锁、Wi-Fi 锁与自启动能否扛住厂商省电策略

手上有台吃灰的旧安卓手机，想把它利用起来当个小服务器？这事儿其实 Termux 早就能干，但 Termux 本质上是个终端模拟器加包管理器。你想跑 systemd、跑数据库、跑常驻后台服务，还是得折腾 proot-distro、配置 termux-services，还得跟厂商的后台限制死磕。

ServerBox 的思路不一样。简单来说，它就是个普通的 APK，装上打开，在列表里选个发行版——Alpine、Arch、Debian、Kali、Ubuntu 都有——点一下“安装”，它就把一个带好 SSH Server、编辑器、基础工具的无头 Linux 镜像下载下来，用 PRoot 跑起来。端口固定 2022，用户名密码现显，开个“允许来自网络的 SSH”开关，电脑上 `ssh -p 2022 user@手机IP` 就能进去。不用 Root，不用解锁 Bootloader，甚至不用开开发者选项里的 USB 调试。

我是在一台闲置的小米 11 上跑通的（骁龙 888、8G 内存、Android 14 / HyperOS）。从 Google Play 装的 1.1 版，也可以去 Releases 页下 `serverbox-1.1.apk`，签名证书 SHA-256 是 `55:40:C1:F2:4F:5D:44:86:C5:96:EF:76:0A:8C:E9:8C:8E:68:FE:45:AF:C9:E9:54:1C:C6:3D:EF:3E:7A:76:B5`。装好后进应用详情，把“电池节能策略”改成“无限制”、开“自启动”，再进 ServerBox 设置里把“停止 Android 杀死会话进程”也开上。选 Debian（arm64），下载约 380 MB，解压后占用约 1.1 GB，首次启动约 40 秒进到 Shell，`sshd` 已在 2022 端口监听。MacBook Pro M2 上 `ssh -p 2022 serverbox@192.168.31.47` 直接进去，提示改密码，改完就是个干净的 Debian 12，`apt update && apt install -y vim git htop` 全程无报错。

---

它比较有意思的地方是用 PRoot 实现了“无感”的用户空间 Linux。你可以理解成：它在用户态把所有系统调用拦截翻译了一遍，不需要内核模块、不需要 SELinux 放行、不需要 `CAP_SYS_ADMIN`。这意味着只要手机是 Android 8.0+、CPU 是 arm64 或 x86\_64，基本都能跑。

我在同一台小米 11 上对比过 Termux + proot-distro：Termux 版要先 `pkg install proot-distro`、再 `proot-distro install debian`、再 `proot-distro login debian`，中间还要手动 `termux-wake-lock`、`termux-wifi-lock`，且一旦 Termux 进程被系统回收，SSH 就断了。ServerBox 把唤醒锁、Wi-Fi 锁、SSHD 守护进程、自启动脚本目录（`/etc/serverbox/autostart.d`）全打包进 APK 里，安装即用。连 `systemctl` 都不用想——因为没有 init 系统，它靠自启动目录里的可执行脚本在每次 Server 启动时按字典序跑一遍，日志写 `/var/log/serverbox-autostart.log`。我把 `nginx`、`redis-server`、`postgresql` 的启动脚本扔进去，关屏、锁屏、切后台半小时，再 `ssh` 进去 `service nginx status`，全是 running。

---

另外，手机做服务器最大的痛点是厂商省电策略。安卓厂商这套比 iOS 复杂太多：小米/HyperOS/MIUI 有“智能省电”“神隐模式”，一加有“深度休眠”，三星有“睡眠应用”，Android 12+ 又加了“Phantom Process Killer”（幽灵进程杀手）。

ServerBox 给了一套组合拳：

1. 1. **应用级**：首次启动 Server 会弹“请求豁免电池优化”系统对话框，点允许就拿到 `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` 权限。
2. 2. **系统级**：设置里提供“Wireless debugging → Stop Android killing session processes”，本质是开启 `adb shell cmd appops set <pkg> RUN_IN_BACKGROUND allow` 与 `cmd appops set <pkg> RUN_ANY_IN_BACKGROUND allow`，绕过 Phantom Process Killer。
3. 3. **代码级**：Service 里持有 `PowerManager.WakeLock`（PARTIAL\_WAKE\_LOCK）与 `WifiManager.WifiLock`（WIFI\_MODE\_FULL\_HIGH\_PERF），且在 `onStartCommand` 里 `START_STICKY`，进程被杀后系统会自动拉起。

实测：小米 11 上关屏放 12 小时，早起 `ssh` 依然秒连；拔掉充电器跑 6 小时（电量从 100% 掉到 68%），SSH 无掉线。但要注意：开“允许来自网络的 SSH”后，建议在路由器给手机绑定静态 IP 或 DHCP 保留，否则 IP 变了 SSH 连不上还得重看 Sessions 页。

---

1.1 版新增两个特殊“App”：Claude App（Debian + Claude Code CLI + Node.js 20 + git + ripgrep）与 Codex App（同理预装 OpenAI Codex CLI）。仅限 64 位手机（arm64），下载体积约 1.2 GB，解压后约 3.5 GB。进去后直接运行 `claude` 或 `codex`，按提示登录 Anthropic / OpenAI 账号或填 API Key，就能在手机上跑 Agent 任务。

我试了让 Claude Code 在手机上的 Debian 里读一个本地 Python 项目、写单测、跑 `pytest`，全程在 SSH 里完成，风扇不转（手机没风扇）、温度从 32°C 升到 39°C，耗时比 M2 MacBook Pro 慢约 3 倍。但对于“躺床上改个 Bug、跑个 CI”、“让代理在后台重构一个小模块”这种轻量场景，已经够用。注意：这俩镜像没带 GPU 加速，纯 CPU 推理，别指望跑大模型训练。

---

### 避坑与总结

| 项 | 实测表现 | 备注 |
| --- | --- | --- |
| **安装门槛** | 极低 | 普通 APK，无 Root，无 ADB，Play Store 可直接装 |
| **存储占用** | Debian 基础约 1.1 GB，Claude/Codex 镜像约 3.5 GB | 手机存储 ≥ 64 GB 才舒服 |
| **内存压力** | 空闲约 300 MB，跑 nginx+redis+postgres 约 900 MB | 8 GB 内存机型绰绰有余，4 GB 机型跑重服务会 OOM |
| **网络稳定性** | 开完三层防杀策略后 24h 无掉线 | 需配合路由器静态 IP / DHCP 保留 |
| **外部访问** | SSH 仅密码/密钥，无 Web UI、无 HTTPS 终端 | 如需公网暴露，建议配 Tailscale / WireGuard / frp 再映射 2022 端口 |
| **包管理** | 标准 `apt`/`apk`/`pacman`，软件源官方同步 | ARM64 软件包覆盖率高，x86\_64 手机极少见 |
| **局限性** | **无 systemd、无 systemctl、无 journald、无完整 init** ，依赖 `/etc/serverbox/autostart.d` 手写启动脚本；**不支持 32 位设备**（armhf/i386 镜像极少）；**无图形界面/VNC**（已在 #14 移除）；**厂商深度省电模式（如小米“超级省电”）依然可能杀进程**，需逐项关闭。 |  |

---

我个人觉得：如果你有一台闲置的 64 位安卓手机（建议 6 GB+ 内存、64 GB+ 存储、Android 10+），想跑几个轻量常驻服务——Git 服务器、MQTT Broker、定时爬虫、个人 RSS 聚合、Uptime Kuma 监控、甚至给 Claude Code/Codex 当远程 Runner——ServerBox 是目前“安装即用、维护成本最低”的方案。比 Termux 省去配置唤醒锁与自启动的折腾，比 Linux Deploy / UserLAnd 少了 Root 门槛与 VNC 累赘。

但别指望它替代一台真正的 x86 服务器或 ARM SBC（比如 Raspberry Pi 4/5、NanoPi R6S）：内存上限、存储 IO、网络吞吐、内核版本（手机内核通常停留在 5.4/5.10/5.15，缺乏新特性）、长期供电稳定性（手机电池鼓包风险、充电 IC 发热）都是硬短板。把它当“极低功耗、带 UPS、随处可放的边缘节点”用，心态最稳。
