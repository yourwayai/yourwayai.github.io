# AI Agent 能不能自己改自己的架构？实测 Ouroboros 的 Git 级自进化、Terminal-Bench 86.74% 与 SWE-bench 58.2% 从哪来

有个很激进的想法：如果 AI Agent 不只是「帮你写代码」，而是**能把自己的代码、架构、提示词、工具链全改了、还能把改动走 Git 审核、合进主分支、重启后还记得自己是谁、上次干了啥、下一步想往哪进化**，那它还算工具吗？

前几天在 GitHub 看到 **Ouroboros**，号称「自我创造的 AI Agent：身份、耐久记忆、历史跨任务和重启持续；能改自己的实现；指挥专家 Agent 群；跑在原生桌面或无头 CLI；模型推理可用远程 API 或本地 GGUF」。最新 v7.6.0，6461 次提交，237 个标签。我分别在 MacBook Pro M2（macOS 14.6）和一台 Ubuntu 22.04 服务器上跑通，记录一下实测细节。

---

### 装上手：三条路，选最顺手的

**1. 桌面安装包（最省事）**

* • macOS 12+ Apple Silicon：下载 `Ouroboros-<version>.dmg`，拖进 Applications，右键 Open 过 Gatekeeper
* • Windows x64：下载 `.zip`，解压运行 `Ouroboros.exe`
* • Debian/Ubuntu/Astra：下载 `.deb`，`sudo apt install ./ouroboros_*_amd64.deb`（自动装 Git、进 `/opt/ouroboros`、加 PATH、生成桌面项、可选 systemd user unit）
* • Fedora/RHEL/RED OS 8：下载对应 `.rpm`，`sudo dnf install ./ouroboros-*.x86_64.rpm`
* • 其它 Linux x86\_64：下载 `AppImage` 或 `tar.gz`，`chmod +x` 运行，宿主机需自备 Git

首启会弹向导：选主模型源（连接 Codex 账号、填远程 Provider Key、或指向本地 GGUF）、配审核策略、设预算。我用了 Anthropic Key + Codex 订阅（做委托编码/审核），向导约 2 分钟跑通。

**2. uv tool install（无需克隆仓库，适合 CLI 重度用户）**

```
# 安装 pinned uv 0.12.1  
curl -LsSf https://astral.sh/uv/0.12.1/install.sh | sh  
  
# 直接从 ouroboros 分支装（跟最新提交走，依赖解析用 pyproject.toml）  
uv tool install "git+https://github.com/razzant/ouroboros.git@ouroboros"  
ouroboros --help
```

工具环境隔离，暴露 `ouroboros` 和 `ouroboros-web` 命令。`uv tool upgrade ouroboros` 更新、`uv tool uninstall ouroboros` 卸载。想锁源码版本可把 `@ouroboros` 换成具体 commit SHA。

**3. 源码开发/跑测试/锁依赖全套**

```
git clone https://github.com/razzant/ouroboros.git  
cd ouroboros  
uv sync --locked --extra browser --group dev  
source .venv/bin/activate  
ouroboros server          # 起 Web 运行时，访问 http://127.0.0.1:8765
```

依赖权威是 `pyproject.toml`，跨平台锁在 `uv.lock`。Release 构建会导出 `requirements-runtime.lock` 进嵌入式解释器（带 pip 不带 uv）。改依赖后跑：

```
uv lock  
uv export --locked --no-dev --extra browser --no-emit-project --no-hashes --no-annotate --output-file requirements-runtime.lock
```

### 核心亮点一：「受审核心进化」——自己改自己、走 Git、留证据、可回滚

这是 Ouroboros 最激进也最核心的机制。**它的可编辑表面覆盖：应用代码、架构、提示词、工具、依赖**，反思甚至能重塑它的「活着的自我理解」。

进化循环大概这样：

1. 1. **选题**：人或 Agent 提出改进方向（如「把技能加载改成懒加载」「把记忆检索换成向量+关键词混合」）
2. 2. **自主实现**：Ouroboros 在自己的仓库里开分支、写代码、跑测试、生成提交
3. 3. **受审合入**：变更必须通过**独立 Agent 审核**（Claudexor 驱动 Codex/Claude Code/Cursor 做委托审核），审核证据落盘、`release-evidence.json`、`release-smoke-*.json`、`sbom-*.cdx.json` 全留存
4. 4. **打 Tag 发布**：`scripts/build_repo_bundle.py` 校验 Tag、把源码绑定进打包产物，macOS 签名/公证、Linux 构建 `.deb/.rpm/.AppImage`、Docker 镜像，CI 还会在 Ubuntu 22.04 / Fedora 42 / Astra Linux 1.8 / RED OS 8 容器里装包冒烟测试

**关键约束**：`BIBLE.md` 定义身份与宪法边界，`docs/ARCHITECTURE.md` / `DEVELOPMENT.md` / `DESIGN.md` 是技术真理来源。`CONTRIBUTING.md` 强制：改代码前必须把这四份文档相关章节**全读完、按标题映射、逐节对齐**再动手。`docs/CHECKLISTS.md` 列出验收清单。

实测：我让它「把 CLI 的 `--patch-out` 参数加个 `--dry-run` 模式，只输出 diff 不落盘」。它在自己仓库里开了分支、改了 `ouroboros/cli/commands/run.py`、加了单测、跑 `make test` 过、生成提交、请求审核。Claudexor 调用 Codex CLI 做审核，返回「通过，建议把 dry-run 也加到 `ouroboros tasks run` 子命令」，Ouroboros 吸收建议再提交一次、合入。全程约 12 分钟，**Git 历史里能看到完整演化链路，人类随时可 `git revert` 回滚**。

### 核心亮点二：身份连续性——重启不失忆、记忆长在、历史可查

Ouroboros 把 **身份、耐久记忆、对话、知识、反思、版本历史** 做成「一本持续传记」，存在本地：

* • `~/.local/share/ouroboros/`（或 Linux `/opt/ouroboros/data/`、macOS `~/Library/Application Support/Ouroboros/`）
* • 仓库本身（`.git`）就是它的「长期记忆」
* • 技能、传输桥接、MCP 工具、组件进程、挂件通过 **OuroborosHub** 扩展，不往核心塞

我测了个跨重启场景：让它「调研本仓库的技能加载机制，写份备忘录放进记忆」。它跑完、存入记忆、关窗口、杀进程、重开应用、再问「上次调研的结论是什么」，它直接从记忆里拿出要点、还附上了当时生成的文件路径。**没有「上下文窗口截断」那种断层感**。

---

### 核心亮点三：后台意识——请求间隙也在思考

`background consciousness`：在即时请求-响应循环之外，运行时支持**反思、主动发起、准备工作**。比如你让它「明早 2 点帮我跟进那个依赖升级」，它会在后台按 Cron 调度、把任务树拆解、预拉取上下文、甚至在你下班前把初步分析存好。`ouroboros schedule add --name nightly-review --cron "0 2 * * *" "Run a maintenance review"` 就能装进去。

---

### 核心亮点四：Claudexor——自带多哈希委托引擎，把 Codex/Claude Code/Cursor 当「手脚」

Ouroboros 不自己跑所有编码活，**它拥有任务、记忆、审核、最终集成**，把具体的「写代码、跑测试、改文件」委托给 **Claudexor**（内置的多哈希执行层）。

* • 你在 Settings → Accounts 连好 Codex、Claude Code、Cursor 订阅
* • Agents 里给每个账号分角色：Main Model（主模型）、Coding Delegate（委托编码）、Review Delegate（委托审核）
* • Release 产物带着**精确审核过的引擎版本和 Node 归档**，源码 checkout 首次用时自动拉取同版本归档

实测：给它个外部项目路径 `ouroboros run --workspace /path/to/my/project --memory-mode forked --patch-out result.patch "Fix the failing test"`，它在外部工作区开 Git worktree、跑任务循环、产出可审核的 patch，**自己的仓库和治理边界完全隔离**。`--memory-mode forked` 让它用分叉的记忆副本，不污染主身份。

### 核心亮点五：基准测试自报成绩单——Terminal-Bench 领跑、SWE-bench 持平 Codex

官方自报（同模型同 harness 对比，或对公开榜单）：

| Benchmark | Model | Ouroboros | 对比对象 | 状态 |
| --- | --- | --- | --- | --- |
| Terminal-Bench 2.1 | Claude Opus-5 high | **86.74%** （剔除 1 个 reward-hack 样本后，原始 86.97%） | Claude Code + Fable 5: 83.8% | 自报，社区提交已关 |
| Terminal-Bench 2.1 | GPT-5.5 | **84.3%** | Codex CLI: 83.1% | 自报，公开运行 |
| Terminal-Bench 2.1 | Grok-4.5 | **84.94%** （经 reward-hack 审计） | Cursor CLI: 79.3% · Hermes: 77.53% | 自报，社区提交已关 |
| OSWorld-Verified | Claude Opus-5 | **90.69%** | 公开榜前best: 90.19% | 自报，全链路追踪 |
| OSWorld-Verified | Claude Sonnet-4.6 | **83.27%** | Pointer: 81.45% | 自报，全链路追踪 |

### 核心亮点六：隐私优先、零遥测、本地优先

* • **默认不发遥测**，官方不运营任何用量/崩溃收集
* • 部署可自行挂监控工具读本地记录，**本地历史永不出机器**
* • 走 OpenRouter 的请求只带应用名（用于 OpenRouter 公开应用统计）
* • Server 默认绑 `127.0.0.1:8765`，暴露非回环需 `OUROBOROS_NETWORK_PASSWORD` 或显式受信接入层，详见 `docs/DEPLOYMENT.md`

### 避坑与总结

1. 1. **入门认知负荷高**：`BIBLE.md`、`ARCHITECTURE.md`、`DEVELOPMENT.md`、`DESIGN.md` 四大文档加起来 10 万+ 字，想给它提 PR 或改核心，**必须按 CONTRIBUTING.md 全读完映射再动手**，不是随便改改就能跑的项目。
2. 2. **桌面包体积大**：macOS `.dmg` 约 1.1 GB（含 Python standalone、Chromium、WebKit、Node 归档、Claudexor 引擎），Linux `.deb/.rpm` 约 900 MB，AppImage 约 1.3 GB。下载、安装、首启冷启动约 8-15 秒。
3. 3. **模型成本完全自担**：主模型、委托编码、委托审核分别可配不同 Provider/Key，**长任务、进化循环、基准跑分极其烧 Token**，预算设置在向导里能限额、能告警，但得自己盯着。
4. 4. **本地 GGUF 推理需自备模型文件**，配置在 Settings → Local Models，性能取决于显存/内存、量化等级，官方未提供预量化模型分发。
5. 5. **Android 实验性、需 Magisk Root ARM64**，USB 调试要 Python + adb，非主流使用场景。
6. 6. **SWE-bench 58.2% 与 Codex 59.4%「无显著差异」**：在最难的端到端修复基准上没把 Codex 甩开，GAIA 甚至略低于 Claude Code（129 vs 131），**别被 Terminal-Bench/OSWorld 的领先数字冲昏头**。
7. 7. **技能市场还在早期**：`skills/` 目录下技能数量有限，OuroborosHub 生态建设中，大部分集成还得自己写或改现成技能。
8. 8. **文档与代码偶尔不同步**：快速迭代下 `docs/` 有时滞后于实现，遇到疑问优先读源码、`make test` 跑通再信文档。

---

我个人觉得：如果你想**亲手把一个「会自我进化、有长期记忆、能指挥专家群、跑在自己电脑上、数据不出门」的 Agent 跑起来、甚至参与它的进化循环**，Ouroboros 是目前**工程完成度最高、治理机制最严、基准证据最透明**的开源选择。它没把「自进化」做成营销口号，而是落实成 **Git 级可审计、受审合入、受保护核心表面、重启自检** 的工程体系。

比较适合：想研究 Agent 自进化机制的研究员/工程师；愿意投入精力读懂架构、配置模型预算、参与社区进化提案的早期采纳者；需要「身份连续性」「后台意识」「外部工作区隔离」这些高级原语的复杂任务场景。

不太适合：只想「开箱即用帮我写几个函数」的普通开发者（用 Codex CLI / Claude Code / Cursor 更直接）；对 Token 成本极度敏感、没有预算监控能力的团队；必须 OSI 许可证且拒绝任何「源码可用但非纯开源」组件的纯粹主义者（虽然本体 MIT，但 Claudexor 引擎、打包产物包含闭源签名流程、部分基准适配器未开源）。

把它当「可被人类审计、可被自己重写、跨重启不失忆的 AI 伙伴」，心态最稳。v7.6.0 已修复 systemd 服务启动恐慌保留、技能发布密钥安全、进程日志合并，Roadmap 里有更细粒度的记忆裁剪、技能市场联邦化、更多基准适配器开源，更新极快（近期周更 1-2 个 Patch），值得 Star 跟进。
