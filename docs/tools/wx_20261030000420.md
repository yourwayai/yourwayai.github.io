# Agent 读不了推特和小红书，该自己逐个装工具，还是交给一层路由？

刷到 Agent-Reach 是因为它的 README 开头就很欠揍：「给你的 AI Agent 一键装上互联网能力」，然后给出了一句让 Agent 自己装自己的话——把 install.md 的链接复制给它就行。我见过太多让 Agent 装自己的项目最后变成让 Agent 拆自己，所以这次先翻了它的边界声明，才决定认真看看。

### 💻 部署实录

它的用法分两层。给 Agent 的一句话是：

```
帮我安装 Agent Reach：https://raw.githubusercontent.com/Panniantong/agent-reach/main/docs/install.md
```

手动装则是这套（install.md 原文）：

```
pipx install https://github.com/Panniantong/agent-reach/archive/main.zip  
agent-reach install --env=auto                # 默认只读：只体检并列出缺失项  
agent-reach install --env=auto --system       # 你明确授权后才真装、真写配置  
agent-reach install --env=auto --dry-run      # 先预览会做什么
```

我在自己 Mac 上实测到第一步就撞了墙：系统 Python 是 3.9.6，而 pyproject 的 requires-python 写的是 `>=3.10`，pip 直接拒绝：

```
ERROR: Package 'agent-reach' requires a different Python: 3.9.6 not in '>=3.10'
```

按文档的 PEP 668 预案换 3.12 venv 重装时，安装动作被我这边的工具链拦下等授权，没有跑完，所以下文所有关于 doctor 输出的内容我都没有真机日志可引用。[此处插入你本地实测的 `agent-reach doctor` 输出截图]

卸载倒是有完整预案：`agent-reach uninstall` 会清掉 `~/.agent-reach/`、各 Agent 的 skill 文件和 mcporter 的 MCP 配置，`--dry-run` 只预览，`--keep-config` 保留 token 重装时用。

### 📌 它是路由层，不是包装层

这个项目的核心思路我比较认同：它不自己读网页，只负责选型、安装、体检、路由。每个平台在 `channels/` 下对应一个文件，里面是一份有序的后端列表——首选挂了就顺位往下。比如推特是 twitter-cli ▸ OpenCLI ▸ bird，B 站是 bili-cli ▸ OpenCLI ▸ 搜索 API，Reddit 只剩 OpenCLI ▸ rdt-cli 两条登录态路线，因为匿名接口早被封了。

换接入方式等于调列表顺序，不是重写代码。README 里给了两个实例：2026 年 6 月 yt-dlp 被 B 站风控封死（412），它切到 bili-cli，用户零操作；2026 年 3 月一批单平台 CLI 集体停更，它换了路由。一个 98k Star 的项目敢把「我们会换代」写进 README 首屏，比承诺「永久可用」诚实。

安装后的交互也对味：Agent 读完它自带的 SKILL.md，直接去调 Jina Reader、gh CLI、yt-dlp 这些上游工具，中间没有包装层。`agent-reach doctor` 会真实探测每个候选后端是不是真能用（不只是看命令存不存在），坏的给修复处方。等于把「每个平台踩一遍坑」的体力活外包了。

设计上还有几处克制值得点名：凭据只落在本机 `~/.agent-reach/config.yaml`，权限 600；install.md 给 Agent 划了硬边界——不准 sudo、不准动 agent 工作目录、不准装清单外的包；推特只接受 Cookie-Editor 手工导出，它不替你登录。对这类天天碰登录态的工具来说，这个姿态少见。

### 📊 避坑与总结

丑话说前面，几件事按严重程度排：

1. 1. **安全扫描报告挂着没人回**。2026-10-12，一个叫 SkillSpector v2.12.0（NVIDIA）的扫描器给它打了 100/100 的 CRITICAL，结论是「DO NOT INSTALL」，命中项包括 cli.py 里的 getattr 反射调用、30 处凭据路径与环境变量访问、transcribe.py 的云元数据端点访问、30 处 shell=True 等。这条 issue（#802）目前 open，零公开回复。要说明的是：这是第三方扫描器的自动判定，不是权威机构的实锤，部分命中项（cookie 提取、curl 上游）大概率是设计使然；但 PE3 和 AST9 这类命中，值得维护者正面回应。我无法证实也无法排除，装不装你自己判断。
2. 2. **doctor 的 ✅ 不等于真能跑**。#811 复现：doctor 报 RSS ok，但 SKILL 让 Agent 跑系统 python3 时直接 `ModuleNotFoundError: feedparser`——体检用的解释器和文档里命令用的解释器不是同一个。同类问题在 #685、#623 已有记录。
3. 3. **仓库还忙着**。截至 2026-10-16，开放 issue 94 个、开放 PR 124 个；版本 1.6 在 release 分支上修 Windows 测试失败和 mypy，正式版没出。
4. 4. **门槛说清楚**：Python ≥3.10；本地电脑不需要代理，只有部署到服务器才需要（约 $1/月，README 口径）；需要 Cookie 的平台（推特、小红书等），README 自己都提醒用小号，封号风险自担。

所以我的判断分场景：如果你在玩 Claude Code、OpenClaw、Cursor 这类 Agent，想让它们隔着登录墙读全网，又不想一个平台一个平台踩坑，它现在是现成的路由层，装上就能用；如果你要进生产环境、对供应链安全零容忍，先把 #802 的回应等出来，或者自己审一遍 channels/ 再说——它开源，审得起。

把它当「Agent 的上网路由层，不是数据管道」用，心态最稳。
