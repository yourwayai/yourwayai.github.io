试 SeeCode 的起因很实际：让模型直接画 SVG 这事我干过，线是歪的、字是叠的、改一处全篇崩。SeeCode 的思路正好反过来——Agent 只写 30 到 150 行 JSON（一种描述「有什么、怎么连、大概摆哪」的轻量数据格式），剩下的布局、走线、字号、动效全交给它的渲染器。我把仓库 clone 下来跑了一圈，先说结论：路子是对的，该挑的刺也不少。

### 💻 部署实录

安装两条路。Claude Code 用户走插件：

```
/plugin marketplace add Aryanutkarsh/seecode  
/plugin install seecode@seecode
```

其他能跑命令行 的 Agent 宿主（Cursor、Codex、Copilot）用 `npx skills add Aryanutkarsh/seecode -g`，Claude.ai 就下载 release 里的 seecode.zip 手动传。

我实测的是 CLI 这条线，因为它的门檻低到离谱——渲染只要 Node，README 写「SVG needs only Node」，我本机 Node v22.22.2，clone 下来直接跑：

```
$ node skills/seecode/scripts/seecode.mjs doctor  
{"ok":true,"version":"0.6.1","checks":{"node":"ok","render":"ok (no dependencies)",  
 "encoders":"ok (bundled)","browser":"ok (Google Chrome)",  
 "static":"ok (png, jpeg, webp, svg)","gif":"ok","mp4":"ok (Chrome H.264)"}}
```

拿官方的架构 spec 真渲染了一次：

```
$ time node skills/seecode/scripts/seecode.mjs render examples/specs/systems/architecture.json --out out.html  
{"ok":true,"out":".../out-architecture.html","type":"architecture",  
 "nodes":7,"edges":6,"motion":"trace","steps":9}  
real  0m0.088s
```

7 个节点 6 条边的架构图，88 毫秒。接着导出：

```
$ node skills/seecode/scripts/seecode.mjs export out-architecture.html --formats svg,png  
{"ok":true,"files":[{"format":"svg","path":".../out-architecture.svg","bytes":338409},  
 {"format":"png","path":".../out-architecture.png","bytes":131658,  
  "width":2661,"height":1611,"scale":2.286}]}
```

SVG 文件头我看了，字体是内嵌的 `data:font/woff2`（base64 直接焊进文件），不是引用外部 CSS——这条对要扔进 PDF 或 Word 的人很关键。总之这条链是真的能跑，不是 PPT 开源。

### 📌 它把「画图」拆成了两半

对我来说它最 interesting 的设计是分工：模型负责说「有什么」，渲染器负责「摆得好看」。README 的原话是模型从不写 SVG，每个命令只输出一行 JSON，出错返回 `E_`/`W_` 短码加一句修复提示，Agent 打补丁重渲染，全程不用读生成的 HTML。

我试了个反例验证这句：故意给个只有数据没重点的 bar spec：

```
$ node skills/seecode/scripts/seecode.mjs validate bad.json  
{"ok":true,"type":"bar","motion":"reveal","steps":1,  
 "problems":[{"code":"I_NO_FOCAL","msg":"no focal bar",  
 "fix":"set \"focal\":\"<label>\" to put the accent on the bar that carries the point"}]}
```

错误带修复提示是真的。也就是说 Agent 画砸了不会越描越黑，它收到的是「这里缺 focal，加上」这种可执行指令。作者自己的示例是写 spec 约 1.4k token，模型直接写 SVG 约 15k——这是作者的账，我没有复测，但按我上面这套流程的量级看，方向不假。

导入这条线也顺手：写了三行 mermaid 丢给 import，它吐回一份 draft spec 和一句「源文件没坐标，节点自动摆的，用 --patch 调 row/col」。等于存量图纸不用重画，反过来被它重排版。

### 📊 避坑与总结

该挑的刺：

1. 1. **联网是硬依赖，而且用户有意见**。我 grep 了产物 HTML，外部请求就两类：Google Fonts（Fraunces、IBM Plex Sans/Mono）和 jsDelivr 上的三个 GIF/MP4 编码器。仓库仅有的 2 个 open issue 全部在要一个「跳过 Google Fonts」的开关（#3、#4，其中 #4 已有 PR），说明离线场景或内网部署现在会别扭。SVG 导出内嵌了字体没错，但默认 HTML 不行。
2. 2. **年龄比 Star 数看起来小**。仓库 2026-10-02 创建，两周内在 companion 仓库发了 v0.5.2、v0.6.0、v0.6.1 三个版本，509 Star、23 Fork。迭代快是好事，但 API 兼容性还没经过市场摔打。
3. 3. **交互是重头戏，但我只验了一半**。hover 追踪、路线漫游、分步演示这些 README 说得活灵活现，我实测确认了产物里控件都在（25 个按钮、导出菜单、画布把手都在），但动效细节没录屏验证，按下不表。
4. 4. **水印默认带**。右下角有个 SeeCode 小标记，说一句可以去掉，但默认不是无痕的。

我的判断：如果你受够了让 Agent 画图——字叠字、线乱飞、改一处崩全篇——它的 spec 分工 + 补丁式修复是当下少见靠谱的路子，装上就能用。如果你要的是纯离线、零外网的图表工具，等 #4 合了再说。把它当「Agent 画图的中间层，不是又一张图画笔」用，心态最稳。
