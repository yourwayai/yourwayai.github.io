# 2.5k Star的浏览器鼠标面板：OpenMouse 用 WebHID 免驱动改 DPI 和回报率

给鼠标改 DPI 这事，现在的默认解法是每家的驱动软件装一套：罗技 G HUB、雷蛇雷云、ROG Armoury，一个都跑不掉。OpenMouse 的思路是反的——浏览器里打开网页、插上鼠标、直接改。它能这么做靠的是 WebHID（Chrome 提供的网页直连 HID 设备的接口），不用装任何驱动。我用一个下午把仓库拉下来跑了测试和构建，这篇说实测结果和它的真问题。

### 💻 部署实录

它的开发链路是三件套，我全跑了：

```
git clone --depth 1 https://github.com/OpenMouse-Project/openmouse.git  
npm install        # 实测：20 个包，3 秒  
npm test           # 实测：394 个用例，全过，986 ms  
npm run build      # 实测：tsc --noEmit 通过，vite 构建 1.54s
```

测试输出末尾是这样：

```
# tests 394  
# pass 394  
# fail 0  
# duration_ms 986.018833
```

构建的产物信息也拿到了：

```
dist/assets/main-Dpj705Dy.js   1,792.74 kB │ gzip: 476.04 kB  
✓ built in 1.54s
```

主力 chunk 1.79 MB、gzip 后 476 kB，Vite 自己都弹了超 500 kB 的警告——这个数字下文还会回来找它麻烦。

跑是能跑，但我没有可用的受支持鼠标，也没启动 vite preview 看界面（起本地服务那步你 confirm 说跳过），所以配对、改 DPI 这些真机操作本文不做任何断言。项目自己也把真机门槛写在明处：只支持 Chromium 系浏览器，Firefox 直接出局（issue #777 原话是「unable to get working on firefox, edge, and desktop app」）。

### 📌 分层分得挺清楚

这个项目有意思的地方是 Repository 切法：控制面板（openmouse）只做 UI 和编排，真正收发 HID 报文的编解码和驱动全在独立的 `@openmouse/protocol` 库里，Windows/Linux 上的后台服务 OpenMouse-Bridge 用 Rust 另写一份。加一个新鼠标不用动控制面板——README 说得很直白，只有驱动带来全新的 UI 能力时才需要改这边，其他时候驱动注册表一加，界面自动认。

我数了一下协议库的家底：入口表列了 41 个品牌族（罗技、雷蛇、Endgame Gear、Glorious、VGN、WLMouse、MCHOSE、ATK、Keychron 这些都在），src 下 48 个厂商目录、106 个驱动文件。但它自己也给了退路——README 原话：「导出一个协议只代表实现了这个报文格式，不代表该品牌每个型号都支持」。这句话比多数类似项目老实。

Bridge 那条线也值得一提：设置页只对比 Bridge 版本和最新 release，只取版本号、更新日志和下载链接，绝不后台偷偷更新；能连上 Bridge 时，控制面板优先走它的本地原生 HID 通道而不是浏览器 WebHID——README 说这样能在 Chrome 153+ 收紧受保护接口之后继续用雷蛇那类界面。日常日志带 `[OpenMouse Bridge]` 前缀，可下载的诊断报告里不含 HID 报文原文。

### 📊 避坑与总结

问题按实际影响排：

1. 1. **26 个 open issue 里， aggravating 的都是硬件相关**。#253 是「Razer DeathAdder V2 Pro 昨天还能用，今天不行」这种回归；#301 Glorious Model O 检测不到；#516 罗技设备如果没先跑过 G HUB 就不显示配置文件；#166 巴塞利斯蛇 V3 认错接口。开源外设工具的宿命：没硬件就复现不了，而这些 issue 全都挂着。
2. 2. **「1.0」还没定义**。#142 的标题就是「Define what "1.0 beta" actually means for this app」，#141 是「恢复 1.0 推送前的 CHANGELOG 维护」。版本号 2.0.0 挂着，但成熟度的度量衡还没立。
3. 3. **AGPL-3.0 不是 MIT**。自己用没问题，但如果你想基于它做个对外提供服务的网页版，AGPL 的网络条款要求你把改动开源，心理准备要先有。
4. 4. **体积和兼容的老账**：主包 476 kB gzip（#140 要求拆分）；Linux 上还得手动加 udev 规则（README 给了 VXE R1 SE+ 双接收器的示例，3554:f58f/f58e 两个 ID 都要放行）；设备图存在 Cloudflare R2，还出过一次众包上传把正式图覆盖成狗照片的事故，现在靠 LOCAL\_OVERRIDES 兜底。

我的判断：如果你的鼠标正好在它支持的清单里、你又是 Chrome/Edge 用户，它比装三套驱动清爽，值得常驻浏览器书签；如果你 mix 多品牌外设 + 要 Mac 上开箱即用 + 不能接受 AGPL，它现在替代不了全家桶。把它当「WebHID 外设面板的开源样板，不是成熟驱动管家」用，心态最稳。
