# 28 Star 的直播字幕工具：StreamLingo 用本地 Whisper 加 Ollama 做实时英中互译

看直播最烦的事，是内容刚好卡在语言上：一场英文产品发布，没有中文字幕，走神三秒就跟丢主线。StreamLingo 要做的事很直接——抓 YouTube 直播标签页的声音，本地 Whisper 识别，本地 Ollama 翻译，字幕直接显示在播放器里，音频全程不用动。我在自己 Mac 上把能验的部分都验了，先把边界说清楚：这是 Windows/NVIDIA 项目，我这边没有它要求的硬件，语音链路我跑不了。

### 💻 部署实录

README 的安装路径是为 Windows 写的：下载预览 ZIP（release 带 SHA-256），双击 Setup-StreamLingo.cmd，它让你选一个已装的 Ollama 模型、准备 Python 环境、下载多语 Whisper base 模型，需要时构建扩展；日常启动就是双击 Start-StreamLingo.cmd，扩展在 chrome://extensions 里 Load unpacked 加载 dist/extension。首次 setup 连锅端要 5 分 19 秒，这是 validation.md 里记录的真实安装耗时。

门槛写在明处，不含糊：Chrome 116+，Ollama 带一个本地文本模型，Python 3.11–3.13，NVIDIA GPU 且 CUDA 12.x 带 cuBLAS、cuDNN 9.x，官方验证组合是 CUDA 12.4.1 + cuDNN 9.3。没有 CPU 降级路线——缺运行库直接报错退出。

我能跑的是与模型无关的部分。本机 macOS，shallow clone 后：

```
npm ci && npm run check  
# tests 90 / pass 90 / fail 0  
# Development extension built: .../dist/extension
```

后端按 README 的无模型路径建 venv 装 test 依赖跑 pytest：

```
python -m pytest backend/tests -q  
# 161 passed, 1 skipped, 1 warning in 1.79s
```

这两个数字不是巧合——validation.md 里作者自己记的就是「前端 90 项、[test] 环境 161 通过 1 跳过（需可选语音依赖的上游契约测试，完整环境 162）」。我这边一字不差地对上了，说明仓库文档和代码是同步的，没有虚报测试数。至于真机效果，我这边无卡可跑，全部引用作者的单机数据。

### 📌 把数字摊开写，这点很少见

多数 AI 工具晒 demo，它的 README 直接甩一张性能表。测试环境精确到驱动号：RTX 3080 10 GiB、i7-13700KF、CUDA 12.4.1、cuDNN 9.3.0.75、WhisperLiveKit 0.2.26 + faster-whisper 1.2.1、Whisper 多语 base（beam 1、0.8 秒合段）、Ollama 0.34.2 的 qwen3.5:9b（Q4\_K\_M）。结果是双向 30 分钟合成语音长测：

* • 英→中：672 条完整译文，片段结束到收到译文 P95 2.414 s，字幕额外阅读等待 P95 3.859 s，0 失败
* • 中→英：675 条完整译文，P95 3.172 s，阅读等待 P95 6.120 s（max 9.2 s），0 失败

注意它自己的限定：这是「识别+翻译延迟」，不是 Chrome 端到端延迟；TTS 合成语音的稳定不代表真直播的识别准确率——validation.md 里明说真实直播短测里有专有名词识别错误。作者还做了件狠事：把 5 分 19 秒安装、PowerShell 版本校验、移除 CUDA 路径后以退出码 2 报错列出缺失 DLL，全记进了验收文档。

架构上也干净：Chrome tabCapture + AudioWorklet 采音，经 WebSocket 送 PCM16 单声道 16 kHz 到 127.0.0.1:8765 的本地服务，后端是端口/适配器分层（ports/asr.py、ports/translator.py），Whisper 和 Ollama 都是可替换适配器。隐私边界同样写明：默认全本地，无账号无统计；但如果你把 Ollama 配成非本机端点，识别文本就会发去那个端点——这句提示比多数产品诚实。

### 📊 避坑与总结

该挑的刺，按影响排：

1. 1. **平台和硬件双重门槛**。Windows 之外没验证过，原话是「Linux 和 macOS installation 和 live capture have not been validated」；没有 NVIDIA 卡基本出局，没有 CPU 兜底，CUDA/cuDNN 缺失时是直接退出而不是降级。
2. 2. **成熟度极早期**。28 Star、2 Fork、0 open issue、创建 4 天。validation.md 里所有结论都限定在「单台电脑、单方向、约一分钟」的真实直播验收，完整安装和其他 GPU 机器尚待验证。这不是贬义，是事实陈述。
3. 3. **字幕行为有取舍**。快语速下译文会积压，切换标签页只暂停阅读计时不暂停采集，最快每页至少显示 4 秒，最后的页面 12 秒后消失。没有历史面板、没有手动翻页，清空队列的动作很多（刷新页面、换视频都会清）。
4. 4. **分发渠道原始**。没上 Chrome Web Store，手动 Load unpacked，项目目录不能删——它本质是「本地服务 + 扩展」的组合，不是独立扩展。

我的判断：Windows + NVIDIA 显卡、想在直播里实时读到母语字幕的人，这套本地管线的延迟数字和透明度目前很难找到第二个，值得折腾；Mac/Linux 用户、无独显用户，现在只看这篇了解思路就好。把它当「单机验证过的实验性本地字幕管线，不是即装即用的直播翻译服务」用，心态最稳。
