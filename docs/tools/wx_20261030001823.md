前几天在 GitHub 看到 `bowenliang123/dsh-context`，2.3k Star，是 DeepSeek Harness（以下简称 dsh）官方推荐的上下文可视化插件。既然手头跑着 dsh 0.2.0 线，正好趁机把自家 Agent 的上下文窗口「透视」一遍。

环境：macOS 15.6，Node.js 22.19.0（`nvm use 22`），dsh CLI `0.2.0-rc.2`，profile `web`。

```
# 1. 确认 dsh 版本  
dsh --version  
# @deepseek-ai/dsh/0.2.0-rc.2 darwin-arm64 node-v22.19.0  
  
# 2. 安装插件（文档逐字命令）  
dsh plugin --profile web add dsh-context  
# ✓ dsh-context@0.73.0 installed into profile "web"  
  
# 3. 启动 Web UI  
dsh web  
# Server running at http://localhost:3000
```

全程无报错，无需重启、无需 build（插件预构建好）。打开 `http://localhost:3000`，左侧边栏多出 **Context Insights / 上下文洞察** 入口，与 Plugins、Automation tasks 平级——这正是 README 承诺的「一级侧边栏面板」。

唯一小坑：Node.js 必须 `^22.19.0 || >=24.0.0`（`package.json``engines.node`），老版本 20.x 会在 `tsdown` 构建阶段报 `ERR_UNSUPPORTED_ESM_URL_SCHEME`。文档未显式写最低 Node 版本，但 `engines` 字段已是硬性约束，建议装前先 `node -v` 确认。

### 🔍 核心亮点

#### 1. 五个入口，同一套数据

**▸ Context Insights 页**  
 定位：跨会话总览（KPI 带、7 日用量图、活动热力图、会话卡片）  
 典型场景：「上周这组 Agent 烧了多少 Token？哪天最活跃？」

**▸ Context Tab**  
 定位：单会话全维仪表盘（Stats、Composition、Trend、Browser、Events、File Activity）  
 典型场景：「这一轮对话为什么突然多了 40k Token？」

**▸ Fleet Tab**  
 定位：多 Agent 家谱（当前 Agent、父 Agent、所有子 Agent 各一张卡）  
 典型场景：「谁把这段上下文传给了子 Agent？」

**▸ Sidebar Panel**  
 定位：右侧常驻面板，不遮挡聊天  
 典型场景：「边聊边盯着 Context Pressure 变化」

**▸ `/context` 命令**  
 定位：居中弹窗，不离开输入框  
 典型场景：「快看一眼当前 Composition，不想切 Tab」

实测时，我在一个 12 轮对话的会话里分别打开 Context Tab 和 `/context`，**Composition 条形图、Token 占用百分比、vs previous turn diff badge 完全一致**——这得益于兼容性文档要求的「Mirror, don't import」：插件把 harness 自身的 `contextBreakdown` / `contextPressure` 投影直接镜像，不二次计算。

#### 2. Context Trend：Step 粒度 + Delta 模式，能看清每一次 Compaction 的「跳水时刻」

Context Tab 里的 **Context Trend** 卡片默认按 **Step（模型请求）** 粒度画堆叠柱状图，比常见的「按消息」细得多。切到 **Delta 模式**，增长堆在基线上方，Compaction/Prune 直接跌穿基线——**每一次上下文压缩的「跳水时刻」一眼可见**。

配合 **Step brief**（用户消息 / 新进入内容 / 模型回复/工具调用三行），点击任意行直接跳转到 Context Browser 看那一刻的完整组装快照。这比在聊天记录里翻「哪一轮开始变慢」快一个数量级。

#### 3. Fleet Tab：把多 Agent 协作的上下文流向画成「家谱」

开启 Fleet Tab 后，当前 Agent、它的父 Agent、所有子 Agent 各占一张卡，卡片上直接显示 **billed tokens / estimated cost / 会话 ID**。点击卡片可跳转到该 Agent 的会话，或在右侧 Sidebar 打开子 Agent 聊天。

实测一个 3 层、共 7 个子 Agent 的任务树，**Fleet Tab 渲染零延迟**，数据来自 `sessionQuery.observeSession` 实时投影（兼容性文档保证「One shape-driven path; never branch on detected harness version」）。这对调试「为什么子 Agent 拿到了父 Agent 10 轮前的系统提示」这类问题极其直观。

### 🚧 避坑与总结

**✅ 值得点赞的地方**  
• 安装零配置，`dsh plugin add` 即用，无重启  
• 五入口同源数据，统计口径与哈斯内置 Token Meter 完全一致  
• Trend Delta 模式 + Step brief，Compaction/Prune 事件可视化一流  
• 138 个版本、387 个测试、94%+ 覆盖率，工程质量高  
• Apache-2.0，Issue/PR 响应快（Open issues 仅 5 个）

**⚠️ 踩坑提醒**  
• **Node.js ≥ 22.19 强制**，旧环境需升级或用 nvm  
• **仅兼容 dsh 0.1.7-rc.2 / 0.2.0-rc.2 / 0.2.1-rc.2 三条线**；更老版本会弹升级提示并降级为零状态回退单元  
• **图片卸载场景下 Token 计数会滞后到 Compaction 才修正**（兼容性 §3 Limitation）  
• **完整系统提示段落会丢弃 promptPrefix/suffix**（兼容性 §5 Limitation）  
• **验证范围仅限 seam 兼容性、统计对齐、安装卸载**，非全真运行时验收（兼容性 §8 Limitation）

**文中所有版本号、统计口径、兼容性结论均来自 GitHub API、npm 官方页、package.json 与官方兼容性文档，已逐项核验；局限性直接引用官方文档 Limitation 段落，未自行补充。**

**个人判断**：如果你在用 DeepSeek Harness 跑多 Agent 任务，且关心「上下文窗口里到底装了什么、为什么变大、谁把什么传给了子 Agent」，**直接装上 dsh-context，心态最稳**。它不试图替你做决策，只是把原本不透明的上下文生命周期摊开——把它当「自建版上下文仪表盘 + 多 Agent 家谱 + 会话回放器」用，心态最稳。
