前几天在 GitHub 看到 `eneskirca/nodeterm`，2k Star，标语是「Node-based terminal manager for AI coding agents —— 把终端和 Agent 摆在无限画布上」。作为一个常开十几个终端、又要跑 Claude Code、Codex、Gemini 并行的人，正好拿来实测一遍。

环境：macOS 15.6 (M4 Pro)、Node.js 22.22.2（`nvm use 22`）、tmux 3.5a（`brew install tmux`）、pnpm 9.15.0。

```
# 1. 克隆并进目录  
git clone --depth=1 https://github.com/eneskirca/nodeterm.git  
cd nodeterm  
  
# 2. 安装依赖（用 pnpm，package-lock.json 仅作锁版本参考）  
pnpm install  
# 耗时 ~50s，下载 electron 42.11.12、node-pty、sharp 等原生模块预编译二进制  
  
# 3. 原生模块重建（node-pty、smart-whisper 必跑）  
npm run rebuild  
# electron-rebuild -f -w node-pty,smart-whisper  
# 耗时 ~2min，M4 Pro 原生 arm64 无需交叉编译  
  
# 4. 启动开发模式  
npm run dev  
# electron-vite dev 启动渲染进程 + 主进程  
# 窗口弹出：无限画布、左侧工具栏、右侧检查器
```

**避坑点**：

* • Node.js 必须 `^22.22.2 || ^24.15.0 || >=26.0.0`（`package.json``engines` 硬性约束），Node 20 会在 `electron-rebuild` 阶段报 `N-API version mismatch`。
* • 首次 `npm run rebuild` 若报 `node-pty` 编译失败，macOS 需 `xcode-select --install`，Linux 需 `build-essential` + `python3`，Windows 需 Visual Studio Build Tools 2022 + Python 3.11。
* • tmux 必须在 PATH 里且版本 ≥ 3.2（老版本不支持 `tmux new -s ... -d` 的某些参数），`tmux -V` 确认一下。

### 🔍 核心亮点

#### 1. 「空间化终端」：把 tmux 会话变成可拖拽、可缩放、可分组的节点

这是最直观的体验：**每个终端是一个节点**，而不是标签页。

* • **无限画布**：按住空格拖拽平移，鼠标滚轮缩放（10%400%），节点位置、大小、分组全量持久化到 `/.nodeterm/workspace.json`。
* • **tmux 后端**：节点底层是真实的 `tmux new-session -s nodeterm-<uuid>`，关掉 Electron 进程、甚至重启电脑，**tmux 会话依然在跑**，进程、scrollback、当前目录全保留。再次打开 nodeterm，节点原地复活，Claude Code 还在生成代码。
* • **分组帧**：框选多节点 → 右键「Group」→ 生成可折叠的帧，帧内节点相对位置固定，整体可拖拽。适合「前端项目一组、后端一组、AI Agent 一组」这种心智模型。

**实测场景**：我在画布左侧开一个「主项目」分组（3 个终端：dev server、test watch、git log），右侧开「AI Agents」分组（Claude Code、Codex、Gemini 各一个节点）。缩放到 25% 一眼看到全景，放大到 150% 写代码。关掉 app 重开，**三个 Agent 的对话上下文、运行中的测试、tail -f 的日志全在**——这比 iTerm2/Tabby/WezTerm 的标签页栈强一个数量级。

#### 2. Agent 节点：原生集成 Claude Code / Codex / Gemini / opencode，状态徽章可视化

节点类型里有 **Agent 节点**，不是简单的 `claude` 命令封装：

![](https://images.weserv.nl/?url=https://mmbiz.qpic.cn/mmbiz_png/PPEWQalJCORMu8RCAxDOOicLpf2FqCyWEkRbmyNoSZw4eKtanhfrictNiaXcyI02earmf6LztFeefCxZSHTD2DuIxHhAT5deHXZKicgAdjIXocs/640?wx_fmt=png&from=appmsg)

**关键细节**：

* • **Antigravity Hook**（CLAUDE.md 详细记录）：在 `~/.gemini/config/hooks.json` 注入 `nodeterm-status` bundle，`PreToolUse` 同步拦截，stdout 返回 `{"decision":"ask"}` 即拒绝工具调用。这让 nodeterm 能在 Gemini CLI 层面做**跨进程的权限闸**——甚至能管住同机器上其它 Gemini 实例。
* • **Codex Relay**：`scripts/build-codex-relay.mjs` 编译一个中转二进制，解决 Codex CLI 的 stdin/stdout 管道在 node-pty 里的兼容性问题。
* • **状态徽章实时性**：Agent 启动 → 🟢 RUNNING（脉冲动画） → 等待用户输入 → 🟡 NEEDS YOU（闪烁） → 报错 → 🔴 ERROR。长任务完成会在 macOS 通知中心 / Windows Toast 推送。

**实测**：并行跑三个 Agent（Claude Code 写前端、Codex 写后端、Gemini 写测试），画布上三个节点各自脉冲，子 Agent fan-out 以虚线连接父节点，点击连线可跳转到子节点。**切出去喝杯咖啡回来，通知中心已有「Claude Code 完成」推送，节点已转 🟢**——这对 ADHD/多任务并行者极其友好。

#### 3. 三端同源：桌面端 / Server Edition（浏览器）/ iOS 伴侣，同一套 tmux 会话

这不是三个独立产品，而是**同一核心三种运行模式**：

![](https://images.weserv.nl/?url=https://mmbiz.qpic.cn/sz_mmbiz_png/PPEWQalJCORbhBwb42CR33DzkzREmwxpmzumrJCfEdxpWiaKwWPEvPC2J6hl9IvS0BQibkyrMKWeibCWvg4WJDupHvLEVuywjrBHxKftjsSOaY/640?wx_fmt=png&from=appmsg)

**Server Edition 实测**：`docker run -d -p 3000:3000 -v ~/.nodeterm:/data ghcr.io/eneskirca/nodeterm-server` 启动，浏览器打开 `https://your-server:3000`，**同一个画布、同一组 tmux 会话、同一组 Agent 节点**。iOS 端扫码登录后，能看到节点状态、展开终端输入、收到推送。文档 `docs/SERVER.md` 给了完整的 HTTPS 证书配置、反向代理模板、Tailscale 接入步骤。

### 🚧 避坑与总结

**✅ 值得点赞的地方**

* • tmux 会话真·持久化：重启 app、重启机器，进程、scrollback、cwd 全复活
* • 空间化画布 + 分组帧，符合「散布式思考」的心智模型
* • Agent 节点原生集成四大 CLI，状态徽章 + 推送 + 子 Agent 可视化全链路打通
* • 三端同源（Desktop / Server / iOS），同一套会话无缝流转
* • BUSL-1.1 保护核心商业价值，4 年后转 MIT，开源友好

**⚠️ 踩坑提醒**

* • **Node.js 版本强制**：`^22.22.2 || ^24.15.0 || >=26.0.0`，旧环境需 nvm 升级
* • **Windows 为 beta**：node-pty 需 conpty.dll、electron-rebuild 易卡工具链、Antigravity hook 需处理 cmd.exe 转义与 AutoRun 注册表（CLAUDE.md 有专节）
* • **原生模块重建必跑**：`npm run rebuild` 依赖 Python 3 + C++ 工具链，CI/CD 要缓存 `node_modules/.cache/electron-rebuild`
* • **Server Edition 需自备 HTTPS**：生产建议走 Caddy/Traefik + Let's Encrypt，文档给模板但不托管
* • **BUSL-1.1 限制**：不能作为竞品托管服务（如「nodeterm 云托管」），商业化需联系作者单独授权
* • **iOS 仍在 TestFlight**：正式上架时间不确定，且需同网络或 Tailscale 穿透

**个人判断**：如果你 **「常开多个终端跑并行 AI Agent、受不了标签页藏上下文、想要会话跨重启存活、且能接受 Electron 体量 + tmux 依赖」**，nodeterm 是当前 **唯一把「空间化画布 + Agent 可视化 + 三端同源」做在一起的开源答案**。把它当「自带 tmux 持久化的无限画布终端 + 并行 Agent 指挥台」用，心态最稳。
