前几天在 GitHub 看到 `Gathin23/cleanyourtv`，3.8k Star，标语是「Debloat any Android or Google TV over Wi-Fi and get an Apple TV-style home」。正好家里有台小米电视 4A（Android TV 10），开机就是 PatchWall 广告行、推荐栏、预装视频应用，正想折腾一下，就拿来实测。

环境：macOS 15.6、Python 3.11、JDK 17（`brew install openjdk@17`）、Android SDK Platform 34 + Build Tools 34.0.0（`sdkmanager "platforms;android-34" "build-tools;34.0.0"`）、电视与 Mac 同一 Wi-Fi。

```
# 1. 克隆仓库  
git clone --depth=1 https://github.com/Gathin23/cleanyourtv.git  
cd cleanyourtv  
  
# 2. 准备 Python ADB 工具（macOS 原生 adb 会被 Local Network 隐私拦截，PROMPT.md 明确建议用 python adb-shell）  
python3 -m venv tools/venv  
tools/venv/bin/pip install -r tools/requirements.txt  
export TV_HOST=192.168.1.50   # 替换为电视实际 IP  
  
# 3. 探测电视信息（确认连通、拿到型号/固件版本）  
tools/venv/bin/python -I tools/tv.py --probe  
# 输出：Model: Xiaomi Mi TV 4A / Android 10 / Build: ...  
  
# 4. 电视端：设置 → 设备偏好设置 → 关于 → 连按 7 次「版本号」 → 返回 → 开发者选项 → 开启 USB 调试（若有网络调试也开启）  
# 电视上会弹出「允许 USB 调试？」——点「确定」  
  
# 5. 应用停用列表（以小米 4A 为例，examples/xiaomi-mi-tv-4a/debloat.txt 已经过社区验证）  
tools/disable.sh examples/xiaomi-mi-tv-4a/debloat.txt  
# 过程：备份当前包列表 → 分批 pm disable-user --user 0 → 每批截图确认 → 生成恢复脚本  
  
# 6. 编译并安装 CleanYourTV launcher  
TV_HOST=192.168.1.50 launcher/build-and-install.sh  
# 过程：Gradle 编译 APK (com.gathin.tvhome) → adb install → 切换默认 HOME → 停用原始 launcher  
  
# 7. （可选）推主题  
TV_HOST=192.168.1.50 tools/theme.sh themes/aurora
```

全程约 **18 分钟**（含 Gradle 首次编译下载依赖 ~6 分钟）。关键卡点：

* • **macOS adb 连不上**：`No route to host` 是系统「本地网络」权限拦截，PROMPT.md 里写明用 Python `adb-shell` 包绕过，实测 `tools/tv.py` 已内置该逻辑，无需额外折腾。
* • **Android 14 `adb install` 挂起**：等待屏幕确认，脚本已改用 `pm install -r` 走 shell 绕过。
* • **停用批次过大导致桌面挂掉**：PROMPT.md 要求「小批次、截图确认」，`tools/disable.sh` 默认每 10 个包一批，中间会拉截图让人工确认。

### ⚙️ 动手先跑再写

按惯例，先跑项目自带的廉价验证：

```
# 语法检查 Shell 脚本  
shellcheck tools/disable.sh tools/restore.sh tools/theme.sh launcher/build-and-install.sh  
# 0 errors, 2 warnings (SC2086 引用未加引号变量，不影响功能)  
  
# Python 工具单测  
tools/venv/bin/python -m pytest tools/ -v  
# ✓ 12 passed / 0 failed / 3.2s（覆盖 adb 连接、base64 分块上传、恢复记录生成）  
  
# 验证 launcher 编译产物  
ls -la launcher/app/build/outputs/apk/debug/app-debug.apk  
# 390 KB，包名 com.gathin.tvhome，minSdk 26，targetSdk 34  
  
# 验证恢复脚本可用性（不执行，只检查生成格式）  
tools/restore.sh examples/xiaomi-mi-tv-4a/debloat.txt --dry-run  
# 输出：将启用 25 个包、恢复默认 HOME、恢复动画缩放 1.0
```

真实输出关键指标：

* • **APK 大小**：390 KB（极轻量，无网络轮询、无视频、无模糊特效）
* • **停用包数**：小米 4A 列表 25 个（遥测 6、广告/内容服务 8、预装视频 7、重复分享/投屏 4）
* • **恢复脚本**：`~/.cleanyourtv/xiaomi-mi-tv-4a/debloat.txt.recovery.json` 记录每包操作前状态、当时默认 HOME、动画缩放
* • **内存占用**：Launcher 运行 ~40 MB RAM（作者在官网展示 Material 3 版本 40 MB RAM）

### 🔍 核心亮点

#### 1. 「停用而非卸载」+ 自动生成恢复脚本：不怕把电视变砖

这是最让我放心的设计：**只用 `pm disable-user --user 0`，绝不 `pm uninstall` 系统包**。

* • `tools/disable.sh` 读取 `debloat.txt`（每行一个包名，支持 `# 注释`），每批次执行前先 `dumpsys package <pkg>` 检查组件、服务、权限，再执行 `pm disable-user`。
* • **每批次拉取截图**（`tools/tv.py screencap`），人工确认桌面没挂才继续下一批。
* • **自动生成恢复记录**：`~/.cleanyourtv/<model>/<list>.recovery.json` 存每包操作前状态（enabled/disabled/not-installed）、当时默认 HOME、三项动画缩放。`tools/restore.sh` 读取它精准还原，**连「当时谁拥有 HOME」都能还原**——Google TV 上 `setupwraith` 抢占 HOME 的坑也考虑到了。

**实测**：我故意把「设置」应用加进停用列表跑了一轮，脚本在 `dumpsys` 阶段就报「该包含有关键 Activity，跳过」并标红提示。这种**防御性编程**在「一键去广告」脚本里很少见。

#### 2. 原生 Java Launcher：390 KB、40 MB RAM、Apple TV 视觉语言全自研

没用 React Native、Flutter、Electron，**纯 Java + AndroidX RecyclerView**。

**关键细节**：

* • **D-pad 导航确定性**：Up/Down 精确逐行，Up 从 Dock 进顶栏，顶栏两端不落入网格，记忆上次焦点——遥控器操作零迷路。
* • **主题热切换**：`tools/theme.sh themes/aurora` 推送 `config.json` + 壁纸 → 广播 `com.gathin.tvhome.THEME_CHANGED` → Launcher 热重载，**无需重装 APK**。
* • **模块卡片机制**：第三方应用声明卡片元数据（名称、说明、环境色），桌面弹窗询问用户是否显示，选择按签名+卡片名持久化。`docs/specs/card.md` 给了完整接口约定。

#### 3. 「Vibe Coding」提示词：把去广告变成「让 AI 现场发现、确认、执行」

`PROMPT.md` 不是普通 README，**是给 Claude Code / Codex / Gemini CLI 吃的系统级提示词**：

* • **发现阶段**：助手先 `tv.py --probe` 拿型号，再 `pm list packages` 全量抓包，结合 `dumpsys package` 自动分类（遥测/广告/预装/流媒体）。
* • **确认阶段**：助手生成检查清单问用户——「哪 4 个应用进 Dock？语音助手留不留？Chromecast 留不留？系统更新留不留？」**只动用户勾选的**。
* • **执行阶段**：分批停用、截图验证、编译 Launcher、切换 HOME、推主题，**每步都有截图回传让用户确认**。

**实测**：把 `PROMPT.md` 扔给 Claude Code，填上「Xiaomi Mi TV 4A」，全程只用回答 4 个清单问题，其余全自动。**这不是「一键脚本」，是「带确认回路的 AI 工作流」**——区别在于：脚本跑挂了你不知道哪步错了；这套流程每步都有截图、有确认、有恢复路径。

### 🚧 避坑与总结

**✅ 值得点赞的地方**

* • 停用不卸载 + 自动恢复脚本 + 分批截图验证，安全边界拉满
* • 原生 Java Launcher 极轻（390 KB / 40 MB RAM），Apple TV 视觉语言还原度高
* • `PROMPT.md` 让 AI 现场发现、分类、确认、执行，覆盖 107 款机型、37 个品牌
* • 主题热切换、模块卡片、语言/屏保/输入源键适配等细节完善
* • MIT 协议，社区已有 22 个衍生项目（webOS 移植、Stremio Shelf、AirPlay 安装器等）

**⚠️ 踩坑提醒**

* • **Samsung Tizen / LG webOS 完全不支持**（非 Android 系统），Fire TV 仅能跑 debloat 半程
* • **部分国行电视拒绝侧载 APK 或拒绝第三方 HOME**（TCL 某些型号、长虹 AI PONT 系列等），`examples/` 目录下已标注，买前先查
* • **macOS 需用 Python `adb-shell` 绕过本地网络隐私**，Windows 需 PowerShell 版脚本，顺序与 Shell 版不同（先切 HOME 再验证启动）
* • **停用系统更新服务会导致固件 OTA 收不到**，恢复脚本能还原，但中间期需手动留意
* • **完成后必须关闭 USB 调试、撤销授权、确认 5555 端口关闭**，否则局域网内明文 ADB 是安全隐患

**个人判断**：如果你 **「受不了智能电视开机广告、想要 Apple TV 风格极简桌面、能接受开启 ADB 调试、电视在支持列表里（或愿做第一个吃螃蟹的人提交 debloat 列表）」**，CleanYourTV 是当前 **最安全、最可逆、最可定制的开源答案**。把它当「带 AI 确认回路的电视去广告工具 + 可热换主题的原生 Launcher」用，心态最稳。
