前几天在 GitHub 看到 `kajisho5/ffmpeg-skill`，3k Star，标语是「Local video editor for coding agents: 42 FFmpeg tools with a machine-readable contract and an MCP server」。作为一个常让 Claude Code 用 FFmpeg 剪视频、却总被「参数猜错、容器不支持、再编码画质损、输出没验证」折磨的人，正好拿来实测。

环境：macOS 15.6、Node.js 22.12.0、Python 3.12.7、FFmpeg 7.1（`brew install ffmpeg`）。

```
# 1. 一键安装技能（同时写入 Claude Code / Cursor / Codex 三家配置）  
npx ffmpeg-skill  
# ✓ Installed ffmpeg-skill for claude-code, cursor, codex  
#   Skill written to ~/.claude/skills/ffmpeg-skill  
  
# 2. 机器体检：检查 ffmpeg/ffprobe 及每工具所需组件  
npx ffmpeg-skill doctor  
# {"ok": true, "tools": {"cut.py": {"usable": true}, "caption.py": {"usable": true}, ...}}  
  
# 3. 读取机器可读契约（给规划 Agent 用）  
npx ffmpeg-skill contract --json | head -60  
# {"contract_version": "1.0", "skill": {"id": "ffmpeg-skill", "version": "2.17.1", ...}}  
  
# 4. 直接在 Claude Code 里用自然语言下单  
# "把 interview.mp4 裁掉 0:45-3:10 和 5:00-6:30，压成 60 秒 9:16 竖屏给 Reels"
```

全程无报错。`doctor` 的 `ok: true` 表示**所有工具通用的必需组件**都在，但单个工具可能仍不可用（如 macOS Homebrew 版 FFmpeg 缺 `subtitles` 滤镜导致 `caption.py` 不可用），需看 `doctor --json` 的 `tools` 字段逐项确认。

**避坑点**：

* • Windows 下 `python3` 仅 Microsoft Store 版 Python 在 PATH，官网安装版用 `python` 或 `py` 启动器，README 示例需自行替换。
* • Python 3.9 / FFmpeg 5.x 已弃用（2.x 仍可用，3.0 将移除），建议直接上 Python 3.10+ + FFmpeg 6.1+。
* • 首次运行转录工具（`caption.py --transcribe`、`silence.py --filler --transcribe`）会自动下载模型权重（Parakeet-MLX 从 Hugging Face、faster-whisper/openai-whisper 各自来源），**完全离线跑在本机，音频不上传**。

python3 tests/test_all.py

真实输出关键指标：

* • **Contract 测试**：28 passed / 2.1s（核心守门测试）
* • **全量测试**：156 passed / 47.3s
* • **工具数量**：42 个（`scripts/` 目录下非 `_` 开头的 `.py` 文件）
* • **演示对比**：66 组 before/after（全合成素材可复现）

### 🔍 核心亮点

#### 1. 「契约即代码、代码即契约」：argparse 单一事实来源，零手写 JSON Schema

这是最让我佩服的工程决策：**每个工具的 `input_schema` 从来不手写**，而是在运行 `contract --json` 时，由 `scripts/_contract.py` 实时解析各工具的 `argparse.ArgumentParser` 生成。

```
# scripts/cut.py 片段  
parser = argparse.ArgumentParser()  
parser.add_argument('--segments', required=True, help='Comma-separated HH:MM:SS-HH:MM:SS')  
parser.add_argument('--accurate', action='store_true', help='Re-encode for frame accuracy')  
# ...  
  
# scripts/_contract.py 运行时自动生成对应 input_schema：  
# {"type": "object", "properties": {"segments": {"type": "string"}, "accurate": {"type": "boolean"}}, "required": ["segments"]}
```

**CI 守门**：`tests/test_contract.py` 会把生成的契约与 `scripts/` 目录实况、MCP `tools/list`、文档里的工具数量**全量对比**，任何一处漂移（新增参数未同步、重命名未同步、文档数量未更新）直接阻断合并。

**稳定性承诺（2.x 系列）**：

* • Tool ID、脚本名、CLI 参数、**永不删除/重命名/新增必填**
* • `--json` 输出键、**永不删除/改类型**
* • 退出码、MCP `tools/list` 名称、**永不变**
* • 行为变更仅限缺陷修复或跟随 FFmpeg 更新，**每项必有 CHANGELOG 记录**

#### 2. 「Probe 先行、流式复制、验证收尾」：把「猜参数」变成「量体裁衣」

技能强制的工作流四步走，**Agent 偏离即报错**：

| 阶段 | 工具 | 核心动作 |
| --- | --- | --- |
| **Probe** | `probe.py` | `ffprobe` 拿时长、帧率、分辨率、色域、音频布局，**据实决定策略** |
| **Edit** | 42 个结构化工具 | **不走 shell、不接受滤镜图字符串** 、能 `stream copy` 就不重编码 |
| **Check** | `check.py` | 按平台规范（时长/分辨率/码率/响度/编解码器）逐项核验 |
| **Look** | `look.py` | 生成联系表，Agent **肉眼确认** 画面无黑帧/错位/字幕溢出 |

**实测**：让 Claude Code 「把 4K 60fps 访谈素材裁成 60 秒 9:16 Reels，保持 HDR、响度 -14 LUFS」：

1. 1. `probe.py` 返回：3840×2160、59.94fps、BT.2020 PQ、立体声
2. 2. `cut.py --segments` 按时间戳**流式复制视频流**（仅重编码音频对齐）
3. 3. `fit.py --duration 60 --aspect 9:16 --fit crop` 智能裁剪保主体
4. 4. `loudness.py -I -14 --tp -1` 双遍 EBU R128 归一化
5. 5. `export.py --preset reels` 写入 TikTok/Reels/Shorts 专用标签
6. 6. `check.py --platform reels` 全项 ✓
7. 7. `look.py` 生成 9 张联系表，Agent 汇报：「final.mp4: 59.98s、1080×1920、30fps、HDR PQ、AAC stereo、-13.9 LUFS」

**全程零人工修正参数**，Agent 完全按「量体→裁衣→验收」闭环执行。

#### 3. 42 个工具覆盖「剪→字→音→色→投」全链路，平台导出模板化

工具按功能分层（README Tools 表）：

| 类别 | 工具 | 典型用途 |
| --- | --- | --- |
| **剪辑** | `cut.py``join.py``silence.py``fit.py` | 分段裁剪、拼接、静音移除、定时长/定宽高裁剪填充 |
| **字幕** | `caption.py``karaoke.py` | 逐字弹出/卡拉 OK、SRT/ASS 烧录、可选 `--transcribe` 本地语音识别 |
| **叠加** | `overlay.py``motion.py``brand.py` | 图片/视频/文字水印、关键帧动画、品牌包装 |
| **色彩** | `hdr.py``lut.py``tonemap.py` | HDR→SDR 色调映射、3D LUT 应用、色域转换 |
| **音频** | `loudness.py``dynamics.py``sync.py``noise.py` | EBU R128/ATSC A/85 响度、压缩/扩展/门限、多机位漂移校准、降噪 |
| **投递** | `export.py``check.py``render.py``render.py --template all` | 平台预设导出、合规检查、多平台批量打包输出 `_pack.md` 对比表 |

**平台模板**（`templates/*.json`）内置：

* • **安全区避让**：TikTok 说明栏/点赞栏、Reels 字幕区、Shorts 标题区
* • **响度标准**：TikTok/Reels/Shorts -14 LUFS、YouTube -13 LUFS、Podcast -16 LUFS
* • **编码约束**：H.264 High@L4.1 / HEVC Main10@L5.1、AAC/Opus、关键帧间隔
* • **字幕适配**：`fit_size: "on"` 自动缩字不换行、`brand.json` 统一品牌字号色

**实测**：`render.py talk.mp4 --template all --cues cues.txt --brand brand.json` 一键产出 **8 个平台成品 + `_pack.md` 对比表**，每个成品自带 `check.py` 合规报告。

#### 4. MCP 服务器：同一套工具，Agent 框架零差异调用

`mcp/server.py` 基于 stdio JSON-RPC，**不持有工具表**，每次 `tools/list` 实时从契约派生：

* • **精简模式**（默认）：仅广播 12 个核心工具，保客户端上下文紧凑
* • **全量模式**（`FFMPEG_SKILL_MCP_FULL=1`）：广播全部 42 个工具
* • **工具调用**：`tools/call` 直接映射到 `scripts/<name>.py`，**同一进程、同一契约、同一验证流程**

**实测**：在 Cursor / Claude Desktop / 自建 MCP Client 中配置 `"command": "npx", "args": ["ffmpeg-skill", "mcp"]`，即可让 Agent 通过 MCP 调用 `cut`、`loudness`、`export` 等工具，**无需额外包装、无版本偏移**。

### 🚧 避坑与总结

**✅ 值得点赞的地方**

* • **契约自动生成 + CI 守门**：argparse 单一事实来源，消灭「文档与代码不同步」这类低级错误
* • **Probe 先行 + 流式复制 + 验证收尾**：把「Agent 猜 FFmpeg 参数」变成「Agent 读探针、按契约调用、验收交付」
* • **42 工具全覆盖 + 平台模板化**：从切片到多平台合规导出，一套流程跑通
* • **MCP 直连 + 契约派生工具表**：同一工具集同时服务 CLI、MCP、编程化调用，零包装层
* • **稳定性承诺 + 弃用策略 + 契约版本锁**：工业级 API 演进纪律，适合生产环境依赖
* • **完全本地、离线、无 API Key**：隐私敏感素材可放心处理

**⚠️ 踩坑提醒**

* • **定位是「执行引擎」，不含「大脑」**：不做剪辑决策、不做内容审核、不做创意策划（需配合 `video-production-agent` 等上层 Agent）
* • **Python 3.9 / FFmpeg 5.x 已弃用**，2.x 仍可用但会报警告，3.0 将彻底移除，建议直接升级环境
* • **macOS Homebrew FFmpeg 缺 `subtitles` 滤镜** → `caption.py` 不可用，需自行编译或用 `--transcribe` 生成 SRT 再 `overlay.py` 烧录
* • **Windows 需用 `python` 而非 `python3`**，仅安装器/doctor 自动兼容，手写脚本调用需注意
* • **覆盖文件默认拒绝**（2.0 行为），需显式 `--overwrite`，干净实验需加 `--dry-run` 先看计划
* • **转录引擎可选且离线**：首次跑需下载模型权重（Parakeet-MLX ~300MB、faster-whisper ~150MB），无网环境需预下载

**个人判断**：如果你 **「让 Claude Code/Cursor/Codex 等编码 Agent 拥有可靠、可验证、可离线的视频处理能力、接受『只执行不决策』的职责边界、且能搭建 Python 3.10+ + FFmpeg 6.1+ 环境」**，**ffmpeg-skill 是当前工程最严谨、契约最完备、生态最完整的开源答案**。把它当「Agent 专用的 FFmpeg 结构化执行层 + MCP 网关 + 平台合规导出机」用，心态最稳。
