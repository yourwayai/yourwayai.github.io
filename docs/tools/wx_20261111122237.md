运维过服务器的人都知道这套熟悉的折腾路径：

1. 1. **Prometheus + Grafana + Node Exporter + Alertmanager** —— 功能全，但起步三四个容器、配置文件上百行、内存动辄 1-2GB，小 VPS 根本跑不动。
2. 2. **Zabbix / Netdata / Uptime Kuma** —— 要么 Java 栈重、要么功能单一（只监控、无终端、无主题）、要么告警配置像写代码。
3. 3. **云厂商监控** —— 免费额度有限、数据不在自己手里、跨云厂商聚合还得再搞一套。

**共同痛点**：想要「一个仪表盘看 CPU/内存/磁盘/网络、一个网页终端应急、一个主题换个心情、数据全在自己手里」，却不得不在「重、碎、锁」三选一里妥协。

### 把「监控+终端+主题」做成单二进制、单容器、可扩展的轻量栈

Komari 的定位很克制：**不做全能运维平台，只做「轻量、自托管、可扩展」的服务器监控与控制面板**。

| 维度 | 传统重型栈 | **Komari** |
| --- | --- | --- |
| **部署体量** | 3-5 容器、1-2GB 内存 | **单二进制 / 单容器、6MB、10MB 内存** |
| **数据库** | Prometheus TSDB / MySQL / PostgreSQL | **SQLite（默认）/ MySQL / PostgreSQL 三选一** ，单文件可迁移 |
| **Agent 接入** | 配置文件 + 服务注册 | **脚本/二进制/Docker/自动发现** 四种形态，批量接入一条命令 |
| **终端** | 单独装 ttyd / WebSSH | **内置 Web Terminal** ，同一面板点进去就是 SSH |
| **主题/插件** | Grafana 面板 JSON / 独立插件系统 | **主题市场 + 插件扩展** ，配置热加载、API 开放 |
| **部署门槛** | 需懂 PromQL / 服务发现 / 告警路由 | **一条 `docker run` / 一键安装脚本 / 1Panel/雨云一键部署** |

**核心哲学**：**「轻量不是阉割，是把核心做透、把扩展留开」**——官网写得很实在：「低资源占用，适合个人服务器、边缘设备和多节点环境」。

### 从「裸机」到「可用的监控面板」的完整链路

#### 1. 服务端部署：三种方式，最快 30 秒跑通

**方式 A：Docker（推荐，生产最稳）**

```
docker run -d \  
  --name komari \  
  --restart unless-stopped \  
  -p 25774:25774 \  
  -v komari:/data \  
  ghcr.io/komari-monitor/komari
```

* • 端口 25774：Web UI + Agent gRPC + Web Terminal WebSocket
* • 数据卷 `komari:/data`：SQLite 数据库 + 配置 + 主题/插件目录
* • 启动后浏览器打开 `http://<server-ip>:25774`，默认账号 `admin` / `admin`，**首次登录强制改密码**

**方式 B：一键安装脚本（裸机/轻量容器）**

```
curl -fsSL https://raw.githubusercontent.com/komari-monitor/komari/main/install-komari.sh | bash
```

* • 自动检测架构下载对应二进制、生成 systemd 服务、配置开机自启
* • 适合不想装 Docker 的轻量 VPS、边缘设备

**方式 C：面板一键部署（懒人最爱）**

* • **1Panel 应用商店**搜索「Komari」→ 点击安装
* • **雨云应用商店**搜索「Komari」→ ¥5/月起、小时计费
* • 适合已有面板管理服务器的用户

#### 2. Agent 接入：四种形态，总有一款适配你的环境

| 形态 | 适用场景 | 接入命令 |
| --- | --- | --- |
| **二进制直跑** | 裸机、systemd 管理 | `wget <server>/agent -O komari-agent && ./komari-agent -s <server>:25774 -t <token>` |
| **Docker 容器** | 容器化环境、隔离网络 | `docker run -d --name komari-agent -e SERVER=<server>:25774 -e TOKEN=<token> ghcr.io/komari-monitor/komari-agent` |
| **安装脚本** | 懒得手动配 systemd | `curl -fsSL /install-agent.sh |
| **自动发现** | 同一局域网批量接入 | Agent 启动时广播 UDP，服务端「节点管理」页一键「导入全部」 |

**实测**：在同一 VPC 下 5 台混合架构机器（x86\_64/arm64、Ubuntu/Debian/Alpine），用「自动发现 + 批量导入」，**30 秒全上线**，CPU/内存/磁盘/网络/在线状态秒级刷新。

#### 3. 日常运维：一个面板、三大核心视图

| 视图 | 核心能力 | 实测体验 |
| --- | --- | --- |
| **首页仪表盘** | 所有节点卡片：CPU/内存/磁盘/网络实时曲线、在线状态、负载、uptime | 1 秒刷新、卡片可拖拽排序、点击节点进详情 |
| **节点详情** | 实时/历史图表（1h/24h/7d/30d）、进程列表、Docker 容器监控、磁盘分区、网络接口 | 图表平滑、进程表可按 CPU/内存排序、容器自动识别标签 |
| **Web Terminal** | 浏览器里完整的 SSH 终端、支持多标签、复制粘贴、滚动历史 | **基于 xterm.js + WebSocket** ，延迟感知 <50ms，支持 `vim`/`htop`/`tmux` 全交互 |

**关键细节**：

* • **历史数据保留**：SQLite 默认保留 30 天，可配置保留期/压缩策略
* • **多用户/权限**：Admin/Viewer 角色，Viewer 只读、无终端权限
* • **通知渠道**：Telegram / Discord / Webhook / Email / Bark / PushPlus / Server酱，**告警规则在 UI 里点点点配置**（阈值、持续时间、通知渠道、静默期）

#### 4. 扩展性：主题市场 + 插件系统，把「面子」和「里子」都留开

**主题市场**：

* • 内置 6+ 官方主题（默认、暗色、高对比、Nord、Dracula、Solarized）
* • **Theme Market** 一键安装社区主题（JSON 配置 + CSS 变量），支持实时预览、一键回滚
* • **自定义主题**：按规范写 `theme.json` + `style.css`，放入 `themes/` 目录热加载，**无需重启**

**插件扩展**：

* • **Hook 机制**：节点上线/下线、告警触发、指标采集完成等生命周期挂载自定义逻辑
* • **自定义指标采集器**：实现 `Collector` 接口，按需采集业务指标（如 MySQL QPS、Redis 内存、业务队列长度）
* • **外部脚本集成**：告警触发执行 Shell/Python/Node 脚本，标准输入传入告警 JSON

**实测**：装了个「服务状态徽章」插件（GitHub Release 页面下载 `.so` 放入 `plugins/` 重启），首页卡片右上角多了个「服务健康度」彩色点，**全程无需改代码、无需重编译**。

### 避坑与总结

**✅ 值得点赞的地方**

* • **单二进制/单容器、6MB、10MB 内存**：小 VPS、边缘设备、树莓派全跑得动
* • **SQLite 默认、单文件迁移**：备份/恢复/版本控制全是 `cp komari.db bak.db`
* • **Agent 四形态 + 自动发现**：混合架构、混合部署环境批量接入零摩擦
* • **内置 Web Terminal**：应急运维不再需要单独开 SSH 客户端、配跳板机
* • **主题市场 + 插件热加载**：UI 和能力双扩展，配置即生效、无需重启
* • **完全自托管、MIT 协议**：数据、隐私、部署位置 100% 自己控

**⚠️ 踩坑提醒**

* • **告警引擎非开箱即用**：需自己配通知渠道、写告警规则，无「开箱即用的告警模板库」
* • **无内置日志聚合/链路追踪**：只做指标监控，日志需另配 Loki/ELK/Vector
* • **Agent 自动发现依赖局域网 UDP 广播**，跨 VPC/NAT 环境需手动指定 Server 地址
* • **Web Terminal 权限模型依赖 SSH 配置**：需目标机器 `sshd_config` 允许密钥/密码登录，权限最小化需自行配 `sudoers`
* • **进阶配置文档较少**：反向代理/OAuth/自定义指标/插件开发多靠读源码/社区问答
* • **WebSocket 长连接需反代支持**：Nginx/Caddy/Traefik 需配 `proxy_http_version 1.1; proxy_set_header Upgrade $http_upgrade; proxy_set_header Connection "upgrade";`

**个人判断**：如果你 **「管理 1-50 台服务器、受不了 Prometheus/Grafana/Zabbix 的重与碎、想要『一个仪表盘+一个网页终端+数据全在自己手里』、且能接受『告警规则需手写、日志另配』」**，**Komari 是当前「轻量自托管监控」里工程最扎实、部署最省心、扩展最开放的开源答案**。把它当「单机版『监控+终端』一体机 + 多节点扩展的轻量中控台」用，心态最稳。
