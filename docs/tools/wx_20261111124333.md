前几天在 GitHub 看到 `foru17/neko-master`，4.2k Star，标语是「A modern and elegant dashboard for network traffic visualization and analysis」。手头正好跑着 Clash + Surge 双网关，平时想看流量走向、哪个规则匹配最多、哪个域名最费流量，只能靠 `clash -d` 看日志或 `clash -t` 测延迟，极不直观。正好拿来实测。

环境：macOS 15.6 (M4 Pro)、Docker Desktop 4.38、Node.js 22.12.0、pnpm 9.15.9、已有 Clash 网关（API 端口 9090、Secret `xxx`）、Surge 网关（HTTP API 6170）、同一局域网。

```
# 1. 克隆仓库（浅克隆）  
git clone --depth=1 https://github.com/foru17/neko-master.git  
cd neko-master  
  
# 2. 复制环境变量模板，按需修改  
cp .env.example .env  
# 关键变量：  
# WEB_EXTERNAL_PORT=3000     # Web UI 端口  
# API_EXTERNAL_PORT=3001     # API 端口  
# WS_EXTERNAL_PORT=3002      # WebSocket 端口  
# COOKIE_SECRET=***          # 随机字符串，用于会话加密  
# GEOIP_LOOKUP_PROVIDER=local  # 或 online，需配置 GEOIP_ONLINE_API_URL  
  
# 3. 一键启动（Docker Compose，含可选 ClickHouse）  
docker-compose up -d  
# 或仅 SQLite（不启 ClickHouse）：  
# docker-compose up -d neko-master  
  
# 4. 访问 Web UI  
# http://<server-ip>:3000  
# 首次访问需设置管理员账号/密码
```

全程约 **2 分钟** 跑通。关键体验：**`docker-compose.yml` 把「Web UI(Next.js) + Collector(Node.js+Fastify+WS) + ClickHouse(可选) + Agent(Go)」全编排好了**，环境变量全在 `.env` 里，**首次启动自动建表、建索引、下载 GeoIP 数据库**。

**避坑点**：

* • **Node.js 必须 ≥22**（`package.json``engines` 硬性约束），旧版本会在 `turbo build` 或 `next build` 阶段报错。
* • **pnpm 必须用 9.15.9**（`packageManager` 锁死），别用 npm/yarn。
* • **ClickHouse 为可选 profile**，`docker-compose --profile clickhouse up -d` 才会启动；不启则用 SQLite，数据量大时查询会变慢。
* • **GeoIP 需额外处理**：`GEOIP_LOOKUP_PROVIDER=local` 时需手动下载 `GeoLite2-City.mmdb` 放到 `./geoip/`；`online` 模式需配置 `GEOIP_ONLINE_API_URL`（如 `https://api.ip.sb/geoip/`）。
* • **Agent 为 Go 单独二进制**，需单独部署在网关侧（或同机），通过 `COLLECTOR_WS_PORT=3002` 与 Collector 通信。

### 🔍 核心亮点

#### 1. 「Collector + Agent + Web」三层架构：把「多网关流量聚合」做成统一可视化平台

Neko Master 不只是「一个前端面板」，而是**三层分离的完整数据管道**：

| 层 | 组件 | 技术栈 | 职责 |
| --- | --- | --- | --- |
| **采集层** | **Agent (Go)** | Go 1.23+ / 单二进制 | 部署在网关侧，通过 Clash/Surge API 采集实时流量、连接、规则命中、流量统计，推送到 Collector |
| **汇聚层** | **Collector (Node.js + Fastify + WebSocket)** | Fastify + WS + better-sqlite3 / ClickHouse | 接收多 Agent 数据、聚合去重、持久化、提供 REST + WS API、GeoIP 解析、规则/域名/地区统计 |
| **展现层** | **Web (Next.js 16 + React 19)** | Next.js 16 + React 19 + Tailwind + Recharts + shadcn/ui | 实时仪表盘、历史趋势、规则/域名/地区/网关多维钻取、暗/亮主题、i18n |

**关键设计**：

* • **Agent 纯采集、不存储、不计算**，极轻（~8 MB 二进制），部署在网关同机/同网段
* • **Collector 是核心大脑**：多 Agent 数据去重合并、实时推送 WebSocket、历史落库（SQLite 默认 / ClickHouse 可选）、GeoIP 离线/在线双模式、REST + WS 双协议供 Web 调用
* • **Web 纯展现**：Server Components + Client Components 分层、Server Actions 处理表单、Recharts 实时图表、Tailwind + shadcn/ui 组件库

**实测**：接入 Clash (9090) + Surge (6170) 两个网关，Agent 分别部署在两台网关机器上，**Collector 自动聚合两网关流量，Web UI 顶部下拉框一键切换/聚合查看**，「实时流量」「连接数」「规则命中 TOP 10」「域名 TOP 20」「地区分布」全自动聚合，**零手工拼接**。

#### 2. 「SQLite 默认 + ClickHouse 可选」：把「轻量部署」和「大数据量归档」兼容得极其优雅

这是我看过最聪明的存储分层设计：

| 存储模式 | 适用场景 | 部署方式 | 查询性能 |
| --- | --- | --- | --- |
| **SQLite (默认)** | 单网关、日均 < 100 万条、部署简单 | 单文件 `./data/stats.db`，零配置 | 百万行内毫秒级，支持全文搜索 |
| **ClickHouse (可选)** | 多网关、日均 > 100 万条、长期归档、复杂 OLAP | `docker-compose --profile clickhouse up -d` 单容器 | 亿行秒级聚合、物化视图、自动分区 |

**切换零代码改动**：环境变量 `STATS_QUERY_SOURCE=sqlite|clickhouse` 一键切换，**Collector 自动路由查询**，Web UI 完全无感。

**实测**：我先跑 SQLite 版，日均 20 万条跑了 3 天，`stats.db` 仅 1.2 GB，查询「最近 24 小时域名 TOP 50」约 300ms。切到 ClickHouse 后，同查询 **< 50ms**，且支持「最近 30 天每小时流量趋势」「规则命中率随时间变化」等复杂 OLAP，**不改一行业务代码**。

#### 3. 「规则/域名/地区/网关」四维钻取：把「流量审计」做成了可交互的探索式分析

Web UI 不只是「看图」，而是**四维联动的探索式分析面板**：

| 维度 | 可视化 | 交互 | 实测场景 |
| --- | --- | --- | --- |
| **规则统计** | 条形图（命中次数/流量/连接数） | 点击规则 → 筛选该规则下的域名/连接 | 定位「哪个规则最费流量」「哪个规则误拦」 |
| **域名统计** | 表格（域名/流量/连接数/规则/地区） | 排序/搜索/点击 → 看该域名的连接详情/时间趋势 | 定位「哪个域名偷跑流量」「CDN 域名分流是否生效」 |
| **地区分布** | 世界地图 + 表格（国家/流量/连接数） | 点击国家 → 筛选该地区的域名/规则/网关 | 定位「境外流量异常」「特定地区延迟高」 |
| **网关对比** | 多网关卡片并排（流量/连接/规则） | 切换单网关/聚合视图 | 定位「哪个网关分流异常」「主备切换是否生效」 |

**关键细节**：**所有图表基于 Recharts + WebSocket 实时推送**，「实时模式」下图表每秒自动刷新，**历史模式**下支持「最近 1h/6h/24h/7d/30d」预设 + 自定义时间范围，**暗/亮主题一键切换**，**中英双语 UI 无缝切换**。

#### 4. Agent 部署极简：Go 单二进制、配置即服务、systemd/Docker 双模式

Agent 是整个链路里最「落地」的部分——**纯 Go 编译、无依赖、单二进制、配置文件即服务**：

```
# agent/config.yaml 示例  
collector:  
  ws_url: "ws://collector:3002"  
  token: "xxx"  
gateways:  
  - name: "clash-main"  
    type: "clash"  
    api_url: "http://127.0.0.1:9090"  
    secret: "xxx"  
  - name: "surge-backup"  
    type: "surge"  
    api_url: "http://127.0.0.1:6170"  
    # surge 无 secret
```

**部署模式**：

* • **systemd 服务**：`systemctl enable --now neko-agent`
* • **Docker 容器**：`docker run -d --network host -v ./config.yaml:/app/config.yaml foru17/neko-agent`
* • **健康检查**：`/health` 端点、自动重连 Collector、断线指数退避重连

**实测**：在 Clash 网关机器上跑 `./neko-agent -c config.yaml`，**启动 0.8 秒、内存 6 MB、CPU < 0.1%**，Collector 日志立刻出现「Agent connected: clash-main」。Clash 重启后 Agent 自动重连、**零数据丢失**。

### 🚧 避坑与总结

**✅ 值得点赞的地方**

* • **三层架构清晰**：Agent 采集 / Collector 聚合存储 / Web 可视化，职责单一、水平可扩展
* • **SQLite + ClickHouse 双存储无缝切换**：小规模零配置、大规模横向扩展，查询层零侵入
* • **多网关原生聚合**：Clash/Surge/OpenClash 统一接入、统一聚合、统一可视化
* • **四维钻取（规则/域名/地区/网关）+ 实时 WS 推送**：从「看报表」变成「做分析」
* • **Agent 极简部署**：Go 单二进制、systemd/Docker 双模式、自动重连、极低资源占用
* • **技术栈现代**：Next.js 16 + React 19 + Fastify + Recharts + Tailwind + shadcn/ui + Turborepo
* • **MIT 协议、Docker 一键部署、中英双语文档、架构文档详尽**

**⚠️ 踩坑提醒**

* • **仅支持 Clash/OpenClash/Surge 网关**，不支持 V2Ray/Xray/Trojan/Shadowsocks 等其他核心
* • **ClickHouse 为可选但大数据量必选**，SQLite 单文件在亿行级查询会卡死
* • **GeoIP 需额外配置**：离线需下载 mmdb、在线需配 API、未配置时地区统计全「Unknown」
* • **Agent 需单独部署在网关侧**，无法「中心化无 Agent 采集」
* • **无内置告警/通知系统**，仅有实时仪表盘，异常需人工盯屏或二次开发
* • **无内置用户权限体系**，目前仅单管理员登录，多用户/只读角色需二次开发
* • **ClickHouse 升级/备份需自行运维**，单节点无副本，生产环境需自建集群
* • **文档以中文为主、英文为镜像**，部分进阶配置仅中文文档有

**个人判断**：如果你 **「跑 Clash/OpenClash/Surge 网关、受不了『流量看不见、审计靠猜、多网关分散』、想要『实时仪表盘+历史归档+多维钻取+多网关聚合』的开箱即用方案、且能接受『仅支持 Clash 系、ClickHouse 需自运维、无内置告警』」**，**Neko Master 是当前 GitHub 上架构最清晰、部署最省心、可视化最完善的开源网关流量可视化平台**。把它当「网关流量的 Grafana + 多网关聚合器 + 审计工作台」用，心态最稳。
