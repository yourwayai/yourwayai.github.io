前几天在 GitHub 看到 `Lee-xeo/Claude-Cage`，25 Star，标语是「把 Claude 大小姐关起来，为了更好地保护我们的相遇」。作为一个常用 Claude Code、却总被「环境检测不过、IP 指纹泄露、账号莫名其妙被封」折磨的人，正好拿来实测。

环境：macOS 15.6 (M4 Pro)、已安装 Clash Verge Rev (订阅节点正常)、Git 2.45、无 Docker/VMware/Parallels 等虚拟化软件冲突。

```
# 1. 下载安装包（官网提供 macOS .dmg）  
# 访问 https://lee-xeo.github.io/Claude-Cage/#download  
# 下载 Cage-macOS-arm64.dmg (约 1.2 GB，含 VM 镜像、Mihomo 核心、noVNC 等)  
  
# 2. 安装  
# 双击 .dmg → 拖拽到 Applications → 首次运行右键「打开」绕过 Gatekeeper  
# 首次启动会提示「需要下载客机系统镜像」，选「自动匹配本机系统版本」(macOS 15.6)  
  
# 3. 配置代理  
# 点击「配置网络与代理」 → 「添加来源」 → 导入 Clash YAML 订阅 URL  
# 在节点列表选中一个香港节点 → 点「应用代理」  
# 点击「网络检查」 → 等待 DNS/TCP/TLS/指纹/时区/语言 全绿  
  
# 4. 启动环境  
# 点击「启动 Cage 环境」 → 首次需下载 macOS 15.6 镜像 (~12 GB) → 自动创建 VM、安装工具、配置网络  
# 约 15 分钟完成（M4 Pro 32G，千兆网络）  
# 环境就绪后，点击「打开项目」→ 选一个本地项目文件夹 → 新建终端 → 输入 `claude`
```

全程约 **20 分钟**（含镜像下载）。关键体验：**全程可视化、无需写配置文件、代理/镜像/网络检查全可视化**。

**避坑点**：

* • **仅支持 Apple Silicon Mac (M1/M2/M3/M4)**，Intel Mac 无法跑 macOS 客机（文档明确写了）
* • **首次需下载 ~12 GB macOS 镜像**，需预留 30 GB+ 磁盘空间
* • **网络检查会阻断直连**，代理挂了环境直接离线，**无直连回退**
* • **Windows 11 客机需 Hyper-V**，仅支持 Win11 Pro/Enterprise/Education，Home 版不行
* • **项目间无独立隔离**，所有项目共用同一个 VM、同一套工具/账号/文件系统

### 🔍 核心亮点

#### 1. 「网络隔离 + 指纹伪装」双重护甲：把「环境检测」从代码层面干掉

这是 Cage 最核心的护城河——**不只是「走代理」，而是「全方位伪装」**：

| 隔离维度 | 实现机制 | 实测效果 |
| --- | --- | --- |
| **网络隔离** | gvisor-tap-vsock 虚拟网卡 + Mihomo 核心接管所有流量 | 客机零直连、DNS 强制走代理、UDP/IPv6/ICMP/局域网直连全阻断 |
| **代理管理** | Clash/Mihomo YAML 订阅导入、节点选择、链式代理、出口检查 | 导入 Clash 订阅 URL → 选节点 → 应用 → 网络检查全绿 |
| **指纹隔离** | 时区/语言/键盘布局/屏幕分辨率/时钟源 全伪装 | 支持「自动与代理 IP 同步时区语言」，browserleaks.com 检测全通过 |
| **网络检查** | DNS 泄露/TCP 连通/TLS 指纹/Canvas 指纹/WebRTC/字体枚举/时区语言一致性 | 关键检查未通过时**暂停外网**，不放行任何可疑流量 |

**实测**：在 browserleaks.com / ipleak.net / dnsleaktest.com / whoer.net 全套跑一遍，**零泄露、指纹与代理 IP 完全一致**。网络检查页面还给出「采样证据」截图，**可视化证明「我没泄露」**。

#### 2. 「Claude 全链路适配」：从浏览器登录到 Claude Code 进程，全链路打通

这是 Cage 区别于「通用 VM」的最大差异——**专门为 Claude 使用场景做了全链路适配**：

| 环节 | 适配内容 | 实测体验 |
| --- | --- | --- |
| **浏览器登录** | Cage 内置 noVNC + code-server + Chromium，预配置 User-Agent/指纹 | 打开 Cage 浏览器 → 访问 claude.ai → 扫码登录 → 无验证码、无风控 |
| **Claude Code 进程** | 终端内 `claude` 命令直通、OAuth 授权、API Key 注入 | 终端输入 `claude` → 浏览器弹窗授权 → 回终端直接可用 |
| **Claude Desktop** | 支持在 Cage 内运行官方 Claude Desktop（通过 noVNC） | 双击图标启动、登录同步、与 Cage 浏览器共享会话 |
| **账号管理** | 多账号额度查看、会话分配、授权切换 | 设置里查看各账号额度、新会话选账号、切换无缝 |

**实测**：在 Cage 终端跑 `claude` 写一个 React 组件，**全程零「网络错误」、零「授权过期」、零「环境异常」**。Cage 浏览器里登录 Claude.ai 后，终端里的 `claude` 直接复用会话，**零额外配置**。

#### 3. 「手机远程 + 云端部署 + Tailscale 私网」：把「Claude 办公室」装进口袋

这是 Cage 区别于「本地 VM」的差异化能力——**把隔离环境延伸到手机、服务器、私网**：

| 场景 | 实现方式 | 实测 |
| --- | --- | --- |
| **手机接续** | Android/iPhone 配对电脑 → Cage 移动端页面 → 接续 Claude Code 对话/工具审批/远程浏览器 | iPhone Safari 打开配对链接 → 扫码 → 手机上直接看终端输出、点「批准」工具调用、操作远程浏览器 |
| **云端部署** | SSH 部署到 Linux VPS / 连接现有 Linux 服务器 → 工具/任务/数据留在服务器 | `ssh root@server "bash -c \"$(curl -fsSL https://lee-xeo.github.io/Claude-Cage/install.sh)\""` → 服务器跑 Cage、本地连接 |
| **Tailscale 私网** | Cage 内登录 Tailscale → 查看网络设备 → SSH/Web/TCP 服务直连 | 手机开 Tailscale → 点 Cage 里的内网服务地址 → 直接打开 |

**实测**：在地铁上用 iPhone 接续电脑上未完成的「重构认证模块」任务，**手机上直接看到终端输出、点「批准」工具调用、甚至远程操作 Cage 浏览器改代码**，下班回家电脑上 **Cursor 直接同步、无缝衔接**。

#### 4. 基于 agent-vm + Lima + gvisor-tap-vsock：虚拟化技术栈的「站在巨人肩膀上」

Cage 不造轮子，**站在成熟开源项目肩膀上**：

| 组件 | 版本/来源 | 作用 |
| --- | --- | --- |
| **agent-vm** | sylvinus/agent-vm@652688a | VM 生命周期管理、镜像下载、工具安装、网络配置 |
| **Lima** | lima-vm/lima/v2 | macOS/Linux 上跑 VM、镜像管理、文件共享、端口转发 |
| **gvisor-tap-vsock** | containers/gvisor-tap-vsock | 虚拟网卡、流量拦截、gVisor 沙箱网络隔离 |
| **sshocker** | lima-vm/sshocker | VM 与主机 SSH/SFTP 文件共享 |
| **noVNC** | novnc/noVNC | 浏览器里看 VM 画面、操作 VM |
| **Mihomo** | MetaCubeX/mihomo | 代理核心、Clash 兼容、TUN 模式 |
| **code-server** | coder/code-server | VM 内浏览器 IDE、文件编辑 |

**关键点**：Cage **不造 VM、不造代理、不造网络栈、不造远程桌面**，而是**把成熟组件拼装成「Claude 专用隔离工作区」**。go.mod 里 `replace` 了所有核心依赖到 `third_party/`，**供应链完全可控、可复现构建**。

### 🚧 避坑与总结

**✅ 值得点赞的地方**

* • **网络隔离 + 指纹伪装双重护甲**：零泄露、可视化检查、关键检查失败即断网
* • **Claude 全链路适配**：浏览器登录 → Claude Code → Claude Desktop → 多账号管理，全链路打通
* • **手机远程 + 云端部署 + Tailscale 私网**：把「Claude 工作区」延伸到手机、服务器、私网
* • **站在巨人肩膀上**：agent-vm + Lima + gvisor-tap-vsock + Mihomo + noVNC，不造轮子、供应链可控
* • **多平台原生支持**：macOS/Windows/Linux 三端原生安装包、自动匹配宿主系统版本
* • **MIT 许可、开源透明、社区活跃、文档完善（12 语言）**

**⚠️ 踩坑提醒**

* • **仅支持 Apple Silicon Mac**，Intel Mac 无法跑 macOS 客机（只能跑 Linux/Windows 客机）
* • **Windows 11 客机需 Hyper-V**，仅支持 Pro/Enterprise/Education，Home 版不行
* • **网络仅支持 IPv4 TCP**，UDP/IPv6/ICMP/局域网直连全阻断，依赖这些的工具不可用
* • **项目间无独立隔离**，所有项目共用同一 VM、同一套工具/账号/文件系统
* • **网络检查不保证账号安全**，仅提供采样证据，无法替代完整虚拟化安全审计
* • **首次需下载 ~12 GB 镜像**，需预留 30 GB+ 磁盘、首次启动 ~15 分钟
* • **Intel Mac / Windows ARM64 / Linux ARM64 暂不支持**，硬件门槛较高

**个人判断**：如果你 **「重度使用 Claude Code、受不了封号焦虑、受不了折腾 VPS/指纹浏览器/环境检测、手头有 Apple Silicon Mac 或支持 Hyper-V 的 Windows Pro、能接受『首次下载 12 GB 镜像、项目间共用 VM、仅支持 IPv4 TCP』」**，**Claude Cage 是当前唯一把「网络隔离+指纹伪装+Claude 全链路适配+手机远程+云端部署」做成开箱即用桌面程序的开源答案**。把它当「Claude 专用的隔离工作区 + 网络/指纹护甲 + 手机/云端/私网延伸」用，心态最稳。
