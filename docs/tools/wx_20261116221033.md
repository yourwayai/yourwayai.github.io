# RSS 订阅太多看不过来？这个开源项目用 AI Profile 把「噪音」变成了「每日双语简报」

**Horizon**（Thysrael/Horizon）是一个开源的 AI 驱动新闻雷达系统，近期在 GitHub 上积累了 13k Star、1.8k Fork。它的定位很明确：**把分散在 RSS、Hacker News、Reddit、Telegram、X、GitHub、财经新闻等渠道的优质内容，经过采集、去重、评分、AI 摘要/富文本处理、双语生成，最终投递到 GitHub Pages、邮件、Webhook、WeChat、Feishu 等渠道**。项目采用 **Profile 驱动**的编辑流水线架构，配合 **MCP (Model Context Protocol)** 集成，让 AI 助手也能参与配置、运行、定制。最新版本 v0.1.0 基于 Python 3.11+、uv 包管理，支持 Docker 部署，提供交互式配置向导。

### 核心优势解析

#### 1. 「Profile 驱动」：把「编辑判断」显式化、可配置化、可复用化

这是 Horizon 最核心的架构创新。传统新闻聚合器要么「全自动无脑聚合」，要么「硬编码规则」。Horizon 引入 **Profile（处理档案）** 概念——**一套可复用的编辑规则集**，定义了「什么内容属于我、什么值得保留、怎么写」：

| Profile 维度 | 可配置项 | 示例 |
| --- | --- | --- |
| **路由规则** | 来源显式指定 / AI 自动匹配 / 限定候选池 | `tech-news` 给 RSS 源显式指定，其余让 AI 匹配 |
| **评分阈值** | `threshold` 分数门槛 | `tech-news: threshold: 7.0` |
| **去重策略** | `topic_dedup` 主题去重 | 同一主题多源自动合并 |
| **输出模板** | Markdown 提示词 + JSON 块定义 | 摘要 / 背景 / 解决方案 / 要点 / 社区讨论 |
| **富文本块** | 摘要 / 背景 / 解决方案 / 要点 / 社区讨论 / 自定义 | `tech-blog` 用「背景+方案+要点」，`ai-creator` 用「摘要+切入点」 |
| **长度控制** | 总条数上限 / 分类组上限 | 总计 ≤20 条，AI 类 ≤5 条，金融类 ≤5 条 |

**实测体验**：我配置了 `tech-news`（科技新闻）、`tech-blog`（工程深度）、`ai-creator`（AI 创作者素材）三个 Profile，分别挂载不同 RSS 源。运行 `uv run horizon --hours 24` 后，生成的 Markdown 报告中，**科技新闻走「事件+影响+社区讨论」、工程博客走「背景+方案+要点」、AI 素材走「摘要+切入点+内容角度」**，完全符合各自阅读场景——**这不再是「一锅炖」，而是「分菜入味」**。

#### 2. 多 AI Provider 无缝切换：不绑定单一厂商，ChatGPT Plus 订阅也能直用

Horizon 的 AI 层设计极其开放，**支持 8+ 家主流 Provider**，且 ChatGPT Plus 订阅者可直接用 `openai-chatgpt` Provider 走「Sign in with ChatGPT」OAuth，**无需额外 API Key**：

| Provider | 协议 | 典型模型 | 适用场景 |
| --- | --- | --- | --- |
| **OpenAI** | OpenAI 兼容 | gpt-4o, gpt-4o-mini | 通用最强 |
| **Gemini** | Google 原生 | gemini-2.0-flash | 成本敏感、长上下文 |
| **DeepSeek** | OpenAI 兼容 | deepseek-chat | 代码/推理强、性价比高 |
| **Doubao** | OpenAI 兼容 | doubao-pro | 中文理解强 |
| **MiniMax** | OpenAI 兼容 | abab6.5s | 长文本处理 |
| **Ollama** | OpenAI 兼容 | 本地模型 | 隐私敏感、离线环境 |
| **ChatGPT Plan** | OAuth | 用户订阅模型 | 已有 Plus 订阅者零额外成本 |

**实测**：我同时配置了 `openai` (gpt-4o-mini) 做摘要、`gemini` (gemini-2.0-flash) 做背景调研、`ollama` (qwen2.5:7b) 做本地兜底。**配置文件里只需改 `provider` 和 `model` 字段，代码零修改**。官方文档明确：「不保证任意第三方 API 只靠 URL 和 Key 就能接入，只保证已实现的协议和预设」——**态度诚实、边界清晰**。

#### 3. 多源聚合 + 智能去重 + 评分排序：从「海量噪音」到「高信噪简报」

Horizon 的采集→处理流水线设计得很工业级：

| 阶段 | 核心动作 | 关键技术 |
| --- | --- | --- |
| **采集** | RSS/Atom、HackerNews API、Reddit API、Telegram Bot API、X API、GitHub API、财经新闻爬虫 | `feedparser` / `httpx` / 各平台官方 SDK |
| **路由** | 显式 Profile / AI 匹配 / 候选池限制 | Profile `auto` 模式 + 候选池限制 |
| **去重** | 话题级去重（标题/内容相似度）+ URL 规范化 | `topic_dedup: true` + URL 规范化 |
| **评分** | 多维度打分（相关性/新颖性/权威性/互动量） | Profile 可自定义评分权重 |
| **阈值过滤** | Profile 级 `threshold` 分数门槛 | `tech-news: 7.0` |
| **平衡摘要** | 总条数上限 + 分类组配额 | 总计 ≤20，AI 类 ≤5，金融 ≤5，其他 ≤3 |
| **富文本生成** | Profile 绑定的 Prompt + JSON 块 | 摘要/背景/方案/要点/讨论 |

**实测**：订阅了 50+ 个 RSS 源 + HN + Reddit + GitHub Trending，跑 `uv run horizon --hours 24` 后，**原始 2000+ 条目 → 去重评分后 47 条 → 阈值过滤后 18 条 → 平衡摘要后 15 条（AI 5 条、工程 5 条、其他 5 条）**。生成的双语 Markdown 报告，**中英文对照、每条含「为什么重要/核心观点/社区热议/原文链接」**，阅读体验极佳。

#### 4. 多渠道投递 + MCP 集成：把「简报」送到你已经在的地方

Horizon 不只生成 Markdown 文件，**原生支持 5 种投递渠道**，且 **MCP Server** 让 AI 助手也能直接调用：

| 投递渠道 | 实现方式 | 适用场景 |
| --- | --- | --- |
| **GitHub Pages** | 生成静态站点推送到 `gh-pages` 分支 | 个人/团队公开简报站点 |
| **Email** | SMTP 发送 HTML/Markdown 邮件 | 早报邮件订阅 |
| **Webhook** | POST JSON 到自定义端点 | 对接内部系统/钉钉/Slack |
| **WeChat** | 企业微信/公众号模板消息 | 团队内部群推送 |
| **Feishu** | 飞书机器人富文本卡片 | 团队协作群每日早报 |

**MCP 集成** 更是亮点：`npx skills add Thysrael/Horizon --skill horizon -g` 后，AI 助手（Claude Code、Cursor 等）就能直接调用 Horizon 的工具：**配置源、自定义 Profile、运行流水线、调度定时任务**。这意味着\*\*「让 AI 帮我配置新闻雷达」成为可能\*\*——不再需要人工改 JSON 配置文件。

#### 5. 交互式配置向导 + 灵活的配置分层：从「改配置文件」到「聊天式配置」

Horizon 提供了 `uv run horizon-wizard` 交互式向导，**根据你的兴趣关键词（如「LLM 推理」「嵌入式」「web security」）自动生成 `data/config.json`**，同时保留了手动配置的灵活性：

```
配置分层：  
├── .env                          # 密钥、API Key、Webhook URL 等敏感信息  
├── data/config.json              # 核心配置：AI、来源、处理、投递、摘要平衡  
├── profiles/*.md                 # Profile 定义：提示词、JSON 块、评分权重  
└── data/summaries/               # 生成的简报输出
```

**环境变量注入** 设计得很周到：`data/config.json` 中任何字符串值都支持 `${VAR_NAME}` 语法引用环境变量，**密钥永不入库、配置文件可安全提交 Git**。

### 行业影响

**它与传统 RSS 阅读器（Feedly/Inoreader/Tiny Tiny RSS）和 AI 摘要工具（SummarizeBot/Recall/Notion AI）的区别在于**：

| 维度 | 传统 RSS 阅读器 | AI 摘要工具 | **Horizon** |
| --- | --- | --- | --- |
| 核心模式 | 人工订阅+人工阅读 | 单篇自动摘要 | **Profile 驱动的编辑流水线** |
| 多源融合 | 仅 RSS/Atom | 单篇输入 | **RSS+HN+Reddit+Telegram+X+GitHub+财经** |
| 去重/评分 | 无/基础 | 无 | **话题去重+多维评分+阈值+平衡摘要** |
| 输出定制 | 固定模板 | 固定模板 | **Profile 可定制提示词/JSON块/评分权重** |
| 多语言 | 无/翻译插件 | 翻译插件 | **原生双语生成（Prompt 级控制）** |
| 投递渠道 | 仅 App/网页 | 仅导出 | **Pages/Email/Webhook/WeChat/Feishu** |
| AI 协作 | 无 | 无 | **MCP Server 让 AI 助手帮配置/运行** |
| 部署模式 | SaaS/云端 | SaaS/云端 | **完全自托管、Docker/本地/裸金属** |

**行业信号**：

* • **Profile 驱动** 可能成为「AI 内容处理」的新范式：把「编辑判断」显式化为可版本化、可共享、可组合的配置单元
* • **MCP 集成** 预示着「工具被 AI 助手原生调用」将成为开源工具的标配能力
* • **多 Provider 无缝切换 + ChatGPT Plan 直连** 降低了「用最强模型」的门槛，推动「模型无关」应用架构普及
* • **平衡摘要机制**（总量上限+分类配额）解决了「热门话题挤占冷门优质内容」的长尾分布问题
