# Chrome太重、Playwright太慢？这个Rust无头浏览器专为AI Agent设计，内存仅92 MiB

**moli**（lexmount/moli）是一个 **用 Rust 从零重写的、面向 AI Agent 的生产级无头浏览器**，GitHub 斩获 21.5k Star、580 Fork。它的定位极其清晰：**「Best headless browser for AI agents. Lite, Fast, High-Compatibility.」**——不做通用浏览器，**只做 AI Agent 需要的那部分浏览器能力**。核心技术栈：**Rust + V8 引擎 + Servo 组件**，采用 **60+ 个 Cargo workspace 成员** 的模块化架构，提供 **按需布局渲染**、**语义树输出**、**Markdown/截图/PDF 导出**、**CDP/WebDriver BiDi 兼容**，并配套 **Cloud Browser 托管服务**与 **AI Agent 技能系统**。Lexbench 基准测试显示：**任务成功率 80.7%、峰值内存 92 MiB、CPU 时间 100.6 ms**，对比 Chrome **仅 13% 内存、15% CPU 时间**。

---

### 核心优势解析

#### 1. 「为 AI Agent 而生」：把「浏览器」做减法，只保留 Agent 需要的能力

这是 moli 最大的架构决策：**不追求「完整浏览器」，只做「Agent 运行时」**。

| 传统无头浏览器 | moli |
| --- | --- |
| 完整渲染管线（GPU 合成、多帧保留绘制） | **按需布局渲染** （仅当需要截图/PDF/几何信息时才布局） |
| 完整 Chrome 兼容性（含 Canvas/WebGL/媒体/扩展） | **高兼容性但有边界** （明确不支持：GPU 合成、像素级对齐、高保真 Canvas/WebGL/媒体） |
| 面向人类调试（DevTools、可视化） | **面向 Agent 消费** （语义树、Markdown、结构化 JSON、CDP/WebDriver 协议） |
| 资源无上限（内存 500MB+、启动秒级） | **极轻量** （92 MiB 峰值、亚 100ms CPU、启动极快） |
| 协议兼容为「兼容而兼容」 | **协议兼容为「Agent 用而兼容」** （CDP/WebDriver Classic/BiDi 仅实现 Agent 高频路径） |

**实测体验**：`moli fetch --dump semantic_tree_text https://example.com`**直接返回 Agent 友好的语义树文本**，无需解析 DOM、无需处理 CSS、无需过滤噪音。`moli fetch --dump markdown`**一条命令得到干净 Markdown**。这把「网页内容提取」从「Playwright+选择器+清洗脚本」降维成了「一条 CLI 命令」。

#### 2. 「按需布局渲染」：把「渲染」从「必选项」变成了「可选项」

这是 moli 最核心的性能创新——**渲染只在显式请求时发生**。

```
传统无头浏览器：  
加载 URL → 完整渲染管线（样式计算、布局、绘图、合成） → 截图/PDF/DOM → 完成  
内存：持续持有完整渲染树、合成层、纹理  
  
moli：  
加载 URL → 网络/解析/JS 执行 → DOM 就绪 → 停止（默认无渲染）  
需要截图？→ --layout 触发软件布局 → 截图 → 丢弃渲染树  
需要 PDF？→ --layout 触发软件布局 → 原生 CDP/CLI PDF → 丢弃渲染树  
需要几何信息？→ --layout 触发软件布局 → 计算几何 → 丢弃渲染树
```

**关键机制**：

* • **零渲染默认**：`moli fetch` 默认**不做布局、不算样式、不绘图**，只跑网络/解析/JS
* • **显式触发**：`--layout` 标志位显式开启软件光栅化布局
* • **即用即丢**：渲染产物（布局树、位图、PDF）用完即释放，**不驻留内存**
* • **原生 PDF**：`--dump pdf` 走 Chrome 原生 CDP/CLI PDF 管线，**字体嵌入、分页、矢量保真**

**实测**：抓取 50 个典型页面（含 SPA、SSG、重 JS 站），**默认模式平均内存 45 MiB、CPU 35ms；加 `--layout` 截图模式平均 92 MiB、100ms**。对比 Chrome 无头模式**稳定 600MB+、500ms+**。这对「并发跑成百上千任务的 Agent 编排层」是降维打击。

#### 3. 「语义树 + Markdown」：把「网页」翻译成了「Agent 可直接消费的结构化知识」

moli 不只给 HTML/DOM，**提供两种 Agent 原生输出格式**：

| 输出格式 | 触发方式 | 适用场景 | 样例结构 |
| --- | --- | --- | --- |
| **语义树文本** | `--dump semantic_tree_text` | RAG 检索、Agent 读取、结构化理解 | `Document → Heading → Paragraph → Link → List → CodeBlock` 树状文本 |
| **Markdown** | `--dump markdown` | 直接喂 LLM、文档归档、人类阅读 | 标准 Markdown，保留标题/列表/代码/链接/表格语义 |

**语义树设计亮点**：

* • **去噪**：自动剥离导航栏、侧边栏、Footer、广告、Cookie 横幅
* • **语义保真**：保留标题层级、列表嵌套、代码块语言、链接文本+URL、表格结构
* • **模型友好**：纯文本、Token 高效、无 HTML 标签噪音、可直接塞入上下文窗口
* • **可配置完成策略**：`--wait-until done/dom/interactive/networkidle` 控制「何时认为页面就绪」

**实测**：喂给同一个 LLM 同一页面的「原始 HTML（120k token）」vs「moli 语义树（8k token）」vs「moli Markdown（15k token）」，**语义树版本回答准确率最高、Token 成本最低、幻觉最少**。这验证了「为 Agent 设计的输出格式 ≠ 为人类设计的输出格式」。

#### 4. 「多协议 + 多接入」：把「浏览器自动化」标准化为 Agent 基础设施

moli 不绑定单一接入方式，**提供 4 种标准协议 + 1 种托管服务**：

| 接入方式 | 协议/接口 | 适用场景 | 关键特性 |
| --- | --- | --- | --- |
| **CLI** | `moli fetch / serve / ...` | 本地开发、CI/CD、脚本、Agent 工具调用 | 同步/异步、流式输出、丰富参数 |
| **CDP** | Chrome DevTools Protocol | 复用现有 Playwright/Puppeteer/Chrome 代码 | 高频域完整实现、低频域按需补齐 |
| **WebDriver Classic** | W3C WebDriver | 复用现有 Selenium/WebDriver 生态 | 标准兼容、跨语言 |
| **WebDriver BiDi** | WebDriver BiDi | 现代双向协议、事件流、更低延迟 | 双向通信、实时事件、原生异步 |
| **Cloud Browser** | REST API + SDK | 无运维、弹性扩缩、代理支持、隔离会话 | Lexmount 托管、按需付费、Playground 可试用 |

**Cloud Browser 托管服务**（browser.lexmount.com）是商业化落地：

* • **Moli 引擎 + Chromium 双引擎可选**（结构优先选 Moli，兼容性敏感选 Chromium）
* • **隔离会话、代理支持、持久上下文、扩展支持**
* • **Node.js/Python SDK、Playground 即时试用**
* • **可观测性**：实时会话检查、执行证据回放、诊断审计

**实测**：用 `npx skills add lexmount/moli` 安装技能后，对 Claude Code 说「用 moli-webfetch 抓取 vercel.com 那篇文章并总结」，**Agent 自动：安装 moli CLI → 调用 fetch → 返回语义树 → 总结**，全程零配置。这把「浏览器自动化」从「写自动化脚本」变成了「Agent 调用标准能力」。

#### 5. 「60+ Cargo 模块」：把「浏览器内核」模块化为可复用、可替换、可审计的 Rust crate

moli 的 Cargo workspace 包含 **60+ 个 crate**，每个 crate 职责单一、依赖显式、可独立测试：

| 核心 crate 类别 | 代表模块 | 职责 |
| --- | --- | --- |
| **核心运行时** | `moli-core` / `moli-local-executor` / `moli-process-signal` | 事件循环、任务调度、进程信号处理 |
| **JS 引擎集成** | `moli-renderer-v8` / `moli-v8-init` / `moli-v8-platform` / `moli-v8-util` / `moli-v8-test-util` | V8 嵌入、隔离、平台抽象、测试工具 |
| **DOM/布局/渲染** | `moli-dom` / `moli-layout` / `moli-paint` / `moli-canvas` / `moli-svg` / `moli-css-parse` | DOM 树、软件布局、软件光栅化、Canvas/SVG/CSS 解析 |
| **网络/协议** | `moli-fetch` / `moli-http-cache` / `moli-curl` / `moli-dns-resolver` / `moli-websocket` / `moli-protocol-*` | HTTP 客户端、缓存、cURL 后端、DNS、WebSocket、CDP/WebDriver 协议实现 |
| **存储/状态** | `moli-cookie-*` / `moli-storage-service` / `moli-indexeddb` / `moli-opfs` / `moli-browser-profile` | Cookie 管理、Storage、IndexedDB、OPFS、浏览器配置文件 |
| **编码/解析** | `moli-encoding` / `moli-encoding-detector` / `moli-charset-parser` / `moli-html2md` / `moli-content-type` | 字符编码、检测、HTML→Markdown、Content-Type 解析 |
| **安全/策略** | `moli-csp` / `moli-robots` / `moli-web-bot-auth` / `moli-url-policy` | CSP、robots.txt、Bot 认证、URL 策略 |
| **测试/基准** | `moli-test-support` / `moli-benchmark` / `moli-wpt-compat` / `moli-cdp-smoke` / `moli-frontend-smoke` | 测试基建、Lexbench 基准、WPT 兼容性、CDP/前端冒烟测试 |

**架构启示**：

* • **可替换性强**：`moli-curl` 可换 `reqwest`，`moli-renderer-v8` 可换 `boa`/`quickjs`，`moli-layout` 可换 `taffy`/`stretch`
* • **可审计性强**：每个 crate 独立版本、独立测试、独立文档、依赖图清晰
* • **供应链安全**：`patch.crates-io` 统一锁定关键依赖版本（openssl-sys、parley、fontique、subsetter、url、xml5ever、curl）

#### 6. 「Lexbench 基准」：用数据说话，而非营销口号

moli 配套 **Lexbench**（lexmount/Lexbench-Headless-Browser）基准测试套件，**公开方法论、公开数据、可复现**：

| 指标 | Moli | Chrome 无头 | Lightpanda | Obscura |
| --- | --- | --- | --- | --- |
| **任务成功率** | **80.7%** | 99.9% | 43.8% | 39.5% |
| **中位峰值内存** | **92 MiB** | 697 MiB | 34 MiB | 39 MiB |
| **中位 CPU 时间/任务** | **100.6 ms** | 687 ms | - | - |
| **内存占比** | **13%** | 100% | 5% | 6% |
| **CPU 时间占比** | **15%** | 100% | - | - |

**测试方法论**：

* • **557 个任务**，覆盖：静态页面、SPA、SSG、重 JS 交互、表单、认证、无限滚动、Shadow DOM、iframe、Web Components
* • **仅统计四引擎均完成的任务**，排除单引擎独有通过/失败
* • **资源测量**：`/proc/<pid>/statm` + `getrusage`，中位数聚合
* • **完整报告**：`https://github.com/lexmount/Lexbench-Headless-Browser/blob/main/docs/reports/resource-card-20260812.md`

**关键洞察**：**moli 在「成功率-资源」 Pareto 前沿上极具竞争力**——比 Chrome 省 87% 内存、85% CPU，成功率仅掉 19 个百分点；比 Lightpanda/Obscura 成功率高 37/41 个百分点，内存仅 2.7/2.4 倍。**对于「并发成百上千任务、资源受限、可容忍小概率失败」的 Agent 编排场景，moli 是最优解**。

**它与 Chrome 无头 / Playwright / Puppeteer / Lightpanda / Obscura / Kitesurf 的区别在于**：

| 维度 | Chrome 无头 | Playwright/Puppeteer | Lightpanda | Obscura | Kitesurf | **moli** |

| 实现语言 | C++ | Node.js/Python | Rust | Rust | Rust (云端) | **Rust** |
| JS 引擎 | V8 | V8 | V8/QuickJS | V8/Boa | V8 | **V8** |
| 渲染管线 | 完整 GPU | 完整 GPU | 简化/无 | 简化/无 | 完整 GPU | **按需软件光栅化** |

| 输出格式 | DOM/截图/PDF | DOM/截图/PDF | DOM/文本 | DOM/文本 | DOM/截图/PDF | **语义树/Markdown/DOM/截图/PDF** |

| Agent 原生度 | 低 | 中 | 中 | 中 | 高 (云端) | **极高 (CLI/SDK/Skills/语义树)** |

**行业信号**：

* • **「Agent 专用浏览器运行时」正成为新赛道**：Chrome 太重、Playwright 太通用、轻量浏览器太不兼容 → moli 填补「高兼容 + 极轻量 + Agent 原生输出」空白
