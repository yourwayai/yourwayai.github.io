# OpenMausBot：开源「多 Bot 协作桌面端」，每个联系人都是独立 AI Agent，自带云电脑并行干活

**OpenMausBot**（milind-soni/OpenMausBot）是一个 **开源的、本地优先的「多 AI Bot 协作桌面应用」**，GitHub 斩获 23.9k Star、3.3k Fork。

它的定位极其清晰：**「The open-source Grok Bot alternative: your own team of AI bots, in a chat app.」**——**不做「更聪明的单一助手」，做「一个装着多个专业 Bot 的通讯录」**。核心架构：**Electron + React 19 + TypeScript (strict)**，打包为 **macOS (Apple Silicon + Intel, 签名公证 .dmg) / Windows (x64 安装包) / Ubuntu 24.04 (.deb + AppImage beta)** 三平台原生安装包。**Apache-2.0 协议、无加密货币/代币、独立项目（非 xAI/Meta/OpenAI/Manus 关联）**。

### 核心优势解析

#### 1. 「Bot 通讯录」范式：把「单一助手」拆解为「专业分工的 Bot 团队」

这是 OpenMausBot 最大的交互创新——**把 AI 从「一个万能聊天框」重构为「多个专业联系人」**。

| 传统 AI 助手 | OpenMausBot Bot 通讯录 |
| --- | --- |
| 一个模型、一套人设、一个上下文 | **每个 Bot：独立人格 + 独立模型 + 独立云电脑 + 独立连接应用** |
| 所有任务挤在同一会话 | **并行多任务：销售跟进 Bot 跑邮件、招聘 Bot 筛简历、记账 Bot 对账、SEO Bot 写文章** |
| 上下文污染、指令冲突 | **物理隔离：Bot 间不共享上下文、不抢 Token 预算、不互相干扰** |
| 统一审批、统一监控 | **分布式审批：每个 Bot 只在关键节点 @你，你像管团队一样管它们** |

**实测体验**：打开侧边栏，看到 **「Chief of Staff (Claude Sonnet 5) / Sales Follow-up / Support Triage / Recruiter / Bookkeeper / SEO Growth」** 六个 Bot。**每个 Bot 都是真实的 `claude`/`codex`/`grok` CLI 进程**，运行在各自的云桌面或本机上。**给「Sales Follow-up」发「跟进上周所有未回复线索」，它自动打开 CRM、查邮件、发提醒、回结果**；同时「Recruiter」在另一个云桌面筛简历、**互不干扰、并行推进**。**这不再是「聊天」，是「派工」。**

#### 2. 「Bring Your Own Agents」：零代理、用自己的订阅、数据不出本机

OpenMausBot **不托管模型、不代理 API、不收订阅费**——**它只是个「编排器 + 容器管理器」**。

| 维度 | 传统 AI 应用 | OpenMausBot |
| --- | --- | --- |
| **模型来源** | 自家/代理/混合 | **你的 `claude`/`codex`/`grok` CLI 本地登录** |
| **认证方式** | 平台账号 / API Key | **CLI 原生登录（`claude auth login` / `codex auth` / `grok login`）** |
| **计费归属** | 平台订阅 / 按 Token | **你的 Anthropic/OpenAI/xAI 账单，原价直达** |
| **数据流向** | 经平台服务器 | **CLI 直连模型厂商，OpenMausBot 仅调度进程、转发标准输入输出** |
| **引擎可替换** | 固定 | **Settings → Engines 指向任意 CLI 二进制（版本化构建/Wrapper）** |

**关键设计**：**`claude`/`codex`/`grok` CLI 作为「引擎」被托管**，OpenMausBot 通过标准输入输出与之通信，**完全不接触 API Key、不解密请求、不记录对话内容**。这意味着：

* • **隐私极致**：对话内容仅在 CLI 进程内存与模型厂商之间流动
* • **零锁定**：随时卸载 OpenMausBot，CLI 照常能用、配置照常保留
* • **成本透明**：模型费用 100% 走你自己的账单，**无平台溢价、无隐形 Token 消耗**

#### 3. 「每 Bot 一台云电脑」：把「工具调用」升级为「完整桌面自动化」

这是 OpenMausBot 区别于「MCP/Function Calling/Plugin」架构的核心差异——**不给模型「工具」，给模型「一台电脑」**。

| 传统工具调用 | OpenMausBot 云电脑 |
| --- | --- |
| 模型输出 JSON → 本地执行函数 → 返回结果 | **模型操作完整桌面：打开浏览器/终端/邮件/Excel/任意 GUI 应用** |
| 需预定义 Schema、维护 Wrapper | **零 Schema：模型像人类一样点击、输入、截图、读屏** |
| 受限于预置工具集 | **通用性：云桌面里装什么，模型就能用什么** |
| 无视觉反馈、难调试 | **实时屏幕预览：你在侧边栏看到 Bot 正在「打开 Mail → 搜索发票 → 点击发送」每一帧** |

**云电脑来源**：

* • **免费版**：接入 **boat.dev** 等云桌面提供商，**按需拉起、用完即销毁、自带实时屏幕流**
* • **本地模式**：**指向「这台 Mac/PC」**，Bot 直接操作你的物理机器（需授权、可监控）

**官网演示案例**：「Bookkeeper」Bot 在云桌面里：

```
atlas@cloud: ~  
✓ opened Mail  
✓ found 4 overdue invoices  
✓ reminder sent to Northwind ($1,280)  
✓ reminder sent to Globex ($860)  
✓ reminder sent to Initech ($2,450)  
✓ reminder sent to Hooli ($430)
```

**每一步都有屏幕截图、终端输出、GUI 操作记录**，你随时可介入、暂停、修正。**这把「Agent 能力上限」从「会调 API」直接拉到了「会用电脑」。**

#### 4. 「定时自动化 + 连接应用」：把「被动问答」变成「主动运营」

Bot 不只等你说话，**支持按计划自动执行、连接外部应用**：

| 自动化类型 | 典型配置 | 执行逻辑 |
| --- | --- | --- |
| **定时任务** | `Sales Follow-up: Weekdays at 9:00 AM` / `Support Triage: Every 30 minutes` / `Recruiter: Weekdays at 8:00 AM` | 到点自动唤醒 Bot、拉起云电脑、执行预设流程、结果推送给你 |
| **事件触发** | 邮件到达 / 日历冲突 / GitHub PR / Slack 提及 | Webhook → Bot 唤醒 → 处理 → 回报 |
| **连接应用** | Google (Gmail/Calendar/Drive) / Slack / GitHub / Notion / Linear / 任意 OAuth 应用 | Bot 在云桌面里用 OAuth 登录、操作原生 Web 界面、无需平台侧适配 |

**关键洞察**：**连接应用不走「平台集成」，走「云桌面里的浏览器 OAuth」**。Bot 像人类一样：打开 Gmail → 点授权 → 拿 Cookie/Token → 后续直接用。**这意味着：只要网页版能干的事，Bot 都能干，无需等平台开发 SDK。**

#### 5. 「桌面原生分发 + 签名公证」：把「开源项目」交付为「商业级可信软件」

| 平台 | 分发制品 | 信任链 |
| --- | --- | --- |
| **macOS** | `.dmg` (Apple Silicon + Intel 通用) | **Apple Developer ID 签名 + 公证** → 双击即装、无 Gatekeeper 拦截 |
| **Windows** | `.exe` (x64 安装包) | **代码签名证书** → SmartScreen 通过、标准安装向导 |
| **Ubuntu** | `.deb` + `AppImage` (beta) | **GPG 签名 + APT 仓库** / 单文件可执行 |

**发布工程化**：

* • **GitHub Actions 自动构建三平台制品** → 附带校验和、签名、Release Notes
* • **版本语义化**：`v0.x.y` 预发布、频繁迭代（171 个 `claude[bot]` 贡献说明有自动化）
* • **回滚/历史版本**：`all releases` 页保留全量制品，**用户可锁定稳定版**

**实测安装**：macOS 下载 `.dmg` → 双击 → 拖入 Applications → 打开 → **无任何「未识别开发者」警报、无需 `xattr -d`、无需关闭 SIP**。**这在开源 Electron 应用中极其罕见**，说明维护者投入了真金白银买证书、跑公证流程。

#### 6. 「社区驱动 + 商业可持续」：无币、无融资压力、靠云服务商赞助与专业服务

| 维度 | 典型开源 AI 项目 | OpenMausBot |
| --- | --- | --- |
| **代币/融资** | 常有币/融资/估值压力 | **明确声明：No token, no crypto, no allocation** |
| **商业模式** | SaaS 订阅 / 企业版闭源 | **云提供商赞助 + 专业服务 + 社区捐赠** |
| **云资源** | 自建/用户自付 | **boat.dev / Google Cloud for Startups / Claude for Startups 赞助免费额度** |
| **维护动力** | 创始人全职 / 公司养活 | **主维护者 6393 contributions、10 位核心贡献者、GitHub Actions 自动化** |

**可持续性信号**：**不卖模型调用、不卖数据、不卖 Token**，收入仅来自「帮企业部署/定制/集成」的专业服务、**云厂商为了展示 GPU/桌面能力提供的免费额度赞助**、**用户自愿捐赠**。**这规避了「开源 AI 项目不得不闭源核心功能以求生存」的通病。**

### 行业影响

**它与「ChatGPT / Claude.ai / Grok.com / Manus / Meta Muse / OpenAI dots / Cue by Manus」的区别在于**：

| 维度 | ChatGPT/Claude.ai/Grok.com | Manus/Muse/dots/Cue | **OpenMausBot** |
| --- | --- | --- | --- |
| 核心范式 | 单一聊天助手 | 单一自主 Agent | **多 Bot 并行通讯录** |
| 模型绑定 | 自家模型 | 自家/指定模型 | **Bring Your Own (Claude/Codex/Grok/自定义 CLI)** |
| 执行环境 | 沙箱/工具调用 | 云端容器/VM | **完整云桌面 / 本地物理机** |
| 数据隐私 | 平台可见 | 平台可见 | **本地 CLI 直连模型厂商，平台不碰数据** |
| 并行能力 | 单线程 | 单线程 | **原生多 Bot 并行、各自独立云电脑** |
| 部署形态 | Web/App (云端) | Web/云端 | **桌面原生应用 (签名公证) + 手机伴随端** |
| 扩展性 | 插件/Function Calling | 内置工具 | **云桌面通用性：装什么软件能干什么事** |
| 商业模式 | 订阅/按量 | 待定/企业级 | **开源核心 + 专业服务 + 云厂商赞助** |
| 许可证 | 专有 | 专有/源码可用 | **Apache-2.0（商业友好、可闭源嵌入）** |

**行业信号**：

* • **「多 Agent 专业分工」正成为「AI 生产力工具」的新交互范式**：单一万能助手遇到上下文/注意力/Token 预算天花板，**专业 Bot 团队**是破局路径
* • **「云桌面即工具层」** 把「Agent 能力边界」推向了「通用计算」：**不再为每个能力写 Wrapper，给 Agent 一台电脑**
* • **「本地优先 + BYO Agent (Bring Your Own Agent)」** 成为「隐私敏感/企业合规/成本控制」场景的标准架构：**平台不托管模型、不代理流量、不存数据**
* • **「桌面原生 + 签名公证 + 多平台制品」** 确立了「开源 Electron 应用交付商业级信任」的工程标杆
