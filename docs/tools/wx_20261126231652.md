# Fox：yourwayai 开源的「Markdown AI 伴读工具」，Zed 分栏 + 零复制提问 + 透明 Token 预算，把「读不懂就问」做成了桌面级工作流

**Fox**（yourwayai/fox）是 **yourwayai 团队打造的开源「Markdown AI 伴读桌面工具」**，目前处于 **MVP 规划与 Web 原型阶段**（GitHub 创建于 2026-11-14）。

它的定位极其聚焦：**「Fox，陪你读懂每一段。」**——不做全能编辑器、不做知识库、不做云同步，**只做一件事：让你在阅读 Markdown 时，「划选即问」，AI 回答有上下文、有预算、可追溯、不打断阅读流**。核心交互参考 **Zed 编辑器的分栏模式**：右侧专注阅读原文，左侧围绕文档与 AI 对话。**技术栈**：React 18 + TypeScript + Tailwind CSS + Zustand + 原生 SSE + Prism.js，**规划迁移至 Tauri 2 桌面端**，**隐私优先、本地存储、直连用户自有 AI 端点（OpenAI-compatible / DeepSeek / Ollama）**，**Apache-2.0 意向许可证**（规划中）。

### 核心优势解析

#### 1. 「Zed 风格分栏伴读」：把「阅读」与「提问」物理隔离，互不干扰

这是 Fox 最大的交互创新——**拒绝「单栏聊天式阅读」，采用「双栏并行工作区」**。

| 传统「复制到聊天工具」模式 | Fox 分栏伴读模式 |
| --- | --- |
| 选中文字 → Cmd+C → 切窗口 → Cmd+V → 发送 → 切回文档 → 找阅读位置 | **选中文字 → 浮现 `[✨ 解释]` / `[➕ 加入提问]` → 点击 → 左侧流式回答，右侧位置纹丝不动** |
| 上下文靠记忆/再次复制 | **自动追踪：选区所属标题层级（如 `# Ch1 > ## 1.2 架构`）+ 邻近段落 → 作为上下文注入** |
| 追问需重新说明背景 | **同一文档会话隔离：每个 Markdown 文件绑定独立 AI 线程，切换文档自动切会话** |
| 不知道 AI 读了什么 | **发送预览：系统指令 / 选区原文 / 历史对话 / 预算占用 → 多段式透视，超预算主动告警** |

**实测体验（Web 原型）**：打开一个 2000 行的技术 README，看到不懂的「容器查询」段落，**鼠标划选 → 点 `[✨ 解释]` → 左侧 2 秒内流式输出解释，右侧滚动位置完全保持**；想追问「和媒体查询有什么区别？」，**点 `[➕ 加入提问]` → 补全问题 → 发送**，上下文自动带上刚才的选区+标题路径。**全程零切窗、零复制粘贴、零「刚才在哪读着」。**

#### 2. 「透明上下文预算 + 防静默截断」：把「Token 黑盒」变成「可视可控的预算仪表盘」

这是 Fox 对「AI 伴读信任感」最硬核的工程承诺——**拒绝「静默截断后声称理解全文」**。

| 痛点 | Fox 方案 |
| --- | --- |
| 文档太长超模型上下文 → 静默截断头/尾 → AI 瞎编 | **实时 Token 进度条：当前消耗 / 用户设定预算（如 8k/16k/32k）** |
| 不知道发给模型的是什么 | **「发送内容预览」面板：系统指令 / 选区引用 / 历史对话 / 文档范围 → 逐段可展开/移除** |
| 超预算无感知、无对策 | **超预算主动告警弹窗：一键「清空历史」/「精简选区」/「仅发当前问题」 → 用户显式决策** |
| 追问时历史无限累积 | **预算优先保留：当前问题 + 选区原文 > 最近历史 > 早期历史 → 自动裁剪并标记「历史范围已变更」** |

**关键设计**：**未知模型使用保守 Token 估算（不声称精确）、预留回答空间、文档作为「待分析资料」隔离处理（防提示词注入）**。这让「上下文管理」从「模型内部黑箱」变成了「用户可见、可干预、可审计的预算决策」。

#### 3. 「引用反向定位 + 脉冲高亮」：把「对话引用」变成「原文导航锚点」

解决「AI 回答里引用了原文，我想回去对照，却找不到在哪」的经典痛点。

```
左侧聊天记录：  
┌─────────────────────────────────┐  
│ 💬 用户：解释这段关于容器查询的代码 │  
│ 🤖 AI：这段代码使用了 @container...  │  
│ ┌─────────────────────────────┐   │  
│ │ 📎 引用：# Ch3 > ## 3.2 语法    │   │ ← 点击此卡片  
│ │ @container (min-width: 400px) │   │  
│ └─────────────────────────────┘   │  
└─────────────────────────────────┘  
           ↓ 点击  
右侧 Markdown 阅读区：  
→ 平滑滚动到 `# Ch3 > ## 3.2 语法` 段落  
→ 原文区域「脉冲高亮」2 秒（淡入淡出），自动居中  
→ 阅读位置同步更新，狐狸尾巴随之舒展
```

**工程实现**：**开发时保留 Markdown 源文本与渲染节点的位置映射（`scrollTop` 像素级）**，引用卡片存储 `documentId + headingPath + textRange`，**点击即跳转、高亮、恢复阅读上下文**。这把「问答」与「阅读」真正闭环了。

#### 4. 「狐狸吉祥物：从装饰到状态机」——用「尾巴/耳朵」把抽象状态具象化

Fox 不只是个 Logo，**是一个「有限状态机」的视觉化表达**，承载两类核心反馈：

**尾巴：辅助表达阅读位置（文档侧）**

| 阅读状态 | 尾巴姿态 |
| --- | --- |
| 文档开头 | 自然收拢 |
| 向后推进 | 逐步舒展、轻微抬起 |
| 滚动停止 | 轻摆一次后静止 |
| 到达文末 | 尾尖轻动一次 |
| 快速滚动 | 不重复触发动画 |

**耳朵：辅助表达 AI 状态（对话侧）**

| AI 状态 | 耳朵姿态 | 文字提示 |
| --- | --- | --- |
| 未配置服务 | 自然放松 | 配置 AI 服务 |
| 准备就绪 | 双耳竖起 | 随时可以提问 |
| 等待响应 | 轻动一次 | 正在等待回答 |
| 正在生成 | 保持专注 | 正在回答… |
| 请求失败 | 略微放低 | 请求失败，点击重试 |

**无障碍设计**：**全局仅一个主要动态狐狸、动画不承载唯一信息（始终配合文字/图标）、提供「减少动画」开关（跟随系统 `prefers-reduced-motion` 或手动）、状态变化不抢键盘焦点**。这让「吉祥物」从「可爱摆设」进化为「低干扰、高信息密度的状态指示器」。

#### 5. 「自定义 AI 服务 + 隐私优先」：把「模型选择权、数据控制权」还给用户

Fox **不托管模型、不代理请求、不收订阅费**——**它只是个「本地编排器 + 直连客户端」**。

| 维度 | 典型 AI 阅读插件/SaaS | Fox |
| --- | --- | --- |
| **模型绑定** | 固定/有限选项 | **自定义 Base URL + API Key + Model Name（手填）** |
| **协议支持** | 专有/厂商 SDK | **OpenAI-compatible Chat Completions（含 DeepSeek/Ollama/自建代理）** |
| **数据流向** | 经平台服务器 → 模型厂商 | **浏览器/桌面端直连用户端点 → 模型厂商** |
| **API Key 存储** | 明文 localStorage / 平台数据库 | **Web 原型：localStorage（规划迁移系统凭据库）；桌面端：系统 Keychain / Credential Manager** |
| **隐私承诺** | 隐私政策/合规认证 | **代码级保证：无中间服务器、无遥测、无账户系统、文档不上传** |
| **本地模型** | 通常不支持 | **Ollama 一键预设（免 Key、本地跑、数据不出机）** |

**规划书明确边界**：**第一版仅保证已验证的 OpenAI-compatible 协议范围，不依赖 `/models` 接口（模型名手填）、远程服务强制 HTTPS、本机服务允许 HTTP、「测试连接」提示可能产生少量费用**。这把「模型接入」从「平台许可的白名单」变成了「用户可控的直连配置」。

#### 6. 「从 Web 原型到 Tauri 2 桌面端」：技术栈演进路线图清晰

当前 GitHub 仓库是 **Vite + React Web 原型**（`npm run dev` 秒级热更、免 Rust/Xcode），**规划书明确了迁移路径**：

| 层次 | Web 原型 (当前) | 桌面端 MVP (规划) |
| --- | --- | --- |
| **桌面框架** | 浏览器 (Web) | **Tauri 2 (Rust + WebView)** |
| **本地存储** | localStorage | **SQLite (通过 Tauri 插件)** |
| **密钥管理** | localStorage (过渡) | **系统凭据库** |
| **网络层** | Fetch + SSE | **Rust HTTP 客户端 + SSE 解析（绕过 CORS、证书/代理自控）** |
| **文件访问** | File System Access API / 拖入 | **原生文件系统权限、路径越界校验** |
| **打包分发** | 静态托管 | **签名公证 .dmg/.exe/.deb/AppImage** |
| **Fox 动画** | CSS transform + SVG | **分层 SVG + CSS transform（复用 Web 实现）** |

**核心架构分层**（规划书 6.3）：

```
界面层: Markdown阅读区 / AI对话区 / 服务配置 / Fox状态动画  
    ↓  
本地应用层: 文档读取权限 / 上下文组装预算 / AI Provider适配 / 流式响应取消 / SQLite / 系统凭据库  
    ↓  
用户指定 AI 服务: 直连，无中间代理
```

**开发计划**：**5-6 周、1 名全栈工程师、首发单平台**、6 个阶段里程碑清晰，**第 3 周「阅读→选区→提问→得解释」闭环为硬指标**，Fox 动画可降级为静态状态切换。这让「从原型到产品」的路径极其具体、可执行、可验收。

### 行业影响

**它与「Notion AI / Obsidian 插件 / VS Code Copilot / ChatPDF / 通用聊天工具」的区别在于**：

| 维度 | Notion AI / Obsidian 插件 | VS Code Copilot / Cursor | ChatPDF / 网页聊天 | **Fox** |
| --- | --- | --- | --- | --- |
| **核心场景** | 笔记/知识库写作 | 代码编写 | 单文档问答 | **Markdown 专注阅读 + 伴随提问** |
| **交互范式** | 内联/侧边栏生成 | 编辑器内联/Chat | 上传→聊天 | **Zed 分栏：右读左问、位置锁定** |
| **选区提问** | 需复制/右键菜单 | 右键菜单/快捷键 | 全文上传 | **零复制：划选即现 `[解释]/[加入提问]`** |
| **上下文透明度** | 低/黑盒 | 中/部分可见 | 低/全文上传 | **高：预算进度条+发送预览+超预算告警+可裁剪** |
| **引用回跳** | 无/弱 | 有(代码跳转) | 无 | **强：引用卡片点击→平滑滚动+脉冲高亮** |
| **模型自由度** | 平台绑定 | 平台绑定/有限 | 平台绑定 | **完全自定义：Base URL/Key/Model 手填** |
| **隐私模型** | 云端/数据上传 | 云端/遥测 | 上传平台 | **本地直连/无中间层/Key 进凭据库/无遥测** |
| **多文档隔离** | 笔记本/工作区 | 工作区 | 单文档 | **每文档独立会话，切换即隔离** |
| **阅读位置记忆** | 有 | 有 | 无 | **像素级 scrollTop 恢复，跨会话/重载不丢** |
| **品牌交互** | 无 | 无 | 无 | **狐狸尾巴/耳朵状态机，低干扰高信息密度** |

**行业信号**：

* • **「阅读伴随式 AI」正成为「文档型知识工作」的新交互范式**：不再是「上传文档→聊天」，而是「原地阅读→点选即问→上下文透明→位置不丢」
* • **「Token 预算可视化 + 用户显式裁剪」** 确立了「上下文管理用户主权」的新标准：不再接受「静默截断」
* • **「本地优先 + 直连用户自有端点 + 系统凭据库」** 成为「隐私敏感/企业合规/成本控制」场景的工程基线
* • **「吉祥物即状态机」** 为「AI 状态可感知化」提供了低认知负荷、高信息密度的设计范式
* • **「Tauri 2 + Rust 网络层 + Web 前端」** 确立了「桌面级 AI 原生应用」的性能/安全/分发生态最优解
